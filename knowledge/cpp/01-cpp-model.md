C++ 常被介绍为「带类的 C」，这个说法低估了它。C++ 与 C 的分界线不是「多了类」，而是多了一整套**编译期机制**：构造/析构让资源管理变成自动纪律，模板让类型系统开始做计算，值语义让对象的复制与销毁有统一的规则。这些机制的共同目标是 Bjarne Stroustrup 定下的那句口号——**零开销抽象**（zero-overhead abstraction）：你不用你没用到的功能；你用到的功能，手工写不会更快。

理解这句话是理解 C++ 的钥匙。它不是营销词，而是一份可以逐条验证的契约：虚函数的间接调用就是你手写函数指针的成本，异常处理不开异常时零成本，`std::string` 的析构就是你手写 `free` 的成本。C++ 的所有「复杂」——构造函数、移动语义、模板——都是在回答同一个问题：**怎么把 C 程序员手工做的事变成类型系统自动做的事，且不让自动做的那份变慢**。

## 1. 定位：一门「什么都想要」的语言如何不自伤

C++ 站在一个刁钻的位置上：既要 C 的贴地性能，又要有高级语言的表达力。这门语言的选择造就了它的性格：

| 领域   | C++ 给的东西           | 代价                    |
| ---- | ------------------ | --------------------- |
| 资源管理 | RAII：作用域结束自动释放     | 必须理解构造/析构/拷贝/移动规则     |
| 抽象   | 类、模板、STL：近乎脚本语言的写法 | 编译错误晦涩、编译时间、头文件依赖     |
| 性能   | 零开销抽象，能与 C/汇编同台    | UB 的种类比 C 更多更隐蔽       |
| 生态   | 庞大的标准库与第三方生态       | 语言每三年更新，历史代码风格跨度 40 年 |

「什么都想要」的直接后果是：**C++ 是少数「写对了很难」的语言**。Python 写得难看但很少写得危险；C++ 的编译器放行大量「能跑但错」的代码。所以 C++ 的学习方法必须是**规则驱动**的——先接受一套编码规约（本文与后续篇章会给出），再理解规则背后的机制，最后才知道哪里可以破例。反过来（先自由发挥再补规则）在 C++ 里几乎注定产出事故。

> [!NOTE]
> 什么时候选 C++？性能敏感 + 需要抽象能力 + 能承担工程纪律的场景：游戏引擎、图形、高频交易、数据库内核、浏览器。只需要性能不需要抽象时 C 更简单；需要抽象但性能一般时 Python/Rust/Java 更省心。C++ 的甜蜜区是「既要又要」——它的高复杂度是为这个甜蜜区付的税。

## 2. 与 C 的关系：不是超集，是另一套世界观

C++ 几乎兼容 C 的语法，但**默认行为发生了质变**。列四条最有代表性的：

### 2.1 内存分配：new 的三件事 vs malloc 的一件事

```cpp
// C：分配字节，返回 void*，失败返回 NULL
Widget *w = (Widget *)malloc(sizeof(Widget));

// C++：分配 + 构造 + 失败抛异常
Widget *w = new Widget;          // 自动调用构造函数
delete w;                        // 自动调用析构函数再释放
```

`new` 做三件事（分配、构造、类型检查），malloc 做一件事（给字节）。这个差别在后面所有篇章里不断放大：**C++ 的对象有「生命周期语义」，从构造完成到析构开始**——对象的每一段生命都有类型系统盯着。

### 2.2 类型系统：引用与重载

```cpp
void grow(int &x) { x *= 2; }        // 引用：C++ 的「必须指向有效对象」的指针
int  abs(int x);                     // 重载：同名不同参
double abs(double x);
```

C 里「函数修改外部变量」要传 `int*`（指针可以为空、可以乱指）；C++ 的引用**在语言层面承诺指向有效对象**（虽然实现上还是指针，但契约更强）。重载让一个动词服务多种类型——这两者是 STL 能存在的语法基础。

### 2.3 翻译模型的差异：名字修饰与模板实例化

C++ 支持重载，所以编译器必须把参数类型编进符号名（name mangling：`abs(int)` 和 `abs(double)` 是两个符号）。由此带来 C++ 工程的两大现实：

1. **C 互操作要显式声明**：`extern "C"` 关掉修饰，让 C 编译器/链接器认得符号。
2. **模板实例化发生在编译期**：每个用到的模板实参组合都生成一份代码——这是编译时间与二进制膨胀的来源，也是模板「零开销」的实现方式（生成的就是特化后的机器码）。

### 2.4 头文件的演化

C++ 生态在 C 的头文件模型上长出了自己的花样：`std::` 前缀与命名空间防冲突、`<iostream>` vs `<stdio.h>` 的两套 IO、C++20 的 `import`（模块，头文件的替代品）。工程要点：**标准库一律 `std::` 前缀**（不写 `using namespace std;`——它把几百个名字倒进全局，冲突隐患），头文件放声明、模板除外（模板必须在头文件里，见[第 7 篇](07-templates.md)）。

## 3. 值语义：C++ 世界观的骨架

C++ 对象的默认世界观是**值**：对象就是一段有类型、有边界、可复制、可比较的存储。这个选择与 Java/Python 的「引用语义」世界观截然不同：

```cpp
// C++：值语义 —— b 是 a 的完整副本
std::vector<int> a = {1, 2, 3};
std::vector<int> b = a;              // 拷贝：b 有自己的 1,2,3
b.push_back(4);
// a 仍是 {1,2,3}：两者从此无关

// Java/Python：引用语义 —— b 与 a 是同一个对象
// b = a; b.add(4);  →  a 也变成 {1,2,3,4}
```

值语义的三个工程后果：

1. **别名问题消失**：没有共享可变状态，函数拿到的是副本，「谁改了我的数据」这类 bug 天然不存在。并发编程里值语义是免疫证（[第 13 篇](13-concurrency.md)）。
2. **生命周期简单**：对象的死亡就是作用域结束（或容器销毁），不需要 GC 也不需要手动 free。
3. **拷贝可能昂贵**：vector 有百万元素时拷贝是真拷贝。C++ 的解法是**移动语义**（[第 5 篇](05-copy-move.md)）——「把昂贵拷贝变成廉价所有权转移」，这是 C++11 最重要的机制。

> [!TIP]
> \| C++（值语义）            | Java/Python（引用语义）        |
> \| ------------------ | ----------------------- |
> \| 对象 = 数据本身        | 对象 = 数据的引用          |
> \| 赋值 = 深拷贝          | 赋值 = 传递引用            |
> \| 死亡 = 作用域结束（确定性） | 死亡 = GC 回收（不确定）    |
> \| 共享需要显式（指针/引用） | 共享是默认，隔离才需要（clone） |
> \| 昂贵拷贝 → 移动语义     | 天然共享，无此问题         |

## 4. RAII：一页预览，全书的承重墙

C++ 资源管理的核心思想值得在开篇就立起来（[第 4 篇](04-raii.md)全面展开）：**资源绑定对象，对象的析构函数释放资源，而 C++ 保证析构函数在作用域结束时必定执行**。

```cpp
void process(const std::string &path) {
    std::ifstream file(path);              // 打开文件（构造 = 获取资源）
    if (!file) throw std::runtime_error("open failed");

    std::vector<char> buf(1024 * 1024);    // 分配内存（构造 = 获取资源）

    do_work(file, buf);
}   // ← 无论正常返回还是异常，两个析构都必然执行：close + free
```

对照 C 的版本：每个提前 return 和异常路径都要手动 `fclose`/`free`（[C 篇第 12 篇](../c/12-errors-robustness.md)的 goto cleanup 模式）。C++ 把这个模式从「纪律」升级成了「机制」——**你不可能忘记释放，因为它不是你写的**。

RAII 是理解 C++ 一切的透镜：智能指针是「堆内存的 RAII 包装」（[第 6 篇](06-smart-pointers.md)），锁守卫是「锁的 RAII 包装」，事务类是「数据库事务的 RAII 包装」。后面的篇章里，这个思想会以不同名字反复出现。

## 5. 标准库全景：C++ 的「 batteries included」

C++ 标准库（STL 是它最大的组成部分）的分层地图，后续篇章按此展开：

| 层       | 代表设施                                          | 篇目              |
| ------- | --------------------------------------------- | --------------- |
| 语言机制    | 引用、类、构造/析构、模板、异常、lambda                       | 2、3、4、5、7、10、11 |
| 智能指针    | `unique_ptr` `shared_ptr` `weak_ptr`          | 6               |
| 容器      | `vector` `string` `map` `unordered_map` `set` | 8               |
| 算法与函数对象 | `sort` `find` `transform`、lambda、ranges       | 9               |
| 词汇类型    | `optional` `variant` `string_view` `span`     | 12              |
| 并发      | `thread` `mutex` `atomic` `future`            | 13              |

一条选型直觉贯穿全书：**标准库优先，第三方次之，自造最后**。STL 的容器与算法经过几十年打磨与最广泛的测试，绝大多数「自己写个链表/字符串」的冲动都是 bug 工厂。

## 6. 编译与工程：和 C 共享工具链的差异点

```bash
g++ -std=c++20 -Wall -Wextra -Werror -g -O2 main.cpp -o app
```

- **标准选择**：新项目 `-std=c++20`（concepts、ranges、format 就绪）；C++11 是兼容性底线，C++98 风格代码值得逐步现代化。
- **警告体系**：与 C 同款的 `-Wall -Wextra -Werror`，外加 `-Wshadow`、`-Wconversion` 渐进启用。
- **三套构建**：C 篇的 debug/sanitized/release 策略原样适用，CMake 的 `CMAKE_CXX_FLAGS_DEBUG/SANITIZED/RELEASE` 三配置（[C 篇第 10 篇](../c/10-header-linking.md)的三套配置思想）。
- **编译时间**是 C++ 特有的工程负担：模板实例化 + 头文件包含。缓解手段（前置声明、Pimpl、预编译头、模块）在[第 6 篇](06-smart-pointers.md)与[第 7 篇](07-templates.md)展开。

## 7. 什么时候不该用 C++

1. **不需要极致性能的业务系统**：Go/Java/Python 的开发效率优势碾压，C++ 的复杂度税白交。
2. **内存安全要求极高且团队无 C++ 纪律**：Rust 在类型系统层面强制了 C++ 靠约定保证的东西；新写的系统级代码值得认真评估 Rust。
3. **字符串/集合密集的快速原型**：C++ 的编译-链接循环与显式内存模型拖慢迭代。
4. **团队无规则共识**：C++ 允许的写法跨度极大，没有共同规约的团队写 C++ = 四种语言混跑在一个仓库里。

反过来说，游戏引擎、图形学、高频交易、数据库内核、浏览器、LLM 推理框架——这些「性能与抽象都要」的领域仍是 C++ 的统治区，而且短期内没有替代者。

## 8. 陷阱清单

- 把 C++ 当「带类的 C」写：手动 new/delete、C 风格字符串、裸指针所有权——错过了语言提供的全部自动化机制。
- `using namespace std;` 进头文件：几百个名字污染全局，冲突后报错误导人。
- 忽视值语义与引用语义的边界：`auto x = vec[0]` 是拷贝还是引用取决于类型，[第 2 篇](02-references-auto.md)展开。
- 新项目选 C++98 风格：没有智能指针与移动语义的 C++ 是事故放大器；现代基线 c++17/20。
- 与 C 的 ABI 边界不写 `extern "C"`：链接器找不到符号。
- 认为零开销抽象是「绝对零」：它承诺的是「不比手写慢」，不是「零成本存在」——虚调用、模板膨胀、异常表都有各自的账（各篇展开）。
- 学习路径走反：先自由写再补规则。C++ 必须规则先行（本书的篇章顺序就是规约顺序）。

## 9. 小结

- C++ 与 C 的分界不是「有类」，而是编译期机制：构造/析构、模板、值语义——共同目标是零开销抽象（不用不付钱，用了不比手写慢）。
- 值语义是 C++ 世界观的骨架：对象是可复制的数据本身，别名问题消失、生命周期确定、昂贵拷贝由移动语义解决——这是它与 Java/Python 引用语义世界的根本差异。
- RAII 把资源管理从纪律升级为机制：资源绑定对象，析构自动执行；智能指针、锁守卫都是它的应用。
- 工程基线：`-std=c++20 -Wall -Wextra -Werror`、三套构建配置、`std::` 前缀、标准库优先。
- C++ 的甜蜜区是「性能与抽象都要」；写对它的前提是规则先行——这是全书编排的依据。

## 10. 练习

**1.** 用 C 与 C++ 各写一个「读文件到字符串返回」的函数，对比资源管理代码的行数与出错路径数，说明 RAII 消灭了什么。

> [!TIP]
> 思路 C 版：fopen + 多个失败分支 goto cleanup + fclose；C++ 版：ifstream 构造、失败 throw、无任何手动清理。数「提前退出路径」的数量：C 版每多一个失败检查多一条清理路径，C++ 版恒为 0。RAII 消灭的是「错误路径与资源释放的交叉组合爆炸」。

**2.** 写程序验证值语义：函数内修改传值参数的 vector，主调方的 vector 是否变化？再写一个传 `std::vector<int>&` 的版本对比。这就是「C++ 默认拷贝，共享需显式」的实证。

> [!TIP]
> 思路传值版本：函数内 push\_back 不影响主调方（副本）。传 `vector<int>&` 版本：影响——引用是显式共享。对照 Python：`def f(x): x.append(1)` 的列表参数永远影响调用方。语言默认值的差异决定了一类 bug 的存在与否。

**3.** 在 Compiler Explorer 上对比「手写 3 个 int 的交换」与 `std::swap` 生成的汇编，验证零开销抽象。

> [!TIP]
> 思路 `-O2` 下两者汇编完全一致：std::swap 是模板，实例化后就是手工写的临时变量交换。零开销抽象的检验方法就是这类对照——抽象的语法糖在优化后消失，只留下你手写时的机器码。

**4.** 解释为什么 `malloc(sizeof(Widget))` + 手动调用「构造逻辑」的写法在 C++ 里是错的，即使它能编译。构造函数还承担哪些 `new` 之外的职责？

> [!TIP]
> 思路构造函数不只是「初始化字段」：它建立类不变量（对象从此处于有效状态）、可能获取资源（RAII 的获取端）、参与重载决议与聚合初始化。绕过构造的对象「没有生命周期语义」——它的析构、拷贝、比较全部建立在不变量之上，绕过等于在类型系统背后挖墙脚。

**5.** 写一个 `extern "C"` 的 C++ 函数并从 C 代码里调用它，观察去掉 `extern "C"` 时的链接错误信息，理解 name mangling 的证据链。

> [!TIP]
> 思路`nm cpp.o` 可见 `_Z7cpp_addii` 这类修饰名；`extern "C"` 后变回 `cpp_add`。C 链接器找的是裸名，找不到修饰名 → undefined reference。这条边界就是「C++ 写内核模块/对接 C 库」的第一课。

**6.** 讨论题：同一个「解析 CSV 并统计」的任务，分别用 C++（vector+string+算法）、C（手动内存）、Python 写。对比三者的代码量、内存管理操作数、运行速度，给出三者各自合理的适用场景。

> [!TIP]
> 思路C++ 代码量约为 C 的 1/3（容器与算法接管了内存与循环），速度与 C 同级（零开销抽象），内存管理操作数为 0（RAII）。Python 代码量最少但慢 10\~100 倍。场景推导：性能敏感 + 结构复杂 → C++；极致性能 + 极致控制 → C；快速验证 → Python。「既要又要」正是 C++ 的存在理由。
