MATLAB 的性能问题几乎总是一种形态：**把「对每个元素做的事」写成了显式循环**。向量化就是把循环体的意图翻译成矩阵/索引表达式——既是性能优化，也常常是可读性提升（意图从「怎么算」变成「算什么」）。本篇给出完整的手法清单与测量工作流。

## 1. 循环为什么慢：解释器税与 JIT 的现实

```matlab
% 慢版：每次循环都有「解释执行 + 边界检查 + 临时分配」的税
s = 0;
for k = 1:1e6
    s = s + v(k) * v(k);
end

% 向量化版：一次函数调用，循环下沉到 C/BLAS
s = sum(v.^2);              % 或 v*v'（若行向量）—— BLAS 级速度
```

机制：MATLAB 是解释执行的动态语言，每轮循环的 `v(k)` 索引、类型分派、结果分配都要解释器过手；而 `sum` 的循环在编译好的 C 里连续内存扫描（列优先完美预取）。R2015b 起 JIT（即时编译）把简单循环提速一个量级——**「永远别写循环」已成过时教条**，但「热点循环先试向量化」仍是正确顺序。

## 2. 向量化手法清单

### 2.1 逻辑索引：条件化处理的标准答案

```matlab
% 循环版：找 >10 的元素平方
r = [];
for k = 1:numel(v)
    if v(k) > 10, r(end+1) = v(k)^2; end     % 双重罪：循环 + 动态增长
end

% 向量化：
r = v(v > 10).^2;                            % 一行：掩码过滤 + 逐元素平方
```

### 2.2 维度化汇总：把「沿行/列扫描」交给 dim

```matlab
% 循环版：每行求最大值
for i = 1:size(M,1), rowmax(i) = max(M(i,:)); end
rowmax = max(M, [], 2);                      % dim=2：沿行压缩

[cum, ia] = max(M, [], 1);                   % 每列最大值 + 所在行号
[Mmax, Midx] = max(M, [], 2);                % 双输出的下标同样维度化
```

### 2.3 diff / cumsum / cumprod：递推的专用武器

```matlab
d = diff(v);                       % 相邻差分 v(2)-v(1), ...
c = cumsum(v);                     % 累积和 —— 「前 n 项和」免循环
p = cumprod(v);

% 例：积分（梯形）与求「首次超过阈值的时间」
area = cumtrapz(t, y);             % 累积积分
t_first = t(find(c > 100, 1));     % cumsum + find：状态扫描向量化
```

「当前值依赖历史」的递推看起来必须循环，但**很多递推本质是前缀运算**（cumsum/cumprod/累积最大）——识别出这个模式就多解一类循环。

### 2.4 隐式扩张与 meshgrid：多维公式

```matlab
% 每行减去该行均值（循环 → 隐式扩张一行）
Mc = M - mean(M, 2);                       % (n×1) 自动扩张对齐 (n×m)

% 二维函数采样（[第 2 篇](02-matrices.md)的 meshgrid）
[X, Y] = meshgrid(linspace(-2,2,200));
Z = sin(3*X) .* exp(-Y.^2);
```

### 2.5 accumarray：分桶聚合

```matlab
% bins(1)=1, bins(2)=2, ...：把 vals 按分组下标求和
sums = accumarray(bins(:), vals(:));       % 组 k 的和落在第 k 行
counts = accumarray(bins(:), 1);           % 计数
means = accumarray(bins(:), vals(:), [], @mean);   % 任意聚合函数
```

accumarray 是「groupby 求和」的矩阵形态——与 [table 的 groupsummary](07-data-io.md)（语义层）互补（性能层）。

### 2.6 矩阵化重写：把「相邻元素的关系」变成矩阵乘

```matlab
% 循环版：y(k) = 0.5*x(k) + 0.5*x(k-1)（滑动平均）
for k = 2:n, y(k) = 0.5*(x(k)+x(k-1)); end

% 向量化（一阶差分组合）：
y = [x(1), 0.5*(x(2:end) + x(1:end-1))];
% 或卷积视角：conv(x, [0.5 0.5])
```

「每个输出依赖输入的固定窗口」= 卷积/滤波器形态——filter/conv/矩阵乘（Toeplitz）都是它的向量化出口。

## 3. 预分配：最便宜的优化

```matlab
% 慢：每轮扩容（重分配 + 拷贝，总代价 O(n²)）
x = [];
for k = 1:1e6, x(end+1) = sqrt(k); end

% 快：先定形状再填充（O(n)）
x = zeros(1, 1e6);
for k = 1:1e6, x(k) = sqrt(k); end

x = sqrt(1:1e6);                   % 更快：完全向量化
```

1e6 元素的动态增长实测可达秒级 vs 预分配毫秒级——**「数组尺寸在写循环前就确定」是 MATLAB 的第一性能纪律**。实在无法预知尺寸：分块增长（每次翻倍）或攒元胞后串联。

## 4. profiler 工作流：测量、定位、验证

```matlab
profile on
myBigComputation();
profile viewer             % 打开热点报告：每函数的调用次数/总时间/自时间
profile off

% 报告里点函数名 → 逐行时间（line-level）—— 热点行一眼可见
```

工作流纪律（与[C 篇](../c/13-tools-debugging.md)、[python 篇](../python/12-quality.md)同一套）：**先 profile 再优化**；每次只改一处；timeit 复测：

```matlab
timeit(@() myFun(A))       % 多次测量取中位 —— 别用 tic/toc 的单次读数下结论
```

## 5. 内存意识

```matlab
A = rand(1e4);             % 8×10⁸ B = 800MB —— double 每元素 8 字节的现实
B = A;                     % 写时复制：不立即拷贝（修改时才真正复制）
C = A * A';                % 临时矩阵同样要内存 —— 链式大矩阵运算检查中间体尺寸

% in-place 修正：x = x + 1 是复制；x = x + 1 在函数内对输入参数操作可触发原地
clear largeVar             % 释放；who/whos 查工作区占用
```

大数组的三个内存杠杆：**single 换 double（减半，GPU/深度学习标配）**、**稀疏化（[第 8 篇](08-linear-algebra.md)）**、**分块处理（datastore/tall，[第 7 篇](07-data-io.md)）**。

## 6. 陷阱清单

- 向量化引入巨大临时矩阵：`sum(A.^2)` 的 A.^2 要一份新内存——分段计算或用 dot/norm 内建。
- 「向量化成布尔/整数灾难」：过度嵌套的索引表达式难读难调；可读性向量化（意图清晰）优先于极限向量化。
- timeit 之外用单次 tic/toc 下结论：缓存/JIT 预热让首跑虚高。
- profile 只看总时间：自时间（self time）与调用次数才是热点定位。
- 预分配错形状（行/列）：`zeros(n,1)` vs `zeros(1,n)` 影响后续所有运算与列优先效率。
- 隐式扩张的静默大矩阵：两个大数组隐式扩张乘出巨阵（内存峰值）——扩张方向要显式想清。
- 忽视 JIT 的进步：简单小循环不必强扭向量化（可读性优先）；大循环 + 复杂体仍是向量化主场。

## 7. 小结

- 循环的税是解释开销与临时分配；JIT 时代「简单循环可接受」，但热路径仍按「逻辑索引 → 维度化 → 前缀函数 → 累积/卷积 → 矩阵化」的顺序找向量化出口。
- 六大手法的定位：逻辑索引管条件处理、dim 管沿维汇总、diff/cumsum 管差分与前缀、隐式扩张管异形对齐、accumarray 管分桶、conv/filter/矩阵乘管窗口关系。
- 预分配是第一纪律：尺寸先定后填；动态增长 O(n²) 的定量差距实测可感。
- 性能工作流：profile 定热点（自时间/调用次数）→ 单点修改 → timeit 验证——测量文化优先于技巧堆叠。
- 内存三杠杆：single、稀疏、分块；写时复制让 B=A 便宜，但修改即拷贝。

## 8. 练习

**1.** 用 timeit 对比同一任务的四种实现：显式循环、预分配循环、逻辑索引、完全向量化（如「把向量中 >100 的元素置 0」），记录 n=10⁵ 与 10⁷ 的耗时表。

> [!TIP]
> 思路预期：动态增长 >> 预分配循环 > 逻辑索引 ≈ 向量化。注意 10⁷ 时「内存带宽」成为共同下限——性能优化的收益曲线最终撞物理墙。

**2.** 向量化「两两距离矩阵」：n×d 的数据集算 n×n 欧氏距离，分别用双重循环与隐式扩张 `(X - X').^2` 累加法（或 pdist2 对照），对比耗时与内存。

> [!TIP]
> 思路经典技巧：‖x−y‖² = ‖x‖² + ‖y‖² − 2xᵀy 一行矩阵乘。注意大 n 的临时矩阵与数值精度（平方差公式在近零距离处误差）——性能与数值的两难是真实工程决策。

**3.** 把牛顿迭代（[第 4 篇](04-control-flow.md)练习 2）保持循环（有依赖链），把「每步记录误差历史」改为预分配——展示「算法本身必须循环 + 数据采集可向量化」的混合形态。

> [!TIP]
> 思路递推算法的循环是本质（不能向量化），但循环内的记录、统计可以。性能工作的成熟标志：分清「必须循环的核」与「可向量化的壳」。

**4.** 用 profile 分析一段包含「字符串拼接循环、重复计算常数、大矩阵转置拷贝」的脚本，找出三个热点并逐一修复，记录每次修复后的 timeit 变化。

> [!TIP]
> 思路经典三热点：sprintf 循环（改 join 式 cellstr）、循环内调用不变函数（提出来）、A' 进热循环（预转置）。profile 的逐行视图让「我以为的瓶颈」与「真实瓶颈」的差距显形。

**5.** 用 accumarray 重写「按班级统计成绩的均值/最大值/中位数」三连，并与 groupsummary（table 路线）对照——总结两条路线（性能层 vs 语义层）的选择标准。

> [!TIP]
> 思路accumarray 快且通用（自定义聚合函数），groupsummary 可读且直接输出 table。数据已在 table 且要出报表 → groupsummary；裸数组百万级性能敏感 → accumarray。

**6.** 讨论：MATLAB 代码评审中「把循环改成向量化」何时是坏建议？从「可读性损失、临时内存、隐式扩张风险、维护者水平」四个角度给出反面清单。

> [!TIP]
> 思路坏建议的形态：把 5 行清晰循环压成 3 行嵌套索引魔法、为向量化引入 O(n²) 临时矩阵、JIT 时代对 10 行小循环的执念。性能优化的成本是「维护者的认知负荷」——profile 证明有收益才是入场券。
