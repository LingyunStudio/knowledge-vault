MATLAB 慢的锅九成在写法。向量化消灭显式循环，预分配消灭数组生长，稀疏矩阵消灭多余零——三板斧下来，同一个问题常能快两个数量级。动手优化前先用 profile 找热点，别凭感觉改。

## 向量化替代循环

```matlab
%% ❌ 循环逐点算
n = 1000000;
y = zeros(n, 1);
for k = 1:n
    y(k) = sin(2*pi*k/n);
end

%% ✅ 整段算：没有循环，读起来就是数学公式
k = (1:n)';
y = sin(2*pi*k/n);
```

向量化不只是"把 for 删掉"，而是把"遍历 + 判断"改写成集合运算。常见翻译对照：

| 循环写法 | 向量化写法 |
| --- | --- |
| 逐点算函数值 | `y = f(x)` 直接对数组算 |
| 累加满足条件的元素 | `sum(x(x > 0))` |
| 双重循环求内积 | `dot(a, b)` 或 `a * b'` |
| 每行减去该行均值 | `A - mean(A, 2)`（隐式扩展） |
| 逐点平方 | `x.^2` |

隐式扩展是最容易被忽视的一板斧，很多"逐行处理"的循环都能广播掉：

```matlab
A = rand(1000, 3);
A = A - mean(A);           % 每列减均值：1×3 自动扩展成 1000×3

A = A ./ max(A, [], 1);    % 每列除以最大值，同样一步到位
```

掩码索引、`sum/max/mean` 聚合、隐式扩展是向量化的三板斧。注意 `arrayfun`/`cellfun` 不是提速工具——它们只是语法糖，速度未必比写得好的循环快，用它们图的是可读性。

> [!TIP]
> 不是所有循环都该消灭：迭代收敛、前后依赖（`x(k) = x(k-1) + ...`）这类算法上就串行的循环，向量化不出来，预分配好数组后老老实实循环即可。JIT 对简单循环已经不慢，先测再改。

## 预分配避免数组生长

```matlab
%% ❌ 每轮 end+1：数组每轮整体搬家，总代价 O(n^2)
r = [];
for k = 1:100000
    r(end+1) = sqrt(k);
end

%% ✅ 先定尺寸，按下标写
r = zeros(1, 100000);
for k = 1:100000
    r(k) = sqrt(k);
end
```

MATLAB 数组定长存储，每次追加都要重新分配、整体拷贝，越到后面每轮越贵。尺寸未知时也预分配一个上界、最后截断，仍然远快于 end+1。预分配的类型要和最终内容匹配：存文本用 `cell(1, n)`，存数值才用 `zeros`。

> [!WARNING]
> 判断是否在"数组生长"很简单：循环体里出现 `end+1`、`[acc, x]` 这类追加拼接就是。一条语句的改动，通常快一个数量级起步——这是性价比最高的优化，没有之一。

## 稀疏矩阵省内存

大矩阵里绝大多数是零时，改用稀疏存储：只记非零元的 (行, 列, 值)：

```matlab
i = [1 2 3 4];  j = [1 2 3 4];  v = [10 20 30 40];
S = sparse(i, j, v, 10000, 10000);   % 万阶矩阵，只存 4 个数
E = speye(10000);                    % 稀疏单位阵
S2 = S + E;
[nzR, nzC, nzV] = find(S);           % 取回非零元下标与值
nnz(S)                               % 非零元个数
```

10000×10000 的 double 稠密矩阵约 800 MB，稀疏化后只有几十字节；`\` 求解与特征值计算的时间也大幅下降。但稀疏运算要挑着用：`\`、乘法能保留稀疏性，而 `inv(S)` 或往稀疏阵里加稠密数据会"填满"（fill-in），稀疏性瞬间退化——解方程永远写 `S\b`，别写 `inv(S)`。

> [!WARNING]
> 稀疏不是免费午餐：元素密集的矩阵转成 sparse 反而更慢（多了索引开销）。先用 `nnz(S)/numel(S)` 看非零占比，通常低于 5% 才值得转。

## 热路径上的反面模式

有些写法单看无害，放进热点就拖垮整体：

```matlab
% eval('y = x + 1');                 % ❌ eval 绕过 JIT，报错也难定位
% clearvars                          % ❌ 循环里清工作区：变量反复重建
% s = struct(sprintf('f%d', k), v);  % ❌ 动态字段名，无法静态优化
```

替代方案都很直接：动态拼数据改成数组加一维或 cell 数组；动态字段名改成下标访问；"按名字调用函数"的场合用函数句柄存进结构体或容器（见[函数](05-functions.md)）。另外别把函数调用当洪水猛兽——MATLAB 的调用开销早已不是主要矛盾，为省调用把代码塞成巨型函数是因噎废食，可读性优先。

原则不变：先 profile 确认它是热点，再动手清理；没测过的问题不要修。

## profile 画像

```matlab
profile on
myHeavyFunction(data)      % 跑一遍要测的代码
profile viewer             % 可视化报告：按耗时排序、逐行热点、调用次数
profile off
```

报告先看函数级总耗时排序，再点进最热的函数看逐行明细——优化永远从最热的那几行开始，改一行抵得上乱改一百行。粗掐表用 tic/toc，对比写法用 timeit：

```matlab
tic;  y = sum(x.^2);  toc          % 粗粒度掐表

t1 = timeit(@() sum(x.^2));        % 自动多次运行取稳健均值
t2 = timeit(@() myLoopVersion(x));
t1 / t2                            % 提速倍数
```

`tic`/`toc` 的单次结果受缓存与预热影响大；`timeit` 自动处理多次采样，比较两种写法时用它，别信一次 tic/toc 的孤证。数据规模再往上走的路径是 `parfor`/`gpuArray`（并行计算工具箱）和 tall 数组——但那是三板斧做对之后的事，顺序别反。
