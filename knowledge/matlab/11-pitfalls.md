MATLAB 的坑有明确的分布规律：**默认值**（1-based、列优先、矩阵乘法、i 是虚数）与**动态便利**（自动扩张、动态类型、工作区共享）。本篇把全书陷阱汇编成六类审查清单，附脚本重构路线与跨语言互译表——它是从「能跑的脚本」到「可交付的代码」的检查手册。

## 1. 六类审查清单

### 1.1 索引与形状

- [ ] 下标从 1 开始——与 Python/C 互译处逐一核对（[第 1 篇](01-matlab-model.md)）
- [ ] 线性索引/reshape 想过列优先顺序（`A(:)` 展开）
- [ ] `A'` 与 `A.'`：复数语境一律 `.'`（[第 3 篇](03-operators.md)）
- [ ] 隐式扩张参与的逐元素运算：`assert(isequal(size(a), size(b)))` 或显式 repmat
- [ ] 逻辑索引结果的形状（矩阵掩码拉平成列向量）与后续运算兼容
- [ ] `for c = A` 的「遍历列」语义是有意为之
- [ ] sum/mean/max 的 dim 参数：打印 size 验证压缩方向

### 1.2 浮点与逻辑

- [ ] 无裸 `==` 比较浮点（容差/isequal 量化）（[第 3 篇](03-operators.md)）
- [ ] `&&`/`||` 只用于标量条件；掩码构造用 `&`/`|` + any/all 折叠
- [ ] 迭代收敛用容差 + 最大迭代数，不用 `==`
- [ ] 数值管线全程 double；int 只在图像/接口边界
- [ ] NaN 的传播路径检查过（NaN 会污染 sum/max 与逻辑判断；isnan 显式处理）

### 1.3 性能与内存

- [ ] 循环前预分配（zeros/NaN(size)），无 `x(end+1)`（[第 9 篇](09-vectorization.md)）
- [ ] 热路径向量化候选已评估（逻辑索引/dim/累积函数）
- [ ] profile 的自时间定位过热点；timeit 验证每次修改
- [ ] 大矩阵的临时对象尺寸检查过（`A.^2` 级别的中间体）
- [ ] 稀疏性维护：稀疏矩阵没有与满矩阵意外混算
- [ ] single/稀疏/分块三个内存杠杆按需启用

### 1.4 接口与作用域

- [ ] 函数文件名 = 函数名；help 文档齐全（[第 5 篇](05-functions.md)）
- [ ] 参数校验用 arguments 块（或 nargin 手工检查），输入非法即 error('App:id',...)
- [ ] 函数内变量 local（嵌套函数的共享变量是刻意选择）
- [ ] 无函数名被变量遮蔽（`which -all` 排查过）；不与内建/工具箱重名
- [ ] 匿名函数的值捕获语义与预期一致
- [ ] 全局变量/global 消失（改显式参数）；工作区依赖（脚本当函数用）消除

### 1.5 数据 IO

- [ ] >2GB 的 .mat 用 -v7.3；load 用返回值收进结构体（[第 7 篇](07-data-io.md)）
- [ ] 脏数据导入走 detectImportOptions，不做静默猜测
- [ ] 表格数据用 table（逻辑索引过滤 + groupsummary），数值计算用矩阵
- [ ] 交换格式选对：JSON/CSV/HDF5 而不是 .mat（跨工具）
- [ ] 大数据走 datastore/tall，内存峰值受控

### 1.6 可视化

- [ ] hold on 显式管理叠画；legend 与实际曲线对齐（[第 6 篇](06-plotting.md)）
- [ ] 色图非 jet；三维图配 2D 截面进报告
- [ ] 出图用 exportgraphics（矢量/高分辨率），非截图
- [ ] 样式固化成函数/脚本（字号、线宽、尺寸），不逐图手调

## 2. 脚本 → 函数的重构路线

MATLAB 项目最常见的形态是「一个 500 行的 main.m」。重构的渐进路线：

```text
第 1 步：%% 分节整理 —— 把脚本切成逻辑块（数据加载/处理/绘图）
第 2 步：变量清单化 —— 列出每节读/写的变量，识别「输入/输出/内部」
第 3 步：抽函数 —— 每块变成 function，隐式共享变量变成参数与返回值
第 4 步：加接口 —— arguments 校验 + help 文档 + 错误 error(id, ...)
第 5 步：分离入口 —— main 函数 + if 名字判断（或独立 run 脚本），路径 addpath 固化
```

```matlab
% 重构后的项目形态：
%   main.m            —— 编排（加载数据 → 调 compute → 调 report）
%   compute.m         —— 纯计算（可单独测试）
%   report.m          —— 出图出表（不碰计算）
%   +utils/           —— 私有工具（命名空间）
```

重构的验收标准：**compute.m 可以不依赖任何工作区状态独立运行**——这就是可测试性，也是脚本与程序的分界线。

## 3. 跨语言互译检查表

MATLAB ↔ Python/NumPy 的翻译事故集中在五个点：

| 维度       | MATLAB                | Python/NumPy           | 互译检查             |
| ---------- | --------------------- | ---------------------- | -------------------- |
| 下标       | 1-based                | 0-based                | 公式下标 +1/-1 全表核对 |
| 逐元素     | `.* ./ .^`             | `* / **`（默认逐元素）  | 乘幂符号方向相反！    |
| 矩阵乘     | `*`                    | `@`（`*` 是逐元素）     | 星号的语义翻转        |
| 存储序     | 列优先                 | 行优先（C order）       | reshape/二进制交换核对 |
| 切片       | 含端点（`1:5` = 1..5）  | 半开区间（`1:6`）       | 端点差一系统性偏移    |

二进制数据交换（.mat ↔ scipy.io、HDF5 双向）时存储序 + 类型宽度的核对清单：`endian`、`int8/16/32`、`complex` 布局、结构体字段顺序。

## 4. 反模式速查

| 反模式                              | 一句话修复                          |
| ----------------------------------- | ----------------------------------- |
| `clear all; close all; clc` 开头     | 只在交互实验；函数不需要             |
| 循环里 `eval(sprintf('x%d',k))`      | 用数组/cell 索引（eval 是代码坏味）  |
| 变量名覆盖函数名（`sum = ...`）       | 重命名；which -all 排查             |
| 依赖工作区残留变量的脚本              | 全部显式参数化                      |
| magic number 满天飞                  | 常量集中 + 注释来源                  |
| 手动求逆 inv(A)                      | `A\b`（[第 8 篇](08-linear-algebra.md)） |
| 图用截图进文档                       | exportgraphics                      |
| 复制粘贴改参数跑实验                  | 函数 + 循环/cellfun 批量            |
| 用 i 当循环变量后计算复数            | `1i` 写复数；循环变量换名           |
| 越界赋值默默扩矩阵                   | 预分配 + assert 尺寸                |

## 5. 小结

- 六类清单覆盖全书：索引形状（1-based/列优先/隐式扩张）、浮点逻辑（容差/标量条件）、性能内存（预分配/profile）、接口作用域（local/遮蔽/arguments）、数据 IO（v7.3/table/交换格式）、可视化（hold/色图/导出）。
- 脚本到函数的重构五步：分节 → 变量清单 → 抽函数 → 加接口 → 分离入口；验收标准是「计算函数无工作区依赖」。
- 跨语言互译的五雷区：下标起点、逐元素符号方向、矩阵乘符号、存储序、切片端点——二进制交换再加端序与类型宽度。
- 反模式速查是条件反射层：eval、clear all、变量遮函数、截图出图、复制粘贴实验。

## 6. 练习

**1.** 用六类清单审查你自己写过的一份 MATLAB 代码（或本篇练习的产物），统计各类命中数——哪类问题在你的代码里最密集？

> [!TIP]
> 思路多数自查者的分布：1.3 性能与 1.1 形状类最多（动态便利的直接后果）。审查记录本身就是个人学习地图——命中多的类别回到对应篇目重读。

**2.** 拿一份真实 300 行脚本执行第 2 节的五步重构，产出 main/compute/report 三文件结构；为 compute 写三个测试调用（正常/空输入/错误维度）验证接口健壮。

> [!TIP]
> 思路重构中的「变量清单」一步最痛苦也最有价值——它暴露脚本的隐式数据流。测试三连（正常/边界/非法）是接口校验是否完整的试金石。

**3.** 把一段 MATLAB 代码（含矩阵乘、逐元素运算、切片）逐行翻译成 NumPy，用随机数据验证两边结果一致（容差内）；记录你踩到的每一个翻译坑。

> [!TIP]
> 思路预期踩坑：`*` 语义翻转、切片端点、行/列向量形状（NumPy 的一维无方向）、 reshape 顺序。翻译表格在第二次互译时价值翻倍。

**4.** 为团队写一份「MATLAB 代码准入规约」：从清单中挑 CI 可自动检查项（checkcode/mplint、shellcheck 类静态工具）与评审项各 5 条，并写一个 startup.m 规范项目路径。

> [!TIP]
> 思路自动项：checkcode（MATLAB 自带 lint）、命名冲突扫描、非空 catch、license 预检；评审项：接口文档、预分配、浮点比较、重构边界、工具箱依赖标注。MATLAB 生态的 CI 可用 matlab-batch 驱动测试。

**5.** 讨论：MATLAB 的「动态便利」（自动扩张、隐式扩张、工作区共享）与工程可靠性之间的张力，与[Python 篇](../python/12-quality.md)的类型注解、[C 篇](../c/01-c-model.md)的 UB 管理对照——三种语言各自用什么机制平衡「上手快」与「跑得稳」？

> [!TIP]
> 思路Python：动态但用类型注解 + 测试左移；C：接近硬件但用 UB 条款 + sanitizer 流程；MATLAB：矩阵便利但用 arguments/清单/审查纪律。共同的元答案：**语言的默认服务上手速度，工程可靠性的差额由团队流程补齐**——差额大小决定了各语言「最佳实践」的形态。
