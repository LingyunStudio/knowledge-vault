打开任何一篇 AI 资讯，你会同时看到人工智能、机器学习、深度学习、大模型、强化学习……这些词被混用得厉害。本章不教任何具体算法，只做一件事：把术语放到正确的位置上，建立一张地图，后面十篇文章都挂在这张地图上。

## 三个嵌套的圈：AI ⊃ ML ⊃ DL

三者是**包含关系**，不是并列关系：

- **人工智能（AI）**：让机器表现出智能行为的总称，1956 年达特茅斯会议提出。早期的专家系统、搜索算法、下棋程序都属于 AI，但它们不一定"学习"
- **机器学习（ML）**：AI 的子集。核心转变是：不把规则写死在代码里，而是让程序从数据中归纳规律
- **深度学习（DL）**：ML 的子集。用多层神经网络自动学习特征表示，是这十年大爆发的引擎

用代码对比两种思路的差别：

```python
# 规则法：人把规则写死，规则错了就去改代码
def is_spam(text: str) -> bool:
    return "中奖" in text or "点击链接" in text

# 机器学习：人给数据和标签，程序自己调参数
# 效果不好？给更多数据重新训练，代码一行不改
model.fit(X_train, y_train)
```

传统编程是「人写规则，机器执行」；机器学习是「人给数据和要求，机器自己找规则」。问题越模糊、数据越多，后者的优势越大——你写不出一条能区分所有垃圾邮件的规则，但你能收集一百万封标好类的邮件。

> [!NOTE]
> 大模型（LLM）不是第四个圈，它是深度学习的一个方向——用 Transformer 架构在海量文本上预训练出来的超大神经网络。新名词每天都在造，但这个嵌套结构没变过。

## 三种学习范式

机器学习按"从什么信号中学习"分成三大范式，几乎所有具体方法都能归进去：

| 范式 | 输入信号 | 典型任务 | 例子 |
| --- | --- | --- | --- |
| 监督学习 | 特征 + 标签（标准答案） | 分类、回归 | 垃圾邮件识别、房价预测 |
| 无监督学习 | 只有特征，没有标签 | 聚类、降维、异常检测 | 用户分群、压缩表示 |
| 强化学习 | 环境反馈的奖励信号 | 序列决策 | 游戏对弈、机器人控制 |

三种范式的接口差异，用伪代码看最直观：

```python
# 监督学习：X 是特征，y 是标签，目标是学会 X → y 的映射
model.fit(X, y)

# 无监督学习：没有 y，目标是发现 X 自身的结构
labels = KMeans(n_clusters=5).fit_predict(X)

# 强化学习：没有"标准答案"，只有环境给的奖励信号
# 智能体观察状态 → 选动作 → 环境返回奖励和下一状态 → 循环往复
```

实际项目里三者经常组合使用。训练 ChatGPT 这类模型的三步曲就是典型组合：预训练（自监督，预测下一个词）→ 指令微调（监督学习）→ 人类反馈对齐（强化学习思路）。

## 模型到底是什么

剥开所有包装，**模型就是一个带参数的函数**：

```python
def predict(x, w, b):
    return w * x + b      # 最简单的模型：线性回归，只有两个参数 w 和 b
```

「训练」就是用数据自动寻找让预测误差最小的参数值；「推理」是参数固定后，用这个函数对新输入算输出。深度学习模型无非是把函数堆得更深、参数更多——从几千个到上万亿个量级不等，但"调参数让误差变小"这个本质从未变过。

> [!TIP]
> 遇到任何新名词，先问三个问题：输入输出是什么？参数怎么训练？损失函数是什么？三个都答得上来，你就真的理解它了；一个都答不上来，说明那篇文章在堆砌名词——换一篇。

## AI 不只有大模型

大模型抢走了几乎所有注意力，但工程师实际接触到的 AI 系统大部分是下面这些：

| 方向 | 典型任务 | 常用模型家族 |
| --- | --- | --- |
| 计算机视觉（CV） | 分类、目标检测、分割 | CNN（第 6 章）、ViT |
| 自然语言处理（NLP） | 翻译、摘要、对话、检索 | RNN → Transformer（第 7-8 章） |
| 语音 | 识别（语音转文字）、合成 | 各有专门架构，思想同源 |
| 推荐与搜索 | 点击率预估、排序 | 大量线性模型与树模型（第 3-4 章） |
| 强化学习（RL） | 游戏、机器人、大模型对齐 | 策略网络 + 奖励优化 |

看清一件事：推荐与广告至今是工业界部署量最大的机器学习系统，而它的主力模型长期是逻辑回归和 GBDT——「简单模型 + 好特征」在正确的问题上依然是最优解，不是所有场景都需要大炮。

## 工程师视角：一个 AI 系统长什么样

模型只是系统的一个零件。线上 AI 系统的完整链路：

```text
数据采集 → 清洗/标注 → 特征管道 → 训练与评估 → 部署推理 → 监控与回流 →（循环）
```

- **数据管道**：持续产出干净的训练数据。最脏最累，也最值钱——模型上限由数据决定
- **训练与评估**：本文集 02、09、10 章的主场
- **部署推理**：模型变成一个低延迟的 API 服务，或压缩后嵌入端侧设备
- **监控与回流**：线上数据分布会漂移（用户变了、世界变了），指标跌了要能发现，新数据回流后再训练

做过后端服务的话，类比是现成的：开发 → 测试 → 上线 → 监控。区别在于"测试"变成了概率性的指标，"需求变更"变成了"数据漂移"。

## 一张最小术语地图

下面这些词贯穿全部后续文章，先混个脸熟：

| 术语 | 一句话解释 |
| --- | --- |
| 特征（feature） | 模型的输入，对事物属性的量化描述 |
| 标签（label） | 要预测的目标答案 |
| 损失函数 | 把"预测得好不好"压缩成一个数，越小越好 |
| 梯度下降 | 沿损失下降最快的方向小步迭代调参数 |
| 训练 / 推理 | 求参数的过程 / 参数固定后算结果的过程 |
| 泛化 | 模型在**没见过**的数据上的表现，唯一真正重要的指标 |
| 参数 / 超参数 | 训练学出来的 / 训练前人定的（如学习率） |
| epoch / batch | 全量数据完整过一遍 / 一次参数更新所用的样本组 |
| 过拟合 | 在训练数据上表现好、在新数据上掉链子 |

现在不需要记住定义，只需要知道地图上有哪些站——每个词后面都有专门章节展开。

## 学习路线建议

这套知识的合理顺序：

1. **流程与骨架**（02-05）：机器学习流程、线性模型、树模型、神经网络。这是地基，不依赖任何框架，也是面试和实战里最常考的部分
2. **深度学习主线**（06-08）：CNN 处理图像，序列模型一步步走向注意力，Transformer 与大模型收束全篇
3. **工程环节**（09-11）：训练实践、评估指标、工具生态——把模型"做对"靠这里，也是新手和熟手的分水岭

最后一个提醒：AI 领域的具体模型名、参数量、榜单排名月月在变，但范式和原理的更替慢得多。把学习时间花在后者上，前者当新闻看就够了。
