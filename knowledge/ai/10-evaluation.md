"准确率 95%"可能是份优秀的成绩单，也可能是全预测多数类凑出来的废纸。评估的本质是问对问题：模型在什么问题上、以什么代价、对哪些样本错了。本章把指标背后的取舍讲清楚——指标选错，后面所有努力都在优化一个错误的目标。

## 混淆矩阵：一切的起点

二分类把所有样本分进四个格子：

| | 预测为正 | 预测为负 |
| --- | --- | --- |
| **实际为正** | TP（抓对了） | FN（漏报） |
| **实际为负** | FP（误报） | TN（放对了） |

准确率 = (TP + TN) / 总数。它只有一个数，把两种性质完全不同的错误——漏报和误报——混进了同一个分母。先看矩阵，再谈指标，这是纪律。

```python
from sklearn.metrics import confusion_matrix, classification_report

print(confusion_matrix(y_true, y_pred))       # 行 = 真实类别，列 = 预测类别
print(classification_report(y_true, y_pred))  # 一次性打印全部指标
```

多分类时矩阵扩展成 n×n，对角线是分对的样本数，对角线之外的每个格子都能告诉你"谁被认成了谁"——比准确率信息量大得多。看矩阵的顺序也有讲究：先看对角线占比，再找偏大的格子——它直接指出改进方向（该收集哪类数据、加什么特征）。`classification_report` 给每个类别单独一行精确率/召回率/F1，多分类任务先看它，别只看整体数字。

## 精确率与召回率：定义方向必须分清

两个指标从不同的"分母"出发，方向绝不能混：

- **精确率（Precision）** = TP / (TP + FP)：**预测为正的样本里，多少是真的**——衡量"报出来的准不准"
- **召回率（Recall）** = TP / (TP + FN)：**实际为正的样本里，找出了多少**——衡量"该找的漏没漏"

两者几乎必然此消彼长：把判定门槛调严（只在很自信时判正），精确率升、召回率降；调松则反过来。**优先保哪个，取决于哪种错误更贵**：

| 场景 | 更贵的错误 | 优先指标 |
| --- | --- | --- |
| 垃圾邮件拦截 | 误拦正常邮件（FP） | 精确率 |
| 疾病筛查 | 漏掉病人（FN） | 召回率 |
| 金融欺诈检测 | 漏掉欺诈（FN） | 召回率 |
| 自动封号 | 误封正常用户（FP） | 精确率 |

F1 是两者的**调和平均**——只有两者都高它才高，任何一方趋近 0，F1 都被拖向 0。用调和平均而不是普通平均，正是为了惩罚"偏科"：精确率 1.0、召回率 0.01 的模型，普通平均有 0.5，F1 只有约 0.02。

另一个实用要点：模型输出的是概率，阈值默认 0.5 但应由业务来定。好处是上线后调整精确率/召回率的平衡**不用重训模型**，改一个阈值数字就行——这是工程上最便宜的"模型调优"。

> [!WARNING]
> 类别极度不平衡时（如欺诈样本只占 0.1%），准确率毫无意义——全预测"不是欺诈"也有 99.9%。这种场景看 F1 或精确率-召回率曲线，而不是准确率。

## ROC 与 AUC：与阈值无关的排序能力

大多数分类器输出的不是 0/1 而是概率，先有分数、后有类别（阈值切分）。**ROC 曲线**把阈值从 1 滑到 0，画出每一档下的真阳性率（TPR，即召回率）对假阳性率（FPR）。

**AUC** 是曲线下面积，它有一个概率解释：随机抽一个正样本和一个负样本，模型给正样本更高分数的概率。0.5 等于瞎猜，1.0 是完美排序。

AUC 的价值在于**与阈值无关**——它衡量的是模型把正样本排在负样本前面的能力，适合比较不同模型，或业务阈值还没定的场景。注意它对极度不平衡的数据不够敏感，此时精确率-召回率曲线更能反映真实水平。顺带纠正一个常见误读：AUC 0.9 不代表"90% 的预测是对的"——它是排序能力的度量，别拿它和准确率直接换算。实践里不用手画曲线：`roc_auc_score` 一个函数出 AUC，`RocCurveDisplay.from_predictions` 直接出图。

最后强调一次：阈值的选择是业务问题而非技术问题。把候选阈值和对应的精确率/召回率列成表，拿给业务方选，比算法工程师拍脑袋科学得多。

> [!NOTE]
> AUC 高不代表概率本身可信：一个模型可能排序完美，但把所有概率都报得过高或过低。如果下游要用概率本身（定价、风控额度），还需要校准，sklearn 里有现成的 `CalibratedClassifierCV`。

## 回归任务的指标

分类指标对回归全部失效，回归看的是"数值差多少"：

| 指标 | 含义 | 一句话 |
| --- | --- | --- |
| MAE | 平均绝对误差 | 单位与目标一致，最好向业务方解释 |
| RMSE | 均方误差开根号 | 惩罚大误差，对离群点敏感 |
| R² | 解释了多少方差 | 0 = 和"永远猜均值"一样，1 = 完美，可为负 |

业务汇报优先用 MAE（带单位，"平均偏差 2.3 万元"人人能懂），模型选型可以结合 RMSE 与 R²。R² 有个陷阱要先知道：往模型里加特征它几乎不会下降，所以它只回答"解释了多少"，不能用来判断是否过拟合——过拟合判断仍然靠训练/验证对比。

量纲提醒：MSE 和 RMSE 对目标的单位敏感，房价模型用"元"还是"万元"算出的 RMSE 差一万倍——跨模型比较前先统一单位。

## 交叉验证：让评估更稳

数据少时，单次划分的评估结果波动很大——切分方式换个随机种子，指标可能差出好几个点。K 折交叉验证轮流让每一份数据当一次验证集，取平均：

```python
from sklearn.model_selection import cross_val_score, StratifiedKFold

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)  # 分层：每折保持类别比例
scores = cross_val_score(model, X_train, y_train, cv=cv)
print(scores.mean(), "+-", scores.std())   # 波动（std）本身就是重要信息
```

代价是训练 K 次。小数据集（几百条）上交叉验证几乎是必选项；数据充足时单次划分足够，K 折的训练成本才开始占主导。分数的**波动**（std）比均值更容易被忽略——波动大说明模型对数据切分敏感，先查数据再调参。注意它替代的是"验证集"的角色，测试集依然单独留到最后。K 常取 5 或 10：太小评估不稳，太大训练太贵。

## 数据泄漏：最常见的自欺

指标漂亮、上线崩掉，头号嫌疑人是**数据泄漏**——测试信息以某种方式混进了训练过程。常见形式：

- **预处理泄漏**：在划分数据**之前**对全量数据做标准化、特征选择、缺失值填充——测试集的统计信息提前泄露了
- **特征泄漏**：特征里混进了"未来的答案"（预测用户是否流失，特征里却有"是否已注销"）
- **分组泄漏**：同一用户的多条样本被分到训练集和测试集两侧，模型靠"认人"而非"认规律"得高分
- **时序泄漏**：时间序列任务随机划分，用未来预测过去
- **评估泄漏**：用测试集反复观察、反复选模型，本质是把测试集用成了验证集——回到第 2 章的三次划分

```python
# 反面教材：先在全量数据上 fit 再划分——测试集信息已经泄漏
# scaler = StandardScaler().fit(X_all)

# 正确：只在训练集上 fit，把同一个变换应用到验证/测试
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler().fit(X_train)
X_train_s = scaler.transform(X_train)
X_test_s = scaler.transform(X_test)   # 用的是训练集学到的均值和方差
```

根治手段是把预处理包进 Pipeline（下一章），让交叉验证的每一折都自动"只在训练部分 fit"。

> [!TIP]
> 离线指标与线上效果差距大时，排查顺序：数据泄漏 → 训练/线上数据分布漂移 → 评估口径不一致。泄漏的典型特征是"好得不像话"——小模型就有惊人指标时，先怀疑自己，再庆祝。
