模型结构决定上限，训练功夫决定你能不能摸到上限。同一份代码，会训的人和不会训的人得到的模型可以差出一大截。本章收集最常用的实战知识：从梯度的稳定性，到优化器的选择，再到过拟合的系统性对策。

## 梯度消失与初始化

深层网络反向传播时，梯度是逐层连乘的：每层都乘一个小于 1 的数，传到浅层就趋近于零——**梯度消失**，浅层学不到东西；每层都乘大于 1 的数则**梯度爆炸**，训练直接崩掉。

三个层面的对策，如今成熟的深层网络会同时使用：

- **激活函数**：用 ReLU 系代替饱和的 sigmoid/tanh（第 5 章）
- **初始化**：让每层输出的方差大体一致，别一开始就把信号放大或压死
- **结构组件**：BatchNorm 稳定每层分布，残差连接给梯度开直通车（第 6 章）

```python
import torch.nn as nn

layer = nn.Linear(256, 256)
nn.init.kaiming_normal_(layer.weight)   # He 初始化：配合 ReLU 的事实标准
```

初始化不是"随机给个起点"那么简单——好的初始化让网络在第一步就处于"信号能正常流动"的状态，这是深层网络能训起来的前提。 Xavier 初始化配 tanh、He 初始化配 ReLU，都是围绕"方差别逐层放大或缩小"这一个原则设计的。

## 优化器：SGD 与 Adam

优化器决定"拿到梯度后怎么更新参数"。两个主流选项：

| | SGD（+ 动量） | Adam / AdamW |
| --- | --- | --- |
| 原理 | 沿梯度方向更新，动量累积惯性 | 为每个参数自适应调整步长（一阶+二阶动量） |
| 优点 | 泛化口碑好，调好后最终精度上限高 | 对学习率不敏感，收敛快，省心 |
| 缺点 | 学习率必须仔细调 | 某些任务最终精度略逊（有争议） |
| 常用场景 | 计算机视觉、追求极限 | Transformer 系、快速迭代 |

```python
import torch

optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.01)
```

SGD 加动量的直觉：把梯度看成"小球滚坡"，动量让它在坑里不轻易停、在颠簸路面走得稳。Adam 的直觉：给每个参数配一个"自动刹车"，历史上更新剧烈的参数步子自动迈小些。两种思路不冲突，但实现上二选一。

> [!TIP]
> 不确定就用 **AdamW**——它是 Transformer 类模型的默认选择，也是"能跑就行"场景的保险牌。AdamW 与 Adam 的区别在于 weight decay 的实现方式更正确，如今基本没有理由再用老 Adam。

## 学习率：最重要的一个超参数

如果只能调一个超参数，调学习率。它的行为特征很极端：

- 太大：损失震荡甚至发散（出现 NaN 是典型症状）
- 太小：收敛极慢，或卡在一个半吊子水平
- 合适 + 会调度：事半功倍

现代实践的标配是 **warmup + 余弦退火**：训练初期从很小的学习率线性升到目标值（避免一开始步子太大摔死），之后按余弦曲线缓慢降到接近零——前期热身、后期精修。

```python
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=total_steps)
# 每个 epoch（或每个 step）调用 scheduler.step() 更新学习率
```

## 归一化：BatchNorm 与 LayerNorm

两类归一化层是深层网络能训深的隐形功臣，区别在"沿哪个方向归一化"：

- **BatchNorm**：沿 batch 方向——用整个批次的统计量归一化每个特征。CV 里常用（`nn.BatchNorm2d`），缺点是 batch 太小时统计不稳
- **LayerNorm**：沿特征方向——每个样本自己归一化自己，与 batch 无关。NLP 与 Transformer 的标配（`nn.LayerNorm`）

它们把每层的输入分布拉回稳定区间，让更大的学习率成为可能，同时自带轻度正则效果。

## 过拟合的六种对策

训练集越来越好、验证集开始变差——按性价比排序，依次上这些手段：

1. **更多数据 / 数据增强**：治本。图像的随机裁剪、翻转、色彩抖动；文本的同义替换、回译。变着花样给模型看同类样本，它就没法死记硬背
2. **早停**：盯验证集指标，连续若干轮不提升就停。零成本且几乎必做
3. **L2 正则 / weight decay**：损失里加权重平方惩罚，逼模型保持简单——第 3 章的原理在深度学习里同样成立
4. **Dropout**：训练时随机把一部分神经元输出置零，迫使网络不依赖任何单个神经元，等价于同时训练海量子网络的集成

```python
model = nn.Sequential(
    nn.Linear(512, 256),
    nn.ReLU(),
    nn.Dropout(p=0.5),       # 训练时以 50% 概率置零
    nn.Linear(256, 10),
)
# 优化器里配 weight_decay=1e-4，即 L2 正则
```

5. **减小模型容量**：层数、宽度砍到"刚好能学会训练集"的量级，别盲目堆大
6. **集成与交叉验证**：训多个模型取平均或投票，多个"犯错方式不同"的模型互相纠错

> [!WARNING]
> Dropout 只在训练时生效。推理前必须调用 `model.eval()` 切换到评估模式——忘了这一步，推理结果会带随机性，指标莫名其妙地抖。`model.train()` / `model.eval()` 是 PyTorch 里最容易忘的一对开关。

## 训练问题速查表

| 症状 | 常见原因 | 第一反应 |
| --- | --- | --- |
| 损失纹丝不动 | 学习率太小 / 数据有 bug | 放大学习率；先人肉检查数据喂对没有 |
| 损失 = NaN | 学习率太大 / 数值溢出 | 减小学习率、加梯度裁剪 |
| 训练好、验证差 | 过拟合 | 本章的六种对策 |
| 两个都差 | 欠拟合 / 标签有误 | 加容量之前，先检查 20 条样本和标签 |

这张表覆盖了八成的训练异常，剩下两成去翻框架的 issue 区——你多半不是第一个遇到的人。

## 调参的工程习惯

超参数搜索不是玄学，是流程管理：

- **固定随机种子**：结果不可复现的实验等于没做
- **一次只动一个变量**：同时改学习率和网络宽度，你不知道功劳归谁
- **先小规模试跑**：全量数据跑一小时才出结果的学习率实验是纯浪费——先在子集上把配置跑通
- **记录一切**：配置、指标、日志，哪怕记在一个表格里也行

最后提醒收益排序：调参的收益上限远低于把数据和评估做对——先回头检查第 2 章的流程和第 10 章的指标，再回来炼丹。
