「模型好不好」不是一个数字能回答的——**指标的选择本身就是业务决策**（漏检贵还是误报贵？），而指标的**测量方式**（交叉验证）决定这个数字可不可信。本篇讲指标族与验证方法，重点是「指标 ↔ 业务语义」的映射。

## 1. 分类指标：从混淆矩阵出发

```text
                    预测正        预测负
实际正  |  TP（真阳）   |  FN（假阴=漏报）|
实际负  |  FP（假阳=误报）|  TN（真阴）   |

Accuracy  = (TP+TN)/全部        —— 准确率：全对的占比
Precision = TP/(TP+FP)          —— 查准：报的正例里多少是真的
Recall    = TP/(TP+FN)          —— 查全：真的正例里抓到多少（=TPR）
F1        = 2PR/(P+R)           —— 精确率与召回的调和平均
```

**precision 与 recall 的跷跷板**是分类的核心权衡（阈值调高→precision 升 recall 降；调低反之）：

| 场景           | 漏报代价                | 误报代价        | 优先指标 |
| -------------- | ----------------------- | --------------- | -------- |
| 疾病筛查       | 高（人命）              | 低（复查）      | Recall   |
| 垃圾邮件       | 中（漏邮件进垃圾箱）    | 高（正经邮件被吞）| Precision |
| 风控拦截       | 高（漏坏账）            | 中（误伤好用户）| Recall + 业务成本 |

**Accuracy 的欺骗性**：99% 负样本的数据集上「全预测负」accuracy=99% 但 recall=0——**不平衡数据看 precision/recall/F1/AUC，不看 accuracy**（[第 1 篇](01-ml-overview.md)的基线谬误）。

### 1.1 ROC 与 AUC：阈值无关的整体评价

```text
ROC 曲线：横轴 FPR（假阳率）、纵轴 TPR（召回）——阈值从 1 扫到 0 的轨迹
AUC：曲线下面积 = 随机取一正一负样本，模型给正样本更高分的概率
  AUC=0.5 随机瞎猜；0.7 可用；0.8+ 良好；0.9+ 优秀（视领域）
```

AUC 的优点：**阈值无关**（先评估排序能力，阈值后调）、不平衡数据下比 accuracy 稳健。注意：**PR-AUC 在极端不平衡下比 ROC-AUC 更敏感**（正样本极少时 ROC 被大量负样本稀释）——「PR 曲线看少数类」的惯例。业务落地是「概率 → 阈值」的决策：用 PR 曲线/成本矩阵选阈值（[线性模型的阈值实验](02-linear-models.md)）。

## 2. 回归指标

```text
MAE  = 平均绝对误差        —— 对离群点鲁棒；单位与目标一致（直观）
RMSE = 均方根误差          —— 放大大误差的惩罚（对离群敏感）
R²   = 1 - SSE/SST         —— 解释了多少方差（0=跟猜均值一样，可负=不如均值）
MAPE = 百分比误差          —— 业务语言（「平均偏差 8%」）但除零与接近零的目标有毒
```

选择按业务语义：**财务预测看 MAE/MAPE（钱的单位）、异常敏感场景看 RMSE、汇报看 R²**。注意 RMSE 与 MAE 的差值大 = 存在大误差离群点（诊断信号）。

## 3. 交叉验证：可信的测量

```python
from sklearn.model_selection import cross_val_score, StratifiedKFold, TimeSeriesSplit

cross_val_score(model, X, y, cv=5)                    # 5 折：轮流当验证集
# ★ 分层：每折保持类别比例（分类必用）
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

# 时序数据：绝不能随机折！（用未来验证过去=泄漏）
cv = TimeSeriesSplit(n_splits=5)                       # 时间顺序分割
# 分组数据（同一用户多行）：GroupKFold——同一组不跨折
```

| 数据形态     | CV 方式               | 随机折的灾难                     |
| ------------ | --------------------- | -------------------------------- |
| 独立同分布   | 分层 K 折             | 少数类某折缺失                    |
| 时序         | TimeSeriesSplit       | 用未来数据训练（泄漏，虚高）       |
| 分组（用户） | GroupKFold            | 同用户的行跨训练与验证（记忆泄漏）|

交叉验证的产出是**指标分布**（均值±标准差）而非单值——「模型 A 比 B 好」要用分布说话（差距大于标准差波动才算数）。超参调参时的验证集消耗：嵌套 CV 是学术正解，工程上常「固定 hold-out + CV 调参」折中。

## 4. 类别不平衡：指标之外的应对

```python
# 数据层：重采样
from imblearn.over_sampling import SMOTE          # 少数类合成过采样
# 算法层：类别权重（惩罚少数类错误更多）
model = LogisticRegression(class_weight="balanced")
# 阈值层：按业务成本调阈值（[第 2 篇](02-linear-models.md)）
```

不平衡的三层应对（按优先级）：**指标选对**（不看 accuracy）→ **算法层**（class_weight 常比重采样稳）→ **数据层**（SMOTE 合成——注意合成样本的泄漏风险，只对训练折做）。极端不平衡（1:10000，欺诈）本质是异常检测问题——换算法族（孤立森林/autoencoder）。

## 5. 超参搜索：三种策略

```python
from sklearn.model_selection import GridSearchCV, RandomizedSearchCV

GridSearchCV(model, param_grid, cv=5)               # 网格：全组合（组合爆炸）
RandomizedSearchCV(model, param_dist, n_iter=50)    # 随机：抽 50 组（高维空间更高效）
# 贝叶斯优化：按历史结果选下一组（optuna）——昂贵评估的首选
```

策略排序：**随机搜索 ≥ 网格**（同预算下高维空间覆盖更好——多数超参其实不敏感）、**贝叶斯**（评估贵的模型）、**网格**（2 个超参的小空间）。搜索空间的设计比算法重要：**log 尺度采样学习率/正则项**、每个参数的合理范围来自文档与经验。

## 6. 陷阱清单

- 不平衡数据用 accuracy：基线谬误；PR-AUC/召回优先。
- 时序数据随机 CV：泄漏虚高；TimeSeriesSplit。
- 缩放/编码在全量数据 fit：CV 内也要每折 fit（Pipeline，[第 10 篇](10-toolbox.md)）。
- 测试集反复使用：泛化虚高（[第 1 篇](01-ml-overview.md)）。
- 单点指标比较模型：CV 分布 + 多次重复才是依据。
- 阈值不调直接 0.5：业务成本没进决策。
- AUC 相等就认为模型等价：AUC 不看校准（概率本身准不准——概率校准是另一维）。

## 7. 小结

- 指标 = 业务成本的语言：precision/recall 的跷跷板按「漏报 vs 误报」的业务代价选边；accuracy 在不平衡下有毒。
- AUC 是阈值无关的排序能力评估；极端不平衡看 PR-AUC；概率校准是独立于 AUC 的另一维。
- 交叉验证的可信度规则：分层保比例、时序用顺序分割、分组防跨折泄漏——产出「均值±方差」而非单点。
- 不平衡三层应对：指标 → class_weight → 重采样；极端不平衡换异常检测范式。
- 调参策略：随机/贝叶斯优于网格；搜索空间的设计（log 尺度、合理范围）比算法重要。

## 8. 练习

**1.** 手写混淆矩阵与指标：对一个模型的预测结果（含不平衡分布），手算 accuracy/precision/recall/F1 与「全预测多数类」的基线对比——验证「基线谬误」。

> [!TIP]
> 思路99:1 分布下全猜多数类 accuracy=99%，但 recall=0、F1≈0——「accuracy 的幻觉」亲手算一次终身免疫。

**2.** ROC 与 PR 对比：在 1:100 的不平衡数据上画 ROC 与 PR 曲线，比较两个 AUC 的「好看程度」——验证 ROC 被稀释、PR 更诚实的论断。

> [!TIP]
> 思路ROC-AUC 对不平衡相对稳健但仍偏乐观（大量 TN 撑面积）；PR-AUC 直接聚焦少数类的检索质量。极端不平衡（反欺诈）的标配是 PR。

**3.** 时序泄漏实验：对一个时序预测任务分别用随机 K 折与 TimeSeriesSplit——对比验证集指标（随机折虚高）——把「时序泄漏」做成可视化（训练集时间范围 vs 验证集）。

> [!TIP]
> 思路随机折用 2027 年的数据预测 2026 年——模型「作弊」。时序任务的泄漏检查清单：分割方式/特征时间窗/目标编码的时序性。

**4.** 阈值优化实战：在验证集上用成本矩阵（漏报=100、误报=1）扫描阈值 0~1，找期望成本最小的阈值——对比「默认 0.5」的成本差。

> [!TIP]
> 思路成本矩阵把「业务」编码进阈值决策——最优阈值随成本比漂移。上线后阈值要随分布漂移重校（[第 9 篇](09-deployment.md)）。

**5.** 随机搜索 vs 网格对比：10 维超参空间、同样 100 次评估预算——随机搜索探索到的「不同取值组合数」远多于网格（网格每维只有 ~1.6 个值）——用实验验证这个反直觉结论。

> [!TIP]
> 思路网格 100 次 = 10 维每维只试 100^(1/10)≈1.58 个值（灾难）；随机搜索每维独立覆盖 100 个值。「重要维度少」的事实让随机搜索的覆盖更有效（Bergstra 论文的核心结论）。

**6.** 讨论：为什么「离线指标好」不等于「上线有效」？从「离线-在线的差异」（分布漂移/反馈回路/延迟标签/业务指标不可代理）四个角度分析离线评估的盲区，并说明 A/B 测试在 ML 迭代中的位置——对照[部署监控](09-deployment.md)。

> [!TIP]
> 思路离线指标是「历史分布上的代理指标」——上线后分布漂移（用户行为被模型改变：推荐模型改变用户行为——反馈回路）、标签延迟（转化要 7 天才知）、业务指标（GMV）不可代理。离线指标守门、A/B 定生死——ML 的评估永远是双层的。
