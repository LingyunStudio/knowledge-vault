机器学习的本质可以用一句话说清：**当你无法写出规则时，用数据把它拟合出来**。识别猫（规则写不出）、预测房价（规则太复杂）、推荐内容（规则随人而变）——传统编程「人写规则、机器执行」，机器学习「给数据与答案、机器找规则」。这个视角转换带来一个新的核心矛盾：**模型学到的究竟是「规律」还是「答案本身」**——这就是泛化问题，本篇的核心。

## 1. 三种学习范式

| 范式       | 数据形态                    | 学什么                     | 例子                            |
| ---------- | --------------------------- | -------------------------- | ------------------------------- |
| 监督学习   | (输入, 标准答案) 对          | 输入 → 输出的映射函数       | 垃圾邮件分类、房价预测          |
| 无监督学习 | 只有输入                     | 数据的内在结构              | 用户聚类、降维、异常检测        |
| 强化学习   | 环境 + 奖励信号              | 最大化长期奖励的行为策略     | 游戏 AI、机器人控制、RLHF（[LLM 篇](../llm/04-pretrain-sft-rlhf.md)）|

监督学习是工业主力（绝大多数业务模型），无监督做探索与预处理，强化学习在「试错可模拟」的场景称王。三条范式的数学底座都是[概率论](../prob/01-foundations.md)与[线性代数](../linalg/01-vectors.md)——「在不确定性中估计函数」。

## 2. 泛化：ML 的核心矛盾

```text
训练目标：在训练数据上误差小（拟合）
真正目标：在没见过的数据上误差小（泛化）
矛盾：模型越强 → 训练误差越低 → 但可能只是「背下了训练集」
```

用一个最小实验看清：用 10 个点拟合多项式——

```python
# 一阶（直线）：欠拟合 —— 太简单，抓不住规律
# 十阶（穿过每个点）：过拟合 —— 完美记住训练数据，新数据一塌糊涂
# 三阶：接近真实生成规律（数据本来就是二次/三次生成的）
```

过拟合（overfitting）与欠拟合（underfitting）的第一性解释：**模型的「容量」（表达力）与「数据的真实复杂度 + 噪声量」不匹配**——容量过大时模型连噪声也拟合（噪声不可泛化）。所有防过拟合手段都是这个原理的变体：

| 手段       | 原理                                        |
| ---------- | ------------------------------------------- |
| 更多数据   | 噪声占比下降，规律更凸显（最根本的解法）      |
| 正则化     | 惩罚模型复杂度（L1/L2、dropout）——容量上税   |
| 早停       | 验证误差开始上升就停——别拟合过头             |
| 交叉验证   | 「没见过的数据」的模拟——泛化的可测量化        |

**训练/验证/测试三分**是泛化的工程化：训练集拟合、验证集调参（模型选择）、测试集最终评估——三者的隔离纪律是 ML 的「[测试纪律](../python/12-quality.md)」：测试集被反复触碰 = 性能虚高（与[数据泄漏](09-deployment.md)同罪）。

## 3. 标准工作流：从问题到模型

```text
① 定义问题：预测什么？输入是什么？衡量标准？（准确率？召回？业务指标？）
② 数据收集与清洗：占项目 60%~80% 的时间（脏数据比差模型更致命）
③ 特征工程：把原始数据变成模型可消化的表示
④ 建模与训练：选模型 → 训练 → 调参
⑤ 评估与迭代：验证集评估 → 诊断（偏差/方差）→ 回到 ③ 或 ④
⑥ 部署与监控：线上服务 + 数据漂移监控（[第 9 篇](09-deployment.md)）
```

「机器学习项目 ≠ 训练模型」：模型训练只是第 ④ 步，工程实践的重心在数据（②③）与部署监控（⑥）——**垃圾进垃圾出**（GIGO）的第一定律。数据质量的三查：标签质量（标注错误率）、分布代表性（采样偏差）、泄漏检查（特征里混入了答案）。

## 4. 误差的分解：偏差与方差

```text
期望误差 = 偏差² + 方差 + 不可约噪声
偏差（bias）：模型太简单，系统性偏离真相      → 欠拟合
方差（variance）：模型对训练数据的扰动太敏感   → 过拟合
噪声：数据本身的随机性（不可消除的下限）
```

诊断方法：**训练误差高 → 偏差问题（加容量/特征）；训练误差低但验证误差高 → 方差问题（加数据/正则化）**——这条诊断流程是调参的方向盘（第 4 篇展开）。偏差-方差权衡的现代修正：**大模型时代两者可以同时降低**（更多数据 + 更大模型 + 正则化）——但理解权衡仍是诊断的坐标系。

## 5. 数据的形态：特征与表示

```python
# 特征的类型与处理
numerical   = [1.5, 2.3]           # 数值：标准化（不同量纲）— x' = (x-μ)/σ
categorical = ["red", "blue"]      # 类别：独热编码 / 嵌入
text        = "很好用"             # 文本：分词 → 词向量（[LLM 篇](../llm/02-tokenizer-embedding.md)）
image       = [[[r,g,b]]]          # 图像：像素张量
```

特征工程的本质：**把领域知识注入数据表示**——「异常检测用对数变换让长尾变正态」「日期拆出星期几」。深度学习的部分承诺是「自动学特征」（表示学习），但**表格数据上特征工程仍碾压端到端**（[梯度提升](03-trees-ensembles.md)的统治区）。

## 6. 陷阱清单

- 拿测试集调参：泛化估计虚高；三分隔离是纪律不是建议。
- 只看训练指标上线：过拟合的经典死法；验证/测试指标是唯一信源。
- 忽略数据泄漏（特征含未来信息/答案的衍生物）：模型「好得离谱」时要先怀疑泄漏。
- 数据不平衡不处理（99% 负样本下 accuracy 99%）：指标选择与重采样（[第 4 篇](04-evaluation.md)）。
- 跳过数据清洗直接建模：垃圾进垃圾出；标注质量抽查是第一步。
- 把 ML 当黑盒堆模型：偏差/方差的诊断框架是调参的方向盘。
- 小数据上硬上深度学习：先跑[线性/树模型](02-linear-models.md)做基线——简单基线常打平。

## 7. 小结

- ML 的本质：写不出的规则用数据拟合；范式三分类按「有什么反馈信号」划分。
- 泛化是核心矛盾：容量 vs 数据复杂度+噪声——过拟合的一切对策（数据/正则/早停）都是它的推论。
- 工作流六步的重心在数据与部署：模型训练只是中间一步；数据质量三查（标签/分布/泄漏）先于一切建模。
- 偏差-方差分解是诊断方向盘：训练误差看偏差、验证落差看方差。
- 特征工程注入领域知识；深度学习的表示学习与手工特征在表格 vs 非结构化数据上分治。

## 8. 练习

**1.** 用 sklearn 做多项式拟合实验（本篇第 2 节）：10 个点、1/3/10 阶三个模型，画拟合曲线与训练/测试误差——亲手看「过拟合曲线穿过每个训练点但测试误差爆炸」。

> [!TIP]
> 思路测试点用真实规律+噪声生成。十阶模型的系数数量级（1e6 级）也是过拟合的可见症状——模型在「用疯狂系数追噪声」。

**2.** 数据泄漏实验：构造一个「特征里含目标值的完美代理」（如用「退款金额」预测「是否退款」），观察准确率 99.9%——然后找出泄漏点。建立「好得离谱 = 先查泄漏」的反射。

> [!TIP]
> 思路泄漏的高发位置：时间序列用了未来特征、特征在目标发生后才可计算、按目标分层的随机泄漏。每一类都值得自己造一次。

**3.** 训练/验证/测试纪律实验：在测试集上调 20 次参后，用「真正的全新数据」评估——对比「验证集指标」与「新数据指标」的差距，量化测试集被污染的代价。

> [!TIP]
> 思路反复触碰测试集 = 把测试集变成第二个验证集——泛化估计逐年虚高（ML 竞赛与论文的系统性问题）。Kaggle 的 public/private leaderboard 分割就是防线。

**4.** 偏差方差诊断练习：给一个「训练误差 2%、验证误差 25%」的场景开处方（加数据/正则/降容量），给「训练 30%、验证 32%」开处方——两条处方路线的分界线是训练误差水位。

> [!TIP]
> 思路先看训练误差定「偏差还是方差」：训练误差高=欠拟合（加容量）、训练低验证高=过拟合（加数据/正则）。诊断先于调参——没有诊断的调参是随机搜索。

**5.** 用 [sklearn](10-toolbox.md) 完整走一遍工作流六步：拿一个真实小数据集（如泰坦尼克），从问题定义写到特征处理——记录每一步的真实时间占比，验证「60~80% 在数据」的经验律。

> [!TIP]
> 思路时间日志会颠覆「ML = 调模型」的想象：清洗/特征/验证占大头。这个体感是「数据工程师比建模者稀缺」的原因。

**6.** 讨论：为什么「更多数据」是最根本的过拟合解法，而其他手段都是补救？从「噪声与信号的统计可分性」角度分析（数据多时噪声互相抵消、信号凸显），并讨论数据不可得时的策略排序（正则化/迁移学习/合成数据）——对照[统计估计的样本量直觉](../prob/05-estimation.md)。

> [!TIP]
> 思路样本量的平方根定律（[概率篇](../prob/05-estimation.md)）在 ML 的投影：信号随 n 增长、噪声随 √n 增长——大数据天然更可学。数据不可得时的迁移学习（借别人的数据先验）是现代的次优解——预训练时代的底层逻辑。
