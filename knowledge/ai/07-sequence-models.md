文本、语音、股价、传感器数据有一个共同点：**顺序本身就是信息**。"狗咬人"和"人咬狗"用的是同一批词。MLP 和 CNN 把输入当成一个整体或一片区域看，序列模型则引入"时间"：上一步的处理结果影响下一步。本章沿"RNN → LSTM → 注意力"的路线走到 Transformer 门口。

## 词先要变成向量：Embedding

神经网络吃不了字符串，第一步是把 token 变成向量。one-hot 太稀疏（词表 10 万，向量就 10 万维且只有一个 1），标准做法是**查一张可学习的表**：

```python
import torch.nn as nn

emb = nn.Embedding(num_embeddings=10000, embedding_dim=64)
x = emb(token_ids)   # (batch, seq_len) 的词 id → (batch, seq_len, 64) 的向量
```

每个词 id 对应表里一行向量，随训练一起更新。训练充分后，语义相近的词的向量会自然靠近——这就是常说的**词向量**（word embedding）："国王 - 男人 + 女人 ≈ 女王"这类现象是它的名场面。Embedding 的适用对象远不止词：用户 id、商品 id、任何离散类别都能查表向量化，供后续模型使用。顺带统一称呼：文本的最小处理单位叫 **token**——英文可能是一个词或半个词，中文可能是字或词，本章的"词"泛指 token。

Embedding 也是处理高基数类别特征的现代方案（对照第 4 章的目标编码）：给每个类别一行可学习的向量，让模型自己学出类别之间的远近关系。

## RNN：带记忆的网络

循环神经网络（RNN）的处理方式：一个词一个词地读，维护一份"隐藏状态"当记忆。

```text
h_t = f(W_x·x_t + W_h·h_(t-1) + b)   # 当前输入 + 上一步的记忆 → 新记忆
```

每个时间步用**同一组权重**（这也是一种权值共享），序列读完，最后的隐藏状态就当作整句话的"摘要"交给下游。

```python
rnn = nn.RNN(input_size=64, hidden_size=128, batch_first=True)
out, h_n = rnn(x)    # out: 每一步的隐藏状态；h_n: 最后一步，可当整句摘要
```

问题藏在连乘里。训练时梯度要沿时间一步步传回，链式法则展开是 W_h 连乘 t 次——特征值小于 1 就**梯度消失**（远处的信息学不到），大于 1 就**梯度爆炸**。所以普通 RNN 记不住长距离依赖："这句话里的'它'指的是三行前的主角"这种事，学不会。

## 梯度爆炸好治：裁剪

消失和爆炸的治法不对称。消失难治（下一节的门控就是答案）；爆炸简单——梯度太大就按比例整体缩小：

```python
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)  # 超过阈值整体等比缩小
optimizer.step()
```

一行代码，几乎所有循环网络的训练循环里都会出现。梯度裁剪对 MLP、CNN 同样适用，只是它们爆炸的概率低得多。配套的工程习惯：日志里定期打印梯度范数，它突然变大就是爆炸的前兆。

## LSTM：给记忆装上阀门

长短期记忆网络（LSTM，1997）的解法：把记忆拆成两部分，其中**细胞状态**是一条几乎直通的传送带，信息默认原样保留；再配上三个可学习的**门**控制读写：

| 门 | 管什么 | 一句话 |
| --- | --- | --- |
| 遗忘门 | 决定旧记忆保留多少 | "这条旧信息还重要吗？" |
| 输入门 | 决定新信息写入多少 | "这条新信息值得记吗？" |
| 输出门 | 决定记忆输出多少 | "现在需要回忆多少？" |

门的本体就是一个 sigmoid 层：输出 0 到 1 之间的数当作开关比例——0 全关，1 全开。"该记什么、该忘什么"不再靠梯度硬扛，而是让网络自己学出开关策略。

LSTM 稳的结构原因在于细胞状态的更新以**加法**为主：新记忆 = 旧记忆 × 遗忘比例 + 新写入内容。加法让梯度回传路径上的连乘项大幅减少，长距离梯度有了"高速公路"。代码里能看到这条传送带——细胞状态作为独立输出返回：

```python
lstm = nn.LSTM(input_size=64, hidden_size=128, num_layers=2, batch_first=True)
out, (h_n, c_n) = lstm(x)   # 隐藏状态 h_n 与细胞状态 c_n 分开返回
```

> [!NOTE]
> GRU 是 LSTM 的简化版（两个门），效果接近、参数更少，实践中常被优先选。门控思想的影响比 LSTM 本身更长久——"用可学习的门控制信息流"这一设计后来出现在各种架构里，包括今天的多数大模型。

## RNN 的几种接法

同一个循环结构，输入输出的接法不同，就是不同任务：

| 接法 | 输入 → 输出 | 例子 |
| --- | --- | --- |
| 多对一 | 整句 → 一个值 | 情感分类、序列分类 |
| 多对多（对齐） | 逐词 → 逐词 | 词性标注、命名实体识别 |
| 编码器-解码器 | 句子 → 另一个句子 | 翻译、摘要（下一节） |

## 今天还用 RNN 吗

现实分工已经很清晰：文本主战场被 Transformer 占领（下一章），但循环网络没有死——

- **流式场景**：语音识别、实时翻译要"边听边出结果"，维护一个状态逐帧推理，比每来一个词就重算一遍注意力便宜得多
- **小数据**：参数量小，几千条时序样本也能训得动
- **超长序列**：状态大小恒定，显存不随序列长度增长，长日志与传感数据里仍常见它的身影
- **嵌入式设备**：状态小、算力需求低，端侧部署仍有优势

选型一句话：文本任务直接上 Transformer 系预训练模型；时序任务先跑树模型基线（第 4 章），效果不够再考虑循环网络。

## Seq2Seq 与固定向量的瓶颈

翻译这类"变长输入 → 变长输出"任务的标准架构是**编码器-解码器**（Seq2Seq）：编码器（RNN/LSTM）把源句压缩成**一个固定长度的向量**，解码器从这个向量逐步生成目标句。

问题出在"固定长度"：不管原文是一句诗还是一整段话，全部信息都要塞进同一个向量。序列一长，编码器记不全，翻译质量断崖式下跌——这就是**信息瓶颈**。这不是调参能解决的，是结构性的缺陷。这个架构还有个隐蔽的坑：训练时解码器通常拿**标准答案**当上一步输入（teacher forcing），推理时却只能用自己的输出——一步走偏、步步走偏。注意力缓解了它，但没有根除。

## 注意力：按需回看

注意力机制的解法：解码器每生成一个词时，**直接回看编码器的所有隐藏状态**，按"现在最需要什么"加权取用，而不是只依赖那个被压扁的向量。

```python
# 注意力的骨架（示意代码）
scores = relevance(decoder_state, encoder_states)  # 当前状态与每个源位置算相关度
weights = softmax(scores)                          # 归一化成一组和为 1 的权重
context = weights @ encoder_states                 # 加权平均：重要的位置权重大
```

"相关度"最常用的算法是点积：两个向量越同向，分数越高。思想统一为一句话：**与其把信息硬压缩后传递，不如让每一步按需检索**。加上注意力后，翻译质量立刻上一个台阶，注意力权重可视化后还有一定可解释性——你能看到模型翻译"bank"时到底在看原文哪个词。

注意力最初的用法是"解码器回看编码器"，但很快有人把它用到别处：让序列**自己看自己**（自注意力）。去掉循环、只留自注意力的设想已隐约可见——只差一个把位置信息补回来的办法。

> [!WARNING]
> 注意力在这个阶段只是 RNN 的外挂，RNN 的串行计算仍是性能瓶颈：第 t 步必须等第 t-1 步算完，GPU 的并行能力大量闲置。于是有了终极一问：既然注意力这么好用，能不能干脆扔掉循环？——答案是下一章的主角。
