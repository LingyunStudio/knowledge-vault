指针是 C 的灵魂，也是它最著名的「劝退点」。但指针难学的真正原因不是语法，而是初学者脑中没有内存地图，把指针当成了某个玄妙符号。[第 1 篇](01-c-model.md)已经把地图画好：**内存是一排编号的字节，变量是编号处的一段字节**。在这个画面下，指针的全部定义只有一句话：**指针就是存放地址的变量**。它自己也是变量，也占内存（64 位平台上 8 字节），也有地址——所以才有「指向指针的指针」。

这一篇把指针讲透到四层：解引用与类型的分工、指针运算的合法边界（哪里是 UB 的精确分界线）、const 组合的读法、`void*` 与类型双关的规则。最后一节把三类指针事故（野、悬垂、越界）的成因与防御讲成一套肌肉记忆。

## 1. 地址与解引用：两个互逆的运算符

```c
#include <stdio.h>

int main(void) {
    int x = 42;
    int *p = &x;               // p 存的是 x 的地址

    printf("%p\n", (void *)p); // 地址本身，如 0x7ffc1234
    printf("%d\n", *p);        // 42：顺着地址找到 x，读出它的值
    *p = 100;                  // 顺着地址写进去：x 变成 100
    printf("%d\n", x);         // 100
    return 0;
}
```

- `&x`：取地址运算符，得到「x 所在格子」的编号，类型是 `int *`。
- `*p`：解引用运算符，「顺着 p 里存的编号找到那段内存」，可以读也可以写。

声明语法 `int *p` 的 `*` 属于变量名而不属于类型——一行声明多个变量时就会现形：

```c
int *a, b;      // a 是指针，b 只是 int！
int *a, *b;     // 或者一行一个：int *a; int b;
```

> [!NOTE]
> 打印地址要转成 `(void *)`。`%p` 的约定只对 `void*` 承诺，虽然几乎所有平台对 `int*` 也正常工作——但「契约只签给 void*」这件事本身就是 C 的风格：合法性的边界精确到类型。

### 1.1 类型在指针里的三重角色

所有对象指针占的字节数一样（64 位平台 8 字节），那么 `int *`、`double *`、`char *` 的差别在哪里？类型对指针规定了三件事：

1. **解引用读几个字节**：`*p` 对 `int*` 读 4 字节、对 `double*` 读 8 字节，并按该类型的编码解读（[第 2 篇](02-types.md)）。
2. **+1 跨多远**：`p + 1` 对 `int*` 前进 4 字节、对 `char*` 前进 1 字节。
3. **对齐要求**：解引用 `int*` 时地址应满足 4 字节对齐，违反是 UB（多数平台会崩或变慢，取决于硬件）。

「指针加减法按类型缩放」由此而来——这不是便利设计，而是上面第 2 条的直接后果。

```c
double d[3] = {1.0, 2.0, 3.0};
double *p = d;
p + 1;             // 地址 +8 字节，指向 d[1]
```

## 2. 指针运算：合法与未定义的精确分界

指针运算的规则可以画成一条线段。对指向数组元素的指针 p：

```text
        合法                    合法          合法          合法
   [elem0]  [elem1]  …  [elemN-1]  [末尾后一位]
   p可指向   p可指向         p可指向     ← 唯一允许的「越界」位置
                            ← 从这里解引用，UB
```

| 运算                | 合法性                                |
| ----------------- | ---------------------------------- |
| `p + n`、`p - n`   | 合法，前提是结果仍在数组内或恰指「末尾后一位」            |
| `p1 - p2`         | 合法且有意义的前提：两者指向**同一个数组**；结果类型是 `ptrdiff_t` |
| `p1 < p2`、`==` 等  | 比较合法的前提同样是同一数组（或都指末尾后一位）           |
| 指向单个变量（非数组）       | 法律上视为「长度为 1 的数组」：&x+1 合法（指末尾后一位），但不可解引用 |
| 越过末尾后一位（如 `p + n + 1`） | **UB**——哪怕不解引用                |

「末尾后一位合法、再进一步 UB」的精妙之处在于它恰好支撑了 C 循环的标准写法：

```c
int sum(const int *a, size_t n) {
    const int *end = a + n;        // 指向末尾后一位：合法
    int s = 0;
    for (const int *p = a; p < end; ++p)
        s += *p;
    return s;                      // 循环结束时 p == end，从未解引用它
}
```

> [!WARNING]
> 「指针必须指着同一数组才能相减/比较」不是学究条款。程序里两个不相干的变量在栈上的相对位置是任意的，`&a < &b` 的结果毫无意义且随栈布局变化。优化器正是利用「同一数组内指针关系可推演」做边界检查消除——你在数组外比较指针，等于亲手撕掉了它优化的依据，结果是性能与正确性一起受损。

`ptrdiff_t` 是两个指针相减的正确类型（`<stddef.h>`），大小随平台（64 位系统上 8 字节）。用 int 接指针差在处理超大数组（>2GB）时溢出。

## 3. const 与指针：从右往左读

`const` 与 `*` 的组合有三种排布，读法是**从变量名出发往右看再往左看**：

```c
const int *p;            // p 指向「const int」：*p 只读，p 可改指向
int *const p = &x;       // p 是 const 指针：p 的指向不可改，*p 可读写
const int *const p = &x; // 都不可改
```

区分的实用判断：**const 在 `*` 左边修饰被指物，在 `*` 右边修饰指针本身**。

这个语法存在的意义是**把「谁承诺不改」写进类型系统**，形成接口契约：

```c
/* 函数签名里的 const 是文档：调用方由此知道函数不会动他的数据 */
size_t my_strlen(const char *s);        // 承诺：只读 s
void sort(int *arr, size_t n);          // 无 const：会改写 arr

/* const int * 参数同时防止了手滑与误用 */
void print(const int *a, size_t n) {
    a[0] = 1;       // ❌ 编译期报错：const 挡住了
}
```

const 是**编译期的单向承诺**而不是运行时保护——`const int *p` 指向的对象本身完全可能是可变的，你只是承诺不走 p 这个门去改它。强行绕过（cast 掉 const 后修改**真正声明为 const 的对象**）是 UB：

```c
const int ci = 42;
int *p = (int *)&ci;
*p = 0;                 // ❌ UB：ci 本体是 const，编译器可能已把它折叠进只读段
```

「指向字符串字面量的指针必须是 `const char *`」是同一条规则最常见的现场：字面量存放在只读段（[第 1 篇](01-c-model.md)的五段布局），通过非 const 指针写它 → 段错误。

## 4. 多级指针：为「改指针本身」而生

什么时候需要二级指针？当**被修改的东西本身是指针**时——和「函数要改外部 int 就传 int*」是同一个逻辑，套两层而已：

```c
void set_to_new(int **pp) {
    *pp = malloc(sizeof(int));     // 修改的是调用方的「指针变量」
}

int main(void) {
    int *p = NULL;
    set_to_new(&p);                // 传 p 的地址
    *p = 42;                       // p 已经指向新分配的内存
}
```

最常见的三级结构是 `main` 的 argv 和二维字符串表：

```text
char **argv（argv[0]…argv[argc-1] 是 char*）

argv:   [ptr]──→ [ptr]──→ "prog\0"
        [ptr]──→ [ptr]──→ "-v\0"
        [NULL]           [ptr]──→ "file.txt\0"
```

`argv` 本身是一个指针数组的首地址；`argv[1][2]` 先走第一步取到 `char*`，再解引用到具体字符。判断多级指针的口诀：**每多一层，就多一次「这里存的是地址」**；画图永远比背规则快。

## 5. void*：类型擦除的边界

`void *` 是「不知类型的地址」：任何对象指针都能隐式转成 `void*`，反之亦然（C 里允许，C++ 不允许——这是两语言为数不多的兼容性差异）。它**不能解引用、不能做算术**（不知道步长是几），只能搬运和转交：

```c
void *memcpy(void *dst, const void *src, size_t n);
void *malloc(size_t size);       // 返回 void*：分配的是「无类型的 n 字节」
```

`malloc` 返回 `void*` 正是为了通用性——同一套分配器服务所有类型，调用方负责解读：

```c
int *arr = malloc(10 * sizeof *arr);   // ✅ 用 *arr 反推类型，改类型时这行不用动
double *vec = malloc(n * sizeof *vec);
```

`void*` 的使用纪律只有两条：

1. **转回目标类型必须转对**。把 `int*` 存进 `void*` 再读成 `double*`，是「无效类型访问」，属于[第 1 篇](01-c-model.md)清单里的别名违规 UB。
2. **`void*` 之间不做算术**。需要按字节推进用 `(unsigned char *)`——按字节访问是严格别名规则唯一无条件的例外。

## 6. 三类事故：野、悬垂、越界

指针的所有事故可以归成三类，每类有独立的成因与防御。把它们分开是调试 C 程序的第一项基本功。

### 6.1 野指针：从未初始化的指针

```c
int *p;             // 栈上的 8 字节垃圾
*p = 1;             // 写进随机地址：可能段错误，可能「什么都没发生」但踩坏了别的数据
```

野指针最阴险的地方是**故障点与出错点相距十万八千里**：你污染的是随机一块内存，崩溃发生在之后任何倒霉的地方。防御是机械动作：**声明即初始化**——暂时没有对象可指就置 `NULL`，解引用前判空。

```c
int *p = NULL;      // NULL 解引用是「好崩溃」：地址 0 附近的访问必然段错误，现场清晰
```

### 6.2 悬垂指针：曾经有效，现在失效

两种来源，症状相同——指针还在、指向的内存已不属于你：

```c
/* 来源①：指向已销毁的栈帧（见第 1 篇） */
int *bad(void) { int local = 42; return &local; }

/* 来源②：free 之后继续使用 */
int *p = malloc(sizeof(int));
free(p);
*p = 1;             // ❌ use-after-free：内存可能已被分配给别人
```

use-after-free 是 C 安全漏洞榜的常年前列，因为 freed 内存通常立刻被复用——你写的可能是攻击者精心布置的数据。工程防御三件套：

1. **free 后立刻置空**：`free(p); p = NULL;`——把「悬垂」降级成「空指针解引用」，崩溃点就在案发现场。（对 `p` 本身有效；同一指针的多个拷贝管不到，那是所有权设计问题，见[第 7 篇](07-dynamic-memory.md)。）
2. **不返回栈地址**：需要函数产出数据，用调用方传入的缓冲区或堆分配。
3. **交给工具**：ASan 对 use-after-free 的检出率接近 100%，`-fsanitize=address` 下一行报告定位到释放与使用两处（[第 13 篇](13-tools-debugging.md)）。

### 6.3 越界：差一错误的温床

数组名做参数时退化为指针、长度信息丢失（[第 5 篇](05-arrays-strings.md)详述），于是「知道长度」成了程序员的责任。越界访问的下场和野指针一样随机——往数组后面多写一个字节，踩到的可能是相邻变量、管理元数据（堆分配器的块头！）或返回地址。

```c
int a[10];
a[10] = 0;          // ❌ 合法下标是 0~9；a[10] 是「末尾后一位」，连读都不行
for (size_t i = 0; i <= n; i++) s += a[i];   // ❌ 经典 off-by-one：应为 i < n
```

防御：循环条件统一用 `i < n` 半开区间写法；下标类型用 `size_t` 并保证比较双方同类型（[第 2 篇](02-types.md)）；所有数组访问先想一遍「n 为 0 时这段代码会发生什么」。

> [!TIP]
> 三类事故共享一个元规则：**C 不在运行时检查指针**——没有任何机制在解引用前验证地址合法性。所有检查必须由你的代码显式做，或者交给 sanitizer/valgrind 这类调试工具。把「我的指针总是对的」这句话从脑子里删掉，换成「我的检查在哪里」。

## 7. 指针代码的三条肌肉记忆

1. **声明即初始化**：`int *p = NULL;` 或直接指向有效对象。从源头上消灭野指针。
2. **谁分配谁释放，free 后置空**：所有权单一化（[第 7 篇](07-dynamic-memory.md)展开成完整的所有权设计）。
3. **解引用前必须回答三个问题**：指向有效吗（判空）？还在生命周期里吗（悬垂）？下标在界内吗（越界）？三个问题答不出来就先补检查——这三问的自动化工具就是 sanitizer。

## 8. 陷阱清单

- `int *a, b;`：`*` 只修饰 a；一行一个指针声明。
- 指针相减/比较的对象不是同一数组：无意义且破坏优化器假设。
- `(int *)&ci` 后写入：本体 const 的对象不可写，UB。
- 字符串字面量赋给 `char *` 后修改：字面量在只读段；一律 `const char *`。
- `free(p)` 后继续读/写 p：use-after-free；free 后立即置 NULL。
- 返回局部变量地址：栈帧已销毁；改用出参或堆。
- `a[n]` 当「末尾后一位」解引用：越界 UB；末尾后一位只可比较不可访问。
- 指针转 int 保存：截断；用 `uintptr_t`。
- 把 `void*` 强转回错误类型再解引用：别名违规 UB。
- 忘记 `malloc` 返回值判空：小分配几乎不失败，但失败时不判空就是空指针解引用。
- 对 `void*` 做算术：GNU 扩展允许按 1 字节步进，但不可移植；显式转 `unsigned char*`。

## 9. 小结

- 指针是存地址的变量；类型在指针里的角色是「解引用宽度 + 步长 + 对齐要求」，三者一起解释了指针算术的缩放行为。
- 指针运算的合法域是「数组内 + 恰指末尾后一位」；末尾后一位可比较不可解引用，再向前一步是 UB。同数组指针才能相减（得 `ptrdiff_t`）与比较。
- const 从 `*` 位置区分修饰对象还是修饰指针；函数签名里的 const 是接口契约；绕过 const 修改真正 const 的本体是 UB。
- 多级指针服务「要修改的东西本身是指针」；`char **argv` 的图示是一切多级结构的原型。
- `void*` 是类型擦除的搬运工：不能解引用、不能算术、转回必须转对；`malloc` 返回它正是为了服务所有类型。
- 事故三类：野（未初始化）、悬垂（生命周期已尽）、越界（差一）。元规则是 C 不做运行时指针检查——安全来自「声明即初始化、free 即置空、解引用前三问」加上 sanitizer 的自动化兜底。

## 10. 练习

**1.** 写程序打印 `sizeof(int *)`、`sizeof(char **)`、`sizeof(void *)`、`sizeof(int[5])`、`sizeof(int(*)[5])`，解释结果。

> [!TIP]
> 思路前三个都是 8（64 位平台）：所有对象指针同宽。`int[5]` 是 20 字节的完整数组；`int(*)[5]` 是「指向含 5 个 int 的数组的指针」，仍是指针 8 字节，但步长是 20——为多维数组传参伏笔（[第 5 篇](05-arrays-strings.md)）。

**2.** 画出 `char *names[] = {"alice", "bob", NULL};` 的内存图，写出遍历到 NULL 为止的循环。

> [!TIP]
> 思路 names 是 char* 数组，三个槽位分别指向三段字面量，最后 NULL 是哨兵。`for (char **p = names; *p; ++p) puts(*p);`。哨兵终止是 C 里「不传长度」的第二种方案（另一种是长度参数），argv 就这么工作。

**3.** 实现 `void swap_ptrs(void **a, void **b)`，并用它交换两个 `int*`。解释为什么 `swap(void *a, void *b)` 做不到这件事。

> [!TIP]
> 思路交换的是「指针变量的值」，所以参数必须是指针的地址。`swap(void*, void*)` 拿到的只是地址的拷贝，改它影响不到调用方的变量——与「swap(int,int) 改不了外部 int」完全同构。

**4.** 下面的代码有哪几类事故？逐行标注。

```c
char *get_greeting(void) {
    char buf[64];
    strcpy(buf, "hello");
    return buf;
}

int main(void) {
    char *g = get_greeting();
    char *p;
    if (rand() % 2)
        p = malloc(16);
    printf("%s\n", g);
    free(p);
    return 0;
}
```

> [!TIP]
> 思路 get_greeting 返回栈数组（悬垂①）；p 未初始化（野指针），rand 为奇时未分配，free(p) 要么释放野指针要么漏释放；strcpy 无界拷贝本身是隐患（这里字面量短，但模式危险，见[第 5 篇](05-arrays-strings.md)）。逐行标注事故类型是代码审查的基本功。

**5.** 用 `const` 改写下面的签名，使其契约更精确，并说明每处 const 阻止了什么。

```c
void process(char *src, char *dst, int len);
```

> [!TIP]
> 思路如果 src 只被读取：`void process(const char *src, char *dst, size_t len)`——const 挡住对 src 的写，size_t 修正长度类型。如果 src 与 dst 允许重叠还要用 `restrict` 表达不重叠承诺（性能关键字，见[第 5 篇](05-arrays-strings.md)）。

**6.** 解释为什么 `int *p = malloc(10 * sizeof(int));` 中 `sizeof *arr` 写法比 `sizeof(int)` 更稳健，并指出 `10 * sizeof(int)` 潜在的溢出风险与对策。

> [!TIP]
> 思路 `sizeof *p` 跟着 p 的类型走，数组元素类型改动时分配语句不会失配（类型改了 sizeof 也跟着改）。溢出：10 换成巨大值时乘法在 size_t 内回绕，分配出远小于预期的块。对策：检查乘法上界或用带溢出检查的封装（glibc 有 `reallocarray`）。
