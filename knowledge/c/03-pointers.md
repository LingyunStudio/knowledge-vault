指针是 C 的灵魂：函数修改外部变量、堆分配、链表树图，全靠它。理解指针不需要天赋，只需要建立一个画面——**内存是一排编了号的格子，指针就是格子的编号**。

## 取地址与解引用

两个互逆的运算符撑起指针的全部基础：

- `&x`：取地址，得到变量 x 所在格子的编号
- `*p`：解引用，顺着编号 p 找到那块内存，读写它

```c
#include <stdio.h>

int main(void) {
    int x = 42;
    int *p = &x;                 // p 存的是 x 的地址，类型 int *

    printf("%p\n", (void *)p);   // 打印地址（如 0x7ffd...）
    printf("%d\n", *p);          // 42：顺着地址取值

    *p = 100;                    // 通过指针改写 x 本体
    printf("%d\n", x);           // 100
    return 0;
}
```

声明 `int *p` 的 `*` 属于 p 而不属于 int，一行声明两个变量时容易写错：

```c
int *a, b;      // ❌ a 是指针，b 只是普通 int！
int *a, *b;     // ✅ 两个都是指针；或者干脆一行一个
```

> [!NOTE]
> 在 64 位平台，**所有对象指针都是 8 字节**，与指向的类型无关。类型 `int *`、`double *` 的意义在于告诉编译器：解引用时读几个字节、按什么格式解读、指针 +1 时跨多远。

## 指针与函数：C 的「出参」

C 的函数传参永远是**拷贝**。想让函数修改调用方的变量，只能把地址拷过去：

```c
#include <stdio.h>

void swap(int *a, int *b) {
    int tmp = *a;    // 拷贝 a 指向的值
    *a = *b;
    *b = tmp;
}

int main(void) {
    int x = 1, y = 2;
    swap(&x, &y);               // 必须传地址
    printf("%d %d\n", x, y);    // 2 1
    return 0;
}
```

这是 C 在没有 Rust `&mut` 的世界里最朴素的方案：拷贝地址，通过地址摸到本体。栈帧与生命周期的细节见[函数与作用域](07-functions-scope.md)。

## 指针与数组：一对纠缠的概念

在表达式中，数组名会**退化**（decay）成指向首元素的指针，所以下标和指针可以互换：

```c
int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;                  // 等价于 &arr[0]

printf("%d\n", p[2]);          // 30：指针也能用下标
printf("%d\n", *(arr + 2));    // 30：arr[i] 的本质就是 *(arr + i)
```

`p + 1` 不是地址加 1 字节，而是跨过一个元素的大小（`int` 就是 +4 字节），指针运算自动按类型缩放。

但**数组不等于指针**，最直接的证据是 `sizeof`：

```c
printf("%zu\n", sizeof(arr));    // 20：整个数组的字节
printf("%zu\n", sizeof(p));      // 8：只是一个指针
```

数组退化的推论很扎心：数组传进函数后就只剩指针，长度信息丢失，所以 C 的函数一律要额外传长度：

```c
#include <stdio.h>
#include <stddef.h>

void print_arr(const int *a, size_t n) {    // 必须带上长度
    for (size_t i = 0; i < n; i++)
        printf("%d ", a[i]);
}
```

## NULL：明确的「不指向任何东西」

`NULL` 表示空指针，定义在 `<stddef.h>`（`stdio.h` 等常见头文件也间接提供）：

```c
int *p = NULL;          // 初始化为空，比留随机值安全得多

if (p != NULL) {        // 使用前判空，等价写法 if (p)
    printf("%d\n", *p);
}
```

解引用 NULL 几乎必然段错误——但这是**好**的崩溃：问题明确、现场清晰。真正的杀手是下一节的野指针。

## 野指针：最阴险的错误

野指针 = 指向无效内存的指针。它和正常指针长得一模一样，崩溃位置可能离出错位置十万八千里：

```c
int *p;                 // ❌ 未初始化：里面是随机值
*p = 1;                 // 往随机地址写数据，后果不可预测

int *q = malloc(4);
free(q);
*q = 2;                 // ❌ use-after-free：悬空指针
```

纪律只有一条：**每个指针要么指向有效对象，要么是 NULL，不存在第三种状态**。

```c
int *p = NULL;          // ✅ 出生即判空
free(p);
p = NULL;               // ✅ 释放后立刻置空，杜绝悬空
```

> [!WARNING]
> `free` 后置空救不了所有场景：同一块内存的地址若还存在**另一个**指针里，那个指针照样悬空。多个指针共享一块内存时，谁释放、谁置空必须事先约定——这正是[内存管理](04-memory-management.md)要解决的问题。
