数组是 C 里唯一**不能整体赋值、不能整体传参、不能作为返回值**的复合类型——因为它在任何「传递」场合都会**退化**（decay）成一个光秃秃的指针，长度信息当场丢失。这一个设计决策的连锁反应贯穿整门语言：函数必须额外传长度、字符串必须用 `\0` 结尾、缓冲区溢出成为半个世纪的安全漏洞主题。

理解退化不是背规则，而是看清一件事：**数组什么时候是「完整数组」，什么时候「已经变成了指针」**。这条分界线画清楚，本篇剩下的所有内容——多维数组、字符串函数、安全写法——都是它的推论。

## 1. 数组的本质：连续同类型，带长度的是「盒子」

数组是一段**连续的、同类型的**内存，长度是类型的一部分（`int[5]` 和 `int[6]` 是不同类型）：

```c
int a[5] = {1, 2, 3};      // 部分初始化：剩余元素清零（1,2,3,0,0）
int b[5] = {0};            // 全零惯用法
int c[]  = {1, 2, 3, 4};   // 长度由初始化器反推：int[4]
```

「数组不是指针」有两个铁证，是数组行为的全部秘密所在：

```c
int a[5];
sizeof(a);        // 20：整个数组的字节数（指针只会是 8）
&a;               // 类型是 int(*)[5]：指向「整个数组」的指针，步长 20
a;                // 表达式中：退化为 int*，指向 a[0]，步长 4
```

三条规则浓缩版：

1. **表达式中的数组退化为指向首元素的指针**——除非它是 `sizeof` 的操作数，或 `&` 的操作数（这两处数组保持完整身份）。
2. 做函数参数的数组**必然退化**：`void f(int a[5])` 和 `void f(int a[])` 和 `void f(int *a)` 是**完全相同**的签名，编译器看到的都是 `int*`。方括号里的数字会被无视（写大点唬人没有用）。
3. 退化后的一切后果：长度丢失、不能整体赋值（`a = b` 非法）、不能做函数返回类型、数组之间不能比较（比较的是退化后的地址）。

> [!TIP]
> `&a` 与 `a` 数值相同、类型不同——这是二维数组传参的关键伏笔（第 3 节）。`sizeof` 是唯一「数组还知道自己多大」的场合，所以「在数组定义所在的函数里先算好长度」是 C 的通用自救姿势。

## 2. 退化的代价：长度必须随身携带

退化意味着「数组进了函数就只剩首元素地址」，所以 C 函数处理数组的标准签名永远多一个长度参数：

```c
/* 数组参数的标准形态：指针 + 长度；长度类型 size_t（第 2 篇） */
double mean(const double *a, size_t n) {
    if (n == 0) return 0.0;            // 先处理空：除零防线
    double s = 0;
    for (size_t i = 0; i < n; ++i) s += a[i];
    return s / (double)n;
}

/* 另一种终止方案：哨兵值（argv、字符串就是这么工作的） */
void print_all(const char **items) {   /* 以 NULL 结尾 */
    for (; *items; ++items) puts(*items);
}
```

「长度参数」与「哨兵值」是 C 数据结构的两大流派，各自适合的场景：

| 方案    | 适合                  | 不适合                | 代表                |
| ----- | ------------------- | ------------------ | ----------------- |
| 长度参数  | 二进制块、任意内容（可能含 0 字节） | 参数表膨胀，调用方要自己记住长度   | `memcpy(dst,src,n)` |
| 哨兵终止  | 序列元素有「不可能出现的值」      | 要扫到末尾才知道长度（O(n)），内容受限 | 字符串 `\0`、argv 的 NULL |

### 2.1 二维数组：退化只发生一次

「数组的数组」退化规则只做一次：`int a[3][4]` 在表达式中退化成**指向首行**的指针，类型是 `int (*)[4]`——不是 `int**`！这是初学者第二大坑（第一大是指针本身）：

```c
void print_matrix(int m[][4], size_t rows);   // 等价于 int (*m)[4]
void print_matrix(int **m, size_t rows);      // ❌ 完全错误：类型不匹配
```

`int (*)[4]` 与 `int**` 的内存模型完全不同：

```text
int m[3][4]（一块连续内存，12 个 int）        int **pp（指针的指针）
┌─────────────── 第 0 行 ───────────────┐      pp: [ptr] ──→ [ptr,ptr,ptr]
│ m[0][0] m[0][1] m[0][2] m[0][3]      │              │      │     └→ 数据
├─────────────── 第 1 行 ───────────────┤              │      └→ 数据
│ m[1][0] m[1][1] …                    │              └→ 数据
├─────────────── 第 2 行 ───────────────┤
```

`m[i][j]` 在连续布局下编译为 `*(基址 + i*4 + j)`——一次乘法一次访存，缓存极其友好；在指针的指针布局下是两次跳转。**列数必须写进类型**，因为「每行多宽」是地址计算的一部分——这正是退化后的指针还需要它才能工作 `m+1` 的原因。

动态分配二维数组的三个方案，按推荐顺序：

```c
/* 方案 A（推荐）：一块连续内存，手动按行索引 —— 一次分配，缓存最优 */
int *m = malloc(rows * cols * sizeof *m);
m[i * cols + j] = v;                    // 用宏或内联函数封装下标运算
free(m);

/* 方案 B：先分配行指针数组，再逐行分配 —— m[i][j] 语法可用，行可不等长，但 N+1 次分配 */
int **m = malloc(rows * sizeof *m);
for (size_t i = 0; i < rows; ++i)
    m[i] = malloc(cols * sizeof **m);
/* 释放要倒序逐行 free，再 free 指针数组：漏一步就泄漏 */

/* 方案 C：一块连续内存 + 行指针数组指进内部（两者的混合体） */
int *data = malloc(rows * cols * sizeof *data);
int **m = malloc(rows * sizeof *m);
for (size_t i = 0; i < rows; ++i) m[i] = data + i * cols;
/* 只需两次分配两次释放；兼具 m[i][j] 语法与连续存储 */
```

## 3. C 字符串：一个约定撑起的全部

C 没有字符串类型。所谓字符串，就是**一段以 `\0`（值为 0 的字节）结尾的字符数组**。这个约定的全部后果：

1. **长度是 O(n)**：`strlen` 必须从头扫到尾。在循环条件里写 `i < strlen(s)` 是 O(n²)（先把长度存下来）。
2. **内容不能含 `\0`**：二进制数据（图片、加密块）不是字符串，操作它们用 `memcpy` + 长度，绝不碰 str 系函数。
3. **忘记 `\0` = 越界读写**：所有 str 函数都依赖终止符决定「扫到哪里」。

### 3.1 函数全景与危险分级

```c
size_t  strlen(const char *s);                 /* 长度，不含 \0 */
int     strcmp(const char *a, const char *b);  /* 按字节比较：返回 <0 / 0 / >0 */
char   *strchr(const char *s, int c);          /* 找第一个字符（含 \0 本身） */
char   *strstr(const char *h, const char *n);  /* 找子串 */
char   *strcpy(char *dst, const char *src);    /* ❌ 无界复制 */
char   *strcat(char *dst, const char *src);    /* ❌ 无界追加 */
char   *strncpy(char *dst, const char *src, size_t n); /* ⚠️ 语义陷阱，见下 */
void   *memcpy(void *dst, const void *src, size_t n);  /* 按长度复制任意字节 */
```

**`strcmp` 的返回值只看符号，不看数值**：`strcmp(a,b) == 1` 是错的（glibc 可能返回任何正数），正确判等只有 `== 0`、小于用 `< 0`。

**`strncpy` 是最著名的语义陷阱**，它的真实用途是填充**固定宽度字段**（老式目录表项），不是「安全 strcpy」：

```c
strncpy(dst, src, n);
/* 行为：copy 至多 n 字节；若 src 短于 n，剩余全填 '\0'（浪费）；
        若 src 长于等于 n，恰好复制 n 字节——【不写终止符】！ */
```

也就是说「源串刚好装满」时 dst 不是合法 C 字符串，下一次 `strlen`/`printf` 直接越界奔出缓冲区。**任何教程让你用 strncpy 当安全 strcpy 的，都是把 bug 写进了教材**。现代替代：

```c
/* 方案一：snprintf —— 标准库，永远终止，返回「本想写多少」（可检测截断） */
snprintf(dst, dstsz, "%s", src);

/* 方案二：C23 标准化的 strlcpy（BSD 出身） */
size_t n = strlcpy(dst, dstsz, src);   /* 永远终止，返回 src 长度用于检测截断 */

/* 方案三：手写三行，最透明 */
size_t i = 0;
for (; i + 1 < dstsz && src[i]; ++i) dst[i] = src[i];
dst[i] = '\0';
```

### 3.2 字符串构造：snprintf 是唯一全能选手

拼接、格式化、数字转字符串，全部走 `snprintf`。它的两个特性让它无可替代：**保证终止**（永远最多写 size−1 字节 + `\0`）和**返回完整格式化需要的长度**（返回值 ≥ size 说明被截断了，可以据此重新分配）：

```c
/* 两遍法动态构造：先量再建，不多分配一个字节 */
char *join(const char *a, const char *b) {
    size_t need = snprintf(NULL, 0, "%s/%s", a, b);   /* 第一遍：只算长度 */
    if (need == (size_t)-1) return NULL;              /* 编码错误 */
    char *s = malloc(need + 1);
    if (!s) return NULL;
    snprintf(s, need + 1, "%s/%s", a, b);             /* 第二遍：真正写入 */
    return s;
}
```

数字转字符串同理：`snprintf(buf, sizeof buf, "%d", x)`；反向解析绝不用 `atoi`（不报错），用 `strtol`（[第 2 篇](02-types.md)第 2.4 节）。

### 3.3 缓冲区溢出：为什么「多写一个字节」是国家安全问题

无界函数（`gets`、`strcpy`、`sprintf`、`scanf("%s")`）的漏洞不是「程序出错」级别的，而是**远程代码执行**级别的。原理一句话能说清：

```text
栈帧布局（第 1 篇五段图的局部放大）：
  [ 局部变量 buf[16] ] ← 输入超过 16 字节，从低地址向高地址漫延
  [ 保存的帧指针     ] ← 被覆盖
  [ 返回地址         ] ← 被覆盖成攻击者指定的地址
  → 函数 ret 时跳到攻击者的代码
```

输入数据精准覆盖栈上的**返回地址**，函数返回时就跳到了攻击者布置的代码。现代缓解（栈保护 canary、ASLR、NX 位、`_FORTIFY_SOURCE`）把利用难度抬高了很多，但**根本防御永远是源头不用无界函数**：

| 禁用                          | 替换为                                            |
| --------------------------- | ---------------------------------------------- |
| `gets`（C11 已删除）              | `fgets(buf, sizeof buf, stdin)`                 |
| `strcpy`                    | `snprintf` / `strlcpy` / 手写带界复制                  |
| `strcat`                    | `snprintf(s, sz, "%s%s", a, b)`                 |
| `sprintf`                   | `snprintf`（永远）                                  |
| `scanf("%s", buf)`          | `scanf("%63s", buf)`（宽度必须是「缓冲区大小−1」）             |
| `atoi`                      | `strtol`                                        |

> [!WARNING]
> `scanf` 的宽度参数记法：`%63s` 读最多 63 字符再补 `\0`，需要 64 字节缓冲区。**「宽度 = 缓冲区大小 − 1」这个差一关系在改动缓冲区尺寸时必须同步改**，否则防护本身变成新的差一错误——更稳的路线干脆用 `fgets` + `strtol`。

## 4. 字符、字节与编码：strlen 数的是字节

### 4.1 char 的符号性与 ctype 的陷阱

`char` 的符号性由实现定义（[第 2 篇](02-types.md)），于是连「判断一个字符是不是数字」都有坑：

```c
char c = 'ä';                 // UTF-8 下是两个字节，这里取到一个负值（signed char 平台）
isdigit(c);                   // ❌ ctype 函数要求参数是 [0,255] 或 EOF，负值是 UB！
isdigit((unsigned char)c);    // ✅ 标准姿势：先转 unsigned char
```

**ctype 家族（isalpha/isspace/toupper…）的参数超出 `[0, 255] ∪ {EOF}` 是 UB**——这是隐藏最深的标准条款之一。规则一句话：**凡是来自字符串、可能带符号扩展的 char，进 ctype 前先转 `unsigned char`**。

### 4.2 UTF-8：strlen(“你好”) == 6

C 的字符串函数全是**按字节**工作的，而 UTF-8 是多字节编码（汉字 3 字节）。后果清单：

- `strlen("你好")` 是 6，不是 2——「字符数」和「字节数」从此是两个概念。
- `s[i]` 取的是第 i 个**字节**，可能是某个汉字的中间部分；直接对它调 ctype/toupper 是未定义或无意义的。
- 截断字符串（`buf[10]`）可能把一个多字节字符拦腰斩断——终端会显示乱码。
- **好消息**：UTF-8 的设计使「按字节排序 `strcmp`」恰好等于按码点排序、找单字节字符 `strchr` 也安全。这就是 UTF-8 统治互联网的原因之一——C 字符串函数在它上面「大体能用」。
- **真需要按字符处理**（大小写、字宽、分词）时，C 标准库不够用，上 ICU 或 utf8proc 这类库。

## 5. 字符串与数组的综合事故表

| 事故                       | 根因                  | 防御                          |
| ------------------------ | ------------------- | --------------------------- |
| `sizeof(buf)` 在函数参数里返回 8 | 数组参数退化为指针           | 长度单独传参；尺寸用宏统一管理              |
| `char buf[10]; buf[10]`  | 合法下标 0~9            | 半开区间 `i < n`；边界用 `sizeof buf` 减一 |
| `strncpy` 后忘补 `\0`       | 装满时不终止              | 弃用 strncpy，用 snprintf        |
| `scanf("%s")` 无界         | 没有宽度                | fgets 或 `%63s`              |
| 循环里 `strlen(s)`          | O(n²)               | 循环外存一次长度                    |
| 对二进制数据用 str 系            | 提前遇到 `\0` 停止        | memcpy + 显式长度               |
| 两个相邻字符串字面量意外拼接           | C 的字面量拼接规则          | 数组初始化列表里给每个字符串单独的花括号          |
| `char *p = "hi"; p[0]='H'` | 字面量在只读段           | `const char *p`             |

最后一条值得展开，它足够冷门到值得专门点名：

```c
char *cmds[] = {
    "list", "add", "del"
    "help"                    // ❌ 上一行行尾少了逗号 → "delhelp"
};
```

C 规定相邻的字符串字面量在**翻译期自动拼接**（跨行也拼）。这个特性本用于长文本分行书写，但落在初始化列表里就成了静默的元素合并——编译器不告警，数组悄悄少一个元素、多一个更长的字符串。

## 6. 陷阱清单

- 数组做参数后 `sizeof` 得到指针大小：长度必须显式传。
- `int m[3][4]` 传成 `int**`：类型不同，崩或错。列数要写进参数类型。
- `strncpy` 装满不终止：换 `snprintf`/`strlcpy`。
- `strcmp` 返回值当 −1/0/1 用：只判符号。
- 循环条件里 `strlen`：O(n²)，先存长度。
- `scanf("%s")` 无界、`gets` 已从语言中删除：fgets 或带宽度。
- ctype 函数吃负 char：先 `(unsigned char)`。
- `strlen` 对 UTF-8 数的是字节：字符数另算，截断防腰斩。
- 字符串字面量赋给 `char*` 并修改：只读段，段错误。
- 初始化列表漏逗号触发字面量拼接：元素静默合并。
- 二进制数据交给 str 系函数：`\0` 截断；用 memcpy。
- 动态二维数组逐行分配后漏 free 行指针数组：先逐行 free 再 free 数组。

## 7. 小结

- 数组在表达式中退化为首元素指针，唯 `sizeof` 与 `&` 例外；做参数必然退化——「指针 + 长度」与「哨兵终止」是补回长度信息的两大流派。
- 二维数组是连续内存 + 行主序，退化后类型是 `int (*)[列数]`，与 `int**` 是两种内存模型。动态二维优先「一块连续内存 + 下标运算」，兼顾缓存与分配次数。
- C 字符串是 `\0` 约定：长度 O(n)、内容不能含 0、忘记终止就是越界。strncpy 的真实语义是填固定宽度字段，不是安全复制；安全的构造与拼接只有 `snprintf` 一个全能答案。
- 缓冲区溢出的危害等级是远程代码执行：无界函数（gets/strcpy/sprintf/scanf %s）逐一替换为带界版本，是 C 代码审查的固定检查项。
- char 的符号性是实现定义，ctype 函数吃负值是 UB——进 ctype 前转 unsigned char。strlen 数字节不数字符，UTF-8 下「字符数」是另一个量。
- 相邻字符串字面量自动拼接：长文本分行的特性，初始化列表漏逗号时的陷阱。

## 8. 练习

**1.** 写出以下四个 sizeof 的值并解释：`int a[10]; sizeof(a)`、`sizeof(a[0])`、`sizeof(&a[0])`、以及把 a 传入 `void f(int b[10])` 后 `sizeof(b)` 的值。

> [!TIP]
> 思路 40、4、8、8。函数参数位置的 `b` 已退化为 `int*`——方括号里的 10 被无视。这组对比就是「数组 vs 指针」的一课：同一名字，在定义处与在参数处是两种东西。

**2.** 实现 `char *str_trim(const char *s)`：去掉首尾空白，返回新分配的字符串（调用方负责 free）。要求处理全空白、空串、NULL 输入。

> [!TIP]
> 思路两指针从两端夹逼找边界 → 用 `isspace((unsigned char)c)` → 计算区间长度 → malloc(len+1) → memcpy + 手工补 `\0`。考点：malloc 判空、`(unsigned char)` 提升陷阱、返回动态内存的所有权在文档里写明。

**3.** 为什么 `memcpy` 需要 n 参数而 `strcpy` 不需要？各自适合什么数据？写一个函数把 `int a[10]` 的内容复制到 `int b[10]`，用两种方式。

> [!TIP]
> 思路 memcpy 面向任意字节（可含 \0），长度必须显式；strcpy 面向终止约定字符串。复制方式①循环 `b[i]=a[i]`；②`memcpy(b, a, sizeof a)`——注意在 a 定义可见处 sizeof a 才是 40，进了函数就是 8（退化）。这正是第 6 条陷阱的实战演练。

**4.** 把下面的危险代码逐一修复，并说明每个替换防住了什么攻击场景。

```c
void greet(void) {
    char name[32];
    char msg[80];
    printf("name? ");
    scanf("%s", name);
    strcpy(msg, "hello, ");
    strcat(msg, name);
    printf(msg);
}
```

> [!TIP]
> 思路①`scanf("%31s", name)` 或 fgets 防溢出（栈上返回地址覆盖）；②`snprintf(msg, sizeof msg, "hello, %s", name)` 一次完成拼接且保证终止；③`printf("%s", msg)` 而不是 `printf(msg)`——后者是格式化字符串漏洞（msg 含 %x %n 时可读可写内存），与缓冲区溢出并列的古典漏洞类型。

**5.** 用「一块连续内存」方案实现动态创建 rows×cols 的 double 矩阵，封装 create/free/at 三个函数，并解释下标公式 `i*cols+j` 与行主序的关系。

> [!TIP]
> 思路 create 一次 malloc，free 一次 free，at 返回 `data + i*cols + j`（带行列边界检查返回 NULL 或 assert）。行主序 = 同一行元素地址连续，跨行跳 cols 个元素——与静态 `m[rows][cols]` 的布局完全一致，所以这个方案的数据可以直接交给期望 `double (*)[cols]` 的接口（用 cast 或在分配时按该类型对齐）。

**6.** `char buf[10] = "abcdefghi";` 之后执行 `strncpy(buf, "0123456789ABCDEF", sizeof buf)`，buf 现在是合法字符串吗？验证并修复。

> [!TIP]
> 思路不是：源串长于 10，strncpy 恰好复制 10 字节，没有终止符——strlen 会越界读出去。打印会看到 buf 的 10 字节后面跟着内存里的垃圾。修复：`snprintf(buf, sizeof buf, "0123456789ABCDEF")`，或 strncpy 后强制 `buf[sizeof buf - 1] = '\0'`。
