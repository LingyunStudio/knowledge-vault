R 出生于统计系（Auckland 大学，1993），它的每个语法决策都在回答「统计学家怎么工作」：**数据是向量化的**（一列数据 = 一个向量，不是 for 循环）、**模型是对象**（`lm()` 返回可 summary/plot/predict 的东西）、**交互探索优先**（REPL 是主战场，脚本是其固化）。理解「为统计而生」这个设计目标，R 的怪癖就从「反直觉」变成「有原因」。

## 1. 交互式统计工作台：REPL 优先的工作流

R 与 MATLAB（[matlab 篇](../matlab/01-matlab-model.md)）共享「交互环境 + 脚本固化」的工作形态，但 R 的交互密度更高：

```r
> x <- rnorm(100)          # 生成 100 个标准正态数
> mean(x); sd(x)           # 立刻看均值与标准差
> hist(x)                  # 立刻看分布
> t.test(x, mu = 0)        # 立刻做假设检验
```

「算一步看一步」是统计分析的真实节奏——每个模型都需要「看数据 → 拟合 → 诊断 → 修改」的循环。RStudio 把这个循环组织成四窗格：

```text
┌──────────────┬──────────────┐
│ 源码编辑器    │ 环境变量/历史 │
│ (脚本)        │ (工作区)      │
├──────────────┼──────────────┤
│ 控制台 (REPL) │ 图/文件/帮助  │
└──────────────┴──────────────┘
```

- **脚本窗**写可复现代码（Ctrl+Enter 逐行送控制台执行——「边写边跑」的标准节奏）。
- **环境窗**看当前变量；**绘图窗**接收图表；**帮助窗**是 `?mean` 的去处。
- **Projects**（.Rproj）：每个分析一个项目目录——工作目录、历史、环境随项目隔离（[第 11 篇](11-projects-reports.md)）。

「写脚本时逐行执行」是 R 分析的正确姿势：**脚本 = 已验证的交互序列**，不是写完才跑的程序。

## 2. 向量化：一列数据是一个向量

```r
heights <- c(170, 165, 180, 172)     # c()：concatenate，构造向量
heights + 5                          # 全部 +5（向量化）
heights > 170                        # TRUE FALSE TRUE TRUE（逻辑向量）
heights[heights > 170]               # 170 180 172（逻辑索引过滤）
mean(heights)                        # 173.75
```

R 里没有「裸标量」——单个数是长度为 1 的向量（与 MATLAB 的「标量即 1×1 矩阵」同构思想）。**数据处理的最小单位是整个向量/列**：`sum(x > 0)` 数正数个数、`ifelse(v > 0, v, 0)` 向量化分支——统计计算天然是「对整列做运算」，循环是例外而不是默认（与 [MATLAB 向量化](../matlab/09-vectorization.md)同一哲学，R 甚至更彻底）。

## 3. 一切皆对象：泛型函数体系

R 的 OOP 是**泛型函数**（generic function）风格——不是「对象.方法()」而是「方法(对象)」：

```r
model <- lm(mpg ~ wt, data = mtcars)  # 线性模型 → 一个「模型对象」

summary(model)      # 泛型：根据对象类型分派到 summary.lm
plot(model)         # 泛型：分派到 plot.lm（四张诊断图！）
predict(model, newdata = ...)   # 预测
coef(model); residuals(model); anova(model)
```

`lm` 返回的东西自带一整套配套行为——**summary/plot/predict/anova 对不同模型（lm/glm/lmer/…）都工作**，因为每个模型类提供了自己的方法。这个设计让统计工作流「模型可插拔」：换一个模型类，下游的 summary/predict 语法不变。

R 的对象系统有两代：S3（`summary.lm` 这种按类名命名的函数——简单、动态、主流）与 S4/R5/R6（正式类系统——bioconductor 与特定包用）。**S3 是理解 R 生态的钥匙**：`class(x)` 给对象贴标签，`summary.<标签>` 的函数被 `summary()` 自动分派。

## 4. 设计取向的推论：语法里的统计学

R 的语法处处透着「为统计建模设计」：

```r
mpg ~ wt + cyl               # 公式（formula）：因变量 ~ 自变量——模型规范是一等语法
data = mtcars                # 数据参数：公式里的列名在数据框中查找
NA                           # 缺失值是一等公民（不是 NULL 也不是 NaN——三者的语义差异见第 2 篇）
1:5                          # [1] 2 3 4 5 —— 1-based（与 MATLAB 同党，与 Python 异党）
mean(x, na.rm = TRUE)        # 缺失处理是几乎每个统计函数的参数
```

- **公式接口** `y ~ x1 + x2` 直接翻译统计模型的记号——这是 R 对统计学最重要的语法贡献。
- **NA 传播**：`mean(c(1, NA, 3))` 返回 NA（缺失会传染）——统计正确性优先于便利，`na.rm = TRUE` 是显式开关。
- 函数参数**按全名或前缀匹配**（`na.rm`/`na`）——交互式打字快的取舍。

## 5. 生态版图：R 的分工与对手

| 需求                | R 的答案                        | 对位的 Python 方案        |
| ------------------- | ------------------------------- | ------------------------- |
| 统计建模与检验       | 内建 + CRAN 的海量方法包         | statsmodels/SciPy         |
| 数据整理            | dplyr/tidyverse（[第 5 篇](05-dplyr.md)） | pandas        |
| 可视化              | ggplot2（图形语法，[第 6 篇](06-ggplot2.md)） | matplotlib/seaborn |
| 统计报告            | R Markdown/Quarto（ knit 一体） | Jupyter                   |
| 机器学习工程        | tidymodels                       | scikit-learn/PyTorch      |
| 学术统计前沿        | ★ 新方法常最先出现在 CRAN         | 通常滞后数年              |

CRAN（16000+ 包）是 R 的护城河：**学术统计的新方法几乎总是先有 R 包**（论文作者自己的实现）。Python 的优势在通用工程（部署、深度学习生态、Web）。分工的实践形态：**R 做分析与报告，Python 做工程与产品**——混合团队两者并存（通过 CSV/Parquet/arrow 交换数据）。

## 6. 帮助系统

```r
?mean                # 函数帮助
??timeseries         # 模糊搜索
example(lm)          # ★ 直接运行帮助文档里的示例代码
vignette("dplyr")    # 包的长文教程（CRAN 包的最佳学习材料）
?"/"                 # 运算符的帮助（语法类查询用反引号）
```

`example()` 是 R 帮助系统的独门优势：文档里的示例**可执行**——读文档即实验。vignette（包的论文式教程）是学习一个新包的正道，比博客可靠。

## 7. 陷阱清单

- `<-` 与 `=`：赋值惯例用 `<-`（`=` 留给函数参数）；`->` 与 `<<-` 认识即可少用。
- NA/NULL/NaN 三兄弟：NA 缺失、NaN 数值运算未定义、NULL「不存在」——混用是逻辑 bug 源（第 2 篇）。
- 1-based 索引与「最后一个下标越界不报错」：`x[6]` 在长度 5 的向量上返回 NA 而不是错误——R 的宽容是双刃剑。
- 期待 Python 式「对象.方法」：R 是 `method(obj)` 泛型风格；找方法用 `methods(summary)`。
- 忽略 str()：`str(obj)` 一行看清任何对象的结构——R 调试的第一命令。
- 在脚本里不设工作目录依赖：用 RStudio Project + here 包锚定路径。
- CRAN 包不加版本管理：`renv` 锁定包环境（第 11 篇），否则「半年后跑不出同样的结果」。

## 8. 小结

- R 的设计目标「统计学家的工作台」推导出全部取向：向量化、公式接口、NA 一等公民、泛型函数、交互 REPL 优先。
- RStudio 四窗格 + Project 是标准工作流；「脚本 = 已验证的交互序列」，Ctrl+Enter 逐行执行。
- S3 泛型体系让模型可插拔：lm 返回对象，summary/plot/predict 自动分派——统计工作流的接口一致性。
- 生态版图：CRAN 的学术统计新方法最全、ggplot2/tidyverse 的表达力强；Python 分工在工程与深度学习；混合是常态。
- 帮助系统：`?`/`example()`/`vignette()` 三层——示例可执行是 R 的独门体验。

> [!TIP]

**2.** 用 `str()` 与 `class()` 探察三个对象：向量、data.frame、lm 模型——画出「对象 → 类 → 泛型分派」的关系图。

> [!TIP]

**3.** 把 `example(ggplot2::ggplot)` 跑一遍，逐条看每段示例代码画出的图——用「可执行文档」学习一个包的入口 API。

> [!TIP]
> 思路example() 的输出在绘图窗连续刷新——像看动画演示。这个学习法的效率来自「看到每种调用的实际效果」，比读静态文档快。

**4.** 用公式接口拟合 `lm(mpg ~ wt + factor(cyl), mtcars)`，解释 factor() 在公式里的作用（连续 vs 分类变量的编码差异）。

> [!TIP]
> 思路数值列进公式默认按连续（一个系数），factor 按分类（哑变量编码，每水平一个系数）。这是 R 公式接口「统计语义内置」的代表——同样的语法，类型决定模型结构。

**5.** 对比 R 与 Python（[python 篇](../python/01-python-model.md)）各自解决「读 CSV → 分组求均值 → 画图」的完整代码，列出每个步骤的对应函数与心智模型差异。

> [!TIP]
> 思路R：`read_csv |> group_by |> summarise |> ggplot`（管道 + 声明式）；Python：`pd.read_csv().groupby().mean().plot()`（方法链）。两条链的每一步几乎一一对应——工具差异小于思维差异。
