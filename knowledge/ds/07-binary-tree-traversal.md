链表的每个节点只有一个后继，访问所有节点只有一条路。树不一样：每个节点有两个孩子，「先处理自己还是先处理孩子」变成了必须回答的问题——这个问题的四个答案（先序、中序、后序、层序）就是这篇的全部起点。更麻烦的是树是递归定义的，所以几乎所有树上算法都长得像遍历：判断对称、求树高、算直径、合并子树信息，代码骨架完全相同，只是「在哪一次到访做哪件事」不同。

大多数人在树上栽跟头，不是不会写递归，而是没想清楚信息的流向：哪些信息从根往下传（自顶向下），哪些从叶往上汇总（自底向上）。想清楚这一点，剩下的都是填空题。

## 1. 术语：先把九个词钉死

### 1.1 位置与度量

```text
            A                第 1 层，深度 1，该节点高度 4
          /   \
         B     C             第 2 层
        / \     \
       D   E     F           第 3 层
          / \
         G   H               第 4 层
```

| 术语          | 定义                  | 在这棵树里             |
| ----------- | ------------------- | ----------------- |
| 根（root）     | 唯一没有父节点的节点          | A                 |
| 叶（leaf）     | 没有孩子的节点，度为 0        | D、F、G、H           |
| 深度（depth）   | 从根往下数，根在第 1 层       | G 的深度是 4          |
| 高度（height）  | 从叶往上数，叶的高度是 1       | E 的高度是 2，A 的高度是 4 |
| 层（level）    | 深度相同的节点组成的集合        | {D, E, F} 是第 3 层  |
| 度（degree）   | 孩子的个数；树的度是所有节点度的最大值 | A 的度是 2，树的度是 2    |
| 子树（subtree） | 某个节点及其全部后代          | E 的子树是 {E, G, H}  |
| 森林（forest）  | m 棵（m ≥ 0）互不相交的树的集合 | 删掉 A，得到两棵树的森林     |

深度与高度各有两种口径：**边数口径**（根深度 0，空树高度 −1，CLRS 等教材用这套）与**节点数口径**（根深度 1，空树高度 0，中文教材常用）。只差 1，但混用会让所有公式和代码一起错。本文统一用节点数口径：`空树高度 = 0`、`叶高度 = 1`、`根深度 = 1`，于是有恒等式 `树高 = 最大深度 = 最大层号`。一条顺手的关系：对任意节点 v，`depth(v) + height(v) - 1 <= 树高`，取等号当且仅当 v 落在某条最长的根到叶路径上。上图里 B 满足 `2 + 3 - 1 = 4`（取等），C 是 `2 + 2 - 1 = 3`（小于）。

### 1.2 二叉树不等于「度为 2 的树」

二叉树的定义有两条要件：每个节点**至多**两个孩子，且孩子的左右位置**有序**——只有一个孩子时，它是左孩子还是右孩子也是结构的一部分。「度为 2 的树」有两个读法，都不等于二叉树：

- 读作「树的度为 2」（每个节点至多两个孩子、孩子无序），它比二叉树**少一层信息**：交换某个节点的两个孩子，得到的是同一棵无序树，却是另一棵二叉树。
- 读作「每个节点的度都恰好是 2」，这在有穷树里不存在：叶的度为 0（无向视角下是 1），不可能等于 2。

差多少？n 个节点的二叉树形态数是 Catalan 数 `C(n) = C(2n, n) / (n + 1)`（n = 1…6 时是 1、2、5、14、42、132），而无序有根树的形态数是 1、1、2、4、9、20——n = 3 时已经是 5 对 2。所以「左右有序」必须当真：`left` 和 `right` 是两个不同的字段，判「两棵树相同」要两边都比，而「允许左右互换」是另一个问题（5.2 节判断对称就是它的特例）。另外两点容易被忽略：二叉树允许空树（n = 0），也允许「只有左孩子没有右孩子」的半边空形态，因为空位本身参与结构。这直接导致一条漂亮的性质：n 个节点的二叉树恰好有 n + 1 个空指针域（2.5 节）。

### 1.3 满、完全、完美、平衡：四个词的四个坑

| 术语    | 英文                   | 确切定义                          | 等价判据                             |
| ----- | -------------------- | ----------------------------- | -------------------------------- |
| 完美二叉树 | perfect binary tree  | 每一层的节点数都达到该层上限                | `n = 2^h - 1`；所有叶在同一层且内部节点都有两个孩子 |
| 完全二叉树 | complete binary tree | 按层序编号后，与同高度的完美二叉树的前 n 个编号完全对应 | 层序编号连续无空洞；叶只出现在最后两层              |
| 满二叉树  | full binary tree     | 每个节点要么是叶，要么有两个孩子              | 没有单孩子节点（n₁ = 0）                  |
| 平衡二叉树 | balanced binary tree | 一个族而非一种形态：对外承诺「高度是 O(log n)」  | 常见判据是每个节点左右子树高度差不超过 1            |

> [!WARNING]
> 中文教材的「满二叉树」通常指英文的 **perfect**（每层都满），而英文的 **full** 指「每个节点要么 0 个孩子要么 2 个孩子」。同一个中文词在不同书里指向不同的东西，读英文材料时先看定义，否则「满二叉树有 2^h − 1 个节点」这句话会在 full 的语境里变成错的。

光看定义还是容易混，三个反例一次分清：

```text
① 完全且满，但不是完美        ② 满但不完全              ③ 完全但不满足满

        1                       1                        1
       / \                     / \                      / \
      2   3                   2   3                    2   3
     / \                     / \                      /
    4   5                   4   5                    4
                           / \
                          6   7

    层序 1 2 3 4 5            层序 1 2 3 4 5 _ _ 6 7    层序 1 2 3 4
    编号连续 → 完全           位置 6、7 空缺 → 不完全    编号连续 → 完全
    每节点 0/2 孩子 → 满      每节点 0/2 孩子 → 满       节点 2 只有左孩子 → 不满
    叶不在同一层 → 不完美
```

- ① 说明「完全 ∧ 满」推不出完美：最后一层没铺满时，会有一个叶孤零零留在倒数第二层。
- ② 说明「满」推不出「完全」：层序编号中间出现空洞，数组表示就会浪费。
- ③ 说明「完全」推不出「满」：完全二叉树允许一个只有左孩子的节点（这种节点最多一个，且必是左孩子）。

正确的蕴含关系只有单向的：`完美 ⇒ 完全 ⇒ 平衡`、`完美 ⇒ 满`，反过来一个都不成立。「平衡」是这四个词里唯一没有规定具体形态的：它只约束高度量级，所以完全二叉树是平衡的，红黑树是平衡的（形态可以一边高一边低），而线索二叉树底下那棵树完全可能不平衡。它的对立面是**退化（degenerate）**：n 个节点排成一条链，高度 n，所有 O(h) 的操作退化到 O(n)——这是第 12 节爆栈问题的根源。

## 2. 五条性质的证明

结论可以背，但推导过程决定了你记错时能不能自己救回来。

### 2.1 n₀ = n₂ + 1

记叶节点数为 n₀、只有一个孩子的节点数为 n₁、有两个孩子的节点数为 n₂，总数 `n = n₀ + n₁ + n₂`。

**证法一（边数 = 出度之和）**：树有 n − 1 条边——除根之外的每个节点，恰好有一条从父节点指向它的边。换一个角度数：每条边都是某个节点伸向自己孩子的，所以边数也等于所有节点的出度之和 `0·n₀ + 1·n₁ + 2·n₂`。

```text
n₀ + n₁ + n₂ - 1 = n₁ + 2·n₂
          n₀ + n₂ - 1 = 2·n₂      两边消去 n₁
                   n₀ = n₂ + 1
```

n₁ 被整个消掉了：单孩子节点有多少个，都不影响「叶比双孩子节点多一个」。**证法二（度数和 = 2 × 边数）**：把树当无向图看。每个节点的度 = 孩子数 +（有父节点则 1，否则 0），求和得 `(n₁ + 2n₂) + (n - 1)`；而树有 n − 1 条边，无向图中所有节点的度数和恒为 `2(n - 1)`。令两式相等并代入 `n = n₀ + n₁ + n₂`，得到的是同一个方程 `n₁ + 2n₂ = n - 1`，解出仍是 `n₀ = n₂ + 1`。

两条路殊途同归，因为无向度数恰好等于「出度 + 入度」，而入度之和恒为 n − 1。这也说明 `n₀ = n₂ + 1` 只依赖「树」这个结构，与「二叉」无关。**推广**：对任意树，设 n\_k 是度为 k 的节点数，则 `n₀ = 1 + Σ(k - 1)·n_k`（k ≥ 2），二叉树只是度数上界为 2 的特例。

> [!CAUTION]
> `n₀ = n₂ + 1` 单独**不能**推出「满二叉树」。看这棵树：根 A 有两个孩子 B、C，B 又有两个孩子 D、E，C 只有一个孩子 F。此时 n₀ = 3、n₂ = 2，满足 `3 = 2 + 1`，但 C 是单孩子节点，它不是满二叉树。判满必须额外检查「没有度为 1 的节点」，即 n₁ = 0。

### 2.2 第 k 层最多 2^(k-1) 个节点

**归纳**：第 1 层只有根，1 = 2^0 个。设第 k − 1 层至多 `2^(k-2)` 个，则第 k 层不超过它的两倍，即 `2^(k-1)`。**路径编码（更本质）**：第 k 层的每个节点唯一对应一条从根出发、长度 k − 1 的「左右选择序列」。每位的取值只有两种，所以不同序列至多 `2^(k-1)` 条，而每条序列至多落在一个节点上。取等号要求第 k − 1 层每个节点都有两个孩子——上界完全由「每个节点至多两个孩子」决定，与树的其他部分无关。

### 2.3 高度为 h 的二叉树最多 2^h − 1 个节点

把每层的上界加起来：`1 + 2 + 4 + ... + 2^(h-1) = 2^h - 1`。也可以归纳：空树 h = 0 时上界是 0 = 2^0 − 1；设高 h − 1 的子树上界为 `2^(h-1) - 1`，则高 h 的树最多 `1 + 2·(2^(h-1) - 1) = 2^h - 1`。取到等号的树每层都是满的，正是完美二叉树；反过来完美二叉树的节点数一定是 `2^h - 1`。这条双向关系是后面所有复杂度分析的支点：由它可得 `h >= ceil(log2(n + 1))`，即**任何** n 个节点的二叉树高度至少是 `floor(log2 n) + 1`。

### 2.4 完全二叉树的高度是 floor(log2 n) + 1

设高度为 h，两边夹逼。**上界（对任意二叉树成立）**：h 层的树最多 `2^h - 1` 个节点，所以 `n <= 2^h - 1`，解得 `h >= log2(n + 1)`。

**下界（只对完全二叉树成立）**：完全二叉树按层序编号连续填充，能填到第 h 层说明前面每层都填满了（否则编号出现空洞，与「完全」矛盾），因此 `n >= 2^(h-1) - 1 + 1 = 2^(h-1)`，即 `log2 n >= h - 1`。合并两个方向：`2^(h-1) <= n <= 2^h - 1`，取对数得 `h - 1 <= log2 n < h`，由 h 是整数得 `h = floor(log2 n) + 1`。（顺带一个恒等式：`floor(log2 n) + 1 = ceil(log2(n + 1))`，对所有 n ≥ 1 成立。）

这条性质的工程含量很高：**完全二叉树是所有 n 节点二叉树里高度最小的那一种**。n = 10⁶ 时高度只有 20，n = 10⁹ 时也才 30——这就是堆能把插入和删除堆顶压到 O(log n) 的根基（见 [第 09 篇](09-heap-priority-queue.md)）。

### 2.5 n 个节点的二叉树有 n + 1 个空指针域

数指针：n 个节点每个两个指针域，共 `2n` 个；非空的指针恰好是树里的边数 `n - 1`（每条边由一个指针表示，每个非根节点恰好被一条指针指向）。于是空指针域 `2n - (n - 1) = n + 1`，与形态完全无关：无论完美二叉树还是一条链，都是 n + 1 个。这个数字有两层含义。**空间代价**：链式存储下大约一半的指针域是空的，加上值和两个指针，64 位机器上每个节点至少 24 字节（再叠加对象头与分配器对齐），存 10⁶ 个整数的树光指针就要 16 MB。**现成的机会**：n + 1 个空位不是垃圾，中序线索二叉树（第 10 节）正好把它们全部改造成前驱 / 后继指针——无左孩子的节点用左域存前驱，无右孩子的节点用右域存后继，两边的数量之和恰好等于空域总数，一个不多一个不少。

## 3. 三种存储方式

### 3.1 链式存储

```python
class TreeNode:
    __slots__ = ("val", "left", "right")

    def __init__(self, val=0, left=None, right=None):
        self.val, self.left, self.right = val, left, right
```

`__slots__` 不是装饰：不加它，CPython 会给每个节点额外挂一个 `__dict__`（实测 3 个字段的实例字典占 296 字节，而带 `__slots__` 的实例本身只有 56 字节），100 万个节点就是近 300 MB 的纯浪费。代价要认全：每个节点一次独立分配（分配器开销 + 内存碎片），遍历靠指针跳转（每次都可能缓存未命中，见 [第 03 篇](03-linked-list.md) 的访存分析），n + 1 个空指针，以及「找父节点」必须额外存 parent 指针或重新遍历。

### 3.2 顺序存储：数组表示与下标关系

把节点按层序编号填进数组，编号即下标（本文用 0 起始）：

```text
            1               下标 0
          /   \
         2     3            下标 1、2
        / \   / \
       4   5 6   7          下标 3、4、5、6

数组： [1, 2, 3, 4, 5, 6, 7]
下标 i 的孩子是 2i+1、2i+2；反过来，下标 i 的父亲是 (i-1)//2
```

| 想求的东西（0 起始下标 i，节点数 n） | 公式                       | 用 n = 10 验证              |
| --------------------- | ------------------------ | ------------------------ |
| 左孩子                   | `2i + 1`                 | i = 4 → 9                |
| 右孩子                   | `2i + 2`                 | i = 4 → 10 越界，说明该节点没有右孩子 |
| 父节点                   | `(i - 1) // 2`           | i = 4 → 1                |
| i 是否为叶                | `2i + 1 >= n`            | i = 4 时 9 小于 10，不是叶      |
| i 是否只有左孩子             | `2i + 1 == n - 1`        | i = 4 时 9 = 9，成立         |
| 最后一个非叶节点              | `n // 2 - 1`             | n = 10 → 4               |
| i 所在层（从 1 起）          | `floor(log2(i + 1)) + 1` | i = 4 → 3                |

1 起始的版本是 `2i`、`2i + 1`、`i // 2`，只是编号平移；看教材或代码时先确认用哪套，否则下标差一位，越界或错位就来了。倒数第二行很值得记：`n // 2 - 1` 是最后一个非叶节点，堆的建堆操作正是从这个下标开始往前逐个下沉（[第 09 篇](09-heap-priority-queue.md)），因为再往后的节点全是叶。

**为什么非完全二叉树用数组会浪费**：数组按下标存，深度为 d 的一层无论填了几个节点，都占满了 `2^(d-1)` 个槽位。一条高度 h 的退化链需要 `2^h - 1` 个槽位：h = 20 时是 1048575 个，h = 30 时是 10⁹ 量级，h = 40 时是 1.1×10¹²。反过来，**完全二叉树是唯一零浪费的形态**：数组长度恰好等于节点数 n，一个空槽都没有。这就是「堆必须用完全二叉树」的全部理由——不是审美，是空间复杂度。

```python
from collections import deque


def build(values):
    """层序数组建树，None 表示该位置没有节点（可表达非完全二叉树）。"""
    if not values or values[0] is None:
        return None
    it = iter(values)
    root = TreeNode(next(it))
    q = deque([root])
    while q:
        node = q.popleft()
        for side in ("left", "right"):
            try:
                v = next(it)
            except StopIteration:
                return root
            if v is None:
                continue
            child = TreeNode(v)
            setattr(node, side, child)
            q.append(child)
    return root
```

`build` 里用 `try/except StopIteration` 而不是 `next(it, None)` 是有意的：前者区分「数组用完了」和「数组里真的写了 None」，后者把两者混在一起，将来加校验或日志时无从下手。

> [!WARNING]
> 用哨兵值（−1、0、`#`）当空位的层序数组建树时，先确认树里不会出现这个值。用 −1 当空位的系统里一旦出现值为 −1 的真实节点，那个节点连同它的整棵子树都会静默消失——这类 bug 不报错，只让答案少几个节点。

### 3.3 孩子兄弟表示法：把任意树塞进两个指针

一般树（每个节点可以有任意多个孩子）用固定大小的节点怎么表示？每个节点只存两个指针：第一个孩子（first child）和下一个兄弟（next sibling）。转换规则是：节点的左指针指向它的第一个孩子，右指针指向它的下一个兄弟——转换得到的东西**本身就是一棵二叉树**（每个节点最多两个孩子、左右有序），所以不需要另写一套遍历代码。

```text
一般树：            转成二叉树（左孩子右兄弟）：
      A                     A
    /   \                    \
   B     C                    B
  / \   /                    / \
 D   E F                    D   C
                             \   \
                              E   F

二叉树的先序 A B D E C F  ←→ 一般树的深度优先先序完全一致
但层序变了：二叉树是 [A] [B] [D C] [E F]（兄弟链向右延伸，深度递增）
```

代价与用途：「找第 k 个孩子」要顺着兄弟链走 O(k) 步，而用数组存孩子是 O(1)（代价是节点大小不定 + 额外的动态数组）。这个取舍在工程里非常常见：XML/DOM 的 `firstChild` / `nextSibling`、文件系统的目录项、AST 里的语句链全是这个形状。它同时把两种图遍历落到树上——对一般树做先序就是深度优先（DFS），做层序就是广度优先（BFS），正是 [第 12 篇](12-graph-representation-traversal.md) 的主题在树上的特例。

## 4. 遍历的唯一钥匙：递归序

### 4.1 每个节点被到访三次

递归函数处理一个节点时，执行过程分成三段：刚进入这个节点、左子树处理完返回、右子树处理完返回。所以一趟完整遍历中，**每个节点都被到访三次**（不算指向空节点的调用）。把三次到访按时间顺序记下来，得到的序列叫递归序：

```text
        1
      /   \
     2     3
    / \
   4   5

递归序（不记录空节点，每个节点恰好出现三次）：
  节点:  1  2  4  4  4  2  5  5  5  2  1  3  3  3  1
  次数:  1  1  1  2  3  2  1  2  3  3  2  1  2  3  3

先序 = 取「第 1 次到访」→ 1 2 4 5 3
中序 = 取「第 2 次到访」→ 4 2 5 1 3
后序 = 取「第 3 次到访」→ 4 5 2 3 1
```

于是得到全文最重要的那句话：**先序、中序、后序不是三种算法，而是同一个算法的三个输出位置**——三种遍历的代码唯一差别就是 `out.append(...)` 放在两次递归之前、之间、还是之后。

由这个模型能直接读出所有「序列的性质」：

- 先序的第一个元素一定是根，后序的最后一个元素一定是根，中序里根的位置把序列切成左右两段。第 6 节的重建就建立在这三条上。
- 中序的第一个节点是最左下的节点：从根一路向左，每个节点都在「第 1 次到访后立刻进入左子树」，所以最先走到「没有左孩子」的那个节点，它的第 2 次到访来得最早。
- 节点在第 1 次到访时能拿到「从根下来的信息」（自顶向下），在第 3 次到访时能拿到「两棵子树汇总上来的结果」（自底向上）。所有树上算法都在三个时间点上做文章：求树高在第 3 次到访取 `1 + max(左高, 右高)`；释放内存在第 3 次到访 `free`（孩子已释放完，先序 free 会留下悬空指针）；判断 BST 在第 2 次到访检查前驱（中序单调，见 [第 08 篇](08-bst-balanced-trees.md)）。

### 4.2 三种递归遍历

```python
def preorder(node, out):
    if node is None:
        return
    out.append(node.val)          # 第 1 次到访
    preorder(node.left, out)
    preorder(node.right, out)


def inorder(node, out):
    if node is None:
        return
    inorder(node.left, out)
    out.append(node.val)          # 第 2 次到访
    inorder(node.right, out)


def postorder(node, out):
    if node is None:
        return
    postorder(node.left, out)
    postorder(node.right, out)
    out.append(node.val)          # 第 3 次到访
```

结果累积到参数 `out` 里，而不是让函数返回列表再拼接：后者每一层都要新建列表并拷贝，退化链上会从 O(n) 变成 O(n²)。这是遍历代码里最容易写错的一处性能细节。

### 4.3 三种迭代遍历

改成迭代的动机是硬性的：递归深度等于树高 h，退化树 h = n。CPython 默认递归上限 1000 层（`sys.getrecursionlimit()`），n = 10⁵ 的链直接 `RecursionError`；C 的默认栈 8 MB，每帧几十到几百字节，同样规模会**段错误**——这不是异常，是进程直接死掉。

**先序**：栈里存「待访问的节点」，出栈即访问，入栈时先压右再压左（这样左孩子先出栈）。**中序**：栈里存「还没有输出的祖先链」——一路向左压栈，走到头就弹出输出（此时它的左子树已经走完），然后转向右子树重复。

```python
def preorder_iter(root):
    out, stack = [], [root] if root else []
    while stack:
        node = stack.pop()
        out.append(node.val)
        if node.right:
            stack.append(node.right)   # 先压右：出栈顺序才是先左后右
        if node.left:
            stack.append(node.left)
    return out


def inorder_iter(root):
    out, stack, cur = [], [], root
    while cur or stack:
        while cur:
            stack.append(cur)          # 一路向左，把路径记在栈里
            cur = cur.left
        cur = stack.pop()
        out.append(cur.val)
        cur = cur.right                # 转向右子树，重复
    return out
```

理解中序迭代的关键是**栈的内容**：任意时刻，栈自底向上恰好是当前节点到根的祖先链，而且这些祖先都处于「左子树已处理完、自己还没输出」的状态。记住这一点，才看得懂为什么 `cur = cur.right` 之后还要继续往左走。**后序**最难，因为输出一个节点前必须确认「右子树也走完了」。一个取巧办法：把先序的「根左右」改成「根右左」（把入栈顺序反过来即可），得到的序列整体反转就是后序。

```python
def postorder_iter(root):
    """先序变形成「根右左」，再整体反转。"""
    out, stack = [], [root] if root else []
    while stack:
        node = stack.pop()
        out.append(node.val)
        if node.left:
            stack.append(node.left)
        if node.right:
            stack.append(node.right)
    out.reverse()
    return out
```

真正的单栈写法要额外记一个「上一个输出的节点」`last`：栈顶元素有右子树且 `top.right is not last` 时，说明右子树还没走，先去右边；否则才能输出。这两个状态用递归序看是一目了然的（第 3 次到访才输出），但压成循环后必须用变量显式记住——这就是后序迭代比前两种难写的全部原因。

**Morris 遍历：把空指针变成回程票**。递归和栈都要 O(h) 空间存「从子树回到父节点」的信息，而 2.5 节已证明有 n + 1 个空指针白放着。Morris 的思路是：中序遍历访问完 cur 的左子树后要回到 cur，这个回程信息可以临时写进左子树最右节点的空右指针里——那个节点恰好是 cur 在中序下的前驱。流程是：cur 有左孩子时先去左子树找最右节点，它的右指针为空就把它指向 cur 并进入左子树；右指针已经指向 cur 就说明左子树走完了，把它改回空、输出 cur、进入右子树。cur 没有左孩子则直接输出并向右走。

```python
def morris_inorder(root):
    out, cur = [], root
    while cur:
        if cur.left is None:
            out.append(cur.val)
            cur = cur.right
        else:
            pre = cur.left
            while pre.right is not None and pre.right is not cur:
                pre = pre.right
            if pre.right is None:         # 第一次到 cur：建线索，进左子树
                pre.right = cur
                cur = cur.left
            else:                         # 第二次到 cur：拆线索，输出，进右子树
                pre.right = None
                out.append(cur.val)
                cur = cur.right
    return out
```

每条边至多被走两遍，时间仍是 O(n)（常数约 2\~3 倍），空间 O(1)。把「输出」从第二个分支挪到第一个分支（`pre.right is None` 时输出），就得到 Morris 先序——又一次印证了那句「先中后序只差输出位置」。代价必须讲清楚：遍历过程中树是**临时变形的**（有别的线程在读这棵树就会看到错的指针），代码也更难读。所以它适合「空间真的紧张、且遍历期间独占这棵树」的场合：嵌入式设备、超大规模数据的流式校验，以及把 O(1) 空间当硬要求的面试题。

### 4.4 层序遍历：队列与分层

层序不走递归序那套：它按深度从浅到深访问，用队列实现（先进先出保证同层节点先处理完）。

```python
def level_order(root):
    if root is None:
        return []
    out, q = [], deque([root])
    while q:
        size = len(q)                      # 关键：先冻结这一层的节点数
        level = []
        for _ in range(size):
            node = q.popleft()
            level.append(node.val)
            if node.left:
                q.append(node.left)
            if node.right:
                q.append(node.right)
        out.append(level)
    return out
```

**分层的不变式**：处理任意一层时，队列里恰好只有这一层尚未处理的节点（新入队的下一层节点排在它们后面）。证明很直接：出队一个节点、入队它的两个孩子，孩子排在本层剩余节点的后面，所以本层处理完之前下一层一个都不会被取出。`size = len(q)` 就是给这个不变式拍个快照。忘记分层的后果很具体：输出变成一维列表 `[1, 2, 3, 4, 5, 6, 7, 8]`，所有按层的问题（每层平均值、右视图、最大宽度、最小深度）都得重写。另一种分层写法是每层末尾塞一个哨兵 `None`，但它引入额外的判空分支，而且节点值本身可以是 `None` 时会打架——数长度更干净。

四种写法放在一起对比：

| 遍历           | 时间（最坏） | 额外空间（最坏）     | 备注               |
| ------------ | ------ | ------------ | ---------------- |
| 递归先 / 中 / 后序 | Θ(n)   | O(h) 系统栈     | 代码最短；h = n 时爆栈   |
| 迭代先 / 中 / 后序 | Θ(n)   | O(h) 显式栈     | 栈在堆上，上限高得多       |
| Morris       | Θ(n)   | O(1)         | 临时改写树；常数约 2\~3 倍 |
| 层序           | Θ(n)   | O(w)，w 为最大宽度 | 完美树最后一层 w = n/2  |

这张表里没有「平均 / 摊还」两列——遍历是确定性的，每个节点恰好处理常数次，最好、最坏、平均都是 Θ(n)。树结构上真正需要摊还分析的地方在别处：动态数组扩容、哈希表 rehash、并查集路径压缩。

## 5. 遍历的应用：把「什么时候处理」变成套路

同一个骨架，换个处理时机就是另一道题。下面按信息流向分三类。

### 5.1 层序的变体

四个变体，区别只在「在每层的哪个位置取信息」：

```python
def level_average(root):
    """每层平均值：整层求和后除以个数。"""
    out, q = [], deque([root] if root else [])
    while q:
        size, total = len(q), 0
        for _ in range(size):
            node = q.popleft()
            total += node.val
            if node.left:
                q.append(node.left)
            if node.right:
                q.append(node.right)
        out.append(total / size)
    return out


def right_side_view(root):
    """右视图：每层最后一个节点。"""
    out, q = [], deque([root] if root else [])
    while q:
        size = len(q)
        for i in range(size):
            node = q.popleft()
            if i == size - 1:
                out.append(node.val)
            if node.left:
                q.append(node.left)
            if node.right:
                q.append(node.right)
    return out


def max_width(root):
    """最大宽度：空位也计入宽度，用「堆式下标」保住位置信息。"""
    if root is None:
        return 0
    best, q = 0, deque([(root, 0)])
    while q:
        size = len(q)
        first = last = q[0][1]
        for _ in range(size):
            node, idx = q.popleft()
            last = idx
            if node.left:
                q.append((node.left, 2 * idx + 1))
            if node.right:
                q.append((node.right, 2 * idx + 2))
        best = max(best, last - first + 1)
    return best


def min_depth(root):
    """最小深度：层序遇到的第一个叶子就是答案。"""
    if root is None:
        return 0
    q = deque([(root, 1)])
    while q:
        node, d = q.popleft()
        if node.left is None and node.right is None:
            return d
        if node.left:
            q.append((node.left, d + 1))
        if node.right:
            q.append((node.right, d + 1))
    return 0
```

- **最大宽度必须带上堆式下标**，因为「宽度」定义在位置上，空位也算。只数每层节点个数得到的是「每层节点数」：一棵树的两棵子树上分别挂着下标 3 和下标 6 的节点时，节点数是 2，宽度是 `6 - 3 + 1 = 4`。队列里原本没有位置信息，必须把下标和节点一起入队。
- **最小深度不能照搬最大深度的递归**：最大深度是 `1 + max(左, 右)`，但最小深度不能写成 `1 + min(左, 右)`——当一边为空时 `min` 返回 0，答案变成 1。层序在遇到第一个叶子时立即返回，天然避开这个坑。
- 右视图取每层最后一个、左视图取第一个，没有本质区别。

### 5.2 先序：自顶向下传递

**不变式**：进入一个节点时，参数里带着「从根到父节点」的汇总信息。信息方向是根 → 叶，所以不需要等子树返回任何东西。

```python
def has_path_sum(root, target):
    """是否存在一条根到叶路径，其节点值之和等于 target。"""
    if root is None:
        return False
    if root.left is None and root.right is None:
        return root.val == target
    rest = target - root.val
    return has_path_sum(root.left, rest) or has_path_sum(root.right, rest)


def is_symmetric(root):
    """是否轴对称：两个指针反向推进。"""
    def mirror(a, b):
        if a is None and b is None:
            return True
        if a is None or b is None:
            return False
        return (a.val == b.val
                and mirror(a.left, b.right)
                and mirror(a.right, b.left))
    return root is None or mirror(root.left, root.right)
```

- 路径和用**递减的 target**，而不是「累积路径和」：参数少一个，终止条件直接用 `root.val == target` 判断叶子；后者要在每个叶子比较 `sum == target`，多一个变量。
- 「到叶」必须判断 `left is None and right is None`；对称判断的终止条件更容易写错——只有两个指针同时为空才对称，一个空一个不空立刻返回 False。

### 5.3 后序：自底向上汇总

**不变式**：离开一个节点时，函数返回「以该节点为根的子树」的汇总信息。父节点的答案依赖子节点的答案，所以子节点的答案必须先算出来——这正是后序的定义。

```python
def tree_height(root):
    if root is None:
        return 0
    return 1 + max(tree_height(root.left), tree_height(root.right))


def diameter(root):
    """直径（边数口径）：经过某节点的最长路径 = 左高 + 右高。"""
    best = 0

    def dfs(node):
        nonlocal best
        if node is None:
            return 0
        lh = dfs(node.left)
        rh = dfs(node.right)
        best = max(best, lh + rh)          # 在「拐弯处」结算全局答案
        return 1 + max(lh, rh)             # 向上只返回单边深度

    dfs(root)
    return best
```

两个函数放在一起，就暴露了树形 DP 的核心分工：**返回值 ≠ 全局答案**。`dfs` 返回「以 node 为端点的单边最长深度」，因为父节点能接着往上拼的只有这一条边；而「经过 node 的最长路径」在 node 处拐了弯，没法再往上接，只能在 node 处结算到全局变量。如果让 `dfs` 返回直径本身，父节点拿到的数字无法参与「左 + 右」的拼接，算法直接失效。

## 6. 由两种遍历序列重建二叉树

### 6.1 先序 + 中序：可以唯一确定

推理链条只有三步（全部来自 4.1 的递归序模型）：先序的第一个元素是根；在中序里找到根的位置，左边是左子树全部节点、右边是右子树全部节点，两段长度就是两棵子树的规模；回到先序，根后面的 `left_size` 个元素是左子树的先序、剩下的是右子树的先序。对两段递归执行同样的操作。

```python
def build_from_pre_in(preorder, inorder):
    index = {v: i for i, v in enumerate(inorder)}   # 值 -> 中序下标，O(1) 定位根

    def helper(plo, phi, ilo, ihi):
        if plo > phi:
            return None
        root_val = preorder[plo]
        mid = index[root_val]
        left_size = mid - ilo
        node = TreeNode(root_val)
        node.left = helper(plo + 1, plo + left_size, ilo, mid - 1)
        node.right = helper(plo + left_size + 1, phi, mid + 1, ihi)
        return node

    return helper(0, len(preorder) - 1, 0, len(inorder) - 1)
```

区间一律用闭区间 `[lo, hi]`，终止条件是 `lo > hi`——用左闭右开也能写，两种混用时的 off-by-one 是这类代码最常见的 bug 来源。**复杂度**：递归树每层把区间一分为二（平衡时 O(log n) 层），每层处理 O(n) 个元素，总时间 O(n)；定位根用哈希表是 O(1)，若改成 `inorder.index(root_val)` 线性查找，最坏（退化链）退化为 O(n²)——n = 10⁵ 时约 10¹⁰ 次比较，必然超时。空间是重建出的树 O(n) 加递归栈 O(h)。中序 + 后序同理（后序的最后一个元素是根）。**前提是值互不相同**。哈希表只能为一个值记录一个位置；中序里有重复值时 `mid` 可能是错的，重建出的树能跑但结构和原树不一致。有重复值的场景要靠第 7 节的带空标记序列化。

### 6.2 先序 + 后序：不能唯一确定

给一个必须记住的反例：

```text
先序 = [1, 2]，后序 = [2, 1] 对应两棵不同的树：

     1              1
    /                \
   2                  2

两棵树的先序都是 1 2，后序都是 2 1。
```

病根在「单孩子节点」上：先序告诉我们「根之后先走左子树」，后序告诉我们「根之前先走完左子树」，但当某个节点只有一个孩子时，这个孩子是左还是右**在两种序列里都留不下痕迹**——先序里它紧跟父节点出现，后序里它紧挨父节点之前出现，位置完全一样。

精确结论（可穷举验证）：给定先序 + 后序，与它们一致的树的棵数恰好是 `2^k`，k 是「只有一个孩子的节点」的个数；只有当每个节点都有 0 或 2 个孩子（满二叉树）时 k = 0，序列才唯一确定一棵树。`[1, 2]` 这个例子里 k = 1，所以恰好两棵。

## 7. 序列化与反序列化

树是内存里的指针结构，跨不过进程边界。凡是要把树**传出去或存下来**的场合都需要一套线性表示：跨进程 / 跨语言传输（RPC、消息队列里传递语法树或决策树）、持久化（写文件、写数据库，重启后恢复）、缓存（把树放进 Redis，省掉重新解析或重新计算）、测试与题目输入（`[1, 2, 3, null, 4]` 这种层序数组本身就是一种序列化格式）。**方案一：带空标记的先序序列化**。把 `#` 当作空节点一起写进先序序列，反序列化时按先序递归消费。

```python
def serialize(root):
    out = []

    def dfs(node):
        if node is None:
            out.append("#")            # 空位也要写出来
            return
        out.append(str(node.val))
        dfs(node.left)
        dfs(node.right)

    dfs(root)
    return ",".join(out)


def deserialize(data):
    vals = iter(data.split(","))

    def dfs():
        v = next(vals)
        if v == "#":
            return None
        node = TreeNode(int(v))
        node.left = dfs()
        node.right = dfs()
        return node

    return dfs()
```

**为什么必须写空标记**：不写空位的前序序列会丢掉「某个节点有没有孩子、是左还是右」的信息——这正是 6.2 里先序 + 后序不唯一的同一个病根。补上空标记之后结构信息完备，单靠一个序列就能唯一还原。序列长度是 2n + 1（n 个值加 n + 1 个空标记），时间 O(n)，空间是输出 O(n) 加递归栈 O(h)。

**方案二：BST 的紧凑编码**。如果树是二叉搜索树，只发前序序列就够了，一个空标记都不用——BST 自带值域约束，每个节点都隐含一个「我允许的值区间」，收到值时用区间判断它属于当前子树还是要回溯到上层：递归时带上 `(low, high)`，值不在区间内就返回 `None`（它属于某个祖先的右子树）。序列长度从 `2n + 1` 降到 `n`，省下一半以上——这是「利用结构约束压缩编码」的典型手法，细节和 BST 的性质见 [第 08 篇](08-bst-balanced-trees.md)。

> [!WARNING]
> 序列化格式一旦上线就不能随便改：缓存、消息队列、落盘文件里全是旧格式的数据，换格式要有版本号或兼容读取逻辑。三个具体的坑：节点值里含分隔符（用 `,` 拼字符串时值本身可能是 `1,2`）；空标记与真实值冲突（值可能就是 `#` 或 `-1`）；数值溢出（值域超出 32 位时用文本或明确位宽）。工程里更稳的做法是输出 JSON 数组，把转义交给库。

## 8. 树形 DP 入门

动态规划的本质是用子问题的答案拼出父问题的答案。树结构自带了子问题划分——每个节点的子树就是一个子问题——所以树形 DP 不需要「设计状态划分」，只需要回答两个问题：每个节点向上返回什么？全局答案在哪一步结算？**树高**是最简单的一例：`h(v) = 0`（v 为空）或 `h(v) = 1 + max(h(v.left), h(v.right))`。返回值就是子问题的答案，全局答案就是根的返回值，递推方向从叶到根。

**直径（diameter）**是树中任意两点间最长路径的长度。它不能直接返回：最长路径可能在左子树、可能在右子树、也可能穿过根。所以返回值换成「以 v 为端点的单边最长深度」，全局答案在「穿过 v 的那条路径」上结算：

```text
返回: g(v) = 1 + max(g(v.left), g(v.right))     （节点数口径）
结算: ans = max(ans, g(v.left) + g(v.right))    （边数口径，长度即左高 + 右高）
```

直觉是：任何一条路径都有一个「最高点」，在最高点处它由左右两条下行路径拼成，所以在每个节点处尝试「左高 + 右高」就能覆盖所有路径。复杂度 O(n) 时间、O(h) 递归栈，对比「对每个节点求一次高度」的暴力 O(n²)。代码见 5.3 节的 `diameter`。

> [!TIP]
> 直径问题的套路值得记住：当答案是「路径」而返回值是「单边信息」时，做法永远是「向上只带一条边，拐弯处结算」。最长同值路径、最长交错路径都是同一个模板；到了需要换根的场景，这个模式会变成换根 DP。

**最大路径和**把「求最长」换成「求最大和」，套路不变，只多一条：负贡献可以丢弃——一条路径继续往上接，只有当它对自己有利时才值得接。递推式是 `g(v) = v.val + max(g(v.left), g(v.right), 0)`，结算式是 `ans = max(ans, v.val + max(g(v.left), 0) + max(g(v.right), 0))`。

```python
def max_path_sum(root):
    """每个节点向上返回「单边最大贡献」，全局答案在拐弯处记录。"""
    best = float("-inf")

    def dfs(node):
        nonlocal best
        if node is None:
            return 0
        left = max(dfs(node.left), 0)          # 负贡献直接丢弃
        right = max(dfs(node.right), 0)
        best = max(best, node.val + left + right)
        return node.val + max(left, right)

    dfs(root)
    return best
```

两个边界最能暴露理解程度：全负数时答案必须至少包含一个节点（`best` 初始化为 −inf，每个节点都会用自己更新一次，这是 `max(..., 0)` 与 `best` 初值分工的结果）；单节点时答案就是它自己的值。

**为什么后序是树形 DP 的默认顺序**：后序保证「处理一个节点时，它的两个孩子都已经返回了各自的子问题答案」，而父节点的递推式正是靠这些返回值构成的；换成先序，返回时子节点还没算，递推式无从下手。先序能传的是「从根往下」的信息（路径和、当前深度、祖先链），适合自顶向下与回溯类问题；后序传的是「从叶往上」的信息，适合汇总类与 DP——这就是 5.2 与 5.3 分开写的原因。层序在这两类里都不占优，除非问题本身要求按层处理（5.1 的变体），或者需要避免递归栈。

## 9. LCA：朴素与倍增

最近公共祖先（LCA, lowest common ancestor）是树上最常见的查询：文件系统里两个路径的共同目录、DOM 事件冒泡的公共节点、版本控制系统的合并基点。它还有一个恒等用途——树上两点距离 `dist(u, v) = depth(u) + depth(v) - 2·depth(lca(u, v))`，把路径长度问题变成一次 LCA 查询。

朴素解法：把 u 到根的路径全部标记，再从 v 往上走，遇到的第一个被标记的节点就是 LCA（也可以先把两者对齐到同一深度再一起往上走，两种写法等价）。单次查询 O(h)，退化树上就是 O(n)，q 次查询 O(qh)——对「一次预处理、多次查询」的场景太贵。**倍增（binary lifting）**用 O(n log n) 预处理换 O(log n) 单次查询。核心是一张跳表：`up[k][v]` 表示 v 往上跳 `2^k` 步到达的祖先，构造只有一行——`up[k][v] = up[k-1][up[k-1][v]]`（先跳 2^(k−1) 步，再跳 2^(k−1) 步）。有了它，把「往上跳 d 步」拆成 d 的二进制展开，O(log n) 次跳转即可完成。查询分两步：先把深的那个跳到与另一个同深度（若已成为同一点，它本身就是答案），再从大到小枚举 k，只要 `up[k][u] != up[k][v]` 就同时上跳——最终停在 LCA 的两个孩子上，答案是 `up[0][u]`。两处设计要点：根的父节点设为自己（哨兵，跳过头只会停在根），第二步必须从大到小枚举（一次跳得尽量远但不能跳过 LCA）。

代价是空间 O(n log n)：n = 10⁶ 时 `up` 表是 `20 × 10⁶` 个整数，在 Python 里约 560 MB，必须换方案。替代品各有取舍：欧拉序 + 稀疏表 RMQ 是 O(1) 查询但空间同样 O(n log n)；Tarjan 离线算法用并查集一次处理所有查询，O(n + q) 时间、O(n) 空间，但要求查询离线（见 [第 11 篇](11-union-find.md)）；树链剖分是线性空间 + O(log n) 查询。还有一个便宜的特例：只需要判断「u 是不是 v 的祖先」时，DFS 时记下进入和离开的时间戳 `tin/tout`，判断 `tin[u] <= tin[v] <= tout[u]` 即可，O(1)——这条性质也是 Tarjan 离线与欧拉序做法的基础。

## 10. 线索二叉树

2.5 节算过一笔账：n 个节点的二叉树有 n + 1 个空指针域；而递归遍历用系统栈、迭代遍历用显式栈，两者都要 O(h) 空间存「回程信息」——这些空间明明可以省下来：把空指针改造成指向「前驱 / 后继」的**线索（thread）**，遍历就完全不需要栈。

线索化的前提是给每个节点加两个标志位：`ltag = 1` 表示左指针存的是前驱线索（而不是左孩子），`rtag = 1` 表示右指针存的是后继线索。标志位不是可选项——`node.right` 的类型在两种情况下完全一样，没有标志位无法区分它指向的是右孩子还是后继。

线索化的做法是一次中序遍历顺手改写指针：遍历时记住上一个访问的节点 `pre`，当前的 `cur` 若没有左孩子，就把左指针指向 `pre`（前驱线索）并置 `ltag = 1`；若 `pre` 没有右孩子，就把 `pre` 的右指针指向 `cur`（后继线索）并置 `rtag = 1`。整个过程 O(n) 时间、O(h) 额外空间（借用中序迭代的栈），不新增任何节点。**中序后继的完整规则**（只有两条）：若 `rtag = 1`（没有右孩子），右指针就是线索，直接指向后继，O(1)；若 `rtag = 0`（有右孩子），后继是**右子树的最左节点**——从右孩子出发一路向左，直到遇到 `ltag = 1` 的节点为止。这两条合起来回答了「中序遍历为什么要先走到底再回头」：中序后继要么被线索直接给出，要么藏在右子树的左下角。前驱规则完全对称：`ltag = 1` 时左指针即前驱，否则前驱是左子树的最右节点。于是遍历变成一句话——「一路向左找到第一个节点，然后不停取后继」，不需要栈也不需要递归。

> [!CAUTION]
> 线索化之后，中序最后一个节点的右指针是空的（没有后继可指），但它的 `rtag` 必须显式标成 1。忘了这一步，遍历代码会在「右指针为空」时误以为存在右子树，走进 `None` 直接崩溃——这个 bug 只在遍历到整棵树最右端时才会出现，小数据量的测试很容易漏掉。

线索链的终点还有另一种处理方式：加一个**头节点**，让首节点的左线索与末节点的右线索都指向它，形成循环线索链表，终止条件变成「回到头节点」，代码里少一个 `None` 判断——代价是永远多维护一个节点。工程价值有两面。**结构代价**：每个节点多两个标志位（可以用两个 bit 打包），插入删除都要维护线索，非常容易写错。**性能收益**：遍历 O(n) 时间、O(1) 空间且不需要递归，「找中序前驱 / 后继」从 O(h) 降到 O(1)，对「按中序顺序扫描」的批处理很有意义。所以它主要用在**建好之后只读**的场景：编译器里的语法树、静态数据集的索引、只需顺序扫描一遍的批处理。它更有生命力的地方是那个思想——**用空闲的指针域存辅助信息**，同样的手法在 B+ 树的叶节点链、跳表、并查集路径压缩里反复出现。

## 11. 工程里的树

树的工程应用不是「用到树的形状」，而是「用到树上的某一种遍历」：

| 场景         | 结构                                 | 遍历的角色                                                                  |
| ---------- | ---------------------------------- | ---------------------------------------------------------------------- |
| DOM 树      | 孩子兄弟（`firstChild` / `nextSibling`） | 先序做 DFS（选择器匹配、事件冒泡），层序做 BFS（按层布局）                                      |
| 文件系统       | 目录树                                | `find` 是先序；`rm -r` 必须后序（先删空目录再删自己）                                     |
| 语法树 / AST  | 孩子列表                               | 求值 = 后序（操作数先于运算符，正是后缀表达式的顺序）；解析用栈（[第 04 篇](04-stack.md)）               |
| 决策树        | 二叉树                                | 预测 = 一条根到叶的路径，代价 O(深度)；随机森林是这些树的森林                                     |
| 堆          | 完全二叉树                              | 顺序存储 + 下标运算；`n // 2 - 1` 是建堆起点（[第 09 篇](09-heap-priority-queue.md)）    |
| B 树 / B+ 树 | m 路平衡树                             | 把「二叉」放宽到「m 路」，树高压到 2\~4 层以减少磁盘 I/O（[第 08 篇](08-bst-balanced-trees.md)） |
| Trie       | 多路树                                | 路径即前缀，共享前缀的字符串共用节点（[第 10 篇](10-trie.md)）                               |

两个值得单独说的：**AST 的解释器递归深度受源码嵌套深度限制**，`(((((...)))))` 这种恶意构造能把深度推到几十万层，解释器不设上限就是栈溢出崩溃（真实的 DoS 面，处理办法是解析时限制嵌套深度或改成显式栈）；**决策树的「遍历」只有一条路径**，预测时从根按条件往下走，O(深度) 就结束，这是「树的结构本身就是算法」的例子，与「遍历所有节点」完全不同。

## 12. 陷阱清单

- **递归深度等于树高**。退化树 h = n：CPython 默认上限 1000 层，直接 `RecursionError`；C 的 8 MB 栈在 h 到 10⁵ 量级时溢出（段错误，进程直接死，不是异常）。改法：换显式栈迭代，或让结构自身保持平衡（[第 08 篇](08-bst-balanced-trees.md)）。调大递归上限只是延后问题——它把可控的异常换成了不可控的崩溃。
- **迭代遍历忘判空**。`stack = [root]` 在空树上会把 `None` 压进去，之后 `node.val` 崩溃。所有模板都要么先 `if not root: return []`，要么写 `[root] if root else []`。
- **层序忘记分层**。丢掉 `size = len(q)`，输出变成一维列表，所有按层的问题全部作废。
- **重建时用线性查找定位根**。`inorder.index(val)` 让重建变成 O(n²)，退化链上必然超时；哈希表下标映射是 O(n)，代价是要求值互不相同。
- **「高度」口径混用**。边数口径与节点数口径差 1，`height` 和 `diameter` 用了不同口径时，答案永远差 1 且看起来「差不多对」。口径写在函数注释里，比记在脑子里可靠。
- **空树与单节点是特例**。`diameter(None) = 0`、最大路径和必须至少选一个节点（不能返回 0）、`has_path_sum(None, 0) = False`（空树没有根到叶路径）。写完先在这两个规模上跑一遍。
- **用 −1 或 0 当空位哨兵**。树里一旦真的出现这个值，那个节点连同子树会被静默丢弃。Python 里 `if node.left:` 判的是对象真值（安全），但 `if node.val:` 会把值为 0 的节点当成空——两者只差一个 `.val`。
- **线索树忘了给最后一个节点打标记**（见第 10 节的警告），以及**遍历中修改树结构**：Morris 会临时改写空指针，回收内存会 free 掉正在访问的节点，动手前先想清楚「下一步要读的指针还有效吗」。

## 14. 小结

- 深度从根往下数、高度从叶往上数，口径必须统一；`depth(v) + height(v) - 1 <= 树高`，取等当且仅当 v 在最长路径上。二叉树与「度为 2 的树」的差别是**左右有序**：n = 3 时二叉树有 5 种形态，无序树只有 2 种；空树、半边空都是合法二叉树，这是 n + 1 个空指针域性质的来源。
- 四个易混词的精确关系：`完美 ⇒ 完全 ⇒ 平衡`、`完美 ⇒ 满`，反过来都不成立，反例分别是「完全且满但不完美（n = 5）」「满但不完全（层序有空洞）」「完全但不满（有一个只有左孩子的节点）」。
- 五条性质都能自己推：`n₀ = n₂ + 1`（边数 = 出度之和）、第 k 层至多 `2^(k-1)`（左右选择序列）、高 h 至多 `2^h - 1` 个节点、完全二叉树高度 `floor(log2 n) + 1`（两边夹逼）、空指针域 `n + 1`（指针总数减边数）。
- 三种存储各有分工：链式适合任意形态；顺序存储只对完全二叉树零浪费，非完全形态按 `2^h - 1` 爆炸；左孩子右兄弟把任意树压进两个指针，代价是「找第 k 个孩子」要 O(k)。
- **递归序是理解一切遍历的钥匙**：每个节点被到访三次，先 / 中 / 后序只是「在第几次到访输出」。迭代版分别用「栈 + 先压右」「祖先链」「先序变形 + 反转 / last 指针」实现；Morris 用空指针换 O(1) 空间，代价是临时改写树。
- 层序的核心是「先冻结本层长度」这个不变式；四个变体的差别只在「在每层的哪个位置取信息」，其中最大宽度必须带上下标，最小深度必须在第一个叶子处返回。自顶向下用先序传参（路径和、对称），自底向上用后序汇总（树高、直径、子树信息）；树形 DP 的分水岭是「返回值 ≠ 全局答案」——向上只带一条边，拐弯处结算。
- 先序 + 中序可以唯一重建（哈希表定位根，O(n)），前提是值互不相同；先序 + 后序不行，一致解的个数是 `2^(单孩子节点数)`。
- 序列化要带空标记，或利用 BST 的值域约束省掉空标记；线索二叉树把 n + 1 个空指针改造成前驱 / 后继线索，遍历 O(1) 空间，适合只读场景。

## 15. 练习

**1.** 一棵二叉树有 100 个叶节点、30 个只有一个孩子的节点，问它总共有多少个节点？如果它是满二叉树，叶节点又有多少个？

> [!TIP]
> 思路由 `n₀ = n₂ + 1` 得 n₂ = 99，总数 `n = n₀ + n₁ + n₂ = 100 + 30 + 99 = 229`。若它是满二叉树则 n₁ = 0，叶节点数仍是 100（这条性质只与 n₂ 有关，与 n₁ 无关），此时总数是 199。

**2.** 高度为 5 的二叉树最少有多少个节点？最多有多少个？一棵有 20 个节点的完全二叉树高度是多少？高度为 6 的完美二叉树有多少个节点？

> [!TIP]
> 思路最少 5 个（一条链，每层一个节点）；最多 `2^5 - 1 = 31` 个（完美）。20 个节点的完全二叉树高度是 `floor(log2 20) + 1 = 5`。完美：`2^6 - 1 = 63`。

**3.** 用递归序解释：为什么「中序的第一个节点」是从根一路向左走到底的那个节点？

> [!TIP]
> 思路中序在第 2 次到访时输出。对任意节点，「第 1 次到访后立刻进入左子树」，所以递归会一直向左下沉，直到遇到没有左孩子的节点——它的第 1 次到访之后紧跟着第 2 次到访（中间没有左子树），因此它是最先被输出的节点。

**4.** 为什么带空标记的序列化必须写空位？

> [!TIP]
> 思路不写空位就丢失了「孩子在哪一侧」的信息，这正是先序 + 后序无法唯一重建的同一个病根（一致解有 `2^k` 棵）。补上空标记后结构信息完备，单靠一个序列就能唯一还原；代价是长度从 n 涨到 2n + 1。

**5.** 一个 n = 10⁶ 的链式二叉树退化成了一条链，用递归遍历会怎样？给出至少三种不爆栈的方案并比较空间代价。

> [!TIP]
> 思路Python 默认递归上限 1000 层，直接 `RecursionError`；C 的 8 MB 栈同样溢出（段错误，不是异常）。方案：①显式栈迭代，空间 O(h) = O(n)，但栈在堆上，上限取决于可用内存；②Morris 遍历，O(1) 额外空间，代价是临时改写空指针、常数约 2\~3 倍；③先中序线索化再遍历，O(n) 预处理 + O(1) 遍历，适合反复扫描；④调大递归上限或线程栈大小，只是延后问题，不推荐。

**6.** 为什么 `diameter` 的递归函数返回的是「单边深度」而不是直径本身？把返回值改成直径会发生什么？

> [!TIP]
> 思路父节点能继续往上拼接的只有「以自己为端点的那条路径」，也就是单边深度；而「经过某节点的最长路径」在最高点拐了弯，两个端点都在下方，无法再向上延伸。若返回直径，父节点拿到的值无法参与「左 + 右」的拼接，穿过父节点的那些路径会被漏掉，答案偏小。

**7.** 在中序线索二叉树里怎样 O(1) 找到某节点在中序下的前驱？与找后继的规则有什么对称性？

> [!TIP]
> 思路若 `ltag = 1`（没有左孩子），左指针就是前驱线索，O(1)；否则前驱是**左子树的最右节点**（从左孩子出发一路向右，直到 `rtag = 1`）。与后继规则完全对称：后继是「右子树的最左节点」或右线索。两者合起来让中序遍历可以完全不用栈。
