排序是学习复杂度和取舍的最好教材：同一个问题，十几种算法在时间、空间、稳定性、缓存友好度上各占一头。而且它离生产极近——你每天调的 `sort()` 背后就是本篇内容的取舍结果。

## 一张表看全貌

| 算法           | 平均         | 最坏         | 空间         | 稳定      | 一句话               |
| ------------ | ---------- | ---------- | ---------- | ------- | ----------------- |
| 冒泡 / 选择 / 插入 | O(n²)      | O(n²)      | O(1)       | 插入/冒泡稳定 | 小数据或基本有序（插入 O(n)） |
| 希尔           | O(n^1.3)   | 取步长        | O(1)       | 否       | 插入的分组加速版          |
| 快排           | O(n log n) | O(n²)      | O(log n) 栈 | 否       | 综合最快的通用排序         |
| 归并           | O(n log n) | O(n log n) | O(n)       | **是**   | 稳定 + 链表排序首选       |
| 堆排           | O(n log n) | O(n log n) | O(1)       | 否       | 最坏有保证，缓存不友好       |
| 计数 / 桶 / 基数  | O(n+k)     | O(n+k)     | O(n+k)     | 可稳定     | 非比较，整数/定长键专用      |

两个必须内化的定理：**比较排序的下界是 O(n log n)**（n! 种排列的决策树深度），想突破它就不能比较——按位分桶（计数/基数）正是绕开了比较。

## 快排：分治 + 原地分区

选一个基准（pivot），把小于它的划到左边、大于的划到右边，再递归两边：

```python
def quicksort(a, lo, hi):
    while lo < hi:
        p = partition(a, lo, hi)
        quicksort(a, lo, p - 1)
        lo = p + 1              # 尾递归消除，栈深 O(log n)
```

快排快在三点：分区是连续内存上的原地交换（缓存极友好）、内层循环极简、期望 O(n log n) 且常数小。**最坏 O(n²) 来自糟糕的 pivot**（如已有序 + 固定取头），解法是随机选或三数取中；大量重复元素用三路分区（< = > 三段）。

## 稳定性：相等元素要不要保持次序

稳定 = 相等的键排序后相对次序不变。看似学究，实际决定"多关键字排序"的可行性：

```text
先按姓名排，再按部门稳定排 → 同部门内仍按姓名有序
（不稳定排序会把第一步的成果洗掉）
```

要稳定就选归并系；数据库排序、多级排序都是稳定排序的直接受益者。

## 标准库在用什么（都不止一个算法）

- **Python `sort()`**：Timsort——归并 + 插入的混合，天然段有序的真实数据近乎 O(n)，稳定
- **C++ `std::sort`**：Introsort——快排起步，递归过深处转堆排防 O(n²)，小段转插入；`stable_sort` 才是归并
- **Rust `sort()`**：Timsort 变体（稳定）；`sort_unstable()`：模式消除快排（不稳定但更快）

> [!TIP]
> 语言自带的排序永远是你无脑可用的高水线：经过三十年打磨，混合策略 + 特化分支 + SIMD，手写在绝大多数场景赢不了。**先确认"自带的真不够用"再手写**。

## 手写排序的少数正当理由

1. **键结构特殊**：小范围整数 → 计数排序；定长字符串/多关键字 → 基数排序，从 O(n log n) 降到 O(n)
2. **近似有序**：插入排序 O(n + 逆序对数)，监控系统里新数据基本有序的流是典型
3. **只要部分结果**：最小 K 个 → 堆（O(n log k)）或快速选择（O(n) 平均），不必全排
