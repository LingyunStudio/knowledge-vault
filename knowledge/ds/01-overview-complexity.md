数据结构回答的问题只有一句话：**一组数据用什么方式存放，才能让程序要做的操作最快、最省**。算法是"怎么算"，数据结构是"往哪放"——存放方式决定了某些操作天生就快，另一些天生就慢。所以选型之前，先要会量化"快"和"省"。

## 逻辑结构 vs 存储结构

同一种逻辑结构可以有多种存储实现，这是学数据结构最容易混的一对概念：

- **逻辑结构**：数据之间的抽象关系——线性（一对一）、树形（一对多）、图（多对多）、集合（无序无关系）
- **存储结构**：在内存里怎么落地的——**顺序存储**（一段连续内存，如数组）和**链式存储**（节点 + 指针，如链表），以及二者的混合（如哈希桶里的链表）

栈和队列是逻辑结构（受限的线性表），数组是存储结构。"用数组实现栈"这句话里两者各就各位，就不乱了。

## 大 O：只看增长趋势

大 O 记号描述的是**操作次数随数据量 n 增长的量级**，忽略常数系数和低阶项。它不是运行时间，但数量级正确时足以指导选型：

| 复杂度           | 俗称    | n = 10⁶ 时的直觉                |
| ------------- | ----- | --------------------------- |
| O(1)          | 常数    | 哈希查找、数组下标访问                 |
| O(log n)      | 对数    | 二分查找、平衡树操作                  |
| O(n)          | 线性    | 遍历一遍                        |
| O(n log n)    | 线性对数  | 快排、归并的下界                    |
| O(n²)         | 平方    | 双重循环，n = 10⁶ 就要 10¹² 步，不可接受 |
| O(2ⁿ) / O(n!) | 指数/阶乘 | 只能解 n ≤ 20 左右的小规模           |

> [!TIP]
> 面试和刷题有个经验法则：n ≤ 20 想搜索/状压，n ≤ 500 想 O(n³)，n ≤ 10⁴ 想 O(n²)，n ≤ 10⁶ 想 O(n log n) 或 O(n)。先看数据范围，再定复杂度目标。

三个常被问到的细节：

1. **大 O 是上界**：哈希查找平均 O(1)，最坏 O(n)（全部碰撞），严谨的说法是"平均 O(1)，最坏 O(n)"。
2. **Ω 和 Θ**：Ω 是下界，Θ 是紧确界。快排最坏 O(n²)、平均 Θ(n log n)。
3. **常数因子并非总是可忽略**：n 不大时，O(n) 的顺序遍历常常快过 O(log n) 的树——缓存友好的连续内存经常赢。

## 摊还分析：偶尔贵，平均便宜

动态数组（如 Python 的 list、C++ 的 vector）在满了之后扩容——通常是申请 2 倍空间、整体搬迁，这一次操作是 O(n)。但因为每 O(n) 次追加才触发一次 O(n) 的搬迁，**把代价摊到每次操作上，单次追加是 O(1)**。

```text
追加 1 次 → 满了 → 搬 2 次 → 追加 2 次 → 搬 4 次 → 追加 4 次 ……
n 次追加的总代价 ≤ 2n 次基本写入 → 摊还 O(1)
```

> [!NOTE]
> 摊还 O(1) 不等于每次 O(1)。对延迟敏感的场景（实时系统）要小心单次扩容的长尾，可以预估容量提前 reserve。
