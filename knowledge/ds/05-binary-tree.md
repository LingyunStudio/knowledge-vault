树是表达**层次与包含关系**的结构：文件系统、组织架构、DOM、语法树。它也是后面堆、Trie、B+ 树的公共基础——先把这些术语和遍历内化，后面的结构就是"换了约束的树"。

## 术语一分钟

- **节点 / 根 / 叶子**：顶部无父节点的是根，无子节点的是叶
- **深度 / 高度**：节点到根的层数是深度；树中最深叶子的高度是树高
- **二叉树**：每个节点至多两个孩子；**满二叉树**每层全满；**完全二叉树**只缺最底层右侧——堆的形状要求
- 一个关键计数性质：n 个节点的二叉树里，空指针（空孩子）有 n+1 个——链式存储浪费在哪、线索化为什么可行，都从这来

## 四种遍历，一个框架

递归三行是母版：**先序**（根左右）、**中序**（左根右）、**后序**（左右根），加上按层的**层序**（用队列，即 BFS）。

```python
def preorder(node):
    if not node: return
    visit(node)                    # 根的位置换一下，就是三种序
    preorder(node.left)
    preorder(node.right)
```

每种序都有对应的高频用法：

- **先序**：复制树、序列化、"自顶向下"收集信息
- **中序**：二叉搜索树的中序遍历 = 升序序列——BST 一切与"有序"有关的性质都从这来
- **后序**：需要先知道孩子结果再算父亲（子树大小、树形 DP、释放内存）
- **层序**：最短层数、宽度、"逐层处理"

> [!TIP]
> 迭代写法（显式栈）的核心：先序压栈时先压右孩子后压左孩子；中序沿左链一路压到底再弹；后序可用"前序变形（根右左）+ 结果反转"一步到位。层序用 deque，每层先记下当前队列长度。

## 二叉搜索树：每个节点都是一道分界线

BST 加一条约束：**左子树全部 < 根 < 右子树全部**。查找、插入、删除都是"与当前节点比大小、往一边走"：

```c
Node *find(Node *t, int x) {
    while (t && t->val != x)
        t = x < t->val ? t->left : t->right;
    return t;
}
```

平均 O(log n)——每步淘汰一半。但**复杂度取决于树高**：按序插入 1,2,3,… 会退化成一条链，树高 n，一切操作 O(n)。这是 BST 的致命伤。

### 删除节点的三种情况

1. 叶子：直接删
2. 只有一个孩子：孩子顶上
3. 有两个孩子：找**中序后继**（右子树最左节点，或前驱）换值后删后继——保证中序性质不破

### 平衡：让树高被迫保持 log n

既然瓶颈是树高，就强制它：AVL（严格平衡，插删时旋转）、**红黑树**（近似平衡，旋转少，工程首选——C++ map、Java TreeMap 的底层）。平衡化只改变结构不改中序序列，这就是旋转能成立的原因。

> [!NOTE]
| 结构 | 查找 | 插入 | 有序性 | 备注 |
| --- | --- | --- | --- | --- |
| 哈希表 | O(1) 平均 | O(1) 平均 | 无 | 点查最快 |
| 平衡 BST | O(log n) | O(log n) | 有 | 范围查询/顺序遍历 |
| 有序数组 | O(log n) | O(n) | 有 | 静态数据最优 |

> 要"有序的动态集合"，平衡 BST 是默认答案；磁盘上的有序索引则是 B+ 树的天下（矮胖多叉，减少磁盘寻道）。

## 树上的递归思维

树形问题的通用套路：**"整棵树的答案 = f(根, 左子树的答案, 右子树的答案)"**。写对三件事就够了：递归基（空树返回什么）、左右子树各自的结果、如何合成当前层。子树高度、最大深度、直径、是否平衡，全是这个骨架的变体。
