优先队列回答的问题是：**一堆带优先级的元素，要反复取"当前最重要"的那个**。有序数组插入 O(n)，无序数组取最值 O(n)，都不理想。堆用一棵"半排序"的完全二叉树，把插入和取最值都做到 O(log n)，取最值本身只看一眼 O(1)。

## 两条性质撑起全部

1. **形状：完全二叉树**——除了最底层只缺右侧，其他全满
2. **堆序：父 ≤ 子（小顶堆）或父 ≥ 子（大顶堆）**——注意只约束父子，兄弟之间无序，左右大小也不保证

形状性质带来一个绝妙的数组表示：把节点按层序放进数组，**下标 i 的孩子是 2i+1 和 2i+2，父亲是 (i-1)/2**——零指针开销，缓存友好：

```text
        1                数组: [1, 3, 2, 6, 5, 4]
      3   2              下标:  0  1  2  3  4  5
     6 5 4                     i 的孩子 = 2i+1, 2i+2
```

## 两个基本操作：上浮与下沉

破坏堆序时把违规元素往正确方向换：

- **上浮 sift-up**：新元素放末尾，比父小就交换——插入用，O(log n)
- **下沉 sift-down**：把末尾换到堆顶后，与较小的孩子交换直到安分——弹出堆顶用，O(log n)

```python
import heapq                    # Python 的 heapq 是小顶堆
h = [5, 1, 8]
heapq.heapify(h)                # 原地建堆
heapq.heappush(h, 3)            # 插入 O(log n)
smallest = heapq.heappop(h)     # 弹出最小 O(log n)
# 大顶堆技巧：存相反数 push(-x) / pop 后取负
```

### 建堆为什么是 O(n) 而不是 O(n log n)

从最后一个非叶节点开始**逐个下沉**，看似每个 O(log n)，但绝大多数节点在底层、下沉距离短：高度 h 的节点约 n/2^(h+1) 个，总代价 Σ n/2^h = O(n)。逐个插入则是 O(n log n)。**已知全集建堆用下沉，流式到达才用插入。**

## 三个经典应用

### 1. TopK：K 个最大的数，用小顶堆

直觉反了：求最大的 K 个，**维护的是容量 K 的小顶堆**——新元素比堆顶大才入堆，堆里始终是"当前最大的 K 个"，堆顶是它们中最小的（K 名的门槛）：

```python
def top_k(nums, k):
    h = []
    for x in nums:
        if len(h) < k:
            heapq.heappush(h, x)
        elif x > h[0]:
            heapq.heapreplace(h, x)   # 弹小换大，O(log k)
    return h
```

总代价 O(n log k)——k 通常远小于 n；对比排序的 O(n log n)，且是流式算法（数据不用一次到齐）。面试高频，"为什么不是大顶堆"是必考点：大顶堆得装下全部 n 个才有意义，小顶堆只装 K 个。

### 2. 多路归并：K 个有序链表合一个

K 路各有一个"当前指针"，把 K 个指针的当前值放进小顶堆，弹一个、补该路下一个——总 O(N log K)，归并外排、LeetCode 23 的通用解法。

### 3. 调度与定时器

操作系统的进程调度、网络的超时定时器、Dijkstra 的"当前最近的未定节点"，本质都是优先队列：每次取最高优先级，处理完可能产生新的待办（延迟 = 新任务入堆）。

> [!NOTE]
> 堆只承诺"最快拿到最值"。要遍历有序、要按任意键删除、要找第 K 大之外的排名，堆都不擅长——那是平衡树/有序表的工作。

> [!TIP]
> 判断能不能用堆：问题只需反复**访问极值**、不需要全局有序。需要"中位数"这类动态排名，用对顶堆（一个大顶堆一个小顶堆各管一半）也是堆的看家戏法。
