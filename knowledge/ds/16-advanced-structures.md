前十五篇里的结构，回答的大多是「一个元素在哪」：数组按下标取，哈希表按键取，树按序取。但工程与算法里还有一整类问题，问的不是单个元素，而是「一段区间聚合出了什么」：滑动窗口里的最大值是多少、日志里某个时间段的错误总数、十亿个 URL 里这个爬过没有。把这些问题摊给朴素数组，一次操作就是 O(n)；数据规模一大，这条路就死了。这一篇讲的每件东西，都是对某个**特定操作集**的精确回答：前缀和把「静态区间和」做到 O(1)，树状数组补上「单点更新」，线段树把「区间更新 + 区间查询」收进 O(log n)，稀疏表把「静态区间最值」的查询做到 O(1)，布隆过滤器把「存在性判断」的内存压掉一个数量级。主线是一句选型口诀：**操作集决定结构**——先把你要支持的操作列出来，答案常常是唯一的。

## 1. 一张地图：操作集决定结构

一个数据结构可以看成一份合同：你承诺只做这些操作，它保证每种操作的代价。合同越宽（支持的操作越多），每种操作越贵，代码越长。所以选型的第一步不是「哪个结构最强」，而是「我的操作集到底是什么」。对区间问题，这条代价阶梯长这样：

| 操作集（区间问题）    | 结构        | 单次代价     | 出处    |
| ------------ | --------- | -------- | ----- |
| 建好就不动，查区间和   | 前缀和       | O(1) 查询  | 第 2 节 |
| 建好就不动，查区间最值  | 稀疏表       | O(1) 查询  | 第 5 节 |
| 区间加，最后还原或点查  | 差分        | O(1) 更新  | 第 2 节 |
| 单点加 + 前缀和，在线 | 树状数组      | O(log n) | 第 3 节 |
| 区间加 + 区间和，在线 | 线段树 + 懒标记 | O(log n) | 第 4 节 |
| 操作更怪、写不动线段树  | 分块        | O(√n)    | 第 6 节 |
| 海量存在性、内存紧张   | 布隆过滤器     | O(1)，带误判 | 第 7 节 |

从上往下读：支持的操作越来越多，单次代价越来越贵，代码越来越长。最划算的做法永远是「用最便宜的结构撑住你的操作集」，而不是「上来就上最强的」。前四个结构（前缀和、树状数组、线段树、稀疏表）覆盖了区间问题的绝大多数场景，值得写透；后面的结构是地图上的坐标，知道它们解决什么、什么时候回来查，就够了。

## 2. 前缀和与差分：先把「静态」的便宜占满

前缀和（prefix sum）与差分（difference array）是一对互为逆运算的变换：前者把「区间求和」变便宜，后者把「区间加」变便宜。它们共享同一个前提——**数据一次性给定，之后基本不改**。这个前提看起来苛刻，实际上大量场景满足：日志按天切分后不再变、一次读入的输入、攒一批更新后统一结算。

### 2.1 一维前缀和：区间和的 O(1) 答案

定义 `p[0] = 0`，`p[i] = a[0] + a[1] + ... + a[i-1]`。于是任意半开区间 `[l, r)` 的和就是两个前缀相减：`sum(l, r) = a[l] + ... + a[r-1] = p[r] - p[l]`。`p[0] = 0` 这个哨兵位不是装饰：它让 `l = 0` 的查询和其他情况走同一个公式，省掉一个特判。构造 O(n)，之后每次查询 O(1)，空间 O(n)——区间和这件事，「一次扫描 + 一次减法」就到头了，没有比这更便宜的正确答案。

代价藏在「静态」两个字里：改一个 `a[i]`，`p[i]` 之后的所有前缀全部作废，重算是 O(n)。所以前缀和把全部筹码押在「数据不变」上。什么时候不该用：数据要频繁改（看第 3 节）；或者总共只查一两次——那直接 `sum(a[l:r])` 就行，建前缀和反而多此一举。

### 2.2 二维前缀和：容斥原理

二维是一样的想法：`p[i][j]` 存「左上角 (0, 0) 到 (i-1, j-1)」整个矩形的和。递推时要小心一件事——上面那块和左边那块**把左上角的小矩形算了两遍**，必须减回来：

```text
p[i][j] = a[i-1][j-1] + p[i-1][j] + p[i][j-1] - p[i-1][j-1]
```

查询同理，容斥的方向反过来：

```text
大矩形 p[r2][c2]
┌───────────────────────┐
│ A          │ B        │     A = p[r1][c1]：左上角，被减了两次，加回一次
│            │          │     B = p[r1][c2]：上面整条，减掉
├────────────┼──────────┤     C = p[r2][c1]：左边整条，减掉
│ C          │ 查询区    │     查询区 = 大 - B - C + A
└───────────────────────┘
```

构造 O(n·m)，每次矩形查询 O(1)。图像处理里的积分图（integral image，人脸检测的 Haar 特征就靠它）、二维棋盘的子矩阵求和，全是这个公式。

### 2.3 差分：把「区间加」变成两次单点

现在把需求反过来：不做区间查询，而是要**反复做「区间 \[l, r] 整体加 v」**，最后还原出数组。朴素的区间加是 O(r − l + 1)；差分把它变成 O(1)。

差分数组 `d[i] = a[i] - a[i-1]`，记录的是**相邻元素的变化量**。区间 `[l, r]` 整体加 v 时，区间内部相邻元素的差完全不变，只有两处「断点」变了：进入区间的跳变（l−1 到 l）和离开区间的跳变（r 到 r+1）。所以只需要：

```text
d[l] += v      # l 处多出一跳 +v
d[r+1] -= v    # r+1 处把跳变抵消回去
```

还原就是对 d 做一次前缀和（两种变换互逆），O(n)。整套流程的代价：k 次区间加 O(k)，最后还原 O(n)——适合「攒一批更新、最后统一结算」。典型用途：公交线路每一站上下客的人数还原、给一段日期批量乘折扣再逐天结算。

> [!WARNING]
> 差分的两个高频 bug：① `r + 1` 越界——差分数组要开 `n + 1` 长，`r = n - 1` 时 `d[n]` 是合法的哨兵位，别按 n 开数组；② 还原时把哨兵位也当数据读出来，结果多出一个元素。另外记住它的适用边界：如果「查询」混在「更新」中间随时发生，前缀和与差分同时失效——那是第 3、4 节的主场。

下面把三个工具放进一段可对拍的代码（与暴力实现比对，全部断言通过）：

```python
import random

# ---------- 一维前缀和 ----------
def build_prefix(a):
    """p[i] = a[0] + ... + a[i-1]，p[0] = 0 是哨兵。"""
    p = [0] * (len(a) + 1)
    for i, x in enumerate(a):
        p[i + 1] = p[i] + x
    return p

def query(p, l, r):
    """半开区间 [l, r) 的和 = p[r] - p[l]。"""
    return p[r] - p[l]

# ---------- 二维前缀和 ----------
def build_prefix2(a):
    """p[i][j] = 左上角 (0,0) 到 (i-1, j-1) 的矩形和，第 0 行/列是哨兵。"""
    n, m = len(a), len(a[0])
    p = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            p[i][j] = (a[i - 1][j - 1] + p[i - 1][j]
                       + p[i][j - 1] - p[i - 1][j - 1])
    return p

def query2(p, r1, c1, r2, c2):
    """半开矩形 [r1, r2) x [c1, c2) 的和。"""
    return p[r2][c2] - p[r1][c2] - p[r2][c1] + p[r1][c1]

# ---------- 差分：区间加 + 点查询 ----------
def diff_apply(d, l, r, v):
    """闭区间 [l, r] 整体加 v，只动两个位置。"""
    d[l] += v
    d[r + 1] -= v

def diff_rebuild(d):
    """对差分数组做一次前缀和，还原出真实数组。"""
    out, run = [], 0
    for x in d[:-1]:          # 末位是 r+1 的哨兵位，不属于原数组
        run += x
        out.append(run)
    return out

if __name__ == "__main__":
    random.seed(7)
    a = [random.randint(-100, 100) for _ in range(64)]
    p = build_prefix(a)
    for _ in range(200):
        l = random.randint(0, 63)
        r = random.randint(l, 64)
        assert query(p, l, r) == sum(a[l:r])

    mat = [[random.randint(-9, 9) for _ in range(8)] for _ in range(5)]
    p2 = build_prefix2(mat)
    for _ in range(200):
        r1, r2 = sorted(random.sample(range(6), 2))
        c1, c2 = sorted(random.sample(range(9), 2))
        assert query2(p2, r1, c1, r2, c2) == \
            sum(sum(row[c1:c2]) for row in mat[r1:r2])

    d = [0] * 65
    truth = [0] * 64
    for _ in range(60):
        l, r = sorted(random.sample(range(64), 2))
        v = random.randint(-9, 9)
        diff_apply(d, l, r, v)
        for i in range(l, r + 1):
            truth[i] += v
    assert diff_rebuild(d) == truth
    print("prefix/diff ok")
```

## 3. 树状数组：给前缀和补上「可更新」

前缀和的死穴是改一个点要拖动一整条后缀。树状数组（Fenwick Tree，也叫 Binary Indexed Tree，BIT）的解法出人意料地轻：**不再存「到 i 为止的总和」，而是存「精心挑选的一批块的各自总和」**，让改一个点只牵动 O(log n) 个块，查前缀也只累加 O(log n) 个块。它只有两个循环、一个数组，是本篇性价比最高的「动态」结构。

### 3.1 lowbit：一个位运算撑起一棵隐式树

核心是 `lowbit(i) = i & (-i)`：取出 i 的二进制里**最低位的 1**。原理是补码表示下 `-i` 等于「按位取反再加一」：最低位的 1 右边（全是 0）不变，左边全部翻转，与运算后只剩最低位的那个 1。例如 `i = 12 = 1100₂`，`-12` 的补码是 `...10100`，与起来得 `0100 = 4`。

树状数组规定：`t[i]` 管辖「从 i 往前数 lowbit(i) 个元素」的区间：

```text
i        : 1     2     3     4     5     6     7     8
lowbit(i): 1     2     1     4     1     2     1     8
t[i] 管辖: [1,1] [1,2] [3,3] [1,4] [5,5] [5,6] [7,7] [1,8]

prefix(11)：11 = 1011 → 剥掉最低位：11 → 10 → 8 → 0
            t[11] + t[10] + t[8] = [11,11] + [9,10] + [1,8]，无缝拼出 [1,11]
add(5,+v) ：5 = 0101 → 加上最低位：5 → 6 → 8 → 16
            [5,5] ⊂ [5,6] ⊂ [1,8] ⊂ [1,16]，每个管辖含 5 的节点都收到
```

两条「跳着走」的路径由此解释：

- **前缀查询 `i -= lowbit(i)`**：i 的每个二进制位 1 恰好对应一段不重叠的管辖块，剥一位收一段，收完恰好无缝拼出 `[1, i]`。循环次数 = i 的二进制中 1 的个数，不超过 log₂ n。
- **单点更新 `i += lowbit(i)`**：从 i 跳到「管辖范围包含 i 的更大的块」，一路到根。所有管辖含 i 的节点都在这条链上且只在这条链上。

管辖关系 `i → i + lowbit(i)` 构成一棵隐式的树——「树状」由此得名，但物理上没有任何指针，只有一个长度 n + 1 的数组。这就是它常数小的根源（第 3.4 节细说）。

### 3.2 实现与对拍

```python
import random

class Fenwick:
    """树状数组：1-based，支持「单点加 + 前缀和」。

    t[i] 管辖的区间是 (i - lowbit(i), i]，长度恰好是 lowbit(i)。
    """

    def __init__(self, n):
        self.n = n
        self.t = [0] * (n + 1)        # 下标 0 弃用

    @staticmethod
    def lowbit(i):
        return i & (-i)               # i 的二进制里最低位的 1

    def add(self, i, v):
        """a[i] += v：从 i 出发，跳到所有管辖范围覆盖 i 的节点。"""
        while i <= self.n:
            self.t[i] += v
            i += self.lowbit(i)       # 跳向「包含我的更大的块」

    def prefix(self, i):
        """返回 a[1] + ... + a[i]。"""
        s = 0
        while i > 0:
            s += self.t[i]
            i -= self.lowbit(i)       # 剥掉最低位的 1，换上覆盖它的块
        return s

    def range_sum(self, l, r):
        """闭区间 [l, r] 的和 = 两个前缀和相减。"""
        return self.prefix(r) - self.prefix(l - 1)


def count_inversions(a):
    """逆序对计数：离散化 + 树状数组，O(n log n)。"""
    rank = {v: i + 1 for i, v in enumerate(sorted(set(a)))}
    bit = Fenwick(len(rank))
    inv = 0
    for seen, x in enumerate(a):
        r = rank[x]
        inv += seen - bit.prefix(r)   # 左边比 x 严格大的元素个数
        bit.add(r, 1)
    return inv


def count_smaller_left(a):
    """对每个元素，数它左边严格比它小的元素个数。"""
    rank = {v: i + 1 for i, v in enumerate(sorted(set(a)))}
    bit = Fenwick(len(rank))
    res = []
    for x in a:
        r = rank[x]
        res.append(bit.prefix(r - 1))  # 只统计已插入、值比 x 小的
        bit.add(r, 1)
    return res


if __name__ == "__main__":
    random.seed(7)
    bit = Fenwick(100)
    a = [0] * 101
    for _ in range(2000):
        i, v = random.randint(1, 100), random.randint(-10, 10)
        bit.add(i, v)
        a[i] += v
        l = random.randint(1, 100)
        r = random.randint(1, 100)
        l, r = min(l, r), max(l, r)
        assert bit.range_sum(l, r) == sum(a[l:r + 1])

    for n in (1, 2, 50, 300):
        b = [random.randint(0, 20) for _ in range(n)]
        brute = sum(1 for i in range(n) for j in range(i) if b[j] > b[i])
        assert count_inversions(b) == brute
        brute2 = [sum(1 for j in range(i) if b[j] < b[i]) for i in range(n)]
        assert count_smaller_left(b) == brute2
    print("fenwick ok")
```

实现要点只有三个：下标从 1 开始（0 的 lowbit 是 0，会死循环）；`range_sum` 靠「减法」拼出来；对拍时用暴力 `sum` 逐次核对。这段代码可以直接抄去用。

### 3.3 应用：逆序对与「左边比我小的数」

逆序对（inversion pair）是 `(i, j)` 满足 `i < j` 且 `a[i] > a[j]` 的对数，是衡量序列「乱序程度」的经典指标。暴力数是 O(n²)；用树状数组降到 O(n log n)：

1. **离散化（coordinate compression）**：值域可能很大甚至有负数，先把元素排序去重，映射成「第几小」的排名——树状数组只关心相对大小。
2. **从左往右扫**：扫到 `x` 时，已经插入树状数组的是它左边的全部元素。`bit.prefix(rank[x])` 是左边 ≤ x 的个数，`seen - bit.prefix(rank[x])` 就是左边比 x 严格大的个数——每个 x 的贡献累加起来就是逆序对总数。例如 `[3, 1, 4, 1, 5]` 的逆序对是 3 个：`(3,1)`、`(3,1)`、`(4,1)`。
3. 同一套扫描，把查询换成 `bit.prefix(rank[x] - 1)`，就得到「每个元素左边比它小的个数」——「统计右侧更小元素数」「排名还原」一类问题都是它的变体。

这个模式的通用形状值得记住：**一边扫一边问「已插入的元素里，值在某个范围的有多少个」**。凡是这种「值域上的前缀计数」，树状数组都是标准答案。

### 3.4 能力边界：它快在哪，不能做什么

同样 O(log n)，树状数组实测通常比线段树快数倍，原因都在物理布局上：

- 数组只有 `n + 1` 个位置（线段树要 `4n`，还常常是 `sum`、`lazy` 两个数组）；
- 每个循环体只有一次加法和一次位运算，没有递归调用、没有区间端点的比较与下推；
- 不存储区间端点——端点信息隐含在 lowbit 里。

它能做「区间和」依赖一件事：**加法有逆运算**，所以 `sum(l, r) = prefix(r) - prefix(l-1)`。max 和 min 没有逆，「两个前缀相减」的把戏失效——存在只支持「前缀 max」的变体，但要求更新只能改大不能改小，限制很大。什么时候不该用树状数组：需要区间最值、区间赋值、自定义合并（上第 4 节）；只需要静态区间和（回第 2 节）；n 很小（直接暴力）。「区间更新 + 单点查询」也可以在线做了：把差分数组放进树状数组，区间加变成两次单点 `add`，点查就是一次 `prefix`——这是第 2.3 节的差分在线化，每步 O(log n)。

## 4. 线段树：区间信息的通用合并框架

树状数组的每一步都依赖「加法可逆」。线段树（segment tree）放弃了这个前提，换来通用性：**只要合并操作满足结合律，就能挂上去**——和、最大最小值、gcd、最大子段和、区间乘积，甚至矩阵乘法（结合律成立，交换律不成立也行）。它是区间问题的通用后端，代价是本篇最大的代码量。

### 4.1 每个节点存一段的信息

把整个数组挂在根上，每个节点的值是**它管辖的那一段**上聚合操作的结果；左右孩子对半分：

```text
n = 8，节点编号 o 管闭区间 [l, r]，左孩子 2o，右孩子 2o+1

                  1:[0,7]
             /              \
         2:[0,3]            3:[4,7]
        /      \           /      \
    4:[0,1]  5:[2,3]   6:[4,5]  7:[6,7]
    /   \     /   \     /   \     /   \
 8:[0] 9:[1] 10:[2] 11:[3] 12:[4] 13:[5] 14:[6] 15:[7]
```

两条不变式：① 每个节点的值恒等于其区间的真实聚合结果；② 任意查询区间 `[ql, qr]` 都能拆成 O(log n) 个节点的不交并——从根出发，完全在范围内的直接取，跨越中点的才递归。单点修改沿一条根到叶的路径更新，也是 O(log n)。用 `2o`、`2o+1` 编号是完全二叉树的层序位置，所以数组开 `4n`（安全上界）就够，不需要指针。

### 4.2 懒标记：区间更新的正确姿势

现在要支持「区间 `[l, r]` 整体加 v」。朴素做法一路改到叶子：一次 O(n)。n = 10⁶ 的数组上做 10⁵ 次区间加，10¹¹ 次操作，没有任何机器等得起。懒标记（lazy propagation）的观察是：查询区间拆出的 O(log n) 个节点里，**被完全覆盖的节点不需要通知孩子**——它们的整段都被加了 v，孩子各自该加多少是确定的，可以先记账。

```text
区间 [2, 5] 加 v（n = 8）：

                 1:[0,7]          部分覆盖：下推欠条，两边都递归
               /       \
          2:[0,3]     3:[4,7]      部分覆盖：同上
               \          \
               5:[2,3]   6:[4,5]    完全覆盖：sum 立即更新，
                                    lazy 记账，到此为止，不下探
4:[0,1] 与 7:[6,7] 和区间不相交，从未被访问；全程 5 个节点，没碰任何叶子
```

这就是懒标记的不变式：**节点的 `sum[o]` 已经包含了 `lazy[o]` 的影响，但孩子还没结账**；`lazy[o]` 就是一张「欠条」。只有当后续某个操作必须进入孩子时，才把欠条下推一层（push down）。为什么每步仍是 O(log n)：完全覆盖的节点是 O(log n) 个；被「部分覆盖」而需要下推的边界节点，每层至多 2 个（区间的左右端点各引出一条路径），总层数 O(log n)。

### 4.3 实现：区间加 + 区间和

```python
import random

class SegTree:
    """线段树：区间加 + 区间和，带懒标记。节点编号从 1 开始，孩子是 2o 与 2o+1。"""

    def __init__(self, a):
        self.n = len(a)
        self.sum = [0] * (4 * self.n)
        self.lazy = [0] * (4 * self.n)
        self._build(1, 0, self.n - 1, a)

    def _build(self, o, l, r, a):
        if l == r:
            self.sum[o] = a[l]
            return
        m = (l + r) // 2
        self._build(2 * o, l, m, a)
        self._build(2 * o + 1, m + 1, r, a)
        self.sum[o] = self.sum[2 * o] + self.sum[2 * o + 1]

    def _push_down(self, o, l, r):
        """结清欠条：把本节点的懒标记下推一层，只在必须进入孩子前调用。"""
        if self.lazy[o]:
            m = (l + r) // 2
            self.sum[2 * o] += self.lazy[o] * (m - l + 1)
            self.lazy[2 * o] += self.lazy[o]
            self.sum[2 * o + 1] += self.lazy[o] * (r - m)
            self.lazy[2 * o + 1] += self.lazy[o]
            self.lazy[o] = 0

    def add(self, ql, qr, v):
        self._add(1, 0, self.n - 1, ql, qr, v)

    def _add(self, o, l, r, ql, qr, v):
        if ql <= l and r <= qr:              # 完全覆盖：自身立即更新，孩子记账
            self.sum[o] += v * (r - l + 1)
            self.lazy[o] += v
            return
        self._push_down(o, l, r)
        m = (l + r) // 2
        if ql <= m:
            self._add(2 * o, l, m, ql, qr, v)
        if qr > m:
            self._add(2 * o + 1, m + 1, r, ql, qr, v)
        self.sum[o] = self.sum[2 * o] + self.sum[2 * o + 1]

    def query(self, ql, qr):
        return self._query(1, 0, self.n - 1, ql, qr)

    def _query(self, o, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.sum[o]
        self._push_down(o, l, r)
        m = (l + r) // 2
        res = 0
        if ql <= m:
            res += self._query(2 * o, l, m, ql, qr)
        if qr > m:
            res += self._query(2 * o + 1, m + 1, r, ql, qr)
        return res


if __name__ == "__main__":
    random.seed(7)
    n = 64
    a = [random.randint(-50, 50) for _ in range(n)]
    st = SegTree(a)
    for _ in range(1500):
        l, r = sorted((random.randint(0, n - 1), random.randint(0, n - 1)))
        if random.random() < 0.5:
            v = random.randint(-9, 9)
            st.add(l, r, v)
            for i in range(l, r + 1):
                a[i] += v
        else:
            assert st.query(l, r) == sum(a[l:r + 1])
    print("segment tree ok")
```

> [!WARNING]
> 懒标记是重灾区，三个最常见的错误：① 下推时孩子的区间长度算错——左右孩子的长度是 `m - l + 1` 和 `r - m`，不是对半；② 在「完全覆盖」分支忘了 `sum[o] += v * 长度`，只记了 lazy——欠条记了账，自己的账本却没更新；③ 递归孩子之后忘了用两个孩子重算 `sum[o]`。写线段树必须配一个暴力对拍，随机几千次操作逐一核对。

### 4.4 什么时候必须用它而不是树状数组

四种情形，树状数组无能为力或极其别扭，线段树是标准答案：

1. **信息不可减**：区间 max/min/gcd。树状数组的根基是 `prefix(r) - prefix(l-1)`，max 没有减法。
2. **合并操作自定义**：比如「区间最大子段和」——每个节点存 `(总和, 最大前缀和, 最大后缀和, 最大子段和)` 四元组，合并时用左右孩子的六个量拼出来。只要你能写出 merge 函数，线段树就能维护。
3. **区间赋值 / 区间覆盖**：懒标记的含义从「加多少」换成「赋成什么」，下推语义相应变化（见练习 4）。
4. **在线段树上二分**：比如「从头数第 k 个存活的位置」「第一个前缀和 ≥ x 的位置」——树状数组也能做二分（倍增走法），但线段树把它写成普通的树上下行。反过来，只要需求是「和 + 单点改」，用树状数组；「静态」需求，回第 2、3 节。

## 5. 稀疏表：静态区间最值的 O(1) 查询

线段树查一次区间最值是 O(log n)。如果数据完全静态、查询极其频繁（每秒百万次），连这个 log 都想省——稀疏表（Sparse Table，常称 ST 表）用 O(n log n) 的预处理换 **O(1) 查询**，代价是不支持任何修改。

### 5.1 可重复贡献：为什么 max 可以、sum 不行

核心是倍增预处理：`st[k][i]` 存「从 i 开始、长度 `2^k`」这段的最值，递推只要把两半的现成答案合并：

```text
st[k][i] = max(st[k-1][i], st[k-1][i + 2^(k-1)])
```

查询 `[l, r]` 时取 `k = floor(log2(r - l + 1))`，用**两个长度 `2^k` 的区间**从两头往中间盖：

```text
a = [5, 3, 8, 1, 9, 2]，query(0, 4) = max(a[0..4])

st[0]: [5]  [3]  [8]  [1]  [9]  [2]
st[1]: [5,3] [3,8] [8,1] [1,9] [9,2]     ← 每格 = 左右两半的 max
st[2]: [5,3,8,1]  [3,8,1,9]  [8,1,9,2]

长度 5 → k = 2：取 st[2][0]（盖 [0,4)）与 st[2][1]（盖 [1,5)）
两块重叠（a[1..3] 被算了两遍）——max 不在乎，sum 会翻倍
```

**两个块允许重叠**是 O(1) 的来源——不用精确拼接，随便盖两次就行。但它立刻要求聚合操作「可重复贡献（idempotent）」：`f(x, x) = x`。max、min、gcd 都满足（max(9, 9) 还是 9）；**sum 不满足**——重叠部分被加两遍，结果就错了。这正是「区间和有前缀和、区间最值有稀疏表」这种分工的深层原因：sum 有逆运算所以走前缀相减那条路，max 没有逆运算但幂等所以走重叠覆盖这条路。预处理 O(n log n) 时间与空间，查询 O(1)，永不修改——这是一份锁死的合同。

### 5.2 实现与对拍

```python
import random

class SparseTable:
    """静态区间最大值：O(n log n) 预处理，O(1) 查询，不支持修改。"""

    def __init__(self, a):
        self.n = len(a)
        self.log = [0] * (self.n + 1)          # log[i] = floor(log2(i))
        for i in range(2, self.n + 1):
            self.log[i] = self.log[i // 2] + 1
        self.st = [list(a)]                    # st[k][i]：[i, i + 2^k) 的 max
        k = 1
        while (1 << k) <= self.n:
            prev, half = self.st[k - 1], 1 << (k - 1)
            self.st.append([max(prev[i], prev[i + half])
                            for i in range(self.n - (1 << k) + 1)])
            k += 1

    def query(self, l, r):
        """闭区间 [l, r] 的 max：两个长度 2^k 的（可重叠）区间拼出 [l, r]。"""
        k = self.log[r - l + 1]
        return max(self.st[k][l], self.st[k][r - (1 << k) + 1])


if __name__ == "__main__":
    random.seed(7)
    for n in (1, 2, 3, 16, 40):
        a = [random.randint(-100, 100) for _ in range(n)]
        t = SparseTable(a)
        for l in range(n):
            for r in range(l, n):
                assert t.query(l, r) == max(a[l:r + 1])
    print("sparse table ok")
```

`log` 表预打出来是为了查询里不做浮点对数（浮点的 `log2(8)` 可能算出 2.9999，取整出错——经典边界 bug）。

### 5.3 与线段树的分工

| <br /> | 稀疏表                | 线段树            |
| ------ | ------------------ | -------------- |
| 查询     | O(1)               | O(log n)       |
| 修改     | 不支持（重建 O(n log n)） | O(log n)       |
| 空间     | O(n log n)         | O(n)（数组实现是 4n） |
| 操作集    | 仅幂等聚合（max/min/gcd） | 任何满足结合律的聚合     |

分工一句话：**只查不改 → 稀疏表；要改 → 线段树**。空间差距不是小事：10⁶ 个 8 字节值，稀疏表约 20 层、总共 160 MB 上下，线段树只要 32 MB——数据越大，这条越要先算。中间还有一种真实场景：查询频率不算极端（每秒千次），那 O(log n) 和 O(1) 的差别没有内存差别重要，用线段树反而对。

## 6. 分块：√n 的暴力美学

前面每个结构都在追求 log n，分块（sqrt decomposition）反其道而行：把数组切成约 √n 块，**整块记账、散块暴力**，单操作 O(√n)。它慢于树状数组和线段树，却几乎能支撑任意古怪的操作——很多「线段树写不出来」的题，分块是唯一能快速写对的答案。

### 6.1 整块记账，散块暴力

以「区间加 + 区间和」为例。块长 B，一次区间操作 `[l, r]` 拆成三段：左右两个散块（部分覆盖的块）逐元素处理，O(B)；中间整块打标记，O(n/B)。总代价 `O(B + n/B)`，由均值不等式，B = √n 时取到最小 `2√n`。量化感受一下：n = 10⁵ 时 B 取 316，一次操作约 632 次基本操作，而线段树约 34 次但每次带递归与下推——量级差 √n / log n ≈ 17 倍，这就是「慢但简单」的具体价格。

「整块记账」的正确性靠一个分层不变式：`a[i]` 存基础值，真实值 = `a[i] + 所在块的加标记`；块和数组维护块内基础值之和。任何操作要么只碰基础值并同步块和，要么只碰标记——两者不同时改，就不会乱。

### 6.2 区间加 + 区间和骨架

```python
import math
import random

class SqrtDecomp:
    """分块：区间加 + 区间和。块长 √n，单操作 O(√n)。

    a[i] 存「基础值」，真实值 = a[i] + badd[所在块]；
    bsum[bi] 是块 bi 内基础值的和（不含 badd）。
    """

    def __init__(self, a):
        self.n = len(a)
        self.bs = max(1, math.isqrt(self.n))           # 块长
        self.nb = (self.n + self.bs - 1) // self.bs    # 块数
        self.a = list(a)
        self.bsum = [0] * self.nb
        self.badd = [0] * self.nb
        for i in range(self.nb):
            self.bsum[i] = sum(self.a[i * self.bs:(i + 1) * self.bs])

    def add(self, l, r, v):
        """闭区间 [l, r] 整体加 v。"""
        bl, br = l // self.bs, r // self.bs
        if bl == br:                                   # 同一块：全暴力
            for i in range(l, r + 1):
                self.a[i] += v
            self.bsum[bl] = sum(self.a[bl * self.bs:(bl + 1) * self.bs])
            return
        for i in range(l, (bl + 1) * self.bs):         # 左散块
            self.a[i] += v
        self.bsum[bl] = sum(self.a[bl * self.bs:(bl + 1) * self.bs])
        for i in range(br * self.bs, r + 1):           # 右散块
            self.a[i] += v
        self.bsum[br] = sum(self.a[br * self.bs:(br + 1) * self.bs])
        for bi in range(bl + 1, br):                   # 中间整块：只记账
            self.badd[bi] += v

    def query(self, l, r):
        """闭区间 [l, r] 的和。"""
        bl, br = l // self.bs, r // self.bs
        if bl == br:
            return sum(self.a[i] for i in range(l, r + 1)) \
                + self.badd[bl] * (r - l + 1)
        s = sum(self.a[i] for i in range(l, (bl + 1) * self.bs)) \
            + self.badd[bl] * ((bl + 1) * self.bs - l)
        s += sum(self.a[i] for i in range(br * self.bs, r + 1)) \
            + self.badd[br] * (r - br * self.bs + 1)
        for bi in range(bl + 1, br):
            s += self.bsum[bi] + self.badd[bi] * self.bs
        return s


if __name__ == "__main__":
    random.seed(7)
    n = 100
    a = [random.randint(-50, 50) for _ in range(n)]
    sd = SqrtDecomp(a)
    for _ in range(800):
        l, r = sorted((random.randint(0, n - 1), random.randint(0, n - 1)))
        if random.random() < 0.5:
            v = random.randint(-9, 9)
            sd.add(l, r, v)
            for i in range(l, r + 1):
                a[i] += v
        else:
            assert sd.query(l, r) == sum(a[l:r + 1])
    print("sqrt decomposition ok")
```

> [!WARNING]
> 块长别拍脑袋。理论最优 √n，实际要按操作分布实测调整：散块操作占多数时块长该小些，整块操作占多数时可以大些。另一个隐蔽 bug 是最后一个块长度不足 B——切片时 Python 会自动截短，但「整块」循环里把块长当 B 用就会越界或算重（上面代码只在确认整块覆盖时才用 B，这是刻意的）。

### 6.3 万金油的含义与边界

分块真正的灵活性在于：**每个块内部可以放任何辅助结构**。区间最值——每块维护一个 max；「区间内小于 x 的个数」——每块存一个有序数组，整块二分、散块暴力，修改时重排所在块；甚至区间众数这种线段树很难定义合并的问题，分块加预处理也能做。它的角色是两面的：

- **兜底**：操作怪、时限松、或者赛场上懒标记写不对时，O(√n) 的方案总能救场。10⁵ 量级的 n 和操作数下，632 次基本操作对 C++ 毫无压力，对 Python 也要看常数，但至少量级是对的。
- **不为慢找借口**：操作集规整（纯和、纯最值）时，树状数组与线段树的 log n 比 √n 快一个量级以上，这时候分块只是偷懒。正确姿势是先判断操作集能不能被标准结构覆盖，不能，再上分块。

## 7. 布隆过滤器：用可控误判换内存

「这 10 亿个 URL 里爬过这个吗？」——用哈希集合存 10 亿个 URL，每个几十到上百字节，内存要几百 GB，直接超预算。布隆过滤器（Bloom filter）的回答是：**接受一个很小的误判率，把内存压掉一个数量级以上**。它回答的永远是二值问题「可能存在 / 一定不存在」，且误差是单向的。

### 7.1 机制与单向误判

结构简单到不像话：一个 m 位的位数组，k 个哈希函数。

- **插入**：把元素的 k 个哈希位置全部置 1。
- **查询**：k 个位置全是 1 → 「可能存在」；任何一位是 0 → 「**一定**不存在」。

误差方向由此决定。说「不存在」时，只要有一位 0 就否决了，而置过的位永远不会被清零，所以**绝不会漏报**；说「存在」时，k 个 1 可能只是历史上别的元素恰好把这几位都点亮了——**假阳性（false positive）可能发生**。这就是「存在可能是假、不存在一定真」的单向误判。任何「宁可错杀不可放过」的场景都吃这套语义：拦截一次多余的磁盘读、拦一次注定失败的数据库查询，错了也只是白跑一趟。

### 7.2 误判率与 m/n、k 的关系

一个位在被 k 次哈希点亮后仍为 0 的概率约为 `e^(-kn/m)`（k·n 次随机点亮撒进 m 个位，泊松近似），于是假阳性率：

```text
p ≈ (1 - e^(-kn/m))^k
```

对固定的 m/n 求最优 k（对上式求导令其为零），得 `k = (m/n)·ln 2`，代回去化简得 `p ≈ 0.6185^(m/n)`。直觉版本：每个元素摊到 `m/n` 个位——每元素 3.35 bit → 误判约 20%；9.6 bit → 约 1%；19 bit → 约 0.01%，误判率随内存**指数下降**。内存对比的实测数字：10⁶ 个整数的 Python `set` 实测约 59 MB（哈希表加 100 万个 int 对象），同样规模、1% 误判的布隆过滤器只要 `9.6 × 10⁶ bit ≈ 1.2 MB`——差 50 倍；换成字符串键差距更大（每个字符串对象还有几十字节的头部）。

### 7.3 实现与实测

```python
import math
from hashlib import md5

class BloomFilter:
    """布隆过滤器：可能误报「存在」，绝不漏报「不存在」。"""

    def __init__(self, expected, fp_target=0.01):
        n = max(1, expected)
        self.m = max(8, int(-n * math.log(fp_target) / (math.log(2) ** 2)))
        self.k = max(1, round(self.m / n * math.log(2)))
        self.bits = bytearray((self.m + 7) // 8)

    def _positions(self, item):
        """由一个 md5 摘要派生 k 个位置（双重哈希，省掉 k 次完整哈希）。"""
        if not isinstance(item, bytes):
            item = str(item).encode()
        h = md5(item).digest()
        h1 = int.from_bytes(h[:8], "big")
        h2 = int.from_bytes(h[8:], "big") | 1     # 奇数步长
        return ((h1 + i * h2) % self.m for i in range(self.k))

    def add(self, item):
        for p in self._positions(item):
            self.bits[p >> 3] |= 1 << (p & 7)

    def __contains__(self, item):
        return all(self.bits[p >> 3] >> (p & 7) & 1
                   for p in self._positions(item))


if __name__ == "__main__":
    n, probes = 20000, 20000
    print(f"{'m/n(bit/键)':>12} {'目标':>8} {'实测':>10} {'理论':>10}")
    for fp_target in (0.2, 0.1, 0.05, 0.01):
        bf = BloomFilter(n, fp_target)
        for i in range(n):
            bf.add(f"item-{i}")
        fp = sum(f"probe-{i}" in bf for i in range(probes)) / probes
        print(f"{bf.m / n:>12.2f} {fp_target:>8.2f} {fp:>10.4f} "
              f"{0.6185 ** (bf.m / n):>10.4f}")
        assert all(f"item-{i}" in bf for i in range(0, n, 997))  # 绝无漏报
        assert fp <= fp_target * 2
    print("bloom ok")
```

实测（20000 个键、20000 个未插入的探测串）：m/n 为 3.35、4.79、6.24、9.59 bit 时，实测误判率 0.2057、0.0969、0.0512、0.0097，与理论值 0.2000、0.1000、0.0500、0.0100 几乎重合——公式可以直接当设计依据用。实现里有两个值得学的细节：`k` 个位置由**一个 md5 摘要切两半做双重哈希（double hashing）**派生（Kirsch–Mitzenmacher 技巧，k 次完整哈希变 1 次），以及按目标误判率反推 m 和 k，而不是拍脑袋定大小。

> [!CAUTION]
> 布隆过滤器按「预估元素数」定容量：实际插入量超出预估，误判率就会显著上升且**无法挽回**（不能收缩重建而不丢数据）。它也不支持枚举——你无法从位数组里还原存过什么。误判不可接受的场景（扣款、封禁、安全判断）里，它只能做「快速排除」，最终判断必须回到精确结构。

### 7.4 为什么不能删除，以及真实用途

删除一个元素要把它 k 个位清零，但这些位可能同时属于别的元素——清零直接制造漏报，破坏「不存在一定真」的底线。需要删除时的标准替代是**计数布隆过滤器（counting Bloom filter）**：每个位换成 4 bit 计数器，删除就是减一。代价是空间×4，且计数器可能溢出（一个位被同一元素的不同哈希或大量元素反复命中），工程实现要带溢出处理。更现代的替代是布谷鸟过滤器（cuckoo filter），空间更省且支持删除，这里不展开。

真实系统里的位置：**缓存穿透防护**——查询一个根本不存在的 key，每次都打穿缓存砸到数据库，把全量 key 放进布隆过滤器，查询前先问一句，一定不存在的直接拒绝；**爬虫 URL 去重**——10 亿级 URL，精确集合存不起，1% 的重复抓取可以接受；**数据库读路径**——HBase、Cassandra、LevelDB/RocksDB 在每个数据文件上挂布隆过滤器，查询时先问「这个 key 可能不在这个文件里吗」，是则直接跳过该文件，省掉一次磁盘读。

## 8. 近邻速览：跳表与三件套

以下结构在本板块已有专篇讲透，这里只给坐标。

- **跳表（skip list）**：给有序链表加随机索引层，插入删除靠「抛硬币定层数」替代旋转，期望 O(log n)，范围遍历是纯链表扫描。第 [08 篇](08-bst-balanced-trees.md) 第 7 节有完整实现与 Redis zset 的选型分析。补充一个现实坐标：LevelDB 与 RocksDB 的 memtable（内存中待刷盘的有序表）默认也是跳表，理由与 zset 一致——范围遍历天然（flush 时按序倒出成文件）、实现简单无旋转、插入只在局部接线，配合引用计数可以支撑并发读。
- **堆（第 [09 篇](09-heap-priority-queue.md)）**：只承诺堆顶是最值、其余位置故意不排好，换来「反复取最值」与插入都是 O(log n)。TopK、多路归并、调度器、对顶堆求中位数，全是它的主场。
- **并查集（第 [11 篇](11-union-find.md)）**：只回答一个问题——「这两个元素在同一个等价类里吗」，配合路径压缩与按秩合并，单次操作摊还近 O(1)。连通性、等价类、Kruskal 最小生成树的判环，都是它。
- **Trie（第 [10 篇](10-trie.md)）**：让公共前缀只存一份，前缀存在性、自动补全、最长前缀匹配都是 O(L)。只要需求里出现「前缀」两个字，先想它。

## 9. 可持久化结构：把「版本」当结构的一部分

普通结构的心智模型是「一个随时被覆盖的当前状态」；可持久化（persistent）结构的心智模型是「一组带版本号的状态，每个都随时可读」。做法不神秘：**修改不再原地覆盖，而是把「被改动的路径」复制出来接到新版本上，其余节点两个版本共享**——这叫路径复制（path copying）。以「版本 3 把左子树 A 里的叶子 x 改掉」为例：新建根 R3，R3 指向「A 的副本 A'」和原样共享的 B；A' 里指向「x 的副本 x'」和原样共享的 y。被改动的只有 R3、A'、x' 三个节点，其余全部与版本 2 共享。

单点修改只影响 O(log n) 个节点，所以每个新版本只花 O(log n) 的空间，n 个版本总计 O(n log n)；任意版本的查询都是 O(log n)。这是可持久化线段树（俗称「主席树」）的全部原理，经典应用是「区间第 k 小」：对值域建可持久化线段树，第 i 个版本是「前 i 个元素」的计数，两个版本相减得到任意区间的分布，再顺着计数树下行。

关键直觉是**共享的前提是不可变**：一旦任何操作能原地改节点，共享它的所有版本都被污染。这也是可持久化与函数式编程同源的原因——不可变数据结构的每次「修改」天然产生新版本，Okasaki 的《Purely Functional Data Structures》把这条路走到了理论深处。工程中的对应物比想象的多：**Git 的对象模型**就是一个大规模持久化结构——blob/tree/commit 都是不可变的内容寻址对象，一次提交只新建「被改文件的 blob + 沿途的 tree + commit」，其余与历史共享，`.git` 体积的增长规律正是 O(改动量) 而非 O(仓库总量)；**编辑器的撤销栈**（每步记录受影响区域或命令）；**RocksDB 的 MVCC 快照**（LSM 树的文件不可变，读指定序列号即读到快照）。

什么时候不用：大多数工程场景要的只是「能撤销」或「能读历史」，此时**记录变更日志（命令模式、undo log、WAL、事件溯源）**比可持久化数据结构简单一个量级，也更好调试；需要整份快照且版本很少时，整份拷贝就行，别路径复制。只有「任意历史版本都要 O(log n) 随机访问」这种需求（编辑器的时间旅行调试、OJ 的区间第 k 小）才值得上真结构。写时复制（copy-on-write，COW）是同一个思想在系统层的化身——ZFS/BTRFS 的快照、进程 fork——代价也一样：读多写少时近乎免费，写一多，复制的开销就淹没一切。

## 10. 概率与近似结构：一族共同的取舍

第 7 节的布隆过滤器不是孤例，而是一个家族的成员。这个家族的合同完全相同：**用可控的（通常可配置的）误差，换数量级的内存与速度**；骨架也相同：哈希到统计量，误差随内存按 `1/√m` 或指数级收敛。

| 结构               | 估计什么              | 误差特征             | 典型场景         |
| ---------------- | ----------------- | ---------------- | ------------ |
| HyperLogLog      | 基数（不同元素个数）        | 约 1.04/√m        | 网站 UV 统计     |
| Count-Min Sketch | 元素出现频率            | 只会高估，不会低估        | 热点 key 检测    |
| MinHash          | 两个集合的 Jaccard 相似度 | 标准差约 √(J(1-J)/k) | 文档去重、相似用户    |
| t-digest         | 流式数据的分位数          | 两端极准，中段较粗        | P95/P99 延迟监控 |

各自一句话说透原理：**HyperLogLog** 利用「哈希值开头连续 0 的个数」——0 开头概率 1/2，00 开头 1/4……观察到最大前导零为 L，说明大概见过 2^L 量级的不同元素；m 个寄存器取最大，误差 `1.04/√m`，m = 2¹⁴ 个寄存器（每个 6 bit，共 12 KB）误差 0.81%，12 KB 数出数十亿的基数，Redis 的 `PFADD/PFCOUNT` 就是它。**Count-Min Sketch** 是 d×w 的计数器网格，d = ln(1/δ) 行哈希、w = e/ε 列，点查询取 d 行的最小值——哈希碰撞只会把计数加多，所以估计值 ≥ 真实值，标准用法是「估值超阈值才触发精确统计」。**MinHash** 用「两个集合的最小哈希值相等的概率恰好等于 Jaccard 相似度」，k 个独立哈希函数取平均就把相似度估出来。**t-digest** 把数据压缩成一串质心，压缩策略偏向两端，于是 P99 这种尾部分位数很准而中位数较粗——监控系统的延迟分位数基本都靠它或它的近亲。共同的使用纪律：大多不支持删除与精确枚举，误差是概率保证而非硬上界，上线前拿真实数据分布校准参数；而一旦数据规模让精确结构装不下，这个家族几乎是唯一出路——Kafka 的窗口统计、CDN 的热点缓存、安全设备的异常流检测，背后全是它们。

## 11. 空间索引：给「附近」建索引

一维世界的排序、二分、哈希，到了「附近的人」「这个矩形里有哪些门店」「哪些物体可能相撞」面前全部失效——「近」是二维、三维概念，B 树和哈希表都只有一维的钥匙。空间索引（spatial index）按数据形状分四个流派，选型口诀：点查附近 → 网格桶/Geohash；面与矩形的重叠、包含 → R 树；低维 k 近邻 → KD 树；碰撞检测 → 网格桶（宽阶段粗筛）加扫掠剪枝；能用一层格解决就别上树。

- **网格桶（grid bucket）**：把空间切成均匀格子，点落进 `O(1)` 定位的桶，「找附近」只查邻居桶。最简单，均匀分布下最有效。Geohash 是它的字符串化版本：经纬度反复二分成交错位串再 base32 编码，前缀相同 ≈ 地理相近（注意边界缺陷：格线两侧的两个点前缀完全不同）；Google 的 S2 用球面上的希尔伯特曲线做层级格子，Uber 的 H3 用六边形——六个邻居等距，而方格的四个角邻居距离是边邻居的 √2 倍，对「附近」这个语义六边形更均匀。
- **KD 树（k-d tree）**：交替按 x、y 维度切分的二叉树，低维（d ≤ 10 左右）的 k 近邻与范围搜索平均 O(log n)。**维度灾难**：维度上去后（约 d > 20），任何点的「近邻」都又多又远，剪枝失效，退化到接近线性扫描——高维场景直接暴力加向量化反而更快。
- **四叉树 / 八叉树（quadtree / octree）**：递归四分/八分空间，天然适配地图瓦片、LOD 与稀疏点集。
- **R 树（R-tree）**：不存点，存「包围盒的包围盒」，层级嵌套；面状数据（省份、商圈、矩形物体）的标准答案，PostGIS 的空间索引就是 R 树一族。

## 12. 选型方法论：先问操作集

把前面十几节的经验收拢成一套可执行的流程，三步：

**第一步，写下操作集。** 每种操作的种类与频率（点改还是区间改、查和还是查最值还是查存在性）、数据静态还是动态、在线还是离线（在线 = 每次更新后查询必须立刻反映最新状态；离线 = 可以读完所有数据再统一计算）、要精确还是可近似。这张清单写完，候选结构往往只剩一两个。

**第二步，找撑住操作集的最便宜结构。** 顺序是：标准库现成的（排序数组加 `bisect`、`dict`、`heapq`）→ 零结构方案（前缀和、差分、暴力加剪枝）→ 树状数组 → 线段树 → 分块。复杂度差一个 log，通常不如实现少一百行、少三类 bug。

**第三步，才轮到理论最优。** n = 10⁵、操作 10⁵ 的场景，O(√n) 与 O(log n) 在 C++ 里都能过，在 Python 里都可能悬——先按第 [01 篇](01-complexity-analysis.md) 的反推法定目标复杂度，再在达标方案里选实现成本最低的。

## 13. 小结

- 选型的主线是操作集决定结构：先列清操作种类、频率、静态或动态、在线或离线、精确或近似，答案常常唯一——且 90% 的场景前缀和与分块就够，先看数据规模定目标复杂度，再决定要不要请出本篇的任何结构。
- 前缀和与差分互为逆运算：静态区间和 O(1) 查询靠前者，批量区间加 O(1) 更新靠后者；共享的前提是数据基本不变。
- 树状数组用 `lowbit` 把前缀和拆成 O(log n) 个块的拼接：单点加与前缀和两条「跳着走」的路径；依赖加法可逆，所以做不了 max/min。
- 线段树是区间问题的通用后端：任何满足结合律的合并都能挂上去；懒标记用「欠条」把区间更新的代价从 O(n) 压回 O(log n)，写对它必须配暴力对拍。
- 稀疏表用「两个可重叠块」把静态区间最值的查询做到 O(1)，前提是聚合操作可重复贡献（max/min/gcd 可以，sum 不行）；空间 n log n 是它最大的账单。
- 分块以 O(√n) 换实现灵活：整块记账、散块暴力，块内可以放任何辅助结构，是写不动线段树时的正规兜底。
- 布隆过滤器的误差是单向的：不存在一定真、存在可能是假；`9.6 bit/键` 给 1% 误判，比哈希集合省一个数量级以上内存，但不支持删除（替代：计数布隆）。
- 概率结构家族（HLL、CMS、MinHash、t-digest）共用一份合同：可控误差换数量级的内存与速度；可持久化结构把版本当结构的一部分，但工程上多数「要历史」的需求用变更日志更划算。

## 14. 练习

**1.** 把差分推广到二维：给一个矩阵的子矩形 `(x1, y1)` 到 `(x2, y2)` 整体加 v，只允许 O(1) 完成，最后一次性还原整个矩阵。写出四个改动点与还原方法。

> [!TIP]
> 思路二维差分数组 d，四个点：`d[x1][y1] += v`、`d[x1][y2+1] -= v`、`d[x2+1][y1] -= v`、`d[x2+1][y2+1] += v`（行列各多开一位防越界）。还原对 d 做二维前缀和（先按行再做列，或一次二维递推），得到的就是加完后的矩阵。验证方式与一维相同：和暴力双层循环对拍。

**2.** 第 3.4 节说过「把差分数组放进树状数组」可实现「区间更新 + 单点查询」。更进一步，用**两个**树状数组实现「区间更新 + 区间求和」：区间 `[l, r]` 整体加 v，随时查询任意区间的和，两种操作都 O(log n)。推导需要的公式。

> [!TIP]
> 思路维护差分 d 与 `i·d[i]` 两个 BIT。区间加 `[l, r]` 加 v：BIT1 在 l 处 +v、r+1 处 −v；BIT2 在 l 处 +l·v、r+1 处 −(r+1)·v。查询前缀和：`sum(1..i) = (i + 1)·S1(i) - S2(i)`，其中 S1、S2 是两个 BIT 的前缀和。推导：`Σ a[i'] = Σ_{j≤i} d[j]·(i - j + 1)`，拆成 `(i+1)·Σd[j] - Σj·d[j]`。

**3.** 把第 4.3 节的线段树改造成支持「区间赋值 + 区间和」。懒标记的语义要怎么改？「先加后赋」与「先赋后加」如何处理？

> [!TIP]
> 思路标记改成赋值语义：完全覆盖时 `sum[o] = v × (r - l + 1)`、`lazy[o] = v`；下推时把孩子的 sum 设为 `v × 孩子长度`、孩子的 lazy 直接**覆盖**为 v——赋值会作废孩子原来欠的任何账。加法操作到达带有赋值标记的节点时，必须先 `_push_down` 把旧欠条结清再往下走，否则「先加后赋」的先后语义就乱了。最稳的写法是标记带类型位 `(type, v)`：下推时赋值类型覆盖孩子、加法类型叠加。写完必须对拍。

**4.** 稀疏表能维护区间 gcd 吗？说明理由并给出查询公式。区间「按位与」呢？

> [!TIP]
> 思路都能。gcd 幂等：`gcd(x, x) = x`，重叠区间算两遍不影响；查询公式与 max 完全一致：`gcd(st[k][l], st[k][r - 2^k + 1])`，`k = log[r - l + 1]`。按位与同理：`x & x = x` 幂等。对照第 5.1 节的框架：sum、乘积都不幂等，进不了稀疏表——但 sum 有逆运算（前缀相减），异或也有逆（自身），所以区间异或可以用「前缀异或相减」实现；乘积的前缀相除在元素可能为 0 时失效。「有逆」与「幂等」是两条独立的通道，稀疏表只吃后者。

**5.** 预计要存 10⁷ 个元素、要求误判率 1%，布隆过滤器的位数组要多大？哈希函数个数取多少？和存 10⁷ 个 32 位整数的精确哈希集合比，内存差多少倍？

> [!TIP]
> 思路`m/n = -ln(0.01)/(ln 2)² ≈ 9.59` bit/键，m ≈ 9.59 × 10⁷ bit ≈ 12 MB；`k = 9.59 × ln 2 ≈ 6.64`，取 6 或 7（7 更接近最优）。内存对比分两层：布隆每键约 1.2 字节，比最紧凑的精确结构（int32 数组，4 字节/键 = 40 MB）还省 3 倍多；比 Python set（第 7.2 节实测约 59 B/键）省约 50 倍。键是字符串时差距更大。

**6.** 设计「附近的人」：1000 万移动用户，随时查询「距我 1 km 内的其他用户」。为什么全网一棵 KD 树不是好答案？给出你的方案与查询流程。

> [!TIP]
> 思路用户位置持续变动，KD 树的删除重建成本高，且 1000 万点的在线 kNN 每次都要在全局结构上走一遍。方案：Geohash（6 位，约 1.2 km × 0.6 km 的格）做网格桶，用户按格分桶存哈希表；查询时算出自己的格，查它和 8 个邻居格（解决格线边界问题），再对桶内候选按直线距离精确过滤。更新（用户移动）只是两个桶的 O(1) 搬迁。格粒度按目标半径选，是典型的「用空间粒度换查询规模」。

**7.** 除了树状数组，归并排序也能 O(n log n) 数逆序对。说明归并的做法，并比较两种方法各自适合什么场景。

> [!TIP]
> 思路归并合并时，右半的元素出队说明它比左半剩余的所有元素都小，跨半逆序数 += 左半剩余个数，累加即可（这其实就是第 [14 篇](14-sorting.md) 归并排序的顺带产物）。比较：归并无需离散化、不受值域与负数影响、一次算出总数，离线场景首选；树状数组要离散化，但能在线插入、能回答「每个元素左边比它大的个数」这类逐元素中间结果，且天然适配「边扫描边统计」的流式场景。数据范围小（值域 ≤ 10⁶）时树状数组连离散化都省了。
