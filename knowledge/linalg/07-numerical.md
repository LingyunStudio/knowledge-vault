数学上等价的两个公式，浮点实现可能一个精确一个灾难——**数值计算研究的就是这个鸿沟**。它的两个核心概念必须分清：**条件数**（问题本身的敏感度——先天）与**算法稳定性**（求解方法的误差放大——后天）。[C 篇](../c/02-types.md)的浮点基础（IEEE 754、0.1+0.2≠0.3）在此升级到矩阵与算法层面。

## 1. 条件数：问题的先天敏感度

```text
条件数 κ(A) = ‖A‖·‖A⁻¹‖（方阵）—— 输入误差被放大的最大倍数

解 Ax=b：输入 b 的相对误差 ε → 输出 x 的相对误差最多 κ·ε
κ = 10：丢 1 位精度    κ = 10⁸：16 位有效数字只剩 8 位
κ → ∞：奇异（[第 3 篇](03-solving-systems.md)）
```

条件数是**问题的属性**（与用什么算法无关）——病态问题（κ 大）任何算法都无法完全救：「数据本身敏感，答案天然不可靠」。诊断：`np.linalg.cond(A)`——**κ > 1/ε（双精度 ~10¹⁶）时解基本是噪声**。病态的常见来源：特征尺度悬殊（[第 5 篇](05-eigen.md)练习）、近共线特征（[第 2 篇](../ai/02-linear-models.md)）、多项式基（Hilbert 矩阵）。

**病态的治理**是建模问题不是算法问题：**特征缩放/重新参数化/正则化**（截断 SVD、岭回归——[第 6 篇](06-svd.md)）——在「问题的表述」层面降低敏感度。

## 2. 灾难性抵消：相近数相减的陷阱

```python
# 经典案例：一元二次方程的求根公式
# x² - 10⁸x + 1 = 0 的两个根
import math
a, b, c = 1, -1e8, 1
x1 = (-b + math.sqrt(b*b - 4*a*c)) / (2*a)   # 1e8（正确）
x2 = (-b - math.sqrt(b*b - 4*a*c)) / (2*a)   # ❌ 0.0！真实根 ≈ 1e-8
# 根因：-b 与 sqrt(...) 几乎相等 → 相减抵消 → 有效位全丢

# ✅ 稳定写法：用韦达定理（两根之积 = c/a）算另一个根
x2 = c / (a * x1)                             # ≈ 1e-8
```

灾难性抵消的机制：**两个相近的数相减，结果的「有效位」只剩前导零**——浮点的相对精度在减法中蒸发。识别信号：公式里出现「相近数相减」。对策：**等价变形避开相减**（韦达定理/有理化/泰勒展开）。

```python
# 求和的顺序也有数值后果（[C 篇](../c/02-types.md)）：
sum([1e16, 1.0, -1e16])       # 0.0 —— 1.0 被 1e16 吞掉！
math.fsum([1e16, 1.0, -1e16]) # 1.0（精确求和：Shenstone/Kahan 类算法）
np.sum(arr)                    # numpy 成对求和：比朴素循环好，但 fsum 仍更准
```

「大数吃小数」的求和陷阱在大数据累加（[第 2 篇](../c/02-types.md)的 Kahan、[LLM 训练的 loss](../ai/05-nn-basics.md)）中真实存在——**求和顺序影响精度**不是学究问题。

## 3. 算法稳定性：方法的后天质量

```text
稳定算法：输入的小误差只引起输出的小误差（误差不放大）
不稳定算法：误差在算法步骤中被放大（如灾难性抵消、病态的中间量）

数学等价 ≠ 数值等价（[第 3 篇](03-solving-systems.md)的 inv 案例）：
inv(A)@b 与 solve(A,b) 数学同解，数值天差地别
```

| 数学形式                | 数值稳定形态                        | 原因                       |
| ----------------------- | ----------------------------------- | -------------------------- |
| `x = A⁻¹b`              | `x = solve(A, b)`（LU/QR）          | 不显式构造病态的逆          |
| 正规方程 `(XᵀX)⁻¹Xᵀy`    | QR 或 SVD 直接解 Xw≈y               | XᵀX 条件数平方化            |
| 手写 `sqrt`/级数        | 库函数（内部处理边界与抵消）         | 库做了误差控制              |
| `sum` 朴素累加           | `fsum`/成对求和/Kahan               | 误差不随 n 线性/平方增长    |

「先升宽再计算」的通用技巧（[第 2 篇](../c/02-types.md)）：中间结果用更高精度（float128/升宽整型），只在最终结果收窄。

## 4. 分解方法的选择表

```text
解 Ax=b：
  一般方阵 → LU（带部分主元）                —— O(n³)/2
  对称正定 → Cholesky                        —— 快一倍 + 正定性检验（[第 8 篇](../matlab/08-linear-algebra.md)）
  最小二乘 → QR                              —— 数值稳（[第 3 篇](03-solving-systems.md)）
  病态/需要诊断 → SVD（+截断=正则化，[第 6 篇](06-svd.md)）
  大型稀疏 → 迭代法（共轭梯度 GMRES）+ 预条件  —— O(nnz) 量级（[第 8 篇](../matlab/08-linear-algebra.md)）
特征值：
  一般 → QR 算法（np.linalg.eig）
  对称 → 更快的专用算法（eigvalsh）
  稀疏大矩阵 → Lanczos/ARPACK（eigsh，[第 8 篇](../matlab/08-linear-algebra.md)）
```

选择树的逻辑：**结构越好（对称/正定/稀疏）→ 越快越稳的专用方法**；通用兜底是 SVD（稳但贵）。迭代法的适用判据：**矩阵大到直接分解不可行 + 稀疏**——预条件子（preconditioner）是收敛的关键工程。

## 5. 陷阱清单

- 数学等价当数值等价：inv vs solve、正规方程 vs QR——每一步「重写」都要问数值后果。
- 不查条件数就信结果：κ 报告「答案的可信位数」；病态问题先改建模。
- 灾难性抵消不识别：相近数相减的公式形态；等价变形绕开。
- 浮点比较用 ==（[第 2 篇](../c/02-types.md)）：容差/isclose；矩阵用范数容差。
- 大量小数累加不关注顺序：fsum/成对求和/Kahan；分布式求和的树形聚合。
- 整数与浮点混算的意外：整除/溢出/精度混杂（[C 篇](../c/02-types.md)）。
- 迭代法不做收敛检查与预条件：「跑够多轮」是幻觉；残差范数是停止依据。

## 6. 小结

- 两层概念分清：**条件数 = 问题的先天敏感度**（病态要改建模）、**算法稳定性 = 方法的后天误差放大**（选稳定算法）。
- 灾难性抵消的识别（相近数相减）与对策（等价变形/升宽/库函数）。
- 分解选择树按「结构越好越专用」：LU/Cholesky/QR/SVD → 迭代法处理大型稀疏。
- 「数学等价 ≠ 数值等价」是贯穿纪律：每个数学公式的实现都问一句「数值上它稳吗」。
- 治理病态在建模层：缩放/重参数化/正则化——算法救不了问题本身的敏感。

## 7. 练习

**1.** 条件数实验：构造 κ=1/10⁴/10⁸/10¹² 的一系列矩阵（对角矩阵 diag(1, 10⁻ᵏ) 即可），解同一扰动水平的 Ax=b，画出「κ-解误差」曲线——验证「误差放大 ≈ κ」。

> [!TIP]
> 思路对角矩阵的 κ = 最大/最小对角元之比——可控的病态源。误差曲线的斜率验证「κ 倍放大」的理论——病态的可预测性由此建立。

**2.** 求根公式的两种实现：对一组「大系数」二次方程，用朴素求根公式与韦达定理修正版分别求双根，对比相对误差——定位灾难性抵消发生的根（大根 |x| >> 1 的那个减法）。

> [!TIP]
> 思路b>0 时用公式算的一个根必然经历相近数相减——判据是 b² >> |4ac|。韦达修复（x₂ = c/(a·x₁)）把减法变成除法——「等价变形」的范例。

**3.** 求和顺序实验：对 10⁸ 个随机数（正负混合），比较朴素顺序累加、numpy sum、math.fsum 的结果与「用更高精度算的参考值」的差异——量化三者的精度差距。

> [!TIP]
> 思路朴素累加的误差随 n 增长（随机游走式）、成对求和 ~log(n)、fsum 精确——「求和的数值学」在 loss 计算/统计聚合中直接相关。

**4.** 分解选择实践：同一个「对称正定」系统分别用 LU、Cholesky、SVD 解，对比耗时与误差；故意破坏正定性（改一个元素）看 Cholesky 报错——体验「结构检测」与「专用算法」的联动。

> [!TIP]
> 思路Cholesky 的报错本身是「正定性检验」（[第 8 篇](../matlab/08-linear-algebra.md)）——结构假设的违反被算法当场揭穿。「专用算法 = 更快 + 更多检查」。

**5.** 迭代法体验：构造一个 10⁴×10⁴ 的稀疏对称正定矩阵（scipy.sparse 的对角带），对比「直接分解（慢/爆内存）」与「共轭梯度（CG）」的可行性——理解「稀疏 + 迭代」的组合为什么统治大规模科学计算。

> [!TIP]
> 思路10⁴ 阶稠密分解 = 数百 GB 与 O(n³)；稀疏 CG 每步 O(nnz)、内存 MB 级。「直接法的 O(n³) 墙」由迭代法+稀疏结构翻越——预条件是收敛速度的钥匙。

**6.** 讨论：「数值稳定性」作为一等工程学科，为什么在「数学正确」之外仍不可省？从「浮点是有限的数学」「问题的敏感度不可消除」「算法选择是误差预算的分配」三个角度分析，并对照[传统软件测试](../python/12-quality.md)（确定性断言）与「数值代码测试」（容差+分布+参考解）的差异——数值代码的「测试文化」应该长什么样？

> [!TIP]
> 思路数值代码的测试三件套：参考解（高精度/解析解对照）、梯度检查（[第 5 篇](../ai/05-nn-basics.md)）、性质断言（残差/正交性/守恒量）。「断言相等」被「容差内的性质保持」取代——数值测试是「不变量测试」而非「值测试」。
