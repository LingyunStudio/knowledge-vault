计算机网络是"分层"思想最成功的工程实践：把"把字节从 A 送到 B"这件事，拆成各司其职的一叠协议。**每层只依赖下层提供的服务，只向上层提供服务**——学习、排障、设计，都从分层地图开始。

## 为什么分层

两个主机间的通信涉及物理介质、寻址、可靠传输、应用语义——揉在一起没人能维护。分层的本质是**关注点分离 + 标准接口**：链路换了 Wi-Fi 还是光纤，上层无感；应用换了网页还是邮件，下层无感。

OSI 七层是教学模型，工程上说的是 **TCP/IP 四层**：

| 层   | 职责          | 代表协议                 | 寻址单位   |
| --- | ----------- | -------------------- | ------ |
| 应用层 | 业务语义        | HTTP、DNS、SSH、TLS(半层) | 数据     |
| 传输层 | 端到端：进程到进程   | TCP、UDP、QUIC         | 端口     |
| 网络层 | 跨网：主机到主机、路由 | IP、ICMP              | IP 地址  |
| 链路层 | 同一网络内：跳到跳   | Ethernet、Wi-Fi       | MAC 地址 |

记忆钩子：**链路管一跳，网络管全程找路，传输管两端进程，应用管内容**。

## 封装：每层加一个信封

发送方向下走，每层把上层的整包当作自己的"载荷"，加上自己的头部：

```text
[应用数据]
[TCP头 | 应用数据]                ← 端口、序号
[IP头 | TCP头 | 应用数据]          ← 源/目的 IP
[帧头 | IP头 | TCP头 | 数据 | 帧尾] ← 源/目的 MAC
```

接收方向上走，逐层拆信封。**排障第一问就是"问题在哪一层"**：ping 通但网页打不开 → 链路/网络层健康，问题在传输或应用层；SSH 卡住 HTTP 正常 → 看端口、看防火墙规则，是传输层的事。

## 一次请求的完整旅程

浏览器输入 `https://example.com` 后发生的分层协作（后续文章逐个展开）：

1. **DNS**（应用层）：域名 → IP，缓存逐级查询（第 06 篇）
2. **TCP 握手**（传输层）：SYN → SYN/ACK → ACK，建立连接（第 03 篇）
3. **TLS 握手**：证书验证 + 密钥协商（第 07 篇）
4. **HTTP 请求/响应**（应用层）：发 GET，收 HTML（第 05 篇）
5. **IP 路由**：每一跳查路由表转发（第 02 篇）；ARP 把下一跳 IP 变 MAC（链路层）
6. 沿途 NAT 改写地址（第 02 篇），丢包靠 TCP 重传兜底

> [!TIP]
> 排障心法：**自下而上验证连通，自上而下怀疑协议**。先 ping（网络层）、再 telnet 端口（传输层）、再 curl（应用层）——哪一步开始断，问题就在那一层。

## 两个贯穿全板块的模型

- **端到端原则**：智能放在两端、网络保持简单——IP 层故意只做"尽力而为"，可靠性交给两端（TCP）。这个设计决策解释了互联网为什么能野蛮生长
- **尽力而为**：IP 不承诺送达、不承诺顺序、不承诺时限——所有"保证"都是上层花钱买的服务。理解了这两句，TCP 为什么那么复杂（第 03 篇）就有了答案
