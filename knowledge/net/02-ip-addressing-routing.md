IP 层的任务：**跨过任意多个网络，把包送到目标主机**。支撑它的是两样东西——全局唯一的地址体系（IP 地址），和逐跳决策的地图（路由表）。

## IPv4 地址：网络号 + 主机号

32 位地址（如 192.168.1.20），从来不是"一台机器一个数"那么简单：它的结构是**前缀（哪个网络）+ 后缀（网络里的哪台）**。前缀长度用 CIDR 记法表示：

```text
192.168.1.0/24   前 24 位是网络号 → 254 个可用主机位
/16 → 65534 台     /30 → 2 台（点对点链路的标准用法）

/24 掩码 255.255.255.0：IP & 掩码 = 网络号，判断"同网段"全靠它
```

**同网段直接投递**（ARP 找 MAC 直发）；跨网段交给**默认网关**——这是主机网络配置的本质：IP + 掩码 + 网关三件套。

## 私有地址与 NAT：一张卡养一屋设备

IPv4 只有约 43 亿个地址，不够分。方案是地址复用：保留三段私有网段（10/8、172.16/12、192.168/16），局域网内自由使用，出口由 **NAT（网络地址转换）**统一翻译：

```text
内网 192.168.1.20:54321 → 出口改写为 203.0.113.5:40001 → 服务器
回包按 (端口映射表) 反向改写回内网
```

NAT 缓解了地址枯竭，附带一个安全副作用：外网无法主动连入内网——顺带成了天然防火墙。代价是**破坏端到端**：P2P 打洞、服务器在内网要端口映射，全是 NAT 在"帮倒忙"。

## IPv6：根治方案

128 位地址（2001:db8::1），地址空间近乎无限，不再需要 NAT（端到端回归）、包头精简、内置 IPsec 支持。迁移慢的原因不是技术，是兼容成本：隧道与双栈（同时跑 v4/v6）过渡了二十多年。新部署应默认开启 IPv6。

## 路由：每跳一张表

路由器的工作：收到包 → 查路由表 → 转发到下一跳。匹配规则是 **longest prefix match（最长前缀优先）**：0.0.0.0/0（默认路由）、10.0.0.0/8、10.1.0.0/16 同时命中 10.1.2.3 时，选前缀最长的——**最具体的路由赢**。这就是 VPN/容器网络能"劫持"特定网段流量的原理。

路由表怎么来的：

- **静态**：人工配置（小网络、默认网关）
- **动态协议**：内网 OSPF（链路状态，全网拓扑算最短路——Dijkstra 的实战，第 ds 08 篇）、跨网 BGP（互联网骨干，靠策略与信任链，路由劫持的战场）

```bash
# Linux 看路由表
ip route show
# default via 192.168.1.1 dev eth0    ← 默认网关
# 192.168.1.0/24 dev eth0             ← 直连网段
```

> [!TIP]
> 排障三板斧：**ping 网关**（链路/内网通不通）→ **ping 8.8.8.8**（出口路由通不通）→ **ping 域名**（DNS 的问题还是路由的问题）。traceroute 看每一跳的 IP，能定位丢包发生在运营商哪一段。

## ICMP：IP 层的报务员

ping 用的是 ICMP Echo，traceroute 的原理更妙：发 TTL=1,2,3… 的包，**靠沿途路由器返回的"超时"报文（TTL 用尽）逐跳暴露路径**。ICMP 同时负责"目的不可达"等错误上报——它被防火墙一刀切禁掉时，排障就瞎了半只眼。
