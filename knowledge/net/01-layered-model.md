互联网是一个「横跨全球、由无数异构系统协作」的系统——它唯一可行的组织方式是**分层**：每层只解决一类问题、向上一层提供标准化服务、向下一层使用服务。分层的两个核心收益：**复杂度分解**（每层可独立理解与演进）与**互换性**（WiFi 换成以太网，上层协议完全不用改）。

## 1. TCP/IP 四层与 OSI 七层

| TCP/IP 层 | 职责            | 典型协议              | 寻址单位       |
| -------- | ------------- | ----------------- | ---------- |
| 应用层      | 为应用提供语义化服务    | HTTP、DNS、SSH、SMTP | 数据         |
| 传输层      | 进程到进程的传输（端口）  | TCP、UDP           | 端口 + 数据段   |
| 网络层      | 主机到主机的路由（跨网络） | IP、ICMP           | IP 地址 + 包  |
| 链路层      | 同一物理网络内的帧传输   | 以太网、WiFi、ARP      | MAC 地址 + 帧 |

OSI 七层是「教学细分」（在 TCP/IP 的应用层拆出表示/会话、链路层拆出物理）——**工程实践以 TCP/IP 四层为准，OSI 作词汇表**（「这是七层的问题」= 应用层）。

## 2. 封装：数据如何穿过各层

```text
发送方（逐层封装，每层加自己的头部）：
应用层：  [ HTTP 请求 ]
传输层：  [ TCP 头 | 数据 ]                    ← 加端口
网络层：  [ IP 头 | TCP 头 | 数据 ]             ← 加 IP 地址
链路层：  [ 帧头 | IP 包 | 帧尾 ]               ← 加 MAC 地址

接收方：逐层解封装（每层剥掉自己的头、向上递交）

每一层的「头部」就是该层协议的控制信息——
分层 = 数据被多层「信封套信封」
```

「抓包看分层」：Wireshark/tcpdump 抓一个 HTTP 请求，能看到完整的嵌套（以太网帧 → IP → TCP → HTTP）——**协议分层在抓包工具里是可见的物理结构**（[第 8 篇](08-troubleshooting.md)）。

## 3. 每层的关键问题与机制

| 层   | 核心问题              | 关键机制                      |
| --- | ----------------- | ------------------------- |
| 链路层 | 同一网段内怎么找到对方（物理地址） | MAC 寻址、ARP（IP→MAC 查询）、交换机 |
| 网络层 | 跨网络怎么路由（全球寻址）     | IP 地址、路由表、TTL、ICMP        |
| 传输层 | 进程到进程 + 可靠性/效率的取舍 | 端口复用；TCP（可靠）/UDP（轻快）二选一   |
| 应用层 | 业务语义              | 各协议自己定义（HTTP 的方法/状态码）     |

「端口」的语义（传输层的贡献）：**同一台机器的多个程序共用一个 IP**——端口是进程的地址（80=Web、22=SSH）。连接的完整标识是四元组（源 IP:端口 + 目的 IP:端口）——一台服务器能服务海量并发连接的原因。

## 4. 分层如何决定排障方法论

```text
分层排障（自底向上或自顶向下）：
「打不开网页」的逐层检查：
  链路层：网线/WiFi 连上了吗？（物理层信号）
  网络层：ping 网关通吗？ping 8.8.8.8 通吗？（IP 可达性）
  传输层：telnet 目标 443 通吗？（端口可达）
  应用层：curl -v 看响应（DNS/证书/HTTP 状态）
→ 每层用该层的工具验证该层的职责 —— 故障定位在「第一层失败处」
```

「分层排障」是 [linux 网络工具](../linux/08-network-remote.md)的组织逻辑：ping/ip（网络层）、ss（传输层）、curl（应用层）、dig（应用层的 DNS）——**每层有自己的工具族，按层定位而不是乱试**。

## 5. 端到端原则：互联网的设计哲学

```text
端到端原则：核心网络保持简单，智能放在端点（应用/主机）
  核心只做「尽力而为的包转发」——可靠性、加密、重试由端点负责
TCP 的可靠传输在端点（主机）实现、TLS 加密在端点实现、HTTP 语义在应用实现

收益：核心网络简单可扩展（不需要理解每个应用）；演进发生在端点（无需全网升级）
```

「尽力而为」的 IP + 「端点补齐可靠性」——这个哲学解释了互联网的结构性现象：**丢包是常态**（TCP 负责恢复）、**网络不保证顺序与时延**（应用层自己处理）、**中间设备（NAT/防火墙）只能看到它们所在层的信息**。

## 6. 陷阱清单

- 把 OSI 七层当工程现实：工程是 TCP/IP 四层；OSI 是词汇表。
- 混淆 MAC 与 IP 的角色：MAC 是网段内寻址（跳一跳换）、IP 是端到端寻址（全程不变——NAT 前）。
- 忘记端口是传输层的进程地址：「同一 IP 怎么有多个服务」的困惑。
- 排障不按层走：乱试工具；按层定位「第一失败层」。
- 以为网络可靠有序：IP 尽力而为——丢包/乱序/重复是 TCP 存在的理由。
- 忽视封装对 MTU 的影响：每层头部占用使「有效载荷 < 链路 MTU」——分片与 PMTU 问题。

## 7. 小结

- 分层的收益：复杂度分解 + 层间互换；TCP/IP 四层（应用/传输/网络/链路）是工程现实，OSI 是词汇。
- 封装 = 多层信封：每层头部是该层的控制信息；抓包工具里分层可见。
- 四层的核心问题：网段寻址（MAC/ARP）→ 全球路由（IP）→ 进程与可靠性（端口/TCP·UDP）→ 语义（应用）。
- 分层决定排障方法论：每层用该层工具验证该层职责，定位「第一失败层」。
- 端到端原则：核心简单尽力而为，智能在端点——丢包常态、可靠性靠 TCP、加密靠 TLS。

## 8. 练习

**1.** 用 Wireshark/tcpdump 抓一次网页访问，从抓包中「剥洋葱」：找到以太网帧头、IP 头、TCP 头、HTTP 内容——对照本篇的封装图逐层标注字段。

> [!TIP]
> 思路抓包的每个层字段（MAC、IP、端口、HTTP 方法）与本篇表格一一对应——「协议在电线上的样子」从此不再抽象。过滤表达式 `http` 聚焦应用层。

**2.** 分层排障演练（构造故障）：在虚拟机上依次制造——拔网线（链路）/错网关（网络）/目标端口未监听（传输）/应用异常（应用）——每种故障用「对应层的工具」定位，记录「每层工具与失败特征」对照表。

> [!TIP]
> 思路对照表：链路（ip link / 网线灯）、网络（ping 网关/远端）、传输（ss -tlnp + nc -zv）、应用（curl -v 看状态与内容）。四层四个工具、四个特征。

**3.** 端口与四元组实验：本机开两个监听同端口不同进程（如 127.0.0.1:8080 与 0.0.0.0:8080 的区别），用 ss 观察；再开两个终端连同一服务器端口，在服务器端 ss 看四元组的区分。

> [!TIP]
> 思路连接的区分靠四元组（不只是端口）——服务器 443 端口能同时服务千级连接。「一 IP 多服务」「一端口多连接」的机制都是四元组。

**4.** MTU 与分片实验：用 ping -M do -s 逐渐增大包尺寸找到链路 MTU（如 1500/1492）；理解 VPN overhead 导致的「有些网站打不开」（PMTU 黑洞）——分层头部占用与 MTU 的关系。

> [!TIP]
> 思路每次封装的头部（以太 14 + IP 20 + TCP 20）吃掉 MTU——有效载荷 < 1500。VPN 加封装头部 → 超过 MTU → 分片或丢弃（「能 ping 通但网站打不开」的经典）。

**5.** 协议族地图练习：把你日常使用的网络服务（网页/SSH/DNS/视频会议/文件同步）各映射到「传输层协议 + 端口 + 为什么选 TCP 或 UDP」——用「可靠性 vs 延迟」的取舍解释每个选择。

> [!TIP]
> 思路网页/SSH → TCP（要可靠）；DNS 查询 → UDP（快、重试即可）；视频会议 → UDP/RTP（要实时不要重传）；文件同步 → TCP。每个选择的理由都能追溯到「应用能容忍什么」。

**6.** 讨论：分层模型的「层间解耦」与「跨层优化」的张力——CDN/QUIC/代理服务器都在「打破分层」换取性能，为什么可以？从「分层的目的是管理复杂度而非教条」「同层语义的等价替换（QUIC 在 UDP 上重建传输层）」分析，并指出「跨层优化」的风险（[运维的耦合成本](../linux/11-ops-pitfalls.md)）。

> [!TIP]
> 思路QUIC = 「在 UDP 上重建传输层 + 内嵌 TLS」——绕过 TCP 的内核实现限制（部署新传输协议的自由）与握手合并的收益。打破分层的正当性：等价语义 + 明确收益 + 可控成本——分层的本质是「接口契约」而非「物理隔离」。
