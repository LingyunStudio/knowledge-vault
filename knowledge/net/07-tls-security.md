明文 HTTP 的世界，同一路由上的任何设备都能读你的数据、改你的响应。TLS（TLS 1.2 及以前的前身是 SSL）用**密码学 + 证书体系**把互联网变成端到端密文。本篇讲清两件事：握手如何建立信任与密钥，以及它防什么、不防什么。

## 混合加密：非对称发钥匙，对称送数据

非对称加密（RSA/椭圆曲线）安全但慢，对称加密（AES）快但需要先共享密钥。TLS 的组合拳：

1. **握手**：客户端验证服务器证书（信任问题，见下），双方协商出**会话密钥**
2. **传输**：全部数据用会话密钥做对称加密（AES-GCM/ChaCha20，附完整性认证 AEAD）

TLS 1.3 的改进值得点名：**只保留具备前向安全的密钥交换**（ECDHE，每次会话用临时密钥对）——即使服务器私钥日后泄露，历史会话也解不开；握手从 1.2 的 2-RTT 压到 **1-RTT**，加上会话复用可 0-RTT（有重放风险，只用于幂等请求）。

## 证书：信任的链式传导

"这真的是 example.com 吗"靠 **PKI 证书体系**回答：

```text
根 CA（操作系统/浏览器内置，信任锚）
  → 中间 CA（被根签名授权）
    → 站点证书（example.com，被中间 CA 签名）

验证：签名逐级向上验到根 + 域名匹配 + 有效期 + 未被吊销
```

浏览器地址栏的锁，意思是"**这条连接到你声明的服务器之间加密，且有个 CA 认可这个域名**"——它不保证服务器本身可信。工程要点：

- 全站 HTTPS + **HSTS**（强制浏览器后续只走 https，防降级劫持）
- 证书自动化（ACME/Let's Encrypt，90 天自动续期）——过期导致的宕机事故远多于密钥破解
- 证书透明度（CT）日志：所有签发公开可查，防 CA 乱签

## 它防什么，不防什么

| 威胁 | 机制 | TLS 防吗 |
| --- | --- | --- |
| 嗅探（读流量） | 加密 | ✅ |
| 篡改/注入 | AEAD 完整性 | ✅ |
| 中间人冒充 | 证书验证 | ✅ |
| DNS 劫持指向假站 | 依赖证书+域名核验 | ✅（假站拿不出有效证书） |
| 端点被黑/密钥泄露 | 超出网络层 | ❌ |
| 流量侧信道（包大小/时序） | 元数据泄露 | ❌ |
| 你把密码发给真站，站泄露 | 应用层问题 | ❌ |

> [!TIP]
> 中间人攻击（MITM）的现实入口是**信任根**：企业代理装根证书（DLP 审计就是这么"合法 MITM"的）、用户被诱导装根证书、恶意公共 Wi-Fi + ARP 欺骗。**证书校验失败绝不能点"继续访问"**——那个弹窗就是 TLS 在替你挡刀。

## 应用层常配的几个搭档

- **密码存储**：Argon2/bcrypt 慢哈希 + 盐——TLS 保护传输，哈希保护库被拖
- **JWT/Session**：认证凭据用签名（HMAC/RSA）防篡改；TLS 保护传输，签名保护内容真实性
- **内网也要 TLS**：零信任架构的前提——网络边界不再可信，服务间 mTLS（双向证书）是微服务通信的新默认（Istio 类网格的底座）

> [!NOTE]
> TLS 握手成本（1-RTT + 加解密 CPU）远低于想象——现代硬件上握手微秒级、对称加密几 GB/s，**"HTTPS 比 HTTP 慢很多"是十年前的刻板印象**。真正的性能坑是证书链不完整（客户端补链多一 RTT）和没开会话复用，是配置问题不是协议问题。
