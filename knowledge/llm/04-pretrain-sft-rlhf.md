一个可用的 LLM = **三段塑造**：预训练（pretrain）灌入知识与语言能力 → 指令微调（SFT）学会「按指令回答」→ 对齐（RLHF/DPO）学会「回答得符合人类偏好」。三段的成本比大约是 **100 : 1 : 1**（预训练吃掉绝大部分算力）——理解三段的不同，才能理解模型行为的来源与微调的边界。

## 1. 预训练：能力的灌注

```text
数据：数万亿 token 的互联网文本（网页/书籍/代码/论文）——自监督（[第 1 篇](01-what-is-llm.md)）
目标：下一词预测
产出：一个「博览群书但不会聊天」的基座模型（base model）
      —— 给它问题，它可能继续「编出更多类似问题」而不是回答！
```

**base 模型 vs chat 模型**的区分是使用者的第一课：base 模型是「补全器」——它的人生只有「预测下一词」；chat 模型 = base + SFT + 对齐。「模型不会回答问题」的错误通常是用错了 base 模型或 prompt 形态不对。

预训练的工程形态（[第 3 篇](03-transformer-llm.md)的显存账 × 数据管道 × 分布式）：数千卡数周到数月——**这是巨头与 labs 的游戏**；开源基座（Llama/Qwen/Mistral）的存在让「所有人从预训练起步」变得不必要。数据工程（清洗/去重/配比）是预训练质量的核心——「数据配比」（代码/多语言/数学的比例）直接影响能力面。

## 2. SFT：学会对话的格式与角色

```text
数据：几万到百万条「指令 → 高质量回答」对（人工撰写/模型蒸馏/人工筛选）
形态：<system> 你是助手 </system><user>问</user><assistant>答</assistant>
训练：仍然下一词预测（只对 assistant 部分算损失）——但数据形态变了
效果：模型学会「看到指令 → 给出回答」的格式与角色
```

SFT 的关键洞察：**模型在预训练已具备能力，SFT 教的是「激发与格式」**——指令数据像「唤醒指令」。数据质量的黄金律：**1 万条精标 > 100 万条噪声**（LIMA 论文的核心结论：对齐可能是「表层」的——少量高质量示例足以激发能力）。

SFT 数据的三个来源与陷阱：人工撰写（贵但高质量）、模型蒸馏（便宜但继承模型偏见与风格）、用户日志筛选（真实但要脱敏与审）。**数据多样性 > 数量**（任务覆盖广度）、「回答质量的一致性」决定模型风格。

## 3. RLHF：对齐人类偏好

```text
SFT 之后的问题：模型「会答」但答案的好坏（有用/诚实/无害）需要超越
  「模仿示范」的优化——示范只能给「标准答案」，给不了「偏好排序」

RLHF 三步：
① SFT 起点
② 训练奖励模型（RM）：用人类偏好排序数据（回答 A > 回答 B）训练打分器
③ 强化学习（PPO）：模型生成 → RM 打分 → 用分数作为奖励更新模型
   （让模型的输出分布朝「高奖励」方向移动）
```

RLHF 解决的核心问题：**「好答案」难以用文字示范但容易用偏好表达**——「更简洁、更诚实、更少废话」是排序而非规则。代价与复杂性：RM 可能被钻空子（reward hacking——模型学会讨好 RM 而非真变好）、PPO 训练不稳（RL 的老问题）。

**DPO（Direct Preference Optimization）**的简化：跳过 RM 与 RL，**直接用偏好对做分类式训练**（好答案拉高、坏答案压低）——效果接近 RLHF、工程简单一个量级，成为开源对齐的主流。

### 3.1 对齐的深层机制：「税与税后」

```text
对齐的「税」：对齐会轻微降低原始能力（过强的 RLHF 让模型保守/啰嗦）
对齐的「税后」：能力 × 可用性 —— 用户要的是可用的助手不是原始的补全器
税务规划：对齐强度、风格的调优（不同产品的「性格」由对齐数据决定）
```

「能力来自预训练、行为来自对齐」——这句话是微调决策的基石（[第 7 篇](07-fine-tuning-peft.md)）：**教知识/教领域风格 → 优先考虑 RAG/SFT 数据；改变行为/格式/安全边界 → SFT/DPO**。试图用对齐「灌知识」通常不如检索。

## 4. 训练资源的心账本

```text
预训练：万卡级 —— 巨头领域（开源基座替代）
继续预训练（domain adaptation）：百卡级 —— 领域语料继续灌（领域 LLM）
SFT：单机 8 卡可做 7B~70B（LoRA 更小）—— 团队可及
DPO：与 SFT 同量级 —— 团队可及
RLHF（PPO）：RM 训练 + RL 采样复杂 —— labs 为主

LoRA 的显存逻辑：冻结全参（不训权重不存优化器状态），只训低秩增量矩阵
  → 7B 全参 SFT 需 ~100GB、LoRA 只要 ~20GB（[第 7 篇](07-fine-tuning-peft.md)）
```

## 5. 陷阱清单

- 用 base 模型做对话（不会回答）：分清 base/chat/instruct 版本。
- SFT 数据堆量不堆质：噪声示范教出噪声行为；质量与多样性优先。
- 期待 SFT 灌知识（知识应该 RAG/预训练）：SFT 教格式与行为；知识灌入靠继续预训练。
- RLHF 的 reward hacking：RM 分数高 ≠ 真好；评测要看真实指标（[第 10 篇](10-deploy-engineering.md)）。
- 对齐税的无视：对齐后能力测评（别只看聊天体验）。
- DPO 数据的偏好对质量差（两个都差选一个）：偏好对要「真实的优劣差距」。
- 忘记只对 assistant 部分算损失（把 prompt 也当目标）：训练库的 loss mask 核对。

## 6. 小结

- 三段塑造的分工：预训练灌能力（自监督、算力大头）、SFT 教格式与激发（数据质量黄金律）、对齐塑行为（偏好表达优于规则示范）。
- base vs chat 的区分是使用第一课；SFT 的本质是「唤醒与格式化」而非灌知识。
- RLHF 用奖励模型 + PPO 优化「难以示范的偏好」；DPO 简化为偏好对分类——开源对齐的主流。
- 对齐税的权衡：能力 × 可用性——「能力来自预训练、行为来自对齐」是微调决策的基石。
- 资源心账本：预训练巨头游戏、SFT/DPO 团队可及、LoRA 显存逻辑（[第 7 篇](07-fine-tuning-peft.md)）。

## 7. 练习

**1.** base vs chat 实验找一个开源 base 模型与 chat 模型：同一 prompt（「什么是光合作用？」）对比输出——观察 base 的「续写问题」行为 vs chat 的回答行为；再用 few-shot 让 base 表现出回答形态（[第 5 篇](05-prompting.md)）。

> [!TIP]
> 思路base 模型在 few-shot 下也能「装出」对话——印证「SFT 是格式激发」。这个实验同时是 ICL（[第 1 篇](01-what-is-llm.md)）的复习。

**2.** SFT 数据质量实验：用 1k 条精写数据 vs 10k 条模型自产数据做 LoRA 微调（同一任务），盲评两版输出——验证「质量胜过数量」在你任务上的幅度。

> [!TIP]
> 思路「精写」的定义：多样任务覆盖 + 回答风格统一 + 无事实错误。蒸馏数据的系统性风格污染（[第 7 篇](07-fine-tuning-peft.md)的灾难性遗忘话题）是对照项。

**3.** 偏好对构造练习：为一个「回答啰嗦」的模型构造 DPO 数据对（chosen=精炼版、rejected=啰嗦版）×20 对，做一次 DPO 微调——对比对齐前后的回答长度与质量。

> [!TIP]
> 思路偏好对的「优劣差距要真实」（模型能看出差别）——构造时用「同一内容的不同表达」控制变量。DPO 的强度超参（beta）决定偏离幅度。

**4.** 错误的 loss mask 排查：微调后发现模型「学会了把用户的 prompt 也背出来」——检查数据构造的 loss mask（prompt 部分被算损失了）——这类「训练框架细节」的坑单靠调参救不了。

> [!TIP]
> 思路数据构造的检查：tokenize 后打印 token 与 label 的对齐——「label=-100（不计损失）」只应出现在非 assistant 部分。数据管道的验证（[第 8 篇](../ai/08-training-practice.md)的 batch 肉眼检查）在 LLM 微调同样铁律。

**5.** 对齐税测量：找一个模型的对齐前后版本（base vs instruct）在「知识问答基准」上的差异——量化「对齐税」的幅度，并讨论「为什么必须付」。

> [!TIP]
> 思路对齐税通常 1~5%（有用来换可用性）——过度对齐（拒答过敏/啰嗦）是可优化的税负。RM 的偏差与对齐数据的分布直接决定税率。

**6.** 讨论：为什么「RLHF 之后才有了 ChatGPT 时刻」——同样的 base 模型能力为什么在 2020 年没有引爆产品？从「能力与行为的差距」「交互范式的发现（对话即接口）」「对齐让能力可交付」三个角度分析，并思考「下一个类似的对齐级突破」可能在哪个维度（agent 行为？长程任务？多模态交互？）。

> [!TIP]
> 思路2020 年的 GPT-3 已有 ICL 能力——缺的是「把能力变成听话助手」的对齐与交互范式（InstructGPT, 2022）。技术引爆常发生在「能力已就绪、交付范式突破」的交叉点——agent（[第 9 篇](09-agents-tools.md)）正在复刻这个模式：能力（工具调用）已就绪，等待范式成熟。
