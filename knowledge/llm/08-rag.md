RAG（检索增强生成）用一句话定义：**回答之前先检索相关材料，让模型「看着材料说话」**。它解决 LLM 的三大固有局限（[第 1 篇](01-what-is-llm.md)）：私有知识（模型没见过）、知识更新（训练截止后）、可溯源（幻觉的解药）。RAG 是 LLM 应用架构的第一主角——而它的质量由**整条管线的最弱环节**决定。

## 1. 完整管线：五个环节

```text
离线（入库）：
文档 → ①分块（chunking）→ ②向量化（embedding）→ 向量库

在线（查询）：
用户问题 → ③检索（向量/混合）→ ④重排（rerank）→ ⑤生成（带材料的回答）
```

每个环节都有独立的决策与失败模式——**RAG 的效果诊断必须沿管线逐环节定位**（「答案不好」是五环节中哪个的问题？这是 RAG 调试的第一问）。

## 2. 分块：被低估的第一决策

```text
块太小：语义不完整（「这个方案」指的是什么？——上下文被切断）
块太大：检索粒度粗（相关内容与噪声混在一块）、稀释了嵌入向量
常见起点：256~1024 token，重叠 10~20%
```

分块策略的阶梯：**固定长度切（最简单）→ 递归按分隔符（段落→句子，主流）→ 语义分块（embedding 相似度断句）→ 文档结构感知（按标题/表格/代码块切）**。三个进阶技巧：

- **重叠（overlap）**：相邻块共享 10~20% 内容——跨块边界的句子不丢上下文。
- **父子分块**：检索用小块（精准）、生成喂大块（上下文完整）——检索粒度与生成粒度解耦。
- **元数据随块**：每块带来源（文件/标题/页码/日期）——过滤与引用的基础（第 6 节）。

## 3. 检索：向量 + 混合 + 重排

```python
# 向量检索：问题与块的 embedding 余弦相似度
results = vector_db.search(embed(query), top_k=20)

# ★ 混合检索：向量（语义）+ BM25（关键词）——互补的双路
# 向量擅长语义相似（"退货流程"≈"退款怎么做"）
# BM25 擅长精确匹配（产品名/型号/错误码——字面必须命中）
results = reciprocal_rank_fusion(vector_hits, bm25_hits)
```

向量检索的盲区：**专有名词/型号/代码标识符的语义模糊性**（"ERR_0x80070057" 的向量毫无意义）——**混合检索（向量 + BM25 关键词）**是生产标配。检索后的**重排（rerank）**：用交叉编码器（更准更慢）把 top-20 精排成 top-5——**「召回宽、精排准」的两段式**是质量与成本的平衡。

```text
检索质量的两个指标（[第 4 篇](../ai/04-evaluation.md)的 IR 语境）：
Recall@K：答案所在块被检回的比例（漏检 = 后面全白搭）
MRR/NDCG：正确块的排名（排名靠后 = 生成端吃不到）
```

## 4. Embedding 模型的选型与评测

```text
选型维度：
- 语言与领域匹配（中文任务用中文优化的模型；领域术语的表示质量）
- 维度与长度（嵌入维度 × 存储量；上下文上限决定块大小）
- 榜单（MTEB/C-MTEB）是起点，**自建评测是终点**

自建评测：收集「问题 + 已知正确块」的标注对
→ 测 Recall@K / MRR —— 换 embedding 模型就是跑一遍评测
```

embedding 模型的升级是 RAG 的免费午餐（换模型重建索引即可）——但**评测先行**：不同模型在不同领域/语言的表现差异巨大。索引的工程：向量库选型（Milvus/Qdrant/pgvector——规模与运维的权衡）、增量更新与删除（文档改了向量要同步）。

## 5. 生成端：让模型「照材料说话」

```text
生成 prompt 的关键要素：
1. 材料区隔：<context> 标签包裹检索结果（与指令分离，[第 5 篇](05-prompting.md)）
2. 引用要求：标注答案来自哪块（[1][3]）——可溯源防幻觉
3. 边界指令：材料中没有的信息回答「未找到相关材料」——不编造
4. 冲突处理：材料与常识冲突时以材料为准（或显式说明）
```

生成端的失败模式：**材料在上下文里但模型没照着说**（lost in the middle，[第 3 篇](03-transformer-llm.md)、材料冲突未处理、引用错位。上下文的组织顺序（相关块放头尾）与材料数量（5~10 块为宜——太多稀释注意力）是两个旋钮。

## 6. 高级形态：查询改写与多跳

```text
查询改写（query rewriting）：
  用户问模糊 → LLM 改写成检索友好的查询（"那个东西怎么弄" → "退款申请流程"）
  多轮对话 → 补全指代（"它怎么收费" → "X 产品的收费标准"）

元数据过滤：先按元数据（部门/日期/文档类型）过滤再向量检索
  —— "只搜 2026 年的合同"（纯向量检索做不到的精确性）

多跳（multi-hop）：答案需要串两次检索
  "A 公司 CEO 的母校排名" → 先查 CEO 是谁 → 再查母校排名
  → agent 式的循环检索（[第 9 篇](09-agents-tools.md)）
```

## 7. RAG 的评估：两层分开测

```text
检索层（先行）：golden 数据集（问题→正确块）
  Recall@K / MRR —— 检索不行，生成端无解
生成层（其后）：端到端答案评估
  忠实度（答案是否忠于材料——防幻觉）
  相关性（答案是否回应了问题）
  LLM 评分（用强模型判分）+ 人工抽检校准
```

诊断树：**「答案错」→ 先看检索（正确块检回了吗）→ 检索对就看生成（材料在上下文里但答错）**——两层分开评估才不会「调了检索怪生成、调了生成怪检索」。

## 8. 陷阱清单

- 「答案不好」不定位环节：五环节逐层诊断（检索先行）。
- 分块拍脑袋：块大小/策略是第一决策；父子分块解耦检索与生成粒度。
- 纯向量检索丢关键词命中：混合检索（BM25）标配——型号/错误码场景致命。
- 无重排：向量召回的 top20 噪声直达生成端；交叉编码重排提精度。
- embedding 模型不评测就换/用：自建 golden 评测集；语言与领域匹配。
- 引用与拒答缺失：幻觉的防线（材料外问题显式拒答）。
- 文档更新不同步索引：陈旧检索结果；增量索引管道（[第 9 篇](10-deploy-engineering.md)）。
- RAG 材料堆太多块：稀释注意力；5~10 块 + 重排精选。

## 9. 小结

- RAG 的定位：私有知识/时效/溯源三问题的架构解——「看着材料说话」。
- 管线五环节（分块→嵌入→检索→重排→生成）逐环节诊断；「答案不好」先问检索。
- 检索的组合拳：混合检索（向量语义 + BM25 字面）+ 重排（交叉编码精选）；分块的父子解耦。
- embedding 模型评测先行（golden 对 + Recall@K）；升级是免费午餐但必须回归。
- 生成端的纪律：材料区隔、引用标注、显式拒答——「忠实度」是 RAG 生成层的第一指标。

## 10. 练习

**1.** 分块消融实验：同一文档库用「128 token / 512 token / 父子分块」三方案建索引，用同一组问题测 Recall@5——找到你语料的最佳分块。

> [!TIP]
> 思路分块的最优点与文档结构强相关（FAQ 型 vs 长文型完全不同）——「结构感知分块」常胜过调参。评测集（问题→正确块）是本实验的前置投资。

**2.** 混合检索对比实验：构造「语义查询」（"怎么退钱"）与「关键词查询」（"ERR_0x80070057"）两组问题——对比纯向量/纯 BM25/混合的召回——验证两者的互补性。

> [!TIP]
> 思路预期：语义题向量赢、关键词题 BM25 赢——混合的 RRF 融合在两组都接近最优。「你的查询分布决定配比」。

**3.** 重排收益实验：top-20 向量召回直接喂生成 vs 加 rerank 取 top-5——对比端到端答案的忠实度与相关性评分——量化「召回宽+精排准」的收益。

> [!TIP]
> 思路重排的价值在「生成端的信噪比」：top-20 的噪声块稀释注意力（[第 3 篇](03-transformer-llm.md)）。成本换质量的典型交易。

**4.** 逐环节诊断实战：构造一个「故意失败的 RAG」（分块过小），用「检索指标 vs 端到端指标」的诊断树定位问题——训练「先检索后生成」的诊断直觉。

> [!TIP]
> 思路诊断记录：Recall@5 低（检索层问题）→ 修分块 → 检索指标升但答案仍差 → 检查生成 prompt（第二层问题）。两层指标分开看的纪律。

**5.** 引用与拒答实现：改造生成 prompt，要求「每个论断标注 [块号]、材料中没有则回复未找到」——构造「知识库外问题」测试拒答行为，统计幻觉率的前后变化。

> [!TIP]
> 思路拒答率与召回率的联动：检索失败时模型应该拒答而不是硬答——「检索置信度」传递给生成的接口设计（top 分数阈值）。

**6.** 讨论：RAG 与长上下文（直接塞整本文档）的竞争关系——长上下文降价后 RAG 会死吗？从「成本（token 计费 vs 检索毫秒）」「精度（lost in the middle vs 检索精准定位）」「时效与权限（增量索引/元数据过滤）」三个角度分析，并描述「长上下文 + 检索」的混合形态（检索选章节、整章进上下文）。

> [!TIP]
> 思路长上下文解决「窗口内一次性塞下」，但成本随 token 线性、精度受注意力稀释、权限过滤仍需检索。混合形态是赢家：检索缩小范围（哪些章节相关）→ 长上下文吃整章（上下文完整性）——检索的粒度从「块」升级到「章节」。
