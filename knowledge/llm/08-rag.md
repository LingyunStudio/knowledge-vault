模型的知识冻结在训练截止日，且不含你的私有数据。RAG（Retrieval-Augmented Generation）的思路直白有效：**回答前先从资料库检索相关片段，塞进上下文让模型"开卷作答"**。知识放在外部、随取随更新，不训练一个字。

## 流水线五步

```text
离线索引：文档 → 切块(chunk) → 嵌入(embedding) → 存入向量库
在线回答：用户提问 → 嵌入 → 相似检索 top-k → (重排) → 拼 prompt → 生成 → 带引用
```

```python
# 最小可用 RAG（示意）
from numpy import dot
def answer(question: str) -> str:
    q = embed(question)                                   # ① 问题变向量
    hits = sorted(chunks, key=lambda c: -dot(q, c.vec))[:5]  # ② 向量近邻
    ctx = "\n\n".join(f"[{i+1}] {c.text}" for i, c in enumerate(hits))
    prompt = f"仅依据以下资料回答，引用编号；资料不足则直说。\n\n{ctx}\n\n问题：{question}"
    return llm(prompt)                                    # ③ 生成
```

## 每一步都有坑：效果是"短板之和"

**1. 切块是第一杠杆。** 按固定 token 数切最省事，但常把语义切断。改进：按段落/标题切、加 10~20% 重叠、保留元数据（来源、标题、日期）。切块粒度决定检索精度上限——"查到"一个 3000 字的大块没有意义，答案要能被定位。

**2. 混合检索优于纯向量。** 向量检索擅长语义（"退货政策" ≈ "七天无理由"），但对**精确关键词**（型号、错误码、法规编号）不可靠——这些该走 BM25/关键词检索。两者并行、结果融合（RRF）是标准做法。

**3. 重排（rerank）性价比极高。** 初筛用轻量向量检索取 top-50，再用交叉编码器重排取 top-5：精排模型贵但准，两级漏斗兼顾成本与精度。**上下文塞 50 段不如精挑 5 段**——噪声片段直接拉低生成质量，还烧 token。

**4. 生成端要"强制开卷"。** 提示词必须写明：仅依据资料、逐条引用编号、资料不足就直说——否则模型会拿参数记忆里的旧知识"脑补"，RAG 退化成摆设。

> [!TIP]
> 评测 RAG 分两层看：**检索层**（该找到的片段在不在 top-k 里，recall@k）与**生成层**（答案是否忠实于片段、是否切题）。先看检索层——检索不到的东西，生成端神仙难救。

## RAG vs 微调 vs 长上下文

| | RAG | 微调 | 长上下文直塞 |
| --- | --- | --- | --- |
| 适合 | 知识频繁更新、可溯源 | 行为/格式/风格 | 一次性长文档 |
| 知识更新 | 秒级（改库即生效） | 重新训练 | 手动换上下文 |
| 可解释性 | 强（有引用） | 弱 | 中 |
| 成本结构 | 检索+每请求 token | 一次性训练 | 每请求 token 爆炸 |
| 风险 | 检索错→答错 | 遗忘/过拟合 | 中段遗忘、超限 |

三者是互补不是互斥：**RAG 供事实、微调定行为、长上下文兜底**。企业知识库问答的经典配方就是"微调过的领域模型 + 混合检索 + 重排"。

## 进阶方向

- **Agentic RAG**：让模型自己决定"查不查、查什么、查几轮"，多跳问题（A 依赖 B 依赖 C）按需迭代检索
- **GraphRAG**：把文档抽成知识图谱再检索，擅长"全局性"问题（总结关系、跨文档聚合）
- **缓存与降本**：高频问题的答案缓存、语义缓存（相似问题命中同一答案）
