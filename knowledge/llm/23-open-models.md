开源权重模型（open-weight models）是自托管与私有化部署的原材料（[第 20 篇](20-local-edge.md)）。这个生态的演化速度以「月」为单位——**家族画像与选型方法**比「记住某个模型」更长效。本篇的地域声明：具体型号与分数会过时，选型的**流程与判据**不会。

## 1. 主要家族画像

| 家族           | 出品方        | 性格与擅长                                                 |
| ------------ | ---------- | ----------------------------------------------------- |
| Llama        | Meta       | 生态最广（微调/量化/工具链最先支持）；英文见长                              |
| Qwen         | 阿里         | 中文最强梯队、尺寸谱系全（0.5B\~110B+）、多模态齐                        |
| DeepSeek     | 深度求索       | 推理与代码强、MoE 先锋、训练配方开源透明                                |
| Mistral      | Mistral AI | 欧洲代表、小模型效率高、Apache 友好                                 |
| Gemma        | Google     | 小尺寸质量好、与 Gemini 技术同源                                  |
| Phi          | Microsoft  | 小模型的「教科书质量数据」路线（合成数据[第 19 篇](19-data-engineering.md)） |
| GLM/-command | 智谱/Cohere  | 中文与企业服务                                               |

家族的「性格」由训练配方决定（[数据配比](../llm/19-data-engineering.md)、对齐风格）：**Qwen 的中文与工具调用、DeepSeek 的推理与性价比、Llama 的生态位、Phi 的小尺寸推理**——选型先按「语言/任务/尺寸」过滤家族，再看具体版本。

## 2. 尺寸谱系与任务匹配

```text
尺寸-能力的经验地图（同代模型粗略对照）：
  1~3B：分类/抽取/简单改写（手机端可跑 [第 20 篇](20-local-edge.md)）
  7~9B：日常助手/简单 RAG 生成/结构化抽取（单卡 24G 可微调）
  14~32B：复杂指令/多步任务/领域微调的甜点区
  70B+：接近旗舰的推理与知识（多卡部署）
  200B+/MoE：研究与企业旗舰（部署门槛 [第 3 篇](03-transformer-llm.md)）
```

| 任务           | 建议起步尺寸（经验值）                                  |
| ------------ | -------------------------------------------- |
| 分类/抽取/格式化    | 1.5\~7B                                      |
| RAG 生成/摘要/改写 | 7\~14B                                       |
| 复杂指令/多轮推理    | 14\~32B                                      |
| 数学/代码的深度推理   | 推理模型（[第 13 篇](13-reasoning-models.md)）或 32B+ |
| Agent 主脑     | 14B+（工具调用可靠性随尺寸显著提升）                         |

「尺寸匹配」的验证方法：**用你的评估集测三个候选尺寸**——任务质量随尺寸的收益曲线在某个点趋平（[第 15 篇](15-evaluation-systems.md)），那个点就是性价比甜点。

## 3. 变体的区分：base / instruct / reasoning

```text
同一家族的三种变体（[第 4 篇](04-pretrain-sft-rlhf.md)）：
  base：纯下一词预测的补全器 —— 给问题它可能续写问题
  instruct/chat：SFT+对齐后 —— 听指令、对话
  reasoning：RLVR 训练 —— 思维 token、复杂推理强（[第 13 篇](13-reasoning-models.md)）
```

变体选择的错误代价：**用 base 做助手**（输出续写而非回答）、**用 instruct 做需要长思考的任务**（无思维链能力）、**用 reasoning 做高吞吐简单任务**（成本翻倍）——[第 4 篇练习 1](04-pretrain-sft-rlhf.md)的实验验证过三种形态的行为差异。

## 4. 许可证对照（[第 20 篇](20-local-edge.md)的展开）

| 家族/模型       | 许可类型       | 商用     | 注意条款               |
| ----------- | ---------- | ------ | ------------------ |
| Llama       | Llama 社区许可 | ✅（有条件） | 月活 7 亿以上需另行授权；命名规范 |
| Qwen（多数）    | Apache 2.0 | ✅      | 部分旧版本/尺寸不同         |
| Mistral（多数） | Apache 2.0 | ✅      | ——                 |
| DeepSeek    | MIT（权重）    | ✅      | ——                 |
| Gemma       | Gemma 使用条款 | ✅（有条件） | 使用政策约束             |
| Phi         | MIT        | ✅      | ——                 |

许可证的核对清单（[第 20 篇](20-local-edge.md)）：商用允许、再分发、微调产物的许可继承、使用政策（acceptable use）的约束范围。**「开源权重」的许可差异是真实的商业约束**——同一个微调管线，换模型家族可能意味着换许可证审计。

## 5. 中文与多语言：一个真实的分化维度

```text
中文能力的梯队（按公开评测与社区共识的相对位置）：
  Qwen/GLM/DeepSeek 系（中文语料配比高、tokenizer 效率好 [第 2 篇](02-tokenizer-embedding.md)）
  > Llama/Gemma 系（中文可用但原生感弱）
tokenizer 效率的直接影响：同样的中文内容，
  中文优化模型的 token 数更少 → 成本更低、窗口更「大」（[第 2 篇](02-tokenizer-embedding.md)）
```

多语言场景的选型判据：**目标语言在训练数据中的配比**（model card 与 tokenizer 实测）——「英文评测分数高」不等于「目标语言任务强」。中文为主的部署，Qwen/DeepSeek 系是事实上的默认起点。

## 6. 正确读一次模型发布

```text
新模型发布的解读清单：
① model card：训练数据的时间截止/规模/配比声明
② 评测的「对照系」：与谁比、用什么 prompt、是否自评自家基准
③ 分数的口径：MMLU 的变体（5-shot？普鲁士版？）、代码评测的语言
④ 许可证：权重与使用政策的真实边界
⑤ 生态成熟度：vLLM/微调框架/量化工具的支持情况（发布 ≠ 可用）

务实流程：跑你的黄金评估集（[第 15 篇](15-evaluation-systems.md)）→
  对比 incumbent → 小流量试 → 决策。「榜单惊喜」必须经过自己的评估验证。
```

## 7. 陷阱清单

- 用 benchmark 排名选型：数据污染与任务错配（[第 15 篇](15-evaluation-systems.md)）；自己的评估集为准。
- 忽略变体形态（base/instruct/reasoning）：下载错版本的行为差异（[第 4 篇](04-pretrain-sft-rlhf.md)）。
- 许可证的侥幸（「先用了再说」）：商用条款的审计缺失；法务确认前置。
- 中文场景用英文中心模型：tokenizer 效率与中文能力的双重损失。
- 生态成熟度不查（新发布的模型微调/量化工具链不支持）：工程成本的隐性放大。
- 家族锁定（全链路绑定一个家族）：跨家族的评估与切换路径保留（[多模型抽象](10-deploy-engineering.md)）。
- 「最新 = 最好」：同家族不同尺寸/变体各有定位；你的评估集才是裁判。

## 8. 小结

- 家族画像：Llama（生态）、Qwen（中文与全谱系）、DeepSeek（推理与 MoE）、Mistral（效率）、Gemma/Phi（小模型）——性格由训练配方决定。
- 尺寸-任务匹配：1~~3B 分类、7~~14B 助手与 RAG、14\~32B 复杂任务、70B+ 近旗舰；用评估集找甜点。
- base/instruct/reasoning 三变体的行为差异是使用第一课；许可证（Llama 条款/Apache/MIT）是部署前提。
- 中文与多语言是真实的分化维度：tokenizer 效率与中文配比决定原生体验。
- 「正确读发布」：model card + 口径审视 + 自己的黄金集验证——榜单只是参考。

## 9. 练习

**1.** 家族盲评：把同一批任务（中英混合的对话/代码/抽取）发给两个不同家族的模型（相同尺寸档），盲评（不告知来源）打分——检验你对「家族性格」的感知与实际是否一致。

> [!TIP]
> 思路盲评的设计：去掉水印性特征（自我介绍）、同参数设置、随机顺序。结果常颠覆「名牌偏见」——评估的客观性来自盲测。

**2.** 尺寸-任务曲线：同一任务（如中文客服分类）用 1.5B/7B/14B/32B 同家族模型各跑评估集——画「尺寸-准确率-成本」曲线，找出你任务的甜点尺寸。

> [!TIP]
> 思路曲线的形态：小尺寸快速提升、大尺寸边际递减——甜点在「曲线拐弯处」。再叠加「量化版」的曲线（[第 20 篇](20-local-edge.md)），选型矩阵就完整了。

**3.** tokenizer 效率对比：同一段中文技术文档，分别用中英不同家族的 tokenizer 切分，统计 token 数与「语义单元的完整率」（有多少词被切碎）——量化「tokenizer 是模型的方言」（[第 2 篇](02-tokenizer-embedding.md)）。

> [!TIP]
> 思路实测方法：各家 tokenizer 可独立加载（transformers AutoTokenizer）。中文碎片率 = 非完整词的 token 占比——直接影响成本与模型对中文的「原生理解」。

**4.** 发布解读练习：找一个最近的开源模型发布（model card + 评测表），用第 6 节的清单「审计」它的声明——找出「评测口径、对照系、许可证」中值得警惕的点。

> [!TIP]
> 思路审计的警觉点：与自家基准比较（不可复现）、选择性报告（只报赢的任务）、缺少许可证细节。审计能力 = 「不被营销带节奏」的能力。

**5.** 跨家族微调对比：同一份 SFT 数据分别微调 Llama 与 Qwen（同尺寸档、同 LoRA 配置），盲评微调后的表现——验证「基座性格在微调后的残留」与「数据决定风格」的力量对比。

> [!TIP]
> 思路微调后两模型的「家族残留」（默认风格/语言倾向）仍可辨识——数据能塑造行为，但基座的底层倾向（[第 4 篇](04-pretrain-sft-rlhf.md)的能力来源）不完全可覆盖。选基座即选「起点倾向」。

**6.** 讨论：开源权重生态「快速收敛于少数家族」的现象（Llama/Qwen 系统治了微调生态）——从「生态复利（工具/微调配方/社区知识围绕头部家族累积）」「试错成本（冷门家族的问题排查成本）」「差异化模型的生存空间（领域特化/小语言）」三个角度分析「生态头部化」的机制，并评估「你的项目要不要用非头部家族」的决策框架。

> [!TIP]
> 思路头部化的机制：工具链优先支持头部（微调配方/量化/部署模板都是 Llama/Qwen 的）——非头部的隐性成本是「所有问题自己扛」。决策框架：头部家族无法满足的「差异化需求」（特定语言/极端效率/许可）才考虑非头部——并且要评估「你能否承受成为该家族生态的早期采用者」。
