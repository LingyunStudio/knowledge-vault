大语言模型（LLM）做的事情简单到令人困惑：**给定前面的文字，预测下一个词**。把这个「补全」训练在近乎整个互联网的文本上、把模型规模推到千亿参数，令人惊讶的事情发生了：模型不仅学会了语言，还学会了翻译、编程、推理、问答——**能力从简单的训练目标中「涌现」**。理解 LLM 的第一步是接受这个反直觉事实：没有一个模块叫「推理引擎」，全部能力都是「下一词预测」的副产品。

## 1. 下一词预测：唯一的训练目标

```text
输入：  "中国的首都是"
模型：  P(下一个词 | 前文)  →  "北京" 98%、"上海" 0.5%、...
训练：  海量文本的每个位置都在做这道题（自监督——不需要人工标注！）
       "中国的首都是北京" ← 这句话本身既是输入又是答案
```

自监督是 scaling 的前提：**互联网文本天然就是训练数据**（每个文档的每个词都是「答案」）——不需要标注成本，数据随规模增长。模型学到的隐含知识层层递进：语法 → 事实 → 推理模式 → 「世界如何运作」的压缩表示。

关键的心理模型修正：**LLM 不是数据库**（检索知识）也**不是规则引擎**（查逻辑）——它是一个「**对人类文本的概率分布建模的压缩器**」：训练把万亿 token 压进几十亿参数，推理是「在这个分布里采样」。这个视角解释它的强项（流畅/灵活/上下文学习）与弱点（幻觉/无保证/算术）。

## 2. 涌现与 Scaling Laws

```text
Scaling Laws（Kaplan/Chinchilla）：损失随「参数量 × 数据量 × 算力」的幂律平滑下降
涌现（emergence）：某些能力（多步推理/指令遵循）在小模型上接近零，
                  跨过某个规模后「突然」出现
```

两个概念的关系：**损失平滑下降，但下游任务的能力指标可能跃迁**（量变到质变——能力像「相变」）。Chinchilla 定理的工程结论：**给定算力，数据量与参数量应等比例放大**（早期模型普遍「参数过肥、数据不足」）——这直接塑造了后来「小而多数据」的模型路线（Llama 系）。

涌现的争议与务实态度：部分「涌现」是**度量方式的伪影**（多步推理任务只有全对才得分——平滑的进步在阶梯指标上看不见）。但对工程者，结论一致：**规模确实带来质变的能力，且不可从小模型外推**。

## 3. 能力地图

| 能力      | 说明                    | 来源                                                |
| ------- | --------------------- | ------------------------------------------------- |
| 生成与改写   | 流畅文本生成、风格转换、翻译        | 语言建模的核心                                           |
| 指令遵循    | 按人的指令行事（不继续「补全互联网文本」） | 后训练（SFT/RLHF，[第 4 篇](04-pretrain-sft-rlhf.md)）    |
| 上下文学习   | 看几个示例就会做新任务（不更新权重！）   | 训练分布里的「模式匹配」泛化                                    |
| 代码生成    | 编程是语言能力（代码语料占比高）      | 代码语料的意外收获                                         |
| 推理（CoT） | 分步推理显著提升准确率           | 思维链语料 + RL                                        |
| 工具使用    | 调用搜索/代码执行/API         | function calling 后训练（[第 9 篇](09-agents-tools.md)） |

**上下文学习（in-context learning, ICL）**是最奇特的能力：在 prompt 里给两个「英译中」示例，模型就学会了这个翻译任务——**权重完全没变**，行为从上下文「临时编程」。这使 LLM 成为「任务可编程」的通用接口（prompt 工程的本质，[第 5 篇](05-prompting.md)）。

## 4. 固有局限：设计的另一面

| 局限     | 根因                           | 对策                                        |
| ------ | ---------------------------- | ----------------------------------------- |
| **幻觉** | 下一词预测器「编造可信文本」是本职——它不知道「不知道」 | RAG（[第 8 篇](08-rag.md)）、引用、校验             |
| 知识截止   | 训练数据有时间边界                    | 联网检索、RAG                                  |
| 无状态    | 每次调用失忆（上下文窗口即全部记忆）           | 外部记忆/RAG（[第 8 篇](08-rag.md)）              |
| 算术不可靠  | token 化破坏数字的位结构              | 工具调用（计算器/代码，[第 9 篇](09-agents-tools.md)）  |
| 推理脆弱   | 表面模式可干扰（改个无关词答案就变）           | CoT/自洽性/验证器                               |
| 偏见与安全  | 训练数据的偏见继承                    | 对齐/护栏（[第 10 篇](10-deploy-engineering.md)） |

「幻觉」的正确心智：**模型不是在「撒谎」，而是在「生成最可能的文本」**——被问不知道的事时，它仍然生成「统计上最像答案」的内容。**把 LLM 放在「知识可信」的位置就是架构错误**——检索增强（给它真材料）与工具调用（让它算）是架构层的解法。

## 5. 把 LLM 当什么用：正确的心智模型

```text
✅ 好的心智模型：
   「一个博览群书、极其聪明、但没有你的私有知识、会自信地编造、
     需要明确指令与外部工具的实习生」
   → 给它上下文（RAG）、给它工具（agent）、验收它的输出（评估）

❌ 坏的心智模型：
   「一个知道一切的搜索引擎 / 一个总是正确的数据库 / 一个AI 天才」
   → 幻觉、过信、无验证的自动化
```

工程定位的三层：**LLM 是概率性的**（同输入不同输出——temperature 0 也受实现影响，测试要按分布设计）；**LLM 是可编程的**（prompt/上下文/工具是它的 API）；**LLM 是要监督的**（评估与监控不是可选项，[第 10 篇](10-deploy-engineering.md)）。

## 6. 陷阱清单

- 把 LLM 的输出当事实（无验证自动化）：幻觉是本质属性；关键决策必须有人审/有校验器。
- 期待「再问一遍就不幻觉」：重试不改变概率本质；换架构（RAG/工具）。
- 无状态误解（以为模型「记得」上次的对话）：上下文窗口才是记忆（[第 3 篇](03-transformer-llm.md)）。
- 算术/精确任务直接问模型：token 化破坏数字；用工具。
- 用「涌现」当不用小模型的借口：能力边界要实测——小模型 + 好 prompt/RAG 常够用（[第 7 篇](07-fine-tuning-peft.md)）。
- 忽视分布外的脆弱（训练没见过的输入形态）：边界测试（[第 10 篇](10-deploy-engineering.md)评估）。
- 把 temperature 0 当确定性的保证：浮点/批处理的非确定性仍在；严格复现需控制后端。

## 7. 小结

- LLM 的本质：自监督的下一词预测器——语法/事实/推理全部是压缩互联网文本的副产品；自监督让 scaling 成为可能。
- Scaling laws（幂律）+ 涌现（能力的规模跃迁）：规模带来质变；Chinchilla 定理塑造了「数据与参数平衡」的现代路线。
- 能力地图：生成/指令遵循/上下文学习/代码/CoT/工具——ICL 的「上下文临时编程」是 prompt 工程的理论基础。
- 局限的另一面：幻觉/知识截止/无状态/算术弱——架构层对策（RAG/工具/校验）而非 prompt 祈祷。
- 心智模型：「聪明但需要上下文与监督的实习生」——概率性、可编程、需监督三性质决定工程用法。

## 8. 练习

**1.** 幻觉实验：问一个模型「不存在的文献」（编造一个作者+论文名），观察它「一本正经」生成的引用——然后设计一个「拒答率测试集」（10 个不存在实体 + 10 个真实实体），测模型分辨力。

> [!TIP]
> 思路拒答测试的结果通常惨淡——「知道不知道」不是 LLM 的内建能力。这个实验是「为什么需要 RAG/引用校验」的第一手证据。

**2.** 上下文学习实验：不给任何微调，只在 prompt 里给 3 个「把产品名转成规范 ID」的示例，然后给新输入——观察模型是否学会你的私有格式。再试「示例改成 5 个」「加格式解释」看准确率变化。

> [!TIP]
> 思路ICL 的威力与局限：模式简单时几发示例够用（省微调）；复杂逻辑/大量知识时失效。ICL vs 微调的选型判据（[第 7 篇](07-fine-tuning-peft.md)）从这里建立。

**3.** 温度实验：同一 prompt 分别 temperature=0 与 1.0 各生成 10 次，统计输出多样性——再验证「temperature=0 也不完全确定」（同一模型不同 batch/后端的微妙差异）。

> [!TIP]
> 思路temp=0 的「贪心解码」仍有实现层面的非确定（浮点结合序/批处理）——「确定性」的工程定义要精确到后端（[第 6 篇](06-inference-decoding.md)）。

**4.** 无状态实验：两次独立会话问同一个私人问题（第一次告诉它、第二次再问）——验证「模型不记得」；再把上一轮对话贴进 prompt 验证「上下文即记忆」。

> [!TIP]
> 思路「记忆」的全部来源是上下文窗口与会话管理（应用层的责任）——对话历史的裁剪/摘要（[第 9 篇](09-agents-tools.md)的记忆管理）是应用架构的一部分。

**5.** CoT 对比实验：同一批数学应用题，「直接答」vs「请一步一步思考」——统计准确率差异并分析「哪些题 CoT 帮助最大」（多步 vs 单步）。

> [!TIP]
> 思路CoT 的收益集中在「需要中间步骤」的题（一步直答的题没有收益甚至更差）——「推理预算」与任务结构匹配（[第 5 篇](05-prompting.md)）。

**6.** 讨论：为什么「下一词预测」能涌现出推理等高级能力，而不是只会模仿？从「预测难例需要理解」（预测一段推理的结尾必须自己完成推理）的角度分析「训练压力迫使能力涌现」的机制，并讨论「压缩即智能」假说——对齐训练（[第 4 篇](04-pretrain-sft-rlhf.md)）在其中扮演的角色。

> [!TIP]
> 思路为了在「证明题」「代码续写」上预测准确，模型必须内化推理过程——压缩万类文本的压力迫使通用能力出现。「压缩即智能」：好的压缩器必须理解生成规则。对齐（RLHF）再把这些「原始能力」塑造成「服从人类意图」的行为——能力来自预训练、行为来自对齐。
