[RAG](08-rag.md) 的质量上限由检索决定——而检索的质量由 **embedding 模型**与**向量索引**决定。本篇下潜到这一层：embedding 模型是怎么训练的（理解它的能力边界）、三种检索架构的精度-速度账（选型）、向量数据库的索引内部（参数调优）、以及重排器的定位。

## 1. Embedding 模型是怎么训练的

```text
对比学习（contrastive learning, InfoNCE 损失）：
  正例对（query, 相关文档）拉近；负例对推远
  batch 内的其他样本就是天然负例（in-batch negatives）
  损失：让「正确文档的相似度」在 batch 内最高

难负例（hard negatives）是质量的关键：
  随机负例太容易（一眼假）——模型学不到细粒度区分
  难负例 = 「看起来相关但实际不回答问题」的文档（BM25 高分但不匹配）
  → 用第一阶段模型检索 top-k、排除真相关、保留「难分辨」的做负例
```

「难负例」的直觉值得展开：**embedding 模型的能力来自「学会分辨相似的假货」**——它的全部训练就是不断被喂「更接近的干扰项」。这解释了两个现象：为什么通用 embedding 模型在你的领域表现一般（它没见过你的领域的难负例）、为什么**领域微调 embedding 模型**（用你的领域难负例做对比训练）收益显著。

现代 embedding 的另一要素：**指令化（instruction-tuned）**——查询侧带任务指令（「为这个问题找相关文档：…」），文档侧不带——同一模型可服务不同任务（检索/聚类/分类）。还有**长文本支持**（Matryoshka + 长上下文编码器）。

## 2. 三种检索架构：精度-速度的账

```text
① 双塔（bi-encoder，标准 embedding 检索）：
   query 与文档分别独立编码 → 余弦/点积比较
   文档可离线预计算 → 检索 = 向量库 ANN 查询（毫秒、百万级）
   精度上限：query 与文档「不相交地」编码——细粒度交互丢失

② 交叉编码（cross-encoder，重排器）：
   query 与文档拼成一个输入 → Transformer 联合编码 → 直接输出相关分
   精度最高（全交互）—— 但每个 (query, doc) 对都要跑一次模型 → 无法预计算
   用途：只能做「重排」——对 top-k 精排（[RAG](08-rag.md)）

③ ColBERT / late interaction：
   文档的「每个 token」都预计算向量（多向量）
   查询时：query 的每个 token 与文档 token 做 MaxSim 再求和
   精度接近交叉编码、速度接近双塔之间 —— 存储成本高（多向量）
```

| 维度   | 双塔      | ColBERT（late interaction） | 交叉编码    |
| ---- | ------- | ------------------------- | ------- |
| 精度   | 基线      | 接近交叉编码                    | 最高      |
| 查询速度 | 最快（ANN） | 中（多向量计算）                  | 慢（逐对计算） |
| 索引存储 | 1 向量/文档 | 多向量/文档（大）                 | 无（实时算）  |
| 角色   | 第一阶段召回  | 精排或主力检索                   | 最终精排    |

生产管线「双塔召回 → 交叉编码精排」的两段式（[RAG 第 4 节](08-rag.md)）——ColBERT 是「想要交叉编码精度又嫌全量太贵」的中间选项。

## 3. Matryoshka 嵌入：一个向量多种分辨率

```text
Matryoshka Representation Learning（MRL）：
  训练时让「向量的前 k 维」本身就是一个可用的低维嵌入
  → 同一个 1024 维向量可以截断成 512/256/64 维使用
  截断损失少量精度、节省大量存储与计算

工程用途：
  粗排用短向量（快）、精排用全长（准）—— 两阶段检索免费获得
  存储分层：冷数据存短向量、热数据存全长
```

MRL 的思想与 [SVD 的低秩近似](../linalg/06-svd.md)同源：**信息按重要性排序地压缩**——前 k 维承载大部分语义。选用支持 MRL 的模型（如 OpenAI text-embedding-3、nomic）可免费获得「精度-成本」的运行时旋钮。

## 4. 向量数据库的索引内部

```text
ANN（近似最近邻）的三大索引家族：
① HNSW（分层可导航小世界图）：
   多层图结构：上层稀疏（长边快速导航）、下层稠密（精确）
   查询：从顶层贪心下降到底层 —— O(log n) 级
   参数：M（每节点连接数）↑召回↑内存↑；ef_search（候选队列）↑召回↑延迟↑
② IVF（倒排文件）：
   先把向量聚成 N 个簇（k-means）；查询先找最近的 nprobe 个簇、簇内精确比较
   nprobe 越大召回越高速度越慢
③ PQ（乘积量化）：
   向量切成子段、每段量化成码本索引 —— 大幅压缩存储（有精度损失）
   常与 IVF 组合（IVF-PQ）：十亿级向量的存储方案
```

| 索引       | 召回率  | 速度      | 内存   | 适用            |
| -------- | ---- | ------- | ---- | ------------- |
| HNSW     | 高    | 快       | 大（图） | 默认选择（中小规模）    |
| IVF      | 中    | 快       | 中    | 大规模、可调 nprobe |
| IVF-PQ   | 中低   | 快       | 极小   | 十亿级、容忍精度损失    |
| 暴力（FLAT） | 100% | 慢（O(n)） | 小    | 小数据集/精确性刚需    |

工程要点：**召回率的验证**——「ANN 的近似的代价」要用「暴力搜索的对照集」测量（top-10 的重合率），召回不达标先调 ef\_search/nprobe，再考虑换索引。**过滤**（元数据过滤：租户/日期）的实现差异巨大——「先过滤后检索」（pre-filtering，向量库原生）与「先检索后过滤」（后过滤可能过滤到空）的语义与性能不同——过滤是 [RAG 元数据](08-rag.md)的正确姿势。

## 5. 重排器的家族与选型

```python
# 交叉编码重排（[第 8 篇](08-rag.md)的展开）
from sentence_transformers import CrossEncoder
reranker = CrossEncoder("BAAI/bge-reranker-v2-m3")
scores = reranker.predict([(query, doc) for doc in top_50])
top_5 = rank_by(scores)[:5]

# 家族：
# 交叉编码器（bge-reranker / jina-reranker）：精度高、逐对计算
# ColBERT 式：late interaction，可索引、快于交叉编码
# LLM 重排（用 LLM 判断相关性）：最贵、上下文理解最强
# LLM listwise：把 top-k 一起给 LLM 排序（感知全局）
```

重排的选型判据：**候选集大小与延迟预算**——top-50 精排用交叉编码（几十毫秒级）；更大候选集或更高精度要求用 ColBERT/LLM 混合。重排器的评估与 embedding 同法（golden 对 + NDCG）。

## 6. 评测：检索质量的纪律

```text
检索评测的标准集：
  MTEB（Massive Text Embedding Benchmark）：多任务公开基准
  自建集：你的领域「query → 正确文档」对（[RAG 评估](08-rag.md)）

指标：
  Recall@K：正确文档进前 K 的比例（K = 你喂给生成的块数）
  MRR / NDCG@K：排名质量
  端到端联动：检索指标的提升要传导到「生成答案质量」的验证（[第 15 篇](15-evaluation-systems.md)）
```

「换 embedding 模型」的完整流程：自建评测 → 候选模型跑分 → 重建向量索引 → 端到端回归（[第 8 篇](08-rag.md)）——embedding 是 RAG 的「地基更换」，动它必须全套验证。

## 7. 陷阱清单

- 难负例缺失的训练（随机负例的对比学习）：模型学不到细粒度区分；领域微调配难负例。
- 用余弦相似度当「语义真理」：模型/领域的相对性（[LLM](../llm/02-tokenizer-embedding.md)）；评测先行。
- ANN 召回率不验证：召回损失静默发生；暴力对照集定期校准。
- ef\_search/nprobe 用默认值跑生产：召回-延迟的旋钮要按 SLA 调。
- 后过滤的语义陷阱（先 ANN 后过滤可能过滤到空）：pre-filtering 的向量库能力。
- 维度即正义（维度高=好）：MRL 与压缩的实践说明「合适的维度」优于「最大的维度」。
- 重排只对 top-k 做、召回端从不看：Recall@大K 的天花板先查。
- 多语言语料用单语模型：跨语言检索的召回崩塌；多语言模型（bge-m3 类）。

## 8. 小结

- embedding 训练 = 对比学习 + 难负例——「分辨相似的假货」的能力边界由训练分布决定；领域微调收益大。
- 三架构的精度-速度账：双塔（召回）/ColBERT（中）/交叉编码（精排）——两段式「召回宽+精排准」是生产标配。
- Matryoshka = 向量的多分辨率：粗排短向量、精排全长——免费的两阶段。
- 向量索引的参数（ef\_search/nprobe）是召回-延迟的旋钮；pre-filtering 是元数据过滤的正确语义；IVF-PQ 服务十亿级。
- 检索评测（Recall\@K/MRR/NDCG）是 RAG 的「上半场记分牌」——换 embedding/索引必须全链回归。

## 9. 练习

**1.** 难负例的威力实验：用随机负例 vs BM25 难负例各训练一个小 embedding 模型（sentence-transformers 的训练 API），在你的领域测试集上对比 Recall\@10——量化难负例的贡献。

> [!TIP]
> 思路难负例的来源：用第一阶段模型的 top 检索结果去掉正例。对比实验的差距通常显著——「embedding 的能力来自分辨近似干扰」的直接验证。

**2.** 索引参数扫描：对一个 100 万向量的 HNSW 索引扫描 ef\_search ∈ {16, 64, 256, 1024}，画出「召回率（对照暴力搜索）-查询延迟」曲线——找到你 SLA 的操作点。

> [!TIP]
> 思路曲线的形态：召回快速上升到平台、延迟线性上升——SLA（P99 延迟上限）反推 ef\_search。不同索引类型（IVF 的 nprobe）同款实验。

**3.** ColBERT vs 双塔 vs 交叉编码的三方对比：同一查询集与文档集，对比三架构的 Recall\@10、NDCG、单查询延迟——画出「精度-速度」散点图，标注三种架构的位置。

> [!TIP]
> 思路预期：双塔最快最糙、交叉编码最准最慢、ColBERT 在中间偏准。散点图上「你的延迟预算」画一条竖线——线右边的架构才是候选。

**4.** MRL 截断实验：用支持 MRL 的 embedding（1024 维），分别截断到 64/256/1024 维建索引，对比检索召回与存储/延迟——验证「前 k 维承载大部分语义」并找到你的截断点。

> [!TIP]
> 思路MRL 的截断在中小规模收益不明显（本来就不大）、大规模（亿级）时存储与延迟的节省可观。「维度」是成本方程的变量而非性能指标。

**5.** pre-filtering vs post-filtering 实验：带元数据（category）的数据集上，查询「category=A 且语义相关」，分别用向量库的 pre-filter 与「检索 top-100 后过滤」实现——对比结果集与延迟，构造「post-filter 结果为空」的失败案例。

> [!TIP]
> 思路失败机制：post-filter 在「语义近但 category 错」的文档占满 top-k 时，过滤后为空——pre-filter 在 ANN 搜索时带过滤条件（Qdrant/HNSW 的 filtered HNSW）。「过滤语义」是向量库选型的检查项。

**6.** 讨论：「embedding 模型」与「LLM」的训练目标不同（对比判别 vs 下一词生成），但现代两者在趋同（LLM 的表示可以做检索、embedding 模型在生成化）——从「表示学习的统一趋势」分析两种模型最终会合还是分工？结合 [GenAI 检索的实践判断](08-rag.md)（embedding 索引 vs LLM 重读全库），给出你对「检索的未来」的判断。

> [!TIP]
> 思路趋同的证据：LLM 的上下文学习可以「零样本检索」（prompt 里给文档判断相关性）、embedding 模型在指令化。但「亿级文档的检索」在算力上不可能每次跑 LLM——双塔的效率地位长期存在。判断：「专用 embedding 做第一道漏斗 + 生成模型做最终判断」的分层长期成立——效率分层是物理约束。
