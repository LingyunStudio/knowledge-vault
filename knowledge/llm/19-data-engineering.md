数据工程的地位一句话：**模型能力的上限由数据决定，训练算法只是逼近这个上限**。同样是 7B 模型，数据管线的质量差异能造成碾压级的最终差距——「数据是新的代码」意味着数据工程需要与[软件工程](../python/12-quality.md)同级的纪律：版本化、测试、可追溯。

## 1. 预训练数据管线：五道工序

```text
万亿 token 的数据流水线：
① 获取：网络爬取（CommonCrawl 等）/授权语料/代码/书籍
② 提取：HTML → 纯文本（去广告/导航/模板噪音）
③ 语言识别与过滤：fastText 分类器/启发式
④ 去重：精确 + 近似（本篇核心，第 3 节）
⑤ 质量过滤：启发式规则 + 模型打分

每道工序都是「过滤器」——上一道的质量决定下一道的上限。
FineWeb/The Pile 等公开数据集的文档是这条管线的公开参考实现。
```

「提取」是被低估的工序：**HTML 里 90% 是导航/广告/模板**——提取器的质量（正文识别）决定「语料的信噪比」；提取失败的样本不是「空白」而是「乱码噪音」——比缺失更毒。

## 2. 去重：最重要的单一工序

```text
为什么去重至关重要：
① 效率：重复样本浪费算力（模型反复学同一内容）
② 泛化：重复让模型「记住」而非「泛化」——记忆放大
③ 污染：基准题目重复出现 → 评测虚高（[数据污染](15-evaluation-systems.md)）

两级去重：
精确去重：哈希完全相同的文档 —— 便宜、先做
近似去重：MinHash-LSH —— 「高度相似但不完全相同」的文档
  MinHash：用多个哈希函数把文档签名成短指纹；相似文档的签名相似
  LSH（局部敏感哈希）：把签名分桶，只有同桶的才做精细比较 —— O(n) 级近似
```

```python
from datasketch import MinHash, MinHashLSH

def minhash_sig(text, num_perm=128):
    m = MinHash(num_perm=num_perm)
    for word in text.split():
        m.update(word.encode("utf8"))
    return m

lsh = MinHashLSH(threshold=0.8)
for doc_id, text in corpus:
    sig = minhash_sig(text)
    if lsh.query(sig):                       # 与已有文档高度相似 → 重复
        continue
    lsh.insert(doc_id, sig)
```

去重的力度权衡：**去得太狠丢信息**（合法的重复——FAQ、常用代码模板被误删）、**去得太松记忆放大**——阈值与粒度（文档级/段落级）是工程决策。模板去重（同一模板的数千个实例——导航页/日历页）是独立的一类（精确识别模板结构）。

## 3. 质量过滤：从启发式到模型打分

```text
三级过滤漏斗：
① 启发式规则：文档过短/符号占比过高/重复行率/乱码检测/词表外比率
② 模型打分：用小分类器（在「高质量 vs 低质量」标注上训练）给文档打分
   —— GPT-3 时代用「是否像 Wikipedia」的分类器；现代是更大的打分模型
③ 有害内容过滤：色情/暴力/隐私（PII 检测与脱敏）

过滤的权衡：过滤越严 → 数据越少越干净（质量↑但多样性↓）
  「过滤掉方言/非标准英语」的公平性副作用——过滤规则的社会影响要被审计
```

「质量」的定义本身就是建模决策：**用什么打分模型、阈值多少**，直接塑造模型「像什么」——Wikipedia 风格的过滤会让模型「书面化」，论坛语料的保留让模型「口语化」。数据配比（下节）与过滤标准共同决定模型性格。

## 4. 数据配比：领域的权重

```text
预训练数据的领域配比（示例形态）：
  网页 60% | 代码 15% | 书籍 10% | 学术 5% | 多语言 8% | 其他 2%

配比的影响：代码占比高的模型「推理更强」（代码是最严谨的推理语料）；
  多语言占比决定语言能力分布；数学语料决定数学能力。
进阶：两阶段配比——主体训练用宽配比，最后 5~10% 用「高质量领域数据退火」
  （annealing：微调配比强调目标领域——数据配比的课程学习）
```

配比是「**数据层的模型设计**」：改变配比 = 改变模型的能力倾向——不需要改架构就能「造一个代码特化模型」。配比的实验成本极高（每次试验 = 一次预训练）——小规模 proxy 实验（更小模型 + 同配比）是标准方法。

## 5. SFT 数据工程：三源与质量

```text
[第 4 篇](04-pretrain-sft-rlhf.md)的三源展开：
① 专家手写：贵、准、风格锚点 —— 「黄金标准」的定义者
② 蒸馏（强模型生成）：便宜、可规模 —— ⚠️ 继承教师模型的偏见/风格/幻觉
③ 线上日志筛选：真实分布 —— 隐私脱敏 + 只收好评

SFT 数据的工程清单：
- 任务覆盖度：任务类型的分布统计（别只覆盖 3 种任务）
- 输入多样性：真实用户输入的形态（错字/口语/多语言混合）
- 输出一致性：同任务的风格统一（模型学「示范的平均行为」）
- 质量抽检：随机人工复核率 ≥ 5%（[数据审计](../ai/01-ml-overview.md)）
```

蒸馏数据的「系统性风格污染」是微调的隐性陷阱：**用模型 A 蒸馏出的数据训练模型 B，B 会继承 A 的口头禅、幻觉模式、格式习惯**——数据审计要专门检查「风格污染」（与任务无关的 A 特有表达）。

## 6. 合成数据：能力与崩塌

```text
合成数据的正当用途：
① 蒸馏数据（强模型教弱模型）
② 增强与变体（同题多问、改写扩充）
③ 可验证任务的自动生成（程序生成的数学题+标准答案）

合成数据的深坑——模型崩塌（model collapse）：
  用「模型生成的数据」训练「模型」→ 再用输出训下一代 →
  分布逐代收窄（尾部/稀有模式丢失）→ 世代递退
  对策：合成数据与真实数据混合、控制比例、保留原始数据锚点
```

合成数据的工程纪律：**生成要有多样性机制**（seed/温度/约束变化）、**验证器把关**（可验证任务生成「题目+答案」由程序验证）、**比例控制**（合成:真实 有上限）、**血统记录**（合成数据的生成模型与代数——防「混血崩塌」叠加）。

## 7. RLHF 数据运营

```text
偏好数据的质量维度：
① 标注一致性：同一样本多标注员的一致率（Kappa）—— 一致率低 = 标准不清
② 区分度：chosen 与 rejected 要有「真实差距」（微差的对比教不出偏好）
③ 覆盖度：任务的分布与真实使用的匹配
④ 无泄漏：标注员的身份/情绪影响（批次效应）

标注运营：标注指南（含例子）→ 试标与对齐 → 分批质检 → 争议仲裁流程
```

偏好数据是「人类判断的产品化」——标注指南的质量直接决定 RM 的质量（[RLHF](04-pretrain-sft-rlhf.md)）：**指南里的每个歧义都会变成 RM 的噪声**。

## 8. 数据版本与 lineage

```text
数据版本化的对象：
  原始数据快照 → 清洗/过滤代码（版本）→ 中间产物 → 最终训练集
  + 每个版本的统计指纹（token 数/领域分布/去重率/已知样本抽样对比）

DVC/数据湖的形态：数据集像代码一样有 commit、diff、tag
  「这次训练用了哪份数据」必须能精确回答（[可复现性](../r/11-projects-reports.md)）
```

数据的 lineage 是事故排查的钥匙：「模型在某类问题上变差」→ 定位到「某版本数据引入的坏语料」——没有 lineage 就只能瞎猜。数据的 diff 工具（分布对比/抽样对比）是「数据的 code review」。

## 9. 陷阱清单

- 「数据多 = 好」：重复与低质数据的边际收益为负；去重与过滤先行。
- 提取质量不审计：乱码语料毒化模型；抽样人工阅读提取结果。
- 过滤的社会副作用（方言/少数群体的语料被过滤）：公平性审计。
- 蒸馏数据的风格污染：专查「与任务无关的教师特征」。
- 合成数据无血统记录与比例控制：模型崩塌的渐进积累。
- 数据无版本：结果不可复现、事故不可归因。
- 配比变更无 proxy 实验：直接全量试错是算力赌博。
- 隐私脱敏不彻底（PII 进预训练）：合规与泄露风险；PII 检测的召回率审计。

## 10. 小结

- 数据是上限：管线五道工序（获取/提取/识别/去重/过滤）每道都是过滤器——上一道决定下一道。
- 去重是最重要的单一工序：MinHash-LSH 的近似去重防「记忆放大」与「基准污染」；力度是权衡。
- 配比是数据层的模型设计：领域权重塑造能力倾向；两阶段退火是小成本特化。
- SFT 数据三源（专家/蒸馏/日志）各带陷阱；蒸馏的「风格污染」与合成数据的「模型崩塌」是两代际风险。
- 数据版本与 lineage 是可复现与事故归因的钥匙——「数据即代码」的工程纪律。

## 10. 练习

**1.** 去重管线实践：对一份「含大量转载与改写」的语料集（自己构造或爬取），实现「精确哈希去重 + MinHash-LSH 近似去重」两级管线，统计各级删除量——观察「近似重复」的真实规模。

> [!TIP]
> 思路MinHash 的参数（num\_perm 与 LSH 阈值）决定「相似度门槛」——先在已知重复对上验证检测率再跑全量。去重率的异常（>30% 或 <1%）都是数据源问题的信号。

**2.** 提取器对比：同一批 HTML 页面用三种提取方式（正则/BeautifulSoup 手写/readability 类库/trafilatura）提取，抽样人工对比正文纯度——量化「提取质量」对语料信噪比的影响。

> [!TIP]
> 思路评估提取器的维度：正文的完整性（关键段落没丢）与纯净度（噪音没带进来）——两者常此消彼长。抽样人工评审（[数据审计](../ai/01-ml-overview.md)）是唯一可靠的评估法。

**3.** 合成数据实验：用强模型为一个分类任务生成合成训练数据（每类 100 条），混合不同比例（0%/50%/90% 合成）训练小模型，在真实测试集上评估——画出「合成比例-真实性能」曲线，找拐点。

> [!TIP]
> 思路预期：适度混合提升（多样性）、过量合成下降（分布偏移+模式收窄）——「模型崩塌」的小规模重现。曲线的拐点就是你项目的合成比例上限。

**4.** 数据配比的 proxy 实验：构造「代码占比 0%/20%/40%」三种混合数据，分别微调（而非预训练）同一模型，测代码与通用任务的表现——验证配比对能力面的塑造，并思考 proxy 实验的外推边界。

> [!TIP]
> 思路proxy 实验的外推风险：小模型上的最优配比 ≠ 大模型的最优（容量改变数据需求的形态）——「方向可外推、数值不可外推」。配比实验的结论要标注适用范围。

**5.** 数据 lineage 落地：给一个微调项目建立数据 lineage（数据来源/清洗代码版本/配比/指纹），构造一次「模型在某类问题上退化」的模拟事故，用 lineage 定位到具体数据变更——体验「数据可追溯」的排查威力。

> [!TIP]
> 思路lineage 的排查路径：定位退化类别 → 找该类数据在哪个版本变化 → 对比变更前后的样本 → 找到引入的坏语料。没有 lineage 时这个问题无解（[git 的可追溯](../git/01-object-model.md)的数据版）。

**6.** 讨论：「数据工程」正在从「预处理的脚本」演变为「独立工程学科」——与软件工程的发展史对照（脚本→版本控制→测试→CI），数据工程的哪些阶段已经成熟（版本/去重）、哪些还在早期（质量评估的自动化/lineage 的工具链）？从「测试的对应物」（数据的质量断言）与「CI 的对应物」（数据管道的持续验证）分析「数据 CI/CD」的形态。

> [!TIP]
> 思路数据工程的成熟度地图：版本化（成熟：DVC/lakeFS）、去重与过滤（成熟：标准算法）、质量评估（半成熟：打分模型但标准未统一）、lineage（早期：工具碎片化）、数据测试（早期：分布漂移检测刚起步）。「数据 CI」的形态：每次数据变更跑「分布断言 + 质量抽检 + 下游模型回归」——与[软件 CI](../python/12-quality.md) 的映射是数据工程的方法论纲领。
