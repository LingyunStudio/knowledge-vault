[Transformer 的注意力](03-transformer-llm.md)有两个成本诅咒：**预填充 O(n²)**（序列长度的平方）与 **KV 缓存 O(n)**（每个历史 token 的 K/V 都要存）。上下文从 4K 走向 1M+ 的竞赛，就是在与这两个诅咒作战。本篇讲长上下文的技术栈，再讲试图「从根上换掉注意力」的新架构（线性注意力/SSM）。

## 1. 长上下文技术栈：在注意力框架内作战

```text
① 位置编码的外推：RoPE 的扩展
   PI（位置插值）：把位置坐标线性压缩（100K 的位置标成 8K 内的刻度）
   YaRN：按频率分层的插值 + 温度修正 —— 更少的微调达到更长
② 稀疏/窗口注意力：不是所有 token 都需要互相注意
   滑动窗口（局部）+ 少量全局 token 的混合（Mistral 的形态）
③ FlashAttention：不改变数学、改变「怎么算」
   —— 分块计算 + 在 SRAM 中完成 softmax（不物化 n×n 矩阵）
   —— 显存 O(n)、速度显著提升（IO 感知的精确注意力）
④ KV 压缩：GQA/MQA（[第 3 篇](03-transformer-llm.md)）、KV 量化、逐层丢弃
```

这条技术栈的共同点：**保留注意力的表达力，压低它的成本常数**。「上下文窗口的军备竞赛」（4K→128K→1M）靠的就是这些的叠加——但要区分「**能塞进窗口**」与「**能有效利用窗口**」（[lost in the middle](03-transformer-llm.md)）——后者是数据与训练问题，不是架构能单独解决的。

## 2. 线性注意力与 SSM：换掉注意力的尝试

```text
注意力的本质：每个位置与全部历史做「内容寻址的加权聚合」—— O(n²)
线性注意力的思路：把「softmax(QKᵀ)V」改写成递归形式
  S_t = S_{t-1} + φ(k_t)v_tᵀ      （状态矩阵 S 的常数时间更新）
  y_t = φ(q_t)·S_t                —— 每步 O(1)（相对固定大小的状态）！
代价：固定大小的状态 = 无限精度的记忆不可能——旧信息被压缩/遗忘
```

**Mamba/Mamba-2（状态空间模型 SSM）**是这条路线的代表：用「输入依赖的选择机制」让状态空间模型达到 Transformer 级的语言能力——状态是固定大小的「压缩记忆」，长序列的处理是**线性时间**且**推理时每步常数成本**（KV 不增长！）。

```text
SSM vs 注意力的权衡：
                注意力（Transformer）        SSM/Mamba（线性）
长程召回        ✅ 精确（任何历史 token 可直达）  ❌ 状态有损（压缩记忆）
训练并行        ✅ 全并行                      ⚠️ 需要并行扫描技巧（已解决大半）
推理成本        KV 随上下文线性涨               每步常数（无 KV！）
精确复制        ✅ 强（induction heads）        ⚠️ 弱（精确检索是短板）
```

「精确召回 vs 压缩记忆」是这个权衡的核心：**注意力像一个「可翻阅的完整笔记本」、SSM 像「不断概括的有限记忆」**——需要精确复制历史内容的任务（如 needle 检索）注意力强；需要「整体理解」的长流任务（音频/基因组）SSM 高效。

## 3. 混合架构：两全其美的工程答案

```text
Jamba/Mamba-2-Hybrid 的思路：层间混合
  [注意力层] → [Mamba 层] → [注意力层] → [Mamba 层] …
  少量注意力层保「精确召回」、大量 Mamba 层省「长序列成本」
  → 百万上下文的模型、KV 缓存缩小一个量级
```

混合架构的兴起标志着「架构战争」的务实化：**不是谁取代谁，而是按层分配**——需要精确跨距注意力的地方放注意力、线性衰减足够的地方放 SSM。这与 [CNN vs 注意力](../ai/07-sequence-attention.md)的先验光谱是同一逻辑的层内版。

## 4. 其他前沿一瞥

| 方向              | 一句话                                                            |
| --------------- | -------------------------------------------------------------- |
| 多 token 预测（MTP） | 一次预测多个未来 token：训练信号更密、[推理提速](06-inference-decoding.md)         |
| 字节级模型（BLT）      | 跳过 tokenizer 直接建模字节（消灭 [token 化怪癖](02-tokenizer-embedding.md)） |
| 测试时训练（TTT）      | 推理时更新「快速权重」——把上下文写进参数                                          |
| 稀疏 MoE 的深化      | 更细粒度专家/共享专家设计（[第 3 篇](03-transformer-llm.md)）                  |
| 长思维链的架构适配       | 推理模型的长思维（[第 13 篇](13-reasoning-models.md)）对上下文管理的新要求           |

「字节级模型」值得点名：**tokenizer 的全部怪癖（[第 2 篇](02-tokenizer-embedding.md)）来自「先切 token」**——字节级模型直接建模字节，数字/代码/多语言的边界盲区理论上消失。代价是序列更长（字节 ≈ 4 倍 token）——分层的字节 patch 是折中方案。

## 5. 对应用层的实际含义

```text
架构前沿的「应用层翻译」：
① 长上下文 ≠ 长记忆：架构解决「塞得下」，记忆管理仍是你的事（[第 12 篇](12-context-engineering.md)）
② 模型的「序列长度 SLA」要实测：needle 测试（[第 3 篇](03-transformer-llm.md)）+ 你的真实任务形态
③ SSM/混合模型的「检索短板」：把「精确查找」交给工具/RAG 而不是模型记忆
④ 推理成本的分层：混合架构让「长上下文推理」的成本曲线更平——部署选型的新变量
⑤ 换架构的模型迁移：tokenizer/行为差异 → 评估回归（[第 15 篇](15-evaluation-systems.md)）
```

## 6. 陷阱清单

- 「窗口 1M = 可以塞 1M 有效内容」：lost in the middle 与有效上下文（[第 3 篇](03-transformer-llm.md)）。
- 长上下文下的「精确检索」假设：SSM/滑窗模型的精确召回短板；关键检索走 RAG。
- FlashAttention 被当成「改变数学」：它只是精确注意力的更快实现（结果一致）。
- KV 压缩策略的静默质量损失：压缩率的回归测试（[量化回归](06-inference-decoding.md)同款纪律）。
- 新架构模型的工具调用/微调生态不成熟：能力评测 + 生态核查（[开源模型地图](23-open-models.md)）。
- 混合架构的「注意力层比例」假设可迁移：不同模型的设计选择不同，行为要实测。
- 长思维链模型忽视上下文管理（[第 13 篇](13-reasoning-models.md)）：推理 token 也是上下文。

## 7. 小结

- 长上下文技术栈在注意力框架内作战：RoPE 扩展/稀疏窗口/FlashAttention（不物化 n²）/KV 压缩——「塞得下」进步快于「用得好」。
- 线性注意力/SSM 的本质换轨：O(n²) 精确记忆 → 常数状态的压缩记忆——精确召回是短板、线性成本是红利。
- 混合架构（注意力+SSM 层间混合）是务实答案：按层分配「精确召回」与「压缩效率」。
- 架构前沿对应用的三句话：长上下文不等于长记忆、精确检索交给工具、换架构必须回归评估。
- 「一切皆 token」与「token 化怪癖」的终极解法可能是否定前提——字节级模型的观察值得持续跟踪。

## 8. 练习

**1.** 注意力成本实验：用 PyTorch 手算「朴素注意力」在不同序列长度（1K/4K/16K/64K）下的显存与时间（或对比 FlashAttention 的实现）——画出 n 与成本的关系，验证平方诅咒。

> [!TIP]
> 思路朴素实现在 16K 就会 OOM（n² 矩阵 1GB 级）；FlashAttention 在同长度下显存平缓。实验后「为什么长上下文需要架构级创新」不再是抽象问题。

**2.** RoPE 扩展的评测：找一个 8K 原生模型（或用 RoPE 缩放参数模拟），分别在 8K 内与 8K 外的长度上跑 needle 检索——验证「扩展的窗口」与「有效窗口」的差异（[第 3 篇](03-transformer-llm.md)练习 3 的深化）。

> [!TIP]
> 思路未微调的 RoPE 外推在超出训练长度后 needle 召回下降——PI/YaRN 的价值是「恢复外推区间的召回」。「窗口数字」的营销要经过 needle 审计。

**3.** 精确召回 vs 压缩记忆：构造「在 10K token 的文档中精确找出某个数字」的任务，对比注意力模型与（可获得的）SSM/混合模型的准确率——验证「精确检索是注意力的强项」。

> [!TIP]
> 思路固定状态的记忆必然有损——「哪段被压缩掉」取决于状态更新机制的选择。任务设计时「需要精确复述的部分」放头尾或用工具检索（[第 12 篇](12-context-engineering.md)）。

**4.** 混合架构认知：读一个混合架构（Jamba 类）的技术报告，统计注意力层与 SSM 层的比例与布局，思考「为什么不能全 SSM」——把「精确召回的保留」与布局决策连起来。

> [!TIP]
> 思路少量注意力层的角色：周期性的「精确访问点」——全 SSM 的信息损耗在需要精确复制的任务（代码/检索）上暴露。层间比例是新架构的核心超参。

**5.** 字节级模型思考实验：列出你项目中「tokenizer 造成的三个 bug」（[第 2 篇](02-tokenizer-embedding.md)的 token 边界盲区），评估「字节级模型」是否解决它们、代价是什么（序列长度与算力）——把架构前沿与自己的痛点对表。

> [!TIP]
> 思路字节级的收益（数字/代码/多语言的边界消除）与代价（序列 ×4、算力需求）——你的痛点清单决定「这个前沿值不值得等」。

**6.** 讨论：架构创新的「验证困境」——新架构（Mamba）需要大规模预训练才能证明自己，而大规模预训练只有证明自己才值得投资（鸡与蛋）。从「Scaling Law 的外推可信度」「评测的区分力」「生态锁定」三个角度分析新架构的验证策略（小规模 proxy + 缩放外推），并对照 [transformer 当年](../ai/07-sequence-attention.md)战胜 RNN 的历史——架构更替的「引爆条件」是什么？

> [!TIP]
> 思路transformer 战胜 RNN 的引爆条件：并行训练的吞吐优势（工程决定性）+ 长依赖的精度优势（能力决定性）同时成立。新架构的验证策略：proxy scaling（小模型看趋势）+ 生态共建（工具链）+ 关键任务的差异化胜利。「足够好 + 更好扩」是更替的双条件。
