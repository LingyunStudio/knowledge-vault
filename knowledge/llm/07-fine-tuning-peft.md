「要不要微调」是 LLM 应用的第一决策——答案是**通常不要**：prompt（[第 5 篇](05-prompting.md)）与 RAG（[第 8 篇](08-rag.md)）覆盖 80% 的需求且成本低几个数量级。微调的正确入口是「prompt/RAG 确实解决不了」之后的精确问题：**风格/格式/领域行为的深度定制**。

## 1. 决策树：prompt、RAG 还是微调

```text
问题是什么？
├── 模型缺知识（私有文档/实时信息）→ RAG（知识常变、可溯源）
├── 任务描述不清/输出格式不稳 → prompt 工程 + few-shot + 结构化输出
├── 行为/风格/格式需要深度定制（prompt 控制不住）
│   ├── 输出语言风格、行业格式、固定工作流 → SFT/LoRA
└── 领域语言与概念体系（医疗/法律术语与推理模式）→ 继续预训练 + SFT

判据口诀：知识用检索、行为用训练、两者都缺先做检索再微调行为。
```

微调「教不了」的事：**实时知识**（训练后即过期——RAG 主管知识）、**跨文档推理**（把 100 份文档塞进权重不如放进上下文）。微调「教得好」的事：**稳定输出的格式/风格、领域任务的模式、精简 prompt（把长指令内化）**——这些是「行为层」的塑形。

## 2. LoRA：低秩微调的原理

```text
全参微调：更新全部 W（7B = 70 亿参数的梯度与 Adam 状态——显存爆炸）
LoRA 的假设：微调的「变化量」ΔW 是低秩的（任务调整不需要全维度自由度）
  W' = W + ΔW = W + B·A     （A: d×r，B: r×d，r=8~64 ≪ d）
  只训练 A、B（参数量降到 <1%），W 冻结
  推理时 B·A 可以合并进 W（零额外延迟）
```

LoRA 的三个收益：**显存降一个量级**（[第 4 篇](04-pretrain-sft-rlhf.md)的心账本：不存全参的优化器状态）、**多个 LoRA 适配器共享一个基座**（一个 7B 基座 + N 个任务的轻量适配器热切换）、**基座不被破坏**（合并前可随时卸载）。QLoRA 再进一步：**基座量化到 4bit + LoRA**——单张 24GB 卡微调 33B 模型。

```python
from peft import LoraConfig, get_peft_model
config = LoraConfig(r=16, lora_alpha=32, target_modules=["q_proj", "v_proj"])
model = get_peft_model(base_model, config)     # 只训插入的 LoRA 层
```

超参的语义：**r（秩）**= 任务调整的容量（简单任务 8~16、复杂 32~64）；**target_modules**（注入哪些层——注意力 q/v 是起点，全部线性层更强）；**lora_alpha/r** 的缩放比。

## 3. 数据：微调的真正成本

```text
数据形态：与 [SFT](04-pretrain-sft-rlhf.md) 相同——(指令, 高质量回答) 对
数量：任务狭窄时几百到几千条即可起步（ICL 能做到的不要微调；
      微调追求的是「稳定内化」——1k 精标是常见起点）
质量的黄金律不变：数据决定微调上限——噪声示范教出噪声行为

数据构造的三个来源：
① 专家手写（最贵最准——风格与判据的「黄金标准」）
② 强模型蒸馏（便宜——但要人工抽检与去毒）
③ 线上日志筛选（真实——需脱敏 + 只收「好评输出」）
```

数据构造的细节决定成败：**输入分布要匹配真实使用**（训练集是「理想输入」、线上是「真实输入」→ 泛化落差）、**输出一致性**（同一类问题的回答风格统一——模型学到的是「你示范的平均行为」）。

## 4. 灾难性遗忘与知识注入的边界

```text
灾难性遗忘：微调新任务时，旧能力退化（通用对话变笨/幻觉增多）
原因：权重被新任务梯度拉离原分布——「学新忘旧」

缓解：
① 小学习率 + 少 epoch（轻推而非重塑）
② LoRA（冻结基座本身就是防线——基座能力保底）
③ 混合数据（新任务数据 + 通用数据回放）
④ 评测新旧两套（回归测试：新任务提升 & 旧能力保持）
```

「微调注入知识」的边界要诚实：**少量事实可以微调进去，大量/频繁更新的知识应该 RAG**——知识在权重里意味着「更新要重训、无法溯源、容易幻觉」。经验法则：**知识进上下文（RAG），行为进权重（微调）**（[第 4 篇](04-pretrain-sft-rlhf.md)）。

## 5. 训练实践与评估

```bash
# LLaMA-Factory 等框架的最小流程
llamafactory-cli train lora_config.yaml     # 数据/基座/LoRA 超参在 yaml
llamafactory-cli chat --adapter lora_out    # 聊天验证
```

评估的三层：**训练 loss**（只证明拟合）、**任务测试集**（held-out 的任务指标——精确匹配/人工评审/LLM 评审）、**通用能力回归**（旧能力保持度）。微调的迭代纪律与[prompt 工程](05-prompting.md)同款：**测试集先行、版本化管理、每次改动跑回归**。

## 6. 陷阱清单

- 「先微调再说」的冲动：prompt/RAG 先行；微调是行为定制的最后手段。
- 微调灌实时知识：过期即失效、无法溯源；知识走 RAG。
- 数据分布与真实使用脱节：训练「理想输入」线上「真实输入」；数据要覆盖真实分布。
- 学习率过大/epoch 过多：灾难性遗忘与过拟合；小 lr 少 epoch + 通用能力回归测试。
- LoRA 超参盲调：r 与 target_modules 决定容量；从推荐值起步再扫描。
- 忘记合并或卸载适配器：推理框架的 adapter 加载核对；合并后验证精度一致。
- 微调后只看训练任务：通用回归测试（遗忘检查）必须并行。

## 7. 小结

- 决策树：知识缺→RAG、格式/行为不稳→prompt、深度行为定制→微调——「知识进上下文、行为进权重」的总纲。
- LoRA 的低秩假设（ΔW = B·A）带来显存降级、多适配器共享基座、可合并零延迟——QLoRA 把门槛降到单卡。
- 微调的真实成本在数据：分布匹配真实使用、输出风格一致、来源三路（专家/蒸馏/日志）各有陷阱。
- 灾难性遗忘的防线：小 lr 少 epoch、LoRA 冻结基座、混合回放、新旧双评测。
- 微调与 prompt/RAG 的评估纪律一致：测试集先行、版本化、回归——「能测才能调」。

## 8. 练习

**1.** 决策树演练：对四个需求（「客服回答要引用知识库」「输出要固定成工单格式」「要懂公司内部黑话」「要接入实时库存」）各选方案（prompt/RAG/微调/工具）并说理由——练习「不微调优先」的纪律。

> [!TIP]
> 思路参考答案：知识库→RAG；工单格式→prompt+结构化输出（不行再 SFT）；内部黑话→术语表进 prompt/RAG（深了再继续预训练）；实时库存→工具调用（[第 9 篇](09-agents-tools.md)）。四个里只有格式可能走到微调。

**2.** LoRA 显存账本验证：7B 模型全参微调 vs LoRA(r=16) 的显存估算与实测（或查框架文档）——对照[第 4 篇](04-pretrain-sft-rlhf.md)的心账本，理解「优化器状态」占大头。

> [!TIP]
> 思路全参 ≈ 权重 2 + 梯度 2 + Adam 状态 8 = 12+ 字节/参数；LoRA 只在 r 秩的小矩阵上付这套成本。量化基座（QLoRA）再砍权重项。

**3.** 数据构造实战：为「把混乱的会议纪要转成规范纪要」任务构造 30 条 SFT 数据——设计输入的多样性（不同混乱模式）与输出的格式一致性——体会「数据构造即任务设计」。

> [!TIP]
> 思路输入多样性的清单：长短纪要/多人发言/无序话题/口语化——每个「真实世界的混乱模式」都要在训练集有代表。输出的一致性（模板/术语/省略规则）就是「你定义的任务规范」。

**4.** 遗忘测量实验：微调「古文翻译」任务前后，分别测「通用问答」与「数学」两个回归集——量化遗忘幅度；再用「混合 10% 通用数据」重训对比。

> [!TIP]
> 思路遗忘的度量需要「微调前基线」——没有 baseline 的遗忘检测无从谈起。回放数据的比例是「新任务收益 vs 旧能力保持」的旋钮。

**5.** LoRA 超参小扫：r ∈ {8, 16, 64} 与 target_modules（仅 q,v vs 全线性层）的 2×3 小网格，任务指标对比——找到「容量够用」的配置，体会「秩 = 任务复杂度」的直觉。

> [!TIP]
> 思路简单风格任务 r=8 常够、复杂推理/多任务 r=32~64。观察「r 太大反而过拟合」——容量过大在窄任务上记噪声（[第 1 篇](../ai/01-ml-overview.md)的过拟合回声）。

**6.** 讨论：为什么「RAG vs 微调」的争论在实践中几乎总是「RAG 优先」？从「知识的更新频率与溯源需求」「成本结构（训练 vs 检索）」「失败模式（检索不到 vs 幻觉）」三个角度分析，并描述两者**协同**的形态（微调教「如何用检索结果」）——为什么混合形态（RAG + 行为微调）是高级形态。

> [!TIP]
> 思路RAG 的胜出理由：知识常变（微调的静态权重跟不上）、可溯源（合规刚需）、成本低。协同形态：微调教模型「读检索结果并整合回答」的行为（引用格式/冲突处理），RAG 供内容——「行为在权重、知识在上下文」的完整落地。
