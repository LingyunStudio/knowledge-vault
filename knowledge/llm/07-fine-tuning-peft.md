微调（fine-tuning）是改动模型权重的训练，效果最深、成本最高、翻车风险也最大。动手之前先想清楚：**你要改的是"知道什么"还是"怎么做"？** 前者不该用微调，后者才轮到它。

## 决策树：提示词 → RAG → 微调

```text
模型答不好，因为……
├─ 不知道这条信息（私有数据/新知识/实时变化） → RAG（检索增强，第 08 篇）
│   知识进上下文，不进权重；可随时增删
├─ 知道但表达/格式/风格不对 → 先调提示词与 few-shot
├─ 提示词调到头还是不行（稳定风格、领域术语、紧凑输出、省 token）
│   → 微调
└─ 都要：微调定"行为"，RAG 供"事实" —— 生产系统的常态组合
```

微调擅长的三件事：**输出格式与风格的对齐**（稳定 JSON、特定语气）、**领域任务的适配**（法律/医疗文档的术语与结构）、**能力压缩**（把长思维链蒸馏进小模型，省成本提速度）。它不擅长灌新知识——几千条样本改不动万亿参数的"世界观"，硬灌只会过拟合。

## 全参微调的账本

全参微调 7B 模型：权重 FP16 约 14GB，Adam 优化器还要存梯度和一、二阶动量（各 14GB，混合精度下另加主权重），**总显存轻松破 70GB**——这就把大多数人挡在了门外。参数高效微调（PEFT）就是来省这笔账的。

## LoRA：只训两个小矩阵

核心假设：微调引起的**权重变化量 ΔW 是低秩的**——不用更新整个 W（如 4096×4096），只学两个小矩阵 B(4096×r) × A(r×4096)，r 通常 8\~64，相乘后加回原权重：

```text
W' = W + B·A      可训练参数：2×4096×r ≈ 原参数的 0.5%（r=16 时）
```

- **显存**：冻结原权重（不需梯度/动量），7B 模型 LoRA 一张 24GB 卡可训
- **可插拔**：LoRA 权重是独立小文件（几十 MB），一个基座 + 多套 adapter 按任务热切换；合并回基座则推理零开销
- **QLoRA**：基座再量化到 4bit（NF4）加载，LoRA 部分保持 BF16——7B 全参微调的账本被压到单卡可玩

```python
from peft import LoraConfig, get_peft_model
cfg = LoraConfig(r=16, lora_alpha=32, target_modules=["q_proj", "v_proj"],
                 lora_dropout=0.05, task_type="CAUSAL_LM")
model = get_peft_model(base_model, cfg)   # 之后正常 Trainer 训练
```

## 数据：微调成败的八成

1. **质量 >> 数量**：几百条精修样本常胜过几万条脏数据；错误标签会被模型学得惟妙惟肖
2. **覆盖真实分布**：用线上的真实输入（含脏话、错字、超纲请求），不要自编理想样本
3. **负样本与边界**：该拒答的要给拒答示例，歧义输入给澄清行为
4. **切分留验**：训练/验证集分离，验证集反映业务指标，防"背题"

> [!WARNING]
> **灾难性遗忘**：只喂领域数据，通用能力（对话、常识）会显著退化。对策：混入一定比例的通用指令数据（经验比 1:5~~1:10）、降低学习率、少 epoch（1~~3 轮）——微调是"轻轻推"，不是"重新教育"。

## 上线前自检清单

- 有无干净的对照基线（强提示词 + 强模型）？提升要量化
- 验证集指标（准确率/格式合规率/延迟）是否达标且无回归
- 是否测过分布外输入（没见过的问法、恶意输入）
- 推理成本与迭代周期是否划算：模型能力每半年一大跳，**过度定制的小模型可能被下一代基座直接碾过**——微调越重，越要评估"再训练"的路线成本
