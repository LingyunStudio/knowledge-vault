Transformer 只有一个核心运算——**注意力（Attention）**：序列里每个 token 看一遍所有 token，决定"我该关注谁"，按关注权重加权汇总信息。所有 GPT/Claude/Llama，翻来覆去都是这一个运算的堆叠与修饰。

## 注意力：一次"按相关性加权"的查询

每个 token 发射三个向量：

- **Q（Query）**：我要找什么
- **K（Key）**：我有什么可供匹配
- **V（Value）**：匹配上之后，我实际提供的内容

权重 = Q 与每个 K 的点积相似度（softmax 归一化），输出 = 权重对 V 的加权和：

```python
import numpy as np
def attention(Q, K, V):
    d = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d)      # 相似度，除 √d 防止 softmax 饱和
    W = np.exp(scores) / np.exp(scores).sum(-1, keepdims=True)
    return W @ V                        # 每个 token 的"上下文感知"新表示
```

直觉例子：处理"它"这个 token 时，Q 编码"我在找一个指代对象"，前文"猫"的 K 恰好匹配——"它"的输出向量就吸收了"猫"的信息。**一词多义、指代消解、长程依赖，全是这一步几何运算的产物。**

三个关键修饰：

1. **因果掩码**：GPT 类模型必须"只看过去"——把未来位置的注意力分数置 -∞，否则就是作弊（那是 BERT 的双向世界）
2. **多头**：把 QKV 切成多组并行做注意力，每组学一种关系（语法/指代/位置……），最后拼接。单头只能表达一种"关注模式"
3. **残差与层归一化**：每层的输出加回输入（残差），几十上百层才训得动

## 位置编码：RoPE

注意力对顺序天然失明（打乱输入顺序，输出集合不变）。RoPE 的方案：按位置把 Q/K 向量旋转不同角度，**两个 token 的注意力分数只依赖相对位置差**——训练到 4K、推理外推到 32K 这类"长上下文扩展"技术，基本都在 RoPE 的插值/缩放上做文章。

## 上下文窗口：模型的"工作记忆"

窗口 = 模型一次能处理的 token 数上限。窗口内所有 token 的 QKV 都要在 GPU 上过一遍，两个硬约束由此而来：

1. **注意力计算是 O(n²)**：n 个 token 两两配对。窗口翻倍，prefill 计算量翻 4 倍（有 FlashAttention 等优化，但量级不变）
2. **KV Cache 占显存**：见第 06 篇，长上下文的显存大头不是参数，是缓存

> [!WARNING]
> **"大海捞针"测试（needle-in-a-haystack）通过 ≠ 长上下文可靠**。模型在超长上下文中段的召回与推理质量会衰减（lost in the middle）。工程上：与任务相关的上下文尽量靠近开头或结尾，能用检索裁剪的就别整篇塞。

## 堆叠出智能：参数都长在哪

一层 Transformer ≈ 注意力 + 前馈网络（FFN）。FFN 是两个大矩阵（维度通常是 4 倍隐藏层），**模型参数的大头在 FFN，不在注意力**——它被认为是模型的"事实记忆库"。几十层堆叠，逐层从"字符模式"抽象出"语法—语义—世界知识"。7B/70B 的 B，就是这些矩阵里的权重数。

> [!TIP]
> 记住两个数字感受规模：7B 模型按 16bit 存约 14GB；注意力 O(n²) 意味着把上下文从 8K 拉到 128K，prefill 算力涨约 256 倍。**"模型多大"决定成本下限，"上下文多长"决定成本弹性**。
