2024 年之前，提升模型能力的唯一路径是**训练时扩展**（更多数据/更大模型/更多算力）。o1 与 DeepSeek R1 证明了第二条路：**测试时计算（test-time compute）**——让模型在回答时「多想一会儿」，用更多的推理 token 换取更高的答案质量。这不是 prompt 技巧（[CoT](05-prompting.md) 是外挂的思考框架），而是**训练出来的新物种**：模型被强化学习训练成「先长篇思考、再给出答案」。

## 1. 两条扩展轴

```text
训练时扩展（train-time）：
  更多数据 + 更大模型 + 更多 FLOPs → 损失下降（[Scaling Laws](01-what-is-llm.md)）
  代价：预训练一次的巨额成本；能力提升「事先确定」

测试时扩展（test-time）：
  同一个模型，回答单个问题时花更多推理 token
  → 思考越长，复杂问题的正确率越高（在特定范围内）
  代价：延迟与 token 费用按问题难度分配 —— 「难题多想、简单题快答」
```

两条轴**互补而非替代**：测试时计算在「有明确对错、可验证」的任务上收益最大（数学/代码/逻辑），对「写一首诗」几乎无效（没有对错可收敛）。

## 2. 推理模型是怎么训练的

```text
DeepSeek R1 的公开配方（RLVR）：
① 起点：base 模型
② R1-Zero 路线：直接用「可验证奖励的强化学习」训练
   —— 任务：数学/代码题（答案可自动验证：对/错）
   —— 奖励：答案正确 +1、格式合规加分
   ★ 令人惊讶：没有人工标注的思维链，模型自发学会
     「检查自己的步骤、回头重试、尝试多条路径」——推理行为涌现
③ R1 完整版：少量冷启动 CoT 数据 → RLVR → 拒绝采样生成新 SFT 数据 → 再 RL
④ 蒸馏：把 R1 的长思维链作为 SFT 数据训练小模型 → 小模型也获得推理能力
```

RLVR（RL with Verifiable Rewards）的关键洞察：**数学/代码的答案可以程序化验证**——不需要人类标注偏好（对比 [RLHF](04-pretrain-sft-rlhf.md) 的 RM 路线），奖励信号客观且廉价，RL 可以大规模跑。**「可验证」是训练推理能力的燃料**——这也是为什么推理模型先在数学/代码上突破。

## 3. 思维 token：机制的细节

```text
推理模型的输出 = <think>…长篇思考…</think> + 最终答案
思维内容：自我质疑（「等等，这里不对」）、回溯（「换个方法」）、
          多路径探索（「方法 A 不行，试 B」）、自我验证

工程含义：
① 思维 token 也要计费与占窗口 —— 「答案 200 字、思考 8000 字」是常态
② 思维预算（reasoning effort）是可调参数 —— 低/中/高档位
③ 思维可能被截断（预算耗尽）→ 答案质量下降
④ 思维内容可能泄露敏感中间信息 → 产品层要不要展示、要不要脱敏
```

与 [prompt CoT](05-prompting.md) 的本质区别：prompt CoT 是「外挂的格式」（模型本来不会深想，被要求装作想）；推理模型的思维是**RL 训练出的行为**——模型真的在探索与回溯（从思维 token 的自我纠错模式可见）。推论：**对推理模型说「一步步思考」不仅是多余的，还可能干扰它原生的思考格式**。

## 4. 测试时计算策略

| 策略                    | 机制                                       | 适用                              |
| ----------------------- | ------------------------------------------ | --------------------------------- |
| 长思考（内置）          | 推理模型的原生思维                          | 数学/代码/规划                     |
| Best-of-N + 验证器      | 采样 N 个答案，用验证器挑最好的             | 有验证器的任务（代码跑测试）        |
| 自洽性（self-consistency）| 高温采样多条推理链，投票取多数            | 数值/选择题（[第 5 篇](05-prompting.md)）|
| 分解 + 逐步验证         | 拆子任务、每步验证                          | 长流程任务                          |
| 搜索（MCTS/树搜索）     | 状态空间搜索 + 价值引导                     | 推理模型研究的实验室形态             |

测试时扩展律（test-time scaling laws）：**「性能随思考 token 的对数增长」**——8 倍思考 ≈ 一档能力提升（在可验证任务上）。「思考多长」因此成为成本方程的变量：**数学竞赛题花 2 万 token 值、日常问答花 2 万 token 是浪费**。

## 5. 何时用推理模型：路由判据

```text
用推理模型（思考模式）：
✅ 多步数学/物理计算
✅ 代码调试与算法设计
✅ 复杂规划（多约束调度/行程）
✅ 严谨分析（合同条款比对/逻辑漏洞排查）
✅ Agent 的关键决策节点（[第 9 篇](09-agents-tools.md)）

用普通模式（或小模型）：
✅ 简单检索/改写/翻译
✅ 分类/抽取（格式化任务）
✅ 高频低难度的调用（成本敏感）
✅ 延迟敏感的交互（首字时间）

工程形态：路由器按「任务难度/类型」分流——
  简单任务 → 小模型直出；存疑 → 推理模型；推理也不行 → 人。
```

「自适应思考」是推理模型的演化方向：模型自己判断「这题需要想多久」——简单问题简短思考、难题展开。使用侧的纪律：**为每个用例实测「推理开/关」的质量-成本曲线**（[第 10 篇](10-deploy-engineering.md)的评估体系），而不是凭感觉全局开关。

## 6. 推理模型的 prompt 特点

```text
① 不需要「让我们一步步思考」—— 模型原生就会（写了反而可能打乱格式）
② system prompt 简洁明确—— 任务目标与约束，不教它怎么想
③ 给全上下文：推理模型对「完整信息」的利用更好（它在上下文里做推演）
④ 输出解析要适配思维格式：分离 <think> 与答案（API 通常已分离 reasoning 字段）
⑤ 不要在思维内容上做正则匹配——格式由供应商实现决定，随时可能变
```

## 7. 蒸馏与开源推理模型

```text
R1 的开源策略：发布 R1 的思维链数据作为 SFT 语料
  → 社区用这些数据微调 Qwen/Llama 系小模型 → 小模型获得显著推理提升
  —— 「推理能力可以蒸馏」但「蒸馏版 < 原版 RL」（蒸馏给的是模仿不是探索能力）

工程意义：端侧/低成本场景的「够用的推理模型」路线（[第 20 篇](20-local-edge.md)）
```

## 8. 陷阱清单

- 「推理模型 = 全面更强」：在简单任务上更慢更贵、部分写作任务不升反降；按任务路由。
- 思维预算拍脑袋：难题截断思维 → 质量崩；预算与难度匹配（自适应思考）。
- 对推理模型写长 CoT prompt：干扰原生格式；直接给任务与约束。
- 把思维内容当「模型的真实思考过程」展示给用户：它是生成的合理化文本——展示可以，当「真相」宣传不行（可解释性的边界）。
- 成本失控（长思维 × 高频调用）：思维 token 计费；按调用监控「思维/答案」比。
- 期望推理模型「知道更多事实」：它更擅长**推理**，不更擅长**记住**——事实仍然走 RAG。
- 验证器缺失的 best-of-N：没有可靠验证器时 N 选 1 会选中「最有说服力的错误」。

## 9. 小结

- 范式转变：从训练时扩展到测试时扩展——「难题多想」成为能力的第二增长轴；两者互补。
- 推理模型的训练：RLVR（可验证奖励）驱动推理行为涌现；「可验证性」是燃料，数学/代码先突破。
- 思维 token 是计费与窗口的实体：预算/截断/泄漏是工程参数；prompt CoT 与原生思维是两回事。
- 测试时策略：长思考/best-of-N+验证器/自洽性——按任务的可验证性选。
- 路由纪律：推理模型用于可验证的复杂推理；按实测的质量-成本曲线开关，不凭感觉。

## 10. 练习

**1.** 能力-成本曲线测绘：选 20 道数学题与 20 个改写任务，分别在「普通模型/推理模型（低档）/推理模型（高档）」上运行——画「质量-成本」散点，标注你的任务落在哪个区域。

> [!TIP]
> 思路预期：数学题上推理模型碾压、改写任务上差异微弱但成本 10 倍——「按任务路由」的数据依据。同题多次运行看方差（[第 10 篇](10-deploy-engineering.md)）。

**2.** 思维预算实验：同一批难题在 reasoning effort 低/中/高三档运行——统计「正确率-思维 token 数」曲线，找出「预算加倍的边际收益」递减点。

> [!TIP]
> 思路测试时扩展律的实证：对数收益意味着「预算要花在刀刃上」——难难题加预算、易题省预算。自适应思考是产品化的答案。

**3.** 思维内容分析：收集推理模型的思维 token，分类其行为（验证/回溯/尝试替代方案/计算），统计各类占比——验证「自我纠错」是推理模型质量提升的主要来源。

> [!TIP]
> 思路分类标签可以是：计划/执行/验证/回溯/分支。回溯占比高的任务往往是「收益最大」的任务——思维行为与任务难度的映射。

**4.** 蒸馏效果实测：找一个开源蒸馏推理模型（R1 蒸馏系），在「数学题」与「开放写作」上与基座模型对比——验证「蒸馏提升推理、不提升其他」的边界。

> [!TIP]
> 思路蒸馏数据的分布决定了能力的迁移范围——「数学思维链蒸馏出数学能力」。这也提示：自己蒸馏时，思维链数据要来自你的目标任务域。

**5.** 路由器实现：写一个「难度分类器」（小模型判断问题的推理需求）→ 路由到普通/推理模型——用一组混合难度任务验证路由的准确率与整体成本-质量曲线（对比全走推理）。

> [!TIP]
> 思路路由器的错误成本不对称：把难题错路由到普通模型 = 质量事故；把简单题路由到推理 = 成本浪费。阈值偏向前者——「宁可贵，不可错」按业务定。

**6.** 讨论：「推理 token 的 Scaling Laws」与「预训练的 Scaling Laws」相比，边际收益的结构有何不同？从「可验证性」「任务分布的长尾」「收益的分段性（简单题零收益）」分析，并思考「当推理模型足够便宜时，哪些『传统上需要人类专家逐步推理』的工作会最先被重塑」——与 [Agent 的决策节点](09-agents-tools.md)的关系。

> [!TIP]
> 思路预训练的收益是「均匀的能力垫高」，测试时收益是「按题分配的深度」——两者的成本结构决定了产品形态（订阅制推理 vs 按 token 计费）。最先被重塑的工作：**验证成本低、推理深度值钱**的（代码审查、合同分析、数学建模）——「模型推理 + 程序验证」的组合是 agent 决策节点的内核。
