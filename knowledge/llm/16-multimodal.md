多模态模型回答的问题是：**模型的「语言能力」能不能用在图片、音频、视频上？** 现代答案的统一抽象是：**把一切模态翻译成 token**——图像切成 patch 变成 token、音频切成帧变成 token，然后交给同一个 Transformer（[第 3 篇](03-transformer-llm.md)）。语言能力因此「外溢」到视觉与语音——这就是 VLM（视觉语言模型）与语音助手爆发的架构根基。

## 1. 统一抽象：一切皆 token

```text
LLM 的输入本质：token 序列 → embedding → Transformer
多模态的扩展：不同模态各有「编码器」，把原始信号变成 token：
  文本 → tokenizer（[第 2 篇](02-tokenizer-embedding.md)）
  图像 → ViT 切 patch → 每个 patch 一个 token
  音频 → 分帧编码 → 音频 token
→ 所有模态的 token 进入同一个 Transformer 联合建模
  —— 模型可以在「图片 token」与「文字 token」之间做注意力（跨模态理解）
```

「一切皆 token」的推论：**模态间的能力共享**——文本上学到的推理能力可以用于图像推理（看图解题）；**任务接口统一**——同一模型通过不同输入组合服务不同任务。

## 2. 视觉编码器与 VLM 的组装

```text
VLM 的标准组装（LLaVA 范式）：
图像 → [视觉编码器 ViT] → 一串视觉特征 → [投影层] → 对齐到 LLM 的 embedding 空间
      → 与文本 token 拼接 → [LLM] → 文本输出

视觉编码器（ViT）的做法：
  图像切成 14×14 或 16×16 的 patch → 每个 patch 展平 → 线性投影 → Transformer 编码
  预训练：CLIP 式对齐（图文对训练——「这张图与这段文字是否匹配」）
```

组装的三个工程含义：

1. **视觉编码器是「冻结或微调」的前端**——它决定了「能看见什么」（分辨率、细节粒度）。
2. **投影层是「翻译官」**——把视觉特征翻译成 LLM 能理解的「语言」——多模态能力的质量瓶颈常在这里。
3. **LLM 本体不变**——多模态能力是「外挂视觉前端」，文本推理能力不因看图而消失。

## 3. 图像的 token 经济

```text
一张图的 token 数 = (分辨率/patch 大小)² × 视觉 token 系数
  1024×1024、patch 16×16 → 64×64 = 4096 个 patch → 高分辨率模型 ~1000+ token
多图输入：token 线性叠加 —— 多图任务的成本与窗口预算要精确核算

分辨率与能力的权衡：
  高分辨率 → 小字/表格/细节可见（OCR 必需）
  低分辨率 → 便宜但「看得清轮廓看不清字」
```

与 [文本 token 经济](02-tokenizer-embedding.md)的差异：图像 token 的成本对**分辨率平方级敏感**——「把高分辨率截图直接扔给模型」是成本事故的高发点。工程对策：**按任务选分辨率**（OCR 用高分辨率裁剪、场景理解用低分辨率）、**裁剪 ROI**（只送关键区域）。

## 4. 能力与失败模式

```text
VLM 擅长：
✅ 图文理解：描述/问答/对比
✅ 文档理解：OCR、表格提取、发票结构化（[结构化输出](14-structured-output.md)组合）
✅ 图表解读：趋势与数据的读取（配合精确计算仍需工具）
✅ 截图理解：UI 元素识别（GUI Agent 的基础）

VLM 的失败模式：
❌ 精确计数（「图里有几个人」——视觉 token 不保留个体边界）
❌ 精确空间测量（「这个框宽多少像素」）
❌ 细小文字（低分辨率下幻觉「看似合理」的文字）
❌ 视觉幻觉：描述「图里没有的细节」——与文本幻觉同根（[第 1 篇](01-what-is-llm.md)）
```

「视觉幻觉」的机制与文本幻觉同源：**模型生成「统计上最像」的描述**——图中没有的元素如果「在类似图中常见」，就可能被生成。对策与文本一致：**要求「只描述确定看到的」+ 引用位置（bounding box）+ 关键判断走工具**（OCR 引擎/检测模型做精确任务）。

## 5. 语音：链路与延迟

```text
语音链路（传统三段式）：
音频 → [ASR 语音识别 Whisper 类] → 文本 → [LLM] → 回复文本 → [TTS 语音合成] → 音频
延迟 = ASR + LLM + TTS 的总和（对话体感要求 < 1.5s 级别）

现代形态（端到端语音模型）：音频 token 直接进出 LLM
  —— 保留语气/停顿/情绪，支持自然打断（全双工），延迟更低
```

语音的工程要点：**延迟预算的分配**（每段的毫秒都要抠——流式 ASR 边听边转、流式 TTS 边生成边播）、**打断处理**（用户插话要停住 TTS 并清状态）、**噪声与口音**（真实环境的 ASR 准确率远低于演示）。语音是「延迟敏感 × 状态复杂」的顶配场景——架构上「端到端模型」正在取代「三段拼接」。

## 6. 视频与时序

```text
视频 = 帧序列的视觉 token（数量爆炸：1 分钟 30fps = 1800 帧）
工程方案：
  帧采样（每秒 1~2 帧）/ 分辨率降采样 / 时序压缩编码
应用：视频摘要、监控异常检测、会议录像问答
```

视频的 token 预算是「图像经济 × 时间」——**帧采样策略**（均匀采样 vs 关键帧检测）直接决定成本与信息保留。长视频的理解仍是开放问题——「先分段摘要再汇总」的分层处理是实用解法。

## 7. 多模态应用模式

| 模式        | 组合                                     | 例                                  |
| --------- | -------------------------------------- | ---------------------------------- |
| 文档理解      | VLM + [结构化输出](14-structured-output.md) | 发票/合同字段提取                          |
| 视觉 RAG    | 文档截图入库 → [多模态检索](08-rag.md)            | 版式复杂的 PDF（表格图表混合）                  |
| GUI Agent | 截图 → VLM 理解界面 → 输出点击坐标                 | 自动化操作（[Agent](09-agents-tools.md)） |
| 视觉质检      | VLM + 检测模型 + 规则                        | 生产缺陷初筛                             |
| 语音助手      | ASR + LLM + TTS / 端到端                  | 客服电话/车载                            |

「视觉 RAG」值得展开：传统 RAG 的 OCR 管线（PDF→文本）会丢失**版式信息**（表格结构/图表/图文关联）——**文档截图直接入库、多模态检索、VLM 读图回答**保留了完整视觉语义——版式复杂文档（财报/扫描件）的精度提升显著。代价：图像 token 的存储与成本（[第 6 篇](06-inference-decoding.md)）。

## 8. 陷阱清单

- 高分辨率直塞（成本平方爆炸）：按任务选分辨率 + ROI 裁剪。
- 计数/测量的过度信任：视觉 token 不保留个体边界；精确计数走检测模型。
- 视觉幻觉无防线：要求「描述有据」+ 位置引用 + 低置信拒答。
- 文档理解丢版式：OCR 文本流丢失表格结构——截图方案或版式感知解析。
- 语音链路的延迟失控：三段式逐段优化；流式与端到端是演进方向。
- 多图任务的窗口爆量：token 线性叠加；图数量与分辨率是预算变量。
- 增强与预处理的不一致（训练与推理的图像预处理不同——[skew](../ai/09-deployment.md) 的多模态版）。
- 视频全帧直塞：帧采样策略先行。

## 9. 小结

- 多模态的统一抽象「一切皆 token」：模态各有编码器、共享 Transformer——语言能力外溢到视觉与语音。
- VLM 组装三件：ViT 编码器（看见什么）+ 投影层（翻译）+ LLM（推理）——投影层是质量瓶颈。
- 图像 token 对分辨率平方敏感：按任务选分辨率 + ROI 裁剪——多图的预算核算必须前置。
- 失败模式：计数/测量/小字/视觉幻觉——精确任务走工具（OCR/检测），VLM 管语义。
- 应用模式的黄金组合：VLM + 结构化输出（文档提取）、截图 + Agent（GUI 自动化）、截图入库 + 检索（视觉 RAG）。

## 10. 练习

**1.** 分辨率-能力实验：同一张含小字的文档截图，分别以原始分辨率与缩半分辨率让 VLM 做 OCR——对比字符准确率与 token 成本——建立「分辨率预算」的任务决策表。

> [!TIP]
> 思路OCR 的精度悬崖通常在「字号 × 分辨率」的交叉点——小字场景省分辨率 = 数据毁灭。而场景理解任务在低分辨率下几乎无损。逐任务实测是唯一可靠的分辨率策略。

**2.** 计数失败实验：生成含不同数量物体（3/7/15/40 个）的图片，让 VLM 计数——画出「数量-准确率」曲线，验证「视觉 token 不保留个体边界」的失败模式；再用检测模型（YOLO 类）对照。

> [!TIP]
> 思路少量（≤5）计数可能对、多了系统性偏差——「精确计数」这个需求的正确架构是检测模型计数 + VLM 做语义描述的分工。

**3.** 视觉幻觉测试集：构造「图片 + 诱导性问题」（「图里那辆红车是什么牌子」——图里没有红车）——统计 VLM 顺着编造的比例 vs 拒答比例——量化视觉幻觉并测试「只描述确定看到的」prompt 的防线效果。

> [!TIP]
> 思路诱导问题的幻觉率是 VLM 安全评估的核心指标——与 [文本幻觉测试](01-what-is-llm.md)（不存在文献）同构。位置引用（要求给 bounding box）能显著压制无中生有。

**4.** 文档理解对比：同一份含表格的扫描 PDF，分别走「OCR 文本流 + LLM」与「截图 + VLM」两条管线提取表格——对比表格结构的还原精度——验证「版式信息」的价值。

> [!TIP]
> 思路OCR 版的表格「串行化」丢失行列结构（合并单元格更是灾难）；VLM 直接读图保留二维结构。但 OCR 版便宜且可全文检索——混合（OCR 做检索索引 + VLM 做精读）是务实架构。

**5.** 语音链路延迟拆解：搭一个最小语音对话（Whisper ASR → LLM → TTS），用计时埋点拆解三段的延迟分布——计算总延迟与「自然对话 <1.5s」目标的差距，指出优化优先级。

> [!TIP]
> 思路延迟优化的优先级 = 各段耗时 × 可压缩性：流式 ASR（边说边转）、流式 TTS（首包快）、LLM 的 TTFT（[第 6 篇](06-inference-decoding.md)）。端到端语音模型的吸引力就是消灭「段间等待」。

**6.** 讨论：多模态模型「用一个 Transformer 处理所有模态」与「每模态专用模型」的路线之争——从「跨模态迁移（看图推理借用文本推理）」「模态间干扰（视觉 token 挤占文本能力？）」「工程复杂度」三个角度分析两种路线的得失，并判断你所在的产品应该「多模态一体化」还是「模态分工」。

> [!TIP]
> 思路一体化路线的红利：跨模态任务（看图写代码、语音对话）与统一接口；代价：训练复杂、模态间可能互相干扰（评测要分模态做）。分工路线：每个模态用最优专用模型 + 编排层组合——工程可控但跨模态推理弱。「任务是否需要模态间深度交互」是分界。
