提示词（prompt）是与模型唯一的接口。它不是玄学咒语，而是一种**接口设计**：模型只会响应你给定的上下文，所有信息缺失、歧义、格式混乱，最终都变成输出质量的随机性。本篇给出可复用的方法框架。

## 先立规矩：系统提示

System prompt 是优先级最高的持久指令，适合放：角色与边界、输出格式约定、永远生效的规则。用户消息放具体任务。一次高质量调用通常是：

```text
[system]  你是资深代码评审。只指出问题，按严重程度排序，每条不超过两句话。
          不确定的结论必须标注"待确认"。用中文。
[user]    <待评审代码>

<这里贴代码>
```

三条普适原则：

1. **上下文完整**：模型不知道你没说的话。目标、受众、约束、示例——缺什么它就编什么
2. **具体胜过抽象**："写正式一点"不如"商务邮件语气，避免口语和感叹号"
3. **结构对齐结构**：要列表就明说几条、要 JSON 就给 schema、长输入用 `<doc>` 之类的分隔符包起来

## Few-shot：示例是最强的规格说明

描述十次不如示范一次。在提示里放 2~5 个"输入 → 期望输出"的示例，格式、风格、边界处理全部自动对齐：

```text
将地址规范化为 JSON。
输入: 北京市海淀区中关村大街1号
输出: {"city": "北京", "district": "海淀区", "street": "中关村大街1号"}

输入: 上海市浦东新区世纪大道100号
输出: {"city": "上海", "district": "浦东新区", "street": "世纪大道100号"}

输入: 广州天河路228号
输出: 
```

- 示例要覆盖**边界情况**（缺省份、有歧义），模型会沿用你对边界的处理方式
- 示例标签写"输入/输出"并保持严格一致——模型对格式的模仿是逐字符级的

## 思维链：让模型先想后答

要求"一步步思考"或显式给出推理步骤，能显著提升数学、逻辑、多步任务的准确率：

```text
错误的裸问:  小明有 23 个苹果……问还剩几个？     ← 直接输出，容易口算出错
CoT 版本:    请一步步推理，最后用"答案："给出结果
```

原理：模型按 token 生成，**中间步骤就是它的草稿纸**——每一步生成都有条件地约束下一步，错误率随推理链变长而下降。推理模型（o1/R1 类）把这个思想做进了训练里：内部生成长思维链再输出结论，用户只需给目标。

> [!NOTE]
> CoT 对简单任务反而啰嗦且慢。按任务难度分级：简单任务直接答，中等任务要求分步，复杂任务用推理模型——"提示词分级"是成本与质量的基本平衡术。

## 结构化输出：为下游程序负责

程序消费的输出必须是可解析的。三个手段，由弱到强：

1. **提示约定 + 解析重试**：给 schema、给一个完整示例，解析失败把错误信息喂回去重试
2. **JSON Mode / 结构化输出 API**：主流 API 支持按 JSON Schema 约束生成，语法层面保证合法
3. **函数调用（function calling）**：模型输出结构化的"工具调用意图"，由框架执行——这是 Agent 的地基（第 09 篇）

## 常见反模式

- **一次塞十个任务**：拆开串行/并行调用，单任务质量远高于多任务混合
- **负面指令堆砌**："不要啰嗦不要编造不要……"不如直接说清"是什么"——模型对正向指令的遵循远好于禁令
- **把模型当搜索引擎问事实**：知识截止 + 幻觉，事实类问题应配检索（RAG）或工具
- **零样本死磕**：同一任务反复改写十次，不如加两个示例一次到位
