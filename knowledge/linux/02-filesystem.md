Windows 的世界是「盘符 + 文件夹」；Linux 的世界是**一棵从 `/` 出发的树**——磁盘、U 盘、网络存储都是「挂」到树上的枝干。理解这棵树的第二个层次是：**文件名只是指向 inode 的入口**，真正的文件是另一层结构。目录地图（FHS）与 inode 模型，是本篇的两条主线。

## 1. 挂载树：所有存储汇入一棵树

```bash
df -h              # 看磁盘的「挂载点」与使用量
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda2        98G   42G   51G  46% /          ← 根文件系统
/dev/sda1       512M  312M  201M  61% /boot      ← 另一块分区挂在 /boot 上
tmpfs           7.8G  156M  7.7G   2% /run       ← 内存盘
```

「挂载」= 把一块存储接到树的某个节点上，那个节点之后的内容就来自这块存储。`/home` 可以是独立分区、网络文件系统（NFS）、加密盘——**路径不变，背后是哪块盘对应用透明**。这个模型统一了本地盘、U 盘、CD、NFS、SMB 的访问方式（挂上就用 `cd`）。

`mount`/`umount` 手动挂载，`/etc/fstab` 定义开机自动挂载（每行六个字段：设备、挂载点、文件系统类型、选项、dump、pass）：

```text
UUID=xxxx  /home  ext4  defaults  0  2
```

生产环境 fstab 写错会导致开不了机——改它先用 `mount -a` 验证（模拟挂载全部条目）。

## 2. FHS：目录地图的语义

FHS（Filesystem Hierarchy Standard）规定了「什么放哪里」。背这张表的正确姿势是记住**每个目录的「变更频率」与「归属」语义**：

| 目录                      | 语义                                 | 关键判断                |
| ----------------------- | ---------------------------------- | ------------------- |
| `/bin`, `/sbin`         | 基础命令（用户/管理员）                       | 系统最小可用所需            |
| `/etc`                  | **全系统配置**（纯文本）                     | 可 diff、可版本控制——运维的核心 |
| `/home/用户`              | 用户数据                               | 用户自己负责备份            |
| `/root`                 | root 用户的家（不在 /home，单用户系统也要能用）      | <br />              |
| `/tmp`                  | 临时文件（重启可能清空）                       | 永远不要放重要东西           |
| `/var`                  | **可变数据**：日志 `/var/log`、邮件、缓存、数据库   | 增长区——磁盘报警先看这里       |
| `/usr`                  | 发行版安装的软件（`/usr/bin` 大部分命令在此）       | 包管理器的领地             |
| `/usr/local`            | 管理员手动安装的软件                         | 与包管理器共存不打架的约定位置     |
| `/opt`                  | 第三方整包软件（一个目录一个应用）                  | 大型闭源软件的习惯位置         |
| `/boot`                 | 内核与引导文件                            | 独立分区（历史与稳妥）         |
| `/proc`, `/sys`, `/dev` | 内核视图与设备（[第 1 篇](01-philosophy.md)） | 不是磁盘！               |

`/etc` 的值得单独强调：Linux 的「注册表」是纯文本目录——`grep` 一下就能查配置、`git` 起来就是变更审计、`scp` 一份就是备份。**Linux 服务器运维的基本功一半在 `/etc`**。

软件安装位置的决策树：包管理器装的进 `/usr`（别碰）；自己编译的进 `/usr/local`；整包软件进 `/opt`；「我这台机器只有我用」的小脚本放 `/usr/local/bin` 或 `~/.local/bin`（后者在用户 PATH 里）。

## 3. 路径：绝对、相对与家目录

```bash
/etc/nginx/nginx.conf      # 绝对路径：从 / 出发，无歧义
cd /var/log && cd nginx    # 相对路径：从当前目录出发
cd ..                      # 上一级；cd - 回上一个目录；cd ~ / cd 回家
../conf/extra.conf         # 相对引用（脚本里慎用——依赖调用者的 cwd）
```

- **脚本与配置里一律绝对路径**：相对路径依赖「当前目录」，而当前目录是运行时状态——cron 任务、systemd 服务、SSH 远程执行的 cwd 与你的终端完全不同。这是「脚本在我机器上能跑」的第一大来源。
- `~` 是 Shell 展开的（内核不懂波浪号）——所以它在传给其他程序的参数里不一定有效。

## 4. inode：文件名与文件的分离

### 4.1 模型

磁盘上的每个文件是两样东西的组合：

```text
inode（索引节点）：文件的「身份证」——大小、权限、时间戳、数据块指针
目录项（dentry）：「文件名 → inode 编号」的映射，存在目录的「内容」里
```

目录的本质是**一张「名字 → inode 号」的表**——这就是为什么：

- 同一文件可以有多个名字（硬链接）。
- 文件名不存任何「文件信息」，改名/移动（同一文件系统内）只改目录表，**inode 与数据纹丝不动**——`mv` 几十 GB 文件瞬间完成的原因。
- `ls -i` 显示 inode 号；`stat file` 看完整元数据。

### 4.2 硬链接 vs 软链接

```bash
ln target.txt hard.txt        # 硬链接：多一个「目录项」指向同一 inode
ln -s target.txt soft.txt     # 软链接（符号链接）：一个「指向路径的文件」

ls -li
# 123456 -rw-r--r-- 2 ... target.txt   ← 链接数变成 2（第二列）
# 123456 -rw-r--r-- 2 ... hard.txt     ← 同一 inode 号！
# 789012 lrwxrwxrwx 1 ... soft.txt → target.txt   ← 新 inode，类型是 l
```

| 维度    | 硬链接                | 软链接               |
| ----- | ------------------ | ----------------- |
| 本质    | 同一 inode 的另一个名字    | 存着「路径字符串」的独立文件    |
| 原文件删除 | 无影响（数据还在，链接数 −1）   | 变成**悬垂链接**（指向不存在） |
| 跨文件系统 | ❌（inode 是文件系统内部概念） | ✅（只是路径字符串）        |
| 对目录   | ❌（防环，内核禁止）         | ✅                 |
| 跟随行为  | 「就是同一个文件」          | 大多数命令默认跟随（-h 不跟随） |

硬链接的正当用途：备份快照（rsync --link-dest 的原理）、防误删（多一个名字，删一个还在）。软链接的正当用途：**版本切换**（`/usr/lib/libssl.so.3 → libssl.so.3.0.13`——升级库只需换链接）、配置别名、路径重组。

悬垂软链接（目标被删）不会自动消失，`find -xtype l` 可以找出来清理。

## 5. 文件类型的七种形态

`ls -l` 首字符即类型：

```text
-  普通文件           d  目录
l  符号链接           b  块设备（磁盘）
c  字符设备（终端）    s  套接字（进程间通信端点）
p  命名管道（FIFO）
```

「Linux 一切皆文件」的物证：`/dev/sda` 是 b、`/dev/tty` 是 c、MySQL 的本地 socket 是 s——都通过统一的文件接口访问（[第 1 篇](01-philosophy.md)）。

## 6. 陷阱清单

- 相对路径进脚本/cron：cwd 不可靠；一律绝对路径或脚本开头 `cd` 到固定位置。
- /tmp 放重要数据：重启清空 + 任何本地用户可写（[第 4 篇](04-permissions.md)的粘滞位）；用 mktemp 或用户家目录。
- mv 跨文件系统以为瞬间完成：同 FS 改目录表、跨 FS 是「复制 + 删除」（大文件会真的搬运）。
- 删文件后以为空间立刻释放：进程还开着该文件时空间不释放（/proc/\*/fd 可见）——日志文件 rm 后磁盘仍满的经典原因（`lsof | grep deleted`）。
- 软链接指向相对路径：随链接自身位置变化而漂移；系统级链接一律绝对路径。
- 把 /usr 当自己的 playground：那是包管理器领地；手动安装走 /usr/local、/opt。
- 硬链接目录、跨盘硬链接：内核直接拒绝；那是软链接的活。

## 7. 小结

- 存储是挂到树上的枝干：`df` 看挂载点，fstab 管开机挂载；路径不变、后端存储可替换。
- FHS 的语义记忆法：`/etc` 配置（纯文本可 diff）、`/var` 可变数据（磁盘报警先看 /var/log）、`/usr` 包管理器领地、`/usr/local` 与 `/opt` 管理员自留地、`/tmp` 临时。
- inode 模型：文件名是目录表里的映射，真身是 inode——同一文件系统 mv 瞬间完成、硬链接共享 inode、软链接存路径字符串。
- 硬链接防误删与快照去重；软链接做版本切换与路径重组；悬垂软链接要主动清理。
- 文件类型七种是「一切皆文件」的物证；脚本与配置一律绝对路径。

## 8. 练习

**1.** 用 `ls -li` 与 `stat` 对比一个文件、它的硬链接、它的软链接三者的 inode 号、链接数、类型字符，画出「目录项 → inode → 数据」的图。

> [!TIP]
> 思路硬链接与原文件同 inode（链接数 2），软链接是独立 inode + `l` 类型。图上标出「删除原文件后两条链接各自的下场」——硬链接仍完整、软链接悬垂。

**2.** 实验验证「同一文件系统 mv 瞬时、跨文件系统 mv 是复制」：在 /（与 /tmp 若同盘）内 mv 一个大文件计时，再 mv 到另一块盘/虚拟盘对比。

> [!TIP]
> 思路`df` 先确认挂载点分布。同 FS：目录表改一行；跨 FS：字节级拷贝。这也解释了「为什么有的 mv 会显示进度、有的瞬间完成」。

**3.** 找出系统里三个悬垂软链接（`find / -xtype l 2>/dev/null | head`），分析它们指向的路径为什么消失了。

> [!TIP]
> 思路常见来源：包升级换了带版本号的实体（libxxx.so.3.1 → 升级后没了）、用户目录清理。软链接的「生命周期管理」是它们唯一的弱点。

**4.** 画出你的系统 FHS 图：用 `ls /` 起步，对每个目录给出「语义 + 一个例子文件」，标出哪些在真实磁盘、哪些是内核视图。

> [!TIP]
> 思路`df -h` 对照挂载点区分真磁盘与 /proc /sys /dev /tmp（tmpfs）。画完这张图，「东西放哪」与「东西在哪」的问题终身受益。

**5.** 复现「rm 后磁盘不释放」：用大文件制造磁盘占用，`rm` 后看 `df` 与 `lsof | grep deleted`，解释机制并用最短方法释放空间。

> [!TIP]
> 思路持有该文件的进程（如 `tail -f`）不关闭，inode 引用数不为零。方法：重启该进程，或 `: > /proc/<pid>/fd/<n>` 截断（就地释放）——生产环境日志轮转用 logrotate 而不是裸 rm 的原因。

**6.** 讨论：为什么 Linux 把配置集中在 /etc（纯文本）而 Windows 集中在注册表（二进制）？从「diff/备份/版本控制/出事时的可读性」四个维度对比。

> [!TIP]
> 思路文本配置天然适配 grep/diff/git（组合哲学的延伸）：两台机器 `diff -r /etc` 即可找出配置漂移。注册表的强项是事务与性能，代价是运维透明度。「配置即文档」是 Linux 运维文化的物质基础。
