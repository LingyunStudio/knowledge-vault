从 Windows 转过来的第一道坎：没有 C 盘 D 盘，只有一个从 `/` 长出来的树；第二道坎：扩展名只是名字的一部分，系统并不靠它判断文件类型。理解这两点加上 FHS 布局，你在任何 Linux 机器上都不会迷路。

## 一切皆文件

Unix 的核心设计：**设备、进程信息、套接字，统统抽象成文件**，用同一套读写接口访问。

- `/dev/sda` 是整块硬盘，`/dev/tty` 是你的终端
- `/proc/cpuinfo` "读"一下就是 CPU 信息——它不在磁盘上，是内核实时生成的
- `/dev/null` 是黑洞设备：往里写什么都消失，读它得到 EOF——丢弃输出的标准去处
- 管道、网络连接在内核眼里和文件没有本质区别

这个抽象的价值：一套 open/read/write 打天下，不用为每种资源学一套 API。`free -h` 看内存和 `cat /proc/meminfo` 直接读虚拟文件，看到的是同一份数据——工具的底层全是这套文件接口。

```bash
cat /proc/loadavg             # 系统负载——uptime 显示的数字就来自这里
cat /sys/class/net/eth0/mtu   # 网卡的 MTU 同样是个"文件"
```

## FHS：目录布局是有标准的

FHS（Filesystem Hierarchy Standard）规定了各目录放什么。发行版都遵守它，所以你登录任何机器都能盲猜路径：

| 目录 | 放什么 | 你会经常碰吗 |
| --- | --- | --- |
| `/etc` | 系统与应用的**配置文件**（纯文本） | 是，改配置全在这 |
| `/home/user` | 普通用户的家目录 | 是，你的东西放这 |
| `/root` | root 用户的家目录 | 偶尔 |
| `/var` | 经常变化的数据：日志、缓存、邮件队列 | 是，主要看 `/var/log` |
| `/tmp` | 临时文件，重启可能被清空 | 是 |
| `/usr` | 包管理器安装的软件与资源 | 读，一般不手改 |
| `/usr/local` | 自己编译安装的软件 | 装软件时 |
| `/opt` | 第三方大型软件整体安装（如 IDE） | 偶尔 |
| `/bin`、`/sbin` | 基础命令（现代发行版是指向 `/usr/bin` 的符号链接） | 读 |
| `/dev` | 设备文件 | 挂载磁盘时 |
| `/proc`、`/sys` | 内核与进程信息的虚拟文件系统 | 排查问题时 |
| `/boot` | 内核与引导程序 | 内核升级失败时 |
| `/srv` | 本机对外服务的站点数据（约定俗成，用得不多） | 偶尔 |
| `/run` | 运行时数据：PID 文件、套接字（tmpfs，重启清空） | 偶尔 |
| `/mnt`、`/media` | 手动挂载点 / 可移动介质自动挂载处 | 挂盘时 |

记忆口诀：**配置在 etc，日志在 var，自己装的在 usr/local 或 opt，系统目录别乱动**。家目录之外的操作，八成需要 sudo（见[权限与用户](04-permissions.md)）。`/var/log` 里最常翻的是 `syslog`（或 RHEL 系的 `messages`）系统总日志和 `auth.log` 登录与授权记录；新系统优先用 `journalctl`，但老工具和第三方服务仍在往文件里写。

以 `.` 开头的是隐藏文件，`ls` 默认不显示、`ls -a` 才可见——shell 配置几乎全是隐藏文件（`.bashrc`、`.gitconfig`），这是家目录看起来"很干净"的原因。

> [!NOTE]
> 文件系统**大小写敏感**：`Readme.md` 和 `readme.md` 是两个文件。Windows 上跑得好好的代码（include 路径、import 语句）搬到 Linux 报"文件不存在"，先查大小写。

## 路径：绝对与相对

```bash
cd /var/log          # 绝对路径：以 / 开头，从根出发，在哪个目录敲都对
cd logs              # 相对路径：相对当前目录
cd ..                # 上一级
cd ../..             # 上两级
cd ~                 # 家目录，~ 是 /home/你的用户名 的缩写
cd ~alice            # 别人的家目录（有权限才行）
cd -                 # 上一次所在目录，两个目录间来回横跳
ls -ld /tmp          # -d：看目录本身的属性，而不是列出目录内容
pwd                  # 显示当前目录的绝对路径，拿不准就敲一下
realpath link.txt    # 解析符号链接，给出真实的绝对路径
stat report.txt      # 文件全息信息：大小、inode、属主、三个时间戳
```

`stat` 顺带引出三个时间戳：**mtime**（内容修改时间，`ls -l` 显示的就是它）、atime（最后读取时间）、ctime（inode 变更时间——改名、改权限都会动它，c 是 change 不是 create）。脚本里判断"文件变没变"用的是 mtime。

`~`、`.`、`..` 是 shell 在你敲回车那一刻**展开**的；`.` 和 `..` 是每个目录自带的两个特殊条目，真实文件系统里并不存在名叫 `~` 的东西。

> [!TIP]
> 路径记不全就 `Tab` 补全——它能补目录名，连敲两下列出所有候选。交互时相对路径快，脚本里绝对路径稳，混合使用时注意脚本的工作目录取决于**谁启动了它**。

## 挂载点的直觉

Windows 给每个分区一个盘符；Linux 把每个文件系统**挂到目录树上**：一块新分区接入后，`/data` 这个目录"里面"就是那块盘的内容。

```bash
df -h                        # 各挂载点的磁盘用量（-h 人类可读）
du -sh *                     # 当前目录下各项占多大，和 df 配合定位空间去哪了
du -h --max-depth=1 /var     # 只看第一层子目录的大小，避免刷屏
lsblk                        # 列出所有块设备与挂载关系，比 fdisk -l 直观
sudo mount /dev/sdb1 /data   # 把分区挂到 /data
sudo umount /data            # 卸载
```

几个常见场景：U 盘等可移动介质由桌面环境自动挂到 `/media/用户名/卷标`；云服务器加数据盘走 `mount` + `/etc/fstab`；甚至远程目录也能挂——`sshfs user@host:/remote/path /mnt/remote`，把远端当本地目录读写。主流磁盘文件系统是 ext4 和 xfs，格式化用 `mkfs.ext4`。

开机自动挂载写在 `/etc/fstab`，写错会导致系统起不来——改完先 `sudo mount -a` 验证一遍（不重启就把所有条目挂一次），确认无报错再重启。

由此有一个反直觉的事实：**`rm` 删了大文件，磁盘空间却没变**。原因往往是还有进程握着这个文件——文件要等所有引用（包括打开它的进程）消失才真正释放。`lsof | grep deleted` 能揪出元凶，重启对应进程即可回收。

## 软链接与硬链接

每个文件在磁盘上的真身叫 **inode**（存权限、大小、数据块位置等元信息），目录里存的"文件名"只是指向 inode 的一个**硬链接**。

```bash
ln target.txt hard.txt       # 硬链接：给同一个 inode 再加一个名字
ln -s target.txt soft.txt    # 软链接（符号链接）：一个存着目标路径的新文件
ls -li                       # -i 显示 inode 编号：硬链接两者必然相同
```

| | 硬链接 | 软链接（`-s`） |
| --- | --- | --- |
| 本质 | 同一 inode 的另一个名字 | 独立的小文件，内容是目标路径 |
| 跨文件系统 / 分区 | 不能 | 能 |
| 链接目录 | 不能 | 能 |
| 删除原文件后 | 数据还在（链接数减 1，减到 0 才释放） | 变成悬空链接，指向不存在的路径 |
| 常见用途 | 备份去重、防误删 | 快捷方式、版本切换（如 `python -> python3.12`） |

> [!WARNING]
> `ls -l` 权限位后面的数字就是硬链接数，软链接显示为 1。删除"原文件"后软链接变悬空（`ls` 里标红失效），硬链接毫无感觉——这是区分两者最快的办法。

日常 90% 的场景用软链接。理解硬链接，是为了理解"删除"的真正含义：`rm` 只是删掉一个目录条目，inode 的引用计数归零、数据块才被回收——上一节"删了文件空间没变"就是这个机制在起作用。

同一机制的另一面是 **inode 耗尽**：inode 总数在格式化时就固定了，海量小文件可能在磁盘还有空余时把 inode 用光（表现为"明明有空间却写不进"）。`df -i` 看 inode 使用率——磁盘异常排查时，它是和 `df -h` 并排要查的一项。
