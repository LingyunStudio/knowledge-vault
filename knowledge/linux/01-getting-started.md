服务器上没有图形界面救你，一切操作都发生在命令行里。第一课不是背命令，而是理清三个概念：内核、发行版、shell——搞混它们，你连报错都读不懂。

## 内核与发行版

Linux 严格来说只是**内核**：管理 CPU、内存、磁盘、网络的那层程序。你实际安装、每天打交道的叫**发行版**（distribution）——把内核、shell、包管理器和一堆用户态工具打包成的完整系统。日常说"装个 Linux"，装的其实是某个发行版。

|          发行版          | 包管理    | 典型场景         |
| :-------------------: | ------ | ------------ |
|    Ubuntu / Debian    | apt    | 云服务器最常见，资料最多 |
| Fedora / RHEL / Rocky | dnf    | 企业服务器、红帽系    |
|     Arch / Manjaro    | pacman | 滚动更新，适合折腾    |

命令行层面各发行版 90% 相同，真正的分叉点是包管理器（见[软件包管理](08-packages.md)）。服务器选型一句话：Ubuntu LTS 或 Rocky，别在生产机上追新。

内核版本用 `uname -r` 看，系统版本用 `cat /etc/os-release` 看——求助报环境问题时，先报这两个再报症状，省去一轮反问。

## 终端、shell、bash：三个不是一回事

- **终端（terminal）**：一个窗口程序，负责显示文字、接收键盘输入，本身不解释命令。GNOME Terminal、Windows Terminal 都只是"显示器 + 键盘"
- **shell**：终端里真正干活的程序——读取你敲的每一行，解析后调用对应程序执行；变量、管道、脚本都是它提供的语言能力
- **bash**：shell 的一种实现，Linux 服务器的事实标准。同类还有 zsh（macOS 默认）、fish（交互友好但语法不兼容 POSIX）

打开一个终端 = 终端程序启动并运行一个 shell；SSH 连上服务器，对端给你起的同样是 shell（通常是 bash）。术语 TTY 是历史遗产——早期终端是打字机一样的物理设备，如今泛指文本会话本身（`/dev/tty`、`Ctrl+Alt+F3` 切出的控制台都是这个概念的遗存）。

> [!NOTE]
> "会用 Linux"这句话，80% 的实际含义是"会用 bash 和常用命令"。shell 是你未来几年一直打交道的那个界面，值得系统学，见[Shell 脚本](06-shell-scripting.md)。

## 命令的一般形态

所有命令都长一个样：`命令 + 选项 + 参数`。

```bash
ls -l /etc                 # ls 是命令，-l 是选项，/etc 是参数
ls -lah                    # 短选项可合并：-l -a -h 的缩写
ls --all                   # 长选项用双横线，--all 等价于 -a
grep -rn "password" src/   # 选项带值、参数是目录，结构完全一样
```

含空格的参数必须加引号，否则 shell 会把它拆成多个参数：

```bash
mkdir my docs        # ❌ 创建了 my 和 docs 两个目录
mkdir "my docs"      # ✅ 创建一个名字带空格的目录
```

读别人的命令行、查 man 手册，都按这个结构拆：哪些是开关，哪个是操作对象。

## 第一批命令

```bash
whoami          # 我是谁：当前用户名
pwd             # 我在哪：当前目录的绝对路径
ls              # 这里有什么：列出目录内容
ls -lah         # 长格式 + 含隐藏文件 + 人类可读大小
cd /etc         # 进入 /etc（绝对路径）
cd ..           # 回上一级
cd              # 不带参数：回家目录 ~
cd -            # 回上一次所在目录，两个目录间来回横跳
mkdir -p a/b/c  # 一口气创建多级目录（-p：父目录不存在也一并创建）
```

`cd` 只换目录不换"盘符"——Linux 没有盘符，一切从 `/` 开始，详见[文件系统与目录结构](02-file-system.md)。

三个快捷键的使用频率高于任何一条命令：

- `Tab`：补全命令名与路径，敲两下列出所有候选。养成习惯，少打一半字还防手误
- `Ctrl+R`：反向搜索历史命令，输入关键词即可命中之前敲过的完整命令，再按跳上一条匹配
- `Ctrl+C`：中断当前命令。程序卡死就按它，而不是关掉窗口

> [!TIP]
> `Ctrl+L` 清屏；`Ctrl+U` 删光标前整行、`Ctrl+W` 删一个词——改错字比退格快一个数量级。`history` 整页翻历史，`!$` 引用上一条命令的最后一个参数。

## 先学会读报错

新手期九成的报错就三种，每种都有固定的第一反应：

| 报错                          | 含义                 | 第一反应                                                               |
| --------------------------- | ------------------ | ------------------------------------------------------------------ |
| `command not found`         | 命令没装，或不在 PATH 里    | 先 `type 命令名` 排除拼写；再确认装没装，见[环境变量与 shell 配置](11-environment-vars.md) |
| `No such file or directory` | 路径写错，或当前目录不是你以为的目录 | `pwd` 确认位置，`ls` 确认名字（大小写敏感）                                        |
| `Permission denied`         | 权限不够               | 看清是谁对哪个文件做什么被拒（见[权限与用户](04-permissions.md)），确认该不该 sudo，而不是无脑加 sudo |

报错信息是系统在给线索，不是在批评你。**把报错原文读完整、看清是哪个命令报的**，比随手复制去搜索引擎快得多。

## man：说明书内置在系统里

Linux 的文档哲学是"离线可查"，几乎所有命令都有 man 手册：

```bash
man ls            # 查看 ls 的完整手册
man -k compress   # 关键词检索：哪些命令和 compress 有关
```

手册里只需记三个键：`/` 向下搜索（`n` 跳下一个匹配）、`q` 退出。`man ls` 有几千行，没人通读——带着具体问题去搜，比如"-a 选项到底做了什么"。

```bash
ls --help         # GNU 工具基本都支持，比 man 短得多
type ls           # 这个名字是别名、shell 内建还是外部程序？
which python3     # 这个命令对应的可执行文件在哪
```

`type` 常用来解惑：你以为调用的是程序，实际命中的是 alias 或内建命令。"为什么我的 ls 不带颜色"这类问题，先 `type ls` 再下结论。

## 在哪练：服务器与 WSL

- **WSL2（Windows 用户首选）**：`wsl --install` 一条命令装好 Ubuntu，真 Linux 内核跑在轻量虚拟机里。项目请放在 Linux 侧路径（如 `~/projects`），放在 `/mnt/c` 下 IO 性能差一个量级
- **云服务器**：真实环境，练完顺手把 SSH 密钥配上（见[SSH 与远程操作](09-ssh-remote.md)）。注意按量付费和安全组
- **虚拟机 / Docker 容器**：需要快照、随时推倒重来时用

别在"选哪个环境"上花超过一小时——它们只是外壳，里面跑的都是 bash。WSL 里 Windows 的盘挂在 `/mnt/c`，两边互拷文件直接 `cp` 就行；服务器上没有这些缓冲，敲错命令的代价更真实，这正是它练人的地方。

> [!WARNING]
> 命令行没有回收站。`rm` 删了就是删了，图形界面"反正能撤销"的直觉在这里是致命的。删除前先用同样的通配符跑一遍 `ls` 确认范围，详见[文件操作](03-file-operations.md)。
