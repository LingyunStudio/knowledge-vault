Linux 的学习曲线陡，往往因为学习者把它当成「一堆要背的命令」。实际上 Linux 只有几个核心观念，命令是观念的语法糖：**一切皆文件**（统一的抽象让一个 API 服务所有资源）、**小工具 + 组合**（每个程序只做好一件事，管道把它们串起来）、**用户态与内核态分离**（你的程序通过系统调用请求内核）。建立这三张图之后，命令行不再是咒语集，而是观念的自然表达。

## 1. 一切皆文件：一个抽象统一所有资源

UNIX 的创始人 Ken Thompson 与 Dennis Ritchie 做出了一个延续五十年的设计决策：**把尽可能多的资源抽象成「可以打开、读、写、关闭的文件」**。

```bash
ls -l /dev/sda        # 块设备：磁盘是个「文件」
ls -l /dev/tty        # 字符设备：终端是个「文件」
cat /proc/cpuinfo     # 进程信息：内核把 CPU 信息伪装成文件
echo 3 > /proc/sys/vm/drop_caches      # 「写文件」= 内核操作
```

「文件」这个抽象的收益是惊人的：**一套系统调用（open/read/write/close）服务所有资源**——磁盘、键盘、屏幕、网络、进程信息。你的程序读写磁盘和读写终端用同一组调用；工具处理「文件」的工具因此自动适用于「任何资源」：

```bash
cat /var/log/syslog | grep error      # cat 本来是读文件的，但管道让它能读任何字节流
wc -l < /proc/uptime                  # wc 能数「进程运行时长」的行数 —— 因为它也是文件
```

三个伪装成文件的内核接口值得认识：

| 路径      | 内容           | 典型用法                                 |
| ------- | ------------ | ------------------------------------ |
| `/proc` | 进程与内核状态的实时视图 | `/proc/<pid>/status`、`/proc/meminfo` |
| `/sys`  | 设备与驱动的参数树    | 调整硬件行为（如 LED、调度器）                    |
| `/dev`  | 设备节点         | `dd if=/dev/zero`、终端设备               |

## 2. 分层：你敲的字如何变成机器的动作

```text
┌─────────────────────────────┐
│ 应用层  bash / vim / nginx   │  ← 你的程序与工具
├─────────────────────────────┤
│ 系统调用层  open/read/fork    │  ← 应用进入内核的唯一合法通道
├─────────────────────────────┤
│ 内核  进程/内存/文件系统/驱动  │  ← Linux 本体
├─────────────────────────────┤
│ 硬件  CPU / 磁盘 / 网卡       │
└─────────────────────────────┘
```

术语校准（初学者最常混的三件事）：

- **内核（kernel）**：Linux 本体——进程调度、内存管理、驱动。你从不直接操作它，只通过系统调用。
- **Shell**：一个**普通程序**（bash/zsh/fish），读你敲的字符、解析成命令、调用其他程序。它不是内核的一部分。
- **终端（terminal）**：曾经是物理设备，现在是**模拟终端窗口**——Shell 运行在它里面。「终端」「Shell」「控制台」在口语中常混用，但分层上：终端模拟器（程序）→ 运行 Shell（程序）→ Shell 启动其他程序。

「命令」大多是独立的可执行文件（`/bin/ls`、`/usr/bin/grep`），Shell 只负责找到它们并启动——这个事实解释了很多行为：`cd` 为什么必须是内建（它要改变 Shell 自己的进程属性）、`PATH` 为什么决定命令能不能找到、`which ls` 能定位命令文件。

## 3. 组合哲学：小工具的乐高

Doug McIlroy 的 UNIX 哲学原文：「让每个程序只做好一件事。让程序的输出成为另一个程序的输入。」这不是美学口号，是**工程策略**：

```bash
# 需求：找出当前目录下最大的 5 个文件
du -ah . | sort -rh | head -6

# 需求：统计 nginx 日志里 404 最多的 10 个 URL
cat access.log | grep " 404 " | awk '{print $7}' | sort | uniq -c | sort -rn | head -10
```

第二行七个工具的流水线，在传统框架里是「一个日志分析程序」——而 Linux 里是**七件已存在、已测试、可组合的积木**。对比面向对象语言里「写一个类」的方案：组合方案的每一环都可以单独验证（去掉 `head` 看全量、换 `grep` 的模式调试）、任意两环可以插入新逻辑。**管道是 UNIX 的函数组合**。

这个哲学的另一面是每个工具遵守共同的约定：

- 输入输出是无结构的**字节流/文本行**（后续篇目会讲这个约定的代价与解法）。
- 退出码 0 = 成功，非 0 = 失败（脚本错误处理的基石）。
- 配置在纯文本文件里（`/etc`），可 diff、可版本控制。

## 4. man：内置的权威文档

命令忘了参数不要搜——**手册就在机器里**，而且是权威版本：

```bash
man ls                 # 读 ls 的手册
man -k password        # 关键词搜索（apropos 的别名）：哪些命令跟 password 有关
man 5 crontab          # ★ 第 5 节：crontab 文件的格式（而不是命令本身！）
```

手册分节，同名条目会出现在不同节里——`man crontab` 默认给你第 1 节（命令），但「crontab 文件怎么写」在第 5 节：

| 节 | 内容     | 例子                                 |
| - | ------ | ---------------------------------- |
| 1 | 用户命令   | `man 1 ls`                         |
| 5 | 配置文件格式 | `man 5 sshd_config`、`man 5 passwd` |
| 8 | 管理命令   | `man 8 systemctl`                  |

man 内的阅读：`/关键词` 搜索、`n` 下一个、`q` 退出（分页器 less 的快捷键）。很多现代工具自带 `--help`（快速）与 info/telemetry 文档——**层次是：`--help` 查速记，man 查语义**。

## 5. 发行版：内核 + 打包生态

「Linux」严格说是内核；日常说的 Linux 是**发行版** = 内核 + GNU 工具 + 包管理器 + 桌面/服务器套件。发行版差异的实质是**包管理生态与发布节奏**：

| 阵营        | 包管理           | 代表                   | 适合             |
| --------- | ------------- | -------------------- | -------------- |
| Debian 系  | apt / dpkg    | Debian、Ubuntu、Deepin | 服务器（稳定）、桌面友好   |
| Red Hat 系 | dnf/yum / rpm | RHEL、Rocky、Fedora    | 企业（RHEL 生命周期长） |
| Arch 系    | pacman / AUR  | Arch、Manjaro         | 滚动更新、追新、可控性    |
| 容器路线      | OCI 镜像        | Alpine、distroless    | 容器基础镜像（极小体积）   |

选择逻辑：**服务器选 LTS（长期支持）发行版**（Ubuntu LTS/Rocky），稳定性与安全补丁周期压倒新特性；学习环境用 Ubuntu/Arch 都行；容器里 Alpine（5MB 基底）或官方 runtime 镜像。命令行层面各发行版 95% 一致——**学的是通用的 UNIX 世界观，包管理只是方言**。

## 6. 虚拟环境与远程：你在哪台机器上敲字

学习与使用的真实形态：

```bash
ssh user@server          # 远程登录（[第 8 篇](08-network-remote.md)）—— 服务器世界的主入口
```

- **生产环境 = 远程 Linux 服务器**：多数开发者第一次「真正用 Linux」是在 SSH 会话里——没有鼠标、没有图形界面、一切都通过命令。
- **本地实验**：WSL2（Windows 子系统）、虚拟机、双系统皆可。WSL2 是最低摩擦的入门路径（完整 Ubuntu 用户态 + 文件互通）。
- **风险隔离的习惯**：在虚拟环境/容器里练习危险操作（[第 11 篇](11-ops-pitfalls.md)的 rm 事故），肌肉记忆建立之前不要在重要机器上练习。

## 7. 陷阱清单

- 背命令不建立模型：`grep/sort/uniq` 会忘，管道模型不会；先观念后命令。
- 混淆 Shell 与终端与内核：`cd` 内建、`PATH` 由 Shell 解析、权限由内核执行——分层决定谁管什么。
- 以为 Linux 命令「跨发行版全一样」：包管理器是方言（apt/dnf/pacman）；POSIX 通用部分才可移植。
- 搜索文档先搜引擎：`man -k`、`man 5` 先行——手册比网页更接近你机器上的真实版本。
- 在生产机器上学习：实验用 WSL/虚拟机/容器；rm 类操作肌肉记忆成熟前隔离练习。
- 把 `man 1` 当全部：配置文件格式在第 5 节、管理命令在第 8 节；`man -k` 找入口。

## 8. 小结

- 一切皆文件：统一的文件抽象让一套系统调用服务磁盘/终端/网络/内核信息；`/proc`、`/sys`、`/dev` 是三个内核伪装的文件世界。
- 分层：终端模拟器（窗口）→ Shell（解析与调度）→ 系统调用 → 内核。「命令」多为独立可执行文件，PATH 决定查找。
- 组合哲学：每程序做好一件事 + 字节流管道 = 可验证、可插拔的流水线；约定（文本、退出码 0/非 0、纯文本配置）是组合的粘合剂。
- man 分节阅读（1 命令/5 配置/8 管理），`man -k` 按关键词找命令；`--help` 查速记、man 查语义。
- 发行版 = 内核 + 包生态：服务器选 LTS 阵营，命令行的通用部分跨发行版稳定。
- 学习路径：WSL2/虚拟机起步，SSH 进入服务器世界，危险操作隔离练习。

## 9. 练习

**1.** 用 `man -k` 找出三个你没见过但与你日常任务相关的命令（如压缩、进程、网络），读它们的 man 第一屏，写出一句用途总结。

> [!TIP]
> 思路`man -k compress` 会列出 gzip/bzip2/xz/zstd——同一个任务的竞争方案。读 SYNOPSIS（概要）与 DESCRIPTION 首段即可判断「是否值得深学」。

**2.** 验证「Shell 是普通程序」：`which bash`、`ps -p $$`（当前 Shell 的进程）、在一个 Shell 里启动另一个 `bash --norc` 并退出——观察进程树变化。

> [!TIP]
> 思路`ps -f --forest | grep bash` 看嵌套。理解「Shell 是进程」后，环境变量继承（子进程复制）、作业控制、退出码传递全部有了进程模型的解释。

**3.** 用管道把「查找本机最大的三个目录」组织成流水线，逐段验证：先 `du`，加 `sort`，最后 `head`——体会「每段可单独调试」的组合红利。

> [!TIP]
> 思路`du -h --max-depth=2 /var | sort -rh | head -5`。拆开跑：`du` 的输出是什么形状？`sort -rh` 为什么能正确排人类可读的大小（h 排序的语义）？每段独立可测是组合哲学的核心。

**4.** 探索 /proc：读 `/proc/self/status` 找到你当前 Shell 的内存占用；读 `/proc/<某进程id>/cmdline`；解释为什么这些「文件」的大小都是 0 却能读出内容。

> [!TIP]
> 思路/proc 是内核动态生成的视图——读它触发内核实时构建内容，不存在磁盘上的字节。大小 0 是因为内容无「文件长度」可言。这扩展了「文件」的心智模型：文件接口 ≠ 磁盘存储。

**5.** 在 man 里查 `man 5 crontab`，对比 `man 1 crontab` 的内容差异；再查一个你熟悉的配置文件（如 sshd\_config）的第 5 节，总结第 5 节手册的写作模式。

> [!TIP]
> 思路第 5 节 = 「文件的格式规范」：逐字段说明 + 示例。它回答「配置怎么写」，第 1 节回答「命令怎么用」——两者配对是系统管理的基本阅读姿势。

**6.** 讨论：为什么「退出码 0 表示成功」与直觉（0 = 无错误）相反却能在脚本里形成优雅的错误处理？结合 `&&` 与 `||` 的 Shell 语义写一个「失败即停止」的链条。

> [!TIP]
> 思路`cmd1 && cmd2 || on_error` 的短路链条把退出码变成了控制流。约定本身无所谓对错，**全生态一致**才是价值——这正是组合哲学的元教训：统一约定胜过各自聪明。
