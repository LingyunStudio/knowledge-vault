前端的特殊处境：**你的程序运行在别人的机器上**（用户的浏览器）——你无法控制运行环境（浏览器版本/设备/网络）、代码对用户可见（F12 即源码）、更新即时生效（刷新即新版）。理解这个处境，前端的诸多「怪癖」（兼容性、渐进增强、构建工具）都有了因果。

## 1. 从 URL 到像素：一次页面加载的全链路

```text
输入 URL https://example.com
1. DNS 解析：域名 → 服务器 IP（[net 篇](../net/06-dns.md)）
2. TCP + TLS 握手：建立加密连接（[net 篇](../net/07-tls-security.md)）
3. HTTP 请求/响应：拿到 HTML 文档
4. 解析 HTML → 构建 DOM 树
   ↘ 遇到 <link> CSS → 构建 CSSOM（渲染阻塞）
   ↘ 遇到 <script> → 下载执行（默认阻塞解析！defer/async 改变行为）
5. DOM + CSSOM → 渲染树 → 布局（计算几何）→ 绘制（像素）→ 合成
6. JS 执行：脚本运行、事件绑定、动态修改 DOM
```

两个关键概念从这个链路里长出来：

- **渲染阻塞**：CSS 阻塞渲染（避免裸样式闪烁）、同步 script 阻塞解析（JS 可以改 DOM）——加载性能优化的主战场（`defer`/`async`/关键 CSS）。
- **渲染流水线**：布局（layout）与绘制（paint）有成本——JS 频繁改样式引发重排/重绘是性能问题的常见根因（[第 6 篇](06-dom-events.md)）。

「打开 F12 看这一切」：Network 面板看每步的时序与大小、Performance 面板录制渲染流水线、Elements 面板看 DOM——**DevTools 是前端的第一调试器**（[第 10 篇](10-http-storage.md)的网络细节）。

## 2. 三大语言：结构、样式、行为

| 语言  | 职责         | 形态                             |
| ----- | ------------ | -------------------------------- |
| HTML  | 结构与语义   | 「这是标题、这是按钮、这是导航」   |
| CSS   | 表现         | 「标题多大、按钮什么色、导航在哪」 |
| JS    | 行为与逻辑   | 「点击按钮后发生什么」             |

分离的关注点（separation of concerns）是 Web 的架构基石——HTML 描述「是什么」而不是「长什么样」（语义化，[第 2 篇](02-html.md)），CSS 负责「长什么样」，JS 负责「做什么」。三者的耦合点在 **DOM**（JS 操作 HTML 的接口）与**事件**（用户行为的入口）。

## 3. 浏览器的关键组件

```text
┌─────────────────────────────────────┐
│  用户界面（地址栏/标签页）             │
├─────────────────────────────────────┤
│  浏览器引擎（标签页管理/网络/存储）      │
│  ├─ 渲染引擎：HTML/CSS → 像素          │
│  │    ├ DOM/CSSOM/布局/绘制            │
│  │    └ JS 引擎（V8）：解析/执行/JIT    │
│  ├─ 事件循环：调度 JS 执行（[第 7 篇](07-async.md)）│
│  └─ 存储：cookie/localStorage/IndexedDB│
└─────────────────────────────────────┘
```

- **渲染引擎**（Chrome/Edge 的 Blink、Safari 的 WebKit、Firefox 的 Gecko）：解析与绘制——「不同浏览器长得不一样」的来源（兼容性问题的根）。
- **JS 引擎**（V8/SpiderMonkey/JSC）：JS 的解释与 JIT 编译——V8 的高性能让 JS 从玩具变成平台（Node.js 就是「把 V8 拿出来放服务器上」，[python 篇](../python/01-python-model.md)的运行时同位概念）。
- **事件循环**：JS 单线程模型的调度核心——异步的全部秘密（[第 7 篇](07-async.md)）。
- **同源策略与沙箱**：网页代码的权限被严格限制（不能随意读本地文件/跨域请求）——浏览器是 JS 的「操作系统」，安全模型是它的一部分（[第 10 篇](10-http-storage.md)）。

## 4. 前端工程的地形

```text
原生三件套（HTML/CSS/JS）─── 理解一切的底层
    ↓ 复杂度增长
框架（React/Vue/Svelte）─── 组件化与状态驱动 UI（[第 9 篇](09-react.md)）
    ↓ 构建需求
工具链（npm/Vite/TS）─── 包管理/打包/类型（[第 8 篇](08-modules-tooling.md)）
```

学习路线的争议（先框架还是先原生）在本教程的立场是：**先原生地基（本篇到第 8 篇），再上框架**——框架是原生能力的封装（React 的状态更新底层是 DOM 操作与事件循环），地基不稳则框架的理解浮于 API 表面。

现代前端的两个趋势值得知道：**TypeScript**（JS + 静态类型——渐进类型思想与 [python 篇](../python/12-quality.md)一致）已成事实标准；**构建工具**（Vite/SWC/esbuild）用原生 ESM 与高性能语言重塑了开发体验。

## 5. 渐进增强与响应式：Web 的适应哲学

- **渐进增强**：基础功能在「最低配」环境可用（HTML 结构 + 无 JS 也能导航），增强层（JS/动画）按能力叠加——「核心内容不依赖 JS」是无障碍与稳健性的保障。
- **响应式设计**：一份代码适配手机/平板/桌面（媒体查询、流式布局）——Web 的「跨平台」不是移植而是自适应（[第 4 篇](04-css-layout.md)）。
- **兼容性策略**：面向「evergreen 浏览器」（自动更新的现代浏览器）+ 需要时用构建工具降级（polyfill/transpile）——「支持 IE」的时代已过去，但「了解你的用户在用什么」的纪律不变。

## 6. 陷阱清单

- 从框架入门跳过原生地基：React 报错看不懂（事件循环/作用域/this）；地基先行的学习路线。
- 把 Web 当「本地程序」：无文件系统/无持久内存/跨域受限；Web 平台的安全模型先建立。
- 忽视渲染阻塞与加载时序：script 放头部同步加载；defer/async 与资源优先级。
- 在一种浏览器上测试完事：Safari（WebKit）的行为差异是真实成本；特性检测（feature detection）优于浏览器嗅探。
- DevTools 只用 Elements：Network/Performance/Console 是三大主力面板。
- 「F12 可见」就不在乎代码质量：前端代码同样要测试/审查/工程化（用户看到源码不等于源码可以乱）。

## 7. 小结

- URL 到像素的六步链路（DNS/TCP/HTTP/DOM/渲染树/绘制）+ 两个机制（渲染阻塞、渲染流水线）——性能优化与加载策略的坐标系。
- 三大语言的分工是 Web 的架构基石：结构（语义）、表现（CSS）、行为（JS）通过 DOM 与事件衔接。
- 浏览器组件地图：渲染引擎（兼容性来源）、JS 引擎（V8——Node 的同款心脏）、事件循环、沙箱与同源策略（Web 的安全模型）。
- 工程地形：原生 → 框架 → 工具链；「先地基后框架」的学习路线与 TypeScript 的事实标准地位。
- Web 的处境哲学：运行在别人的机器上——渐进增强、响应式、特性检测是适应性的三大策略。

## 8. 练习

**1.** 用 DevTools 的 Network 面板录制一个网页的加载：找出 HTML/主 CSS/主 JS 各自的时序、大小与依赖关系；解释「为什么 CSS 在 JS 前加载完」。

> [!TIP]
> 思路观察 waterfall 图的串并行：HTML 先到、CSS 渲染阻塞、JS defer 后延。水的瀑布图是「渲染阻塞」概念的具象化。

**2.** 写一个最小页面（无框架）：标题、按钮、点击后改文字——分别用「结构/样式/行为」三文件组织，体会三语言分工与 DOM 的衔接点。

> [!TIP]
> 思路index.html + style.css + script.js 三文件、script 用 defer 引入。这个 20 行的最小标本就是一切框架最终展开成的原语。

**3.** 在 DevTools 的 Performance 面板录制「滚动一个长页面」，找出 layout/paint/composite 的占比；再人为制造「每帧改布局」的循环观察重排的代价。

> [!TIP]
> 思路性能面板的火焰图里 layout（紫色）频繁出现 = 重排风暴——「读写分离批量改样式」的优化动机（[第 6 篇](06-dom-events.md)）由此建立。

**4.** 用 `navigator.userAgent` 与特性检测（`'IntersectionObserver' in window`）两种方式写「能力分支」，讨论为什么社区推荐后者（[git 篇的探测逻辑下放](../git/09-hooks-automation.md)对照）。

> [!TIP]
> 思路UA 嗅探依赖「字符串约定」易错易过时；特性检测直接问「能不能做」。「问能力不问身份」是兼容性的第一原则。

**5.** 关掉 JS 访问一个主流网站（DevTools 里 disable JavaScript），记录哪些功能失效、哪些内容仍可读——评估该站的「渐进增强」完成度。

> [!TIP]
> 思路内容站（新闻/文档）通常内容仍在（HTML 承载）；重交互应用（编辑器）失效。「核心内容不依赖 JS」是无障碍/SEO/稳健性的共同基础。

**6.** 讨论：前端为什么演化出了如此重的工具链（构建/打包/类型检查），而 python/r 脚本没有？从「运行环境不可控」「代码交付给浏览器前需要优化」「类型在大型代码库的必要性」三个角度分析，并与 [python 工程化](../python/12-quality.md)对照。

> [!TIP]
> 思路核心差异：前端的「分发单位」是浏览器要下载与执行的代码——体积/兼容/性能都需要构建期处理；python 的分发单位是源码（解释器在用户侧）。运行环境的可控性决定了工具链的重量。
